# 3.18. 파이프 표현식

파이프 `|>`는 왼쪽 값을 오른쪽 함수에 넘깁니다. 그래서 자유 함수 호출이 이어질 때 실행 순서대로 읽힙니다.

```
pipe_expr       ::= expr "|>" pipe_target
pipe_target     ::= path                          // x |> f        is f(x)
                  | call_expr                     // x |> f(a, b)  is f(x, a, b)
                  | "(" closure_expr ")"          // x |> (|v| v + 1)
```

## 3.18.1. 의미

`|>`는 트레잇이 없는 언어 구문입니다. 컴파일러가 이름 해석 전에 식을 고쳐 쓰고, 결과는 평범한 호출입니다.

| 쓴 것                   | 의미                  |
|-------------------------|-----------------------|
| `x |> f`                | `f(x)`                |
| `x |> f(a, b)`          | `f(x, a, b)`          |
| `x |> p::q::f`          | `p::q::f(x)`          |
| `x |> f::<T>(a)`        | `f::<T>(x, a)`        |
| `x |> (|v| v + 1)`      | `(|v| v + 1)(x)`      |
| `x |> f |> g(a)`        | `g(f(x), a)`          |

왼쪽 피연산자는 호출의 첫 인자가 되어 거기 적은 인자들 앞에 옵니다. 뒤따르는 클로저는 그대로 마지막입니다. 오른쪽의 호출은 값을 받는 그 호출입니다. 그래서 `x |> make(a)`는 `make(x, a)`이고, `make(a)`가 돌려주는 것을 부르지 않습니다(그러려면 먼저 묶으세요: `let g = make(a); x |> g`). 메서드 호출도 값을 첫 인자로 받습니다(`x |> s.push_to(a)`는 `s.push_to(x, a)`). `x`의 메서드를 부를 때는 늘 그렇듯 `.`을 씁니다: `x.trim()`.

```nabi
let words = text
    |> split_words
    |> drop_stop_words(stop)
    |> count_by_word;
```

## 3.18.2. 우선순위

`|>`는 범위를 포함한 다른 모든 연산자보다 약하고 대입보다 강하게 묶이며([3.2.3](302-precedence-and-associativity.md#323-우선순위와-결합성-표)), 좌결합입니다. 그래서 왼쪽의 계산 전체가 넘겨지는 값입니다.

```nabi
a + b |> f          // f(a + b)
x > 0 && ok |> f    // f(x > 0 && ok)
0..n |> total       // total(0..n)
a |> f |> g         // g(f(a))
```

`try`는 피연산자 뒤의 파이프까지 덮고 `catch`는 그보다 약하게 묶입니다. 그래서 `try s |> parse |> scale(2) catch _ { 0 }`은 `(try scale(parse(s), 2)) catch _ { 0 }`입니다([3.14](314-error-control-flow.md)). `try?`와 `try!`도 `??` 앞까지 같은 방식으로 파이프를 덮습니다. `try! s |> parse`는 `try! parse(s)`이고, `try? s |> parse ?? 0`은 `(try? parse(s)) ?? 0`입니다.

줄 바꿈은 공백일 뿐이므로([1.3](../001-lexical/103-statement-terminator.md)) 줄 맨 앞의 `|>`는 위 줄의 식을 이어 갑니다. 3.18.1의 예가 그렇습니다.

## 3.18.3. 오른쪽에 올 수 있는 것

오른쪽은 함수(또는 호출할 수 있는 것)를 가리키는 경로, 호출, 괄호로 감싼 클로저입니다. 그 밖의 것은 무엇을 쓰라고 알려 주는 컴파일 에러입니다. `x |> 2`와 `x |> a + b`는 에러이고, `|>`가 가장 약하게 묶이므로 `x |> f + 1`도 에러입니다(`(x |> f) + 1`로 쓰세요).

`|>`는 고정 토큰입니다([1.10.3](../001-lexical/110-punctuation-and-operator-tokens.md#1103-고정-토큰표)). `#[infix]`로 등록할 수 없고, `a|>b`는 언제나 파이프입니다.
