# 8.7. 코드 생성

`nabic`는 기계어를 직접 만듭니다. 코드 생성기가 nabi-mir를 받아 타깃용 object 파일을 쓰고, `nabic`의 링커가 실행 파일을 만듭니다([9.2.14](../009-tools/902-aot-pipeline.md#9214-링킹실행-파일의-경우)). 모든 최적화 수준과 REPL 셀이 같은 코드 생성기를 씁니다. 코드 생성기가 내보내는 것은 8.8 ~ 8.10의 lowering 규칙이 정하고, 이 문서는 그 앞뒤 단계를 다룹니다.

## 8.7.1. 변환 흐름

```
nabi source
   | parse, name resolution, type check
nabi-hir
   | specialize / monomorphize, desugar
nabi-mir
   | optimization (-O1 and above, 8.7.3)
nabi-mir
   | lowering: layouts, conventions, GC frames, barriers, checks (8.8 ~ 8.10)
LIR (one low-level form for every target)
   | instruction selection, register allocation (above -O0)
machine code
   | object writer
object (Mach-O, ELF, COFF, wasm)
   | nabic's linker
executable
```

모든 단계는 `nabic` 안에서 실행됩니다. 8.8 ~ 8.10의 코드 예시는 의사 코드입니다. 블록과 분기는 nabi-mir의 모양(`bb1:`, `if c then bb2 else bb3`, `goto bb4(x)`)으로 쓰고, 내보내는 코드가 중요한 곳은 바이트 오프셋의 load / store로 씁니다. `nabic`가 읽는 형식은 아닙니다.

## 8.7.2. 각 단계의 책임

| 단계 | 정하는 것 |
|------|-----------|
| nabi-mir → 최적화한 nabi-mir | `-O0`보다 높은 수준의 인라이닝과 단순화(8.7.3) |
| nabi-mir → LIR | 명령어 집합과 무관한 모든 것. 모든 값의 레이아웃(8.8), 호출 규약([8.6](806-calling-convention.md)), shadow stack 프레임, 할당 fast path, write barrier, safepoint poll(8.9), overflow / 경계 검사와 그 panic 메시지 |
| LIR → 기계어 | 명령어 집합 하나(`x86_64`, `aarch64`, i686, armv7, riscv64, riscv32, powerpc64le, s390x, wasm32)의 명령어. `-O0`보다 높으면 어떤 값을 레지스터에 둘지도 정합니다 |
| 기계어 → object | 컨테이너(Mach-O, ELF, COFF, wasm object)와 그 재배치, unwind 정보, `-g`일 때 디버그 정보([9.9.6](../009-tools/909-debug-tools.md#996-디버거-통합-gdb--lldb)) |
| object → 실행 파일 | `nabic`의 링커. `NABI_CC`로 대체합니다([9.2.14](../009-tools/902-aot-pipeline.md#9214-링킹실행-파일의-경우)) |

## 8.7.3. 최적화 수준

| 수준 | nabi-mir | 값 |
|------|----------|----|
| `-O0` | 만든 그대로 | 각자 자기 스택 슬롯에 |
| `-O1` | 최적화. 루프 안의 호출은 `-O2`처럼 인라인, 그 밖에서는 작은 함수와 `#[inline]` 함수와 한 곳에서만 부르는 함수만 | 들어가면 레지스터에 |
| `-O2` | 최적화. 루프 밖에서도 더 큰 본문을 인라인 | 들어가면 레지스터에 |
| `-O3` | `-O2`에 더해 루프 안에서 더 큰 본문을 인라인하고, 스칼라로 남는 루프를 펼침 | 들어가면 레지스터에 |
| `-Os` | 최적화. 본문이 호출과 비슷하게 작을 때만 인라인(루프 안에서는 그 몇 배까지) | 들어가면 레지스터에 |

최적화기는 빌드가 본문을 가진 Nabi 함수의 직접 호출을 인라인합니다. 패키지 자신의 함수, 제네릭 인스턴스, 그리고 빌드마다 프로그램과 함께 컴파일하는 표준 라이브러리의 함수가 그렇습니다. 호출 사이클을 자기 안으로 인라인하지는 않고, `#[inline(never)]`와 `#[cold]` 함수, panic으로 끝나는 경로 위의 호출은 호출로 남습니다. 루프 안으로 인라인한 본문의 호출은 그 루프 안의 호출로 다시 따집니다. 상수로 된 배열(`const` 표)을 피호출자가 읽기만 하는 매개변수로 넘기는 호출은 그 배열을 스스로 만드는 피호출자 사본으로 가므로, 호출이 표를 복사하지 않습니다. 그다음 복사와 상수를 전파하고, 상수 식을 접고, 공통 부분식과 죽은 코드를 없애고, 제어 흐름을 단순하게 하고, 들어오는 길에서 이미 갈 쪽을 아는 분기는 건너뛰어 바로 그쪽으로 가게 하고(인라인한 반복자의 `next()`가 돌려주고 그 둘레의 `for` 루프가 검사하는 `Option`), 자기 꼬리 호출을 루프로 바꾸고, 결과가 늘 들어맞는 overflow 검사를 없애고, 루프 불변 계산을 루프 밖으로 옮깁니다. `-O3`에서는 벡터화기가 스칼라로 남기는 루프(8.7.8. float 합을 쌓거나 함수를 부르는 루프)의 strip도 펼칩니다. strip 하나를 통째로 돌 때 본문을 4번(본문이 길면 2번) 돈 뒤에야 카운터를 검사합니다. 프로그램이 계산하는 모든 값, 모든 trap(overflow, 나눗셈, 경계), 모든 부수 효과는 같은 순서로 남습니다.

`-g`는 어느 수준에서도 생성되는 코드를 바꾸지 않습니다. `-O0`보다 높은 수준에서 최적화기는 자기가 한 일을 디버그 정보를 위해 기록합니다. 인라인한 본문은 호출 아래의 별도 범위가 되고, 대입을 없앤 이름 있는 지역 변수는 그 값을 대신 담은 것(상수, 변수가 보이는 동안 값이 바뀌지 않는 다른 지역 변수, 또는 제자리에서 만든 struct의 필드)을 남깁니다. 그다음 코드 생성기가 코드 범위마다 각 변수가 어디 있는지 적습니다([9.9.6](../009-tools/909-debug-tools.md#996-디버거-통합-gdb--lldb)). `-O3`가 펼친 루프 본문의 복사본에서는 다른 지역 변수의 값으로 남은 변수가 앞선 반복의 값을 보여 줄 수 있습니다.

명령어 선택은 모든 수준에서 같지만, `-O0`보다 높은 수준에서는 루프를 벡터화할 수 있고(8.7.8), RISC-V 코드는 16비트 압축(`C`) 형식이 있고 재배치가 고치지 않는 명령어마다 그 형식을 쓰며, 분기와 점프는 그 형식이 목표에 닿을 때 씁니다. shadow stack 프레임, poll, barrier는 최적화가 끝난 뒤, 실제로 컴파일하는 코드 위에 놓습니다(8.9). 코드는 타깃의 기준 CPU용이지만, `-C target-cpu`와 `-C target-feature`가 켜는 기능 가운데 코드 생성기가 쓰는 것은 예외입니다([0.6.4](../000-meta/006-platform-targets.md#064-simd)). `x86_64`의 AVX2 벡터 루프와 명령어 하나짜리 비트 세기, `aarch64`의 LSE atomic, RCpc acquire load와 바이트 내적, `s390x`에서 `vector`가, `riscv64`에서 `v`가 있을 때의 벡터 루프, `riscv64`와 `riscv32`에서 `zbb`가 있을 때 명령어 하나짜리 회전, `x86_64`에서 `fma`가, `armv7`에서 `vfp4`가 있을 때 하나로 합친 `mul_add`가 그렇고, `-neon`, `-vsx`, `-simd128`은 모든 루프를 스칼라로 둡니다.

## 8.7.4. 연산

- 정수와 부동소수 산술, 비교, `sqrt`, 비트 세기(`count_ones`, `leading_zeros`, `trailing_zeros`), `swap_bytes`, atomic 연산은 명령어입니다(LSE가 없는 `aarch64`의 atomic read-modify-write는 배타적 load / store 루프). `-O0`보다 높은 수준에서 atomic 연산은 프로그램이 요구하는 순서만큼만 강하며, 흔히 쓰는 C++ 대응을 따릅니다. `x86_64`와 `i686`에서는 `SeqCst` store만 fence를 둡니다. `aarch64`에서는 `Relaxed` load와 store가 보통 load와 store이고, acquire load는 `ldar`(`rcpc`가 있으면 `ldapr`), release store는 `stlr`이며, read-modify-write는 LSE나 배타적 명령어의 acquire / release 형태를 씁니다. `armv7`에서는 release 앞과 acquire 뒤에 `dmb`가 옵니다. `powerpc64le`에서는 release 앞에 `lwsync`(`SeqCst`는 `sync`), acquire 뒤에 `lwsync`나 `isync`가 옵니다. RISC-V는 `fence`와 `aq` / `rl` 비트를 씁니다. `s390x`에서는 `SeqCst` store만 직렬화합니다. `wasm32`의 atomic은 순차 일관성입니다. `-O0`에서는 모든 atomic 연산이 순차 일관성(sequentially consistent)이라 어떤 순서도 만족합니다([0.6.4](../000-meta/006-platform-targets.md#064-simd)).
- 명령어 집합에 해당 명령어가 없으면 플랫폼의 지원 루틴을 부릅니다. armv7에서는 모든 폭의 정수 나눗셈(`__aeabi_idiv`, `__aeabi_uidiv`, `__aeabi_ldivmod`, `__aeabi_uldivmod`), 64비트 정수와 부동소수 사이의 변환(`__aeabi_l2d`, `__aeabi_d2lz`, ..), 64비트 곱셈의 오버플로 검사(`__mulodi4`)입니다. soft-float인 riscv32에서는 모든 부동소수 산술, 비교, 변환(`__adddf3`, `__ltdf2`, `__floatdidf`, ..)과 64비트 나눗셈(`__divdi3`, `__umoddi3`, ..)입니다. i686은 64비트 정수 나눗셈을 오브젝트 안의 루틴으로 합니다.
- `-O0`보다 높은 수준에서 `mul_add`는 타깃에 그런 명령어가 있으면(`aarch64`, `powerpc64le`, `s390x`, `riscv64`, `fma`를 켠 `x86_64`, `vfp4`를 켠 `armv7`) 곱셈과 덧셈을 합친 명령어 하나이고, 없으면 런타임의 `nabi_f64_mul_add` / `nabi_f32_mul_add` 호출입니다. 어느 쪽이든 한 번 반올림합니다.
- 나머지 부동소수 메서드(`floor`, `round`, `sin`, `exp`, `pow`, ..)는 libm을 부르는 런타임의 `nabi_f64_*` / `nabi_f32_*` 함수 호출입니다([8.5](805-extern-symbols.md)). 그래서 결과는 항상 타깃의 libm이 내고, 호스트에서 컴파일 시간에 계산하지 않습니다.
- nabi-mir의 분기는 모두 점프 또는 두 갈래 분기입니다. 태그나 정수에 대한 `match`는 arm 순서대로 비교하는 사슬입니다(8.9.3). 점프 테이블은 만들지 않습니다.

## 8.7.5. 가속 영역 라이브러리

Nabi 소스는 코드 생성기에 직접 접근하지 않습니다. 텐서 / 자동 미분 / SIMD / GPU 같은 가속 영역의 라이브러리가 코드 생성기에 닿는 백엔드 인터페이스는 계획만 있고 구현되지 않았습니다. 0.1에서는 `nabic` 자신의 코드 생성기가 유일하고, [8.11.13](811-backend-contract.md#81113-따로-설치하는-코드-생성기)의 따로 설치하는 코드 생성기는 0.2를 위한 초안입니다. 코드 생성기가 오브젝트에 대해 보장해야 하는 것은 [8.11](811-backend-contract.md)이 정합니다.

## 8.7.6. `extern` 함수(런타임 함수)

[Extern "C" 심볼](805-extern-symbols.md)에 나오는 `nabi_*` 함수는 C ABI([8.6](806-calling-convention.md))로 심볼 이름으로 부르고, 링크 때 `libnabir.a`에서 해소합니다. 문자열 동등 비교와 그래서 문자열 패턴은 `nabi_str_cmp`를 부릅니다. TLAB fast path, write barrier의 fast path, safepoint poll은 인라인 코드이고, slow path에서만 `nabi_gc_alloc_slow`, `nabi_gc_wb_slow`, `nabi_runtime_yield`를 부릅니다(8.9.9 ~ 8.9.11).

## 8.7.7. TLS 접근

[Mutator TLS 슬롯](803-tls-slots.md)의 TLS 슬롯은 thread-local 블록 `nabi_tls`의 주소를 거쳐 접근합니다. Nabi 함수는 이 주소를 호출자에게서 숨은 마지막 인자로 받습니다([8.6.6](806-calling-convention.md#866-nabi-함수-사이의-호출-규약)). Nabi 밖에서 들어오는 코드는 진입할 때 한 번, 타깃의 TLS 접근 명령어로 계산합니다([8.3.8](803-tls-slots.md#838-컴파일러-출력-형식)). 그다음 각 슬롯은 그 주소에서 오프셋만큼 떨어진 곳의 load 또는 store입니다.

```
t = <nabi_tls address>            ; the hidden last argument, or computed once at entry
flag = load.u8 [t + 10p+8]        ; yield_flag: offset 88 when p = 8
```

## 8.7.8. 루프 벡터화

`-O0`보다 높은 수준에서 `x86_64`(SSE2, `avx2` 기능이 켜지면 AVX2), `i686`(SSE2), `aarch64`(NEON), `armv7`(NEON, 정수 레인만. NEON은 subnormal 부동소수를 0으로 만듭니다), `powerpc64le`(VMX와 VSX), SIMD128을 켠 `wasm32`, `vector`를 켠 `s390x`(z13. `vector-enhancements-1`(z14)이면 4바이트 부동소수 레인도), `v`를 켠 `riscv64`(벡터 길이가 얼마든 벡터 레지스터마다 128비트)([0.6.4](../000-meta/006-platform-targets.md#064-simd))는, `usize` 카운터를 바뀌지 않는 경계까지 하나씩 올리며 poll하지 않는 루프(카운터 루프의 strip이나 짧은 루프: [8.4.2](804-safepoint.md#842-삽입-위치)) 앞에 벡터 루프를 둘 수 있습니다(`-Os`에서는 벡터 루프가 스칼라 루프와 비슷한 길이가 되는, nabi-mir 문장 24개 이하의 본문만). `List`, 슬라이스, 문자열의 바이트를 도는 `for` 루프(`for x in xs`, `for x in xs[a:]`, `for (i, x) in xs.iter().enumerate()`, `for b in s.bytes()`)도 반복자의 `next()`가 인라인되면 범위 루프처럼 그런 루프가 되고, 최적화기가 경계 검사를 없앤 루프도 그렇습니다. 벡터 루프는 한 가지 폭의 원소로 된 16바이트(AVX2에서는 32바이트) 벡터로 일하고, 하지 않은 반복은 뒤따르는 스칼라 루프에 남깁니다. 루프 본문이 다음만 할 때 벡터 루프가 생깁니다.

- 버퍼(`List`의 버퍼) 원소를 카운터 위치, 카운터에 작은 상수를 더한 위치, 또는 카운터에 루프가 바꾸지 않는 값(슬라이스의 시작)을 더한 위치에서 읽고 씁니다.
- 계산하는 값보다 좁은 원소는 넓히려고만 읽고(`u8`의 `b as u32`), 좁은 원소에는 그 폭으로 좁힌 값만 씁니다(`x as u8`). `powerpc64le`만 빼고 모든 타깃에서 그렇습니다.
- 그 원소와 루프가 바꾸지 않는 값으로 계산합니다. 정수 `+`, `-`, `*`(wrapping이나 checked. `*`는 타깃이 곱할 수 있는 폭만, checked `*`는 곱마다 상위 절반도 주는 폭만: `x86_64`와 `i686`은 2바이트 레인, `aarch64`와 `s390x`는 1~4바이트, `wasm32`는 2바이트와 4바이트, `riscv64`는 모든 폭), `&`, `|`, `^`, `!`, 상수만큼의 시프트, 비교, 정수 사이와 `bool`에서의 `as`, 부동소수 `+`, `-`, `*`, `/`, 부호 반전, `sqrt`, `min`, `max`(`armv7`에서는 빼고), 그리고 타깃과 그 벡터 장치가 둘 다 합칠 수 있을 때의 `mul_add`(`aarch64`, `powerpc64le`, `riscv64`, `fma`를 켠 `x86_64`, 8바이트 레인이거나 `vector-enhancements-1`을 켠 `s390x`)입니다.
- 그런 값으로 분기합니다(`if`, `&&`, `||`). 레인마다 양쪽을 다 계산하고 조건이 고르는 쪽을 남깁니다. 한쪽에서는 모든 레인이 읽어도 되는 원소(모든 반복이 지나는 블록이 읽는 원소, 루프가 지키는 경계 검사 아래의 원소)를 읽을 수 있습니다. 조건의 양쪽이 한 원소에 쓰면 두 쓰기를 합칩니다. 한쪽에서만 쓰려면 마스크를 건 쓰기가 있어야 합니다(AVX2, 4바이트와 8바이트 원소).
- 루프를 일찍 나갑니다(`return`, `break`, 실패한 경계 검사).
- 정수 리덕션을 쌓습니다. `+`나 `-`(wrapping이나 checked), `&`, `|`, `^`, 개수 세기(`if c { n += 1 }`, `n += c as T`), 최솟값이나 최댓값(`m = m.min(x)`, `if x > m { m = x }`)이고, 조건의 한쪽에서 쌓아도 여러 쪽에서 쌓아도 됩니다. 바이트 곱의 합(`s += (a[i] as i32) * (b[i] as i32)`. `dotprod`가 있는 `aarch64`에서는 레인 하나에 곱 넷)도 됩니다. 또는 부동소수 최솟값이나 최댓값을 같은 두 가지 꼴로 쌓습니다.

벡터화한 루프가 하는 일은 스칼라 루프가 원소 하나하나에 하는 일과 같습니다.

- 루프를 나가거나 trap할(overflow, 실패한 경계 검사) 원소가 든 벡터는 돌지 않습니다. 스칼라 루프가 그 벡터의 첫 원소부터 이어받아, 그 원소에서 나가거나 panic하며, 그 앞의 원소는 모두 처리되어 있습니다.
- 리덕션은 레인마다 부분 결과를 두고 끝에 레인들을 합칩니다. checked 합은 음이 아닌 원소와 음수 원소를 따로 더해, 스칼라 루프가 만들 모든 부분합의 범위를 잡습니다(한 반복의 어느 길로 가든 갱신이 한 번일 때). 그 범위의 어느 쪽이든 타입에 들어가지 않으면 루프를 처음부터 스칼라 코드로 다시 돌리므로(그런 루프는 메모리에 쓰지 않습니다), 스칼라 루프가 panic하는 바로 그 자리에서 panic하거나 panic하지 않습니다. 최솟값과 최댓값은 모든 레인이 누산기 값에서 시작합니다. 같은 두 정수 가운데 어느 쪽을 남겨도 드러나지 않습니다. checked인 바이트 곱의 합은 곱의 절댓값 합도 함께 두어 모든 부분합의 범위를 잡고, 그 범위가 타입에 들어가지 않으면 루프를 스칼라 코드로 다시 돌립니다.
- 부동소수 합은 벡터화하지 않습니다. 부동소수 합은 프로그램의 순서대로 더하고, 순서가 다르면 반올림이 달라집니다. 부동소수 최솟값과 최댓값은 모든 입력에서 스칼라 루프와 같은 비트를 냅니다. NaN도 0도 아닌 수들의 최솟값(최댓값)은 어느 순서로 구해도 한 값이라 레인이 구해도 됩니다. NaN이나 0(스칼라 `min` / `max`가 몇몇 타깃에서 피연산자 순서로 부호를 정하는 값)이 든 벡터는 돌지 않고 스칼라 루프가 그 벡터와 나머지를 이어받으며, 루프가 시작할 때 누산기가 NaN이면 루프 전체가 스칼라로 돕니다. `y = a.min(b)` 같은 맵도 NaN이나 두 0이 만나는 벡터는 스칼라 루프에 남깁니다. 곱셈과 덧셈을 명령어 하나로 합치는 것은 프로그램이 `mul_add`를 부를 때뿐입니다.
- 스칼라 루프가 쓰지 않는 원소에는 쓰지 않습니다. 조건의 한쪽에서 하는 쓰기는 마스크를 걸어 쓰거나, 아니면 루프가 스칼라로 남습니다.
- 같은 리스트일 수 있는 두 리스트의 원소는 읽고 쓰는 순서를 지킵니다. 벡터가 그 순서를 바꾸는 곳에서는, 앞의 검사가 서로 다른 버퍼임을 확인할 때만 벡터 루프가 돕니다. 루프가 바꾸지 않는 오프셋에 있는 한 버퍼의 두 행(`r[o1 + i]`와 `r[o2 + i]`)도 같아서, 앞의 검사가 두 오프셋이 같거나 벡터 하나만큼 이상 떨어졌음을 확인할 때만 벡터 루프가 돕니다. 슬라이스의 시작을 거친 인덱스(checked `isize` 덧셈)는 `isize::MAX` 아래에서 정확합니다. 앞의 검사가 시작과 경계가 그보다 훨씬 작은지 확인하고, 아니면 스칼라 루프가 돕니다.
- 벡터 루프는 safepoint에 닿지 않고 poll하지 않습니다. 최대 1024번 반복한 뒤에는 poll을 가진 스칼라 루프가 다시 돕니다.

`-g`에서 벡터 루프의 명령어는 루프 첫 문장의 위치에 있습니다. 벡터 루프가 도는 동안 루프의 변수는 시작할 때의 값을 그대로 가집니다.
