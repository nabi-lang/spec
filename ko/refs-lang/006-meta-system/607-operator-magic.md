# 6.7. 연산자 매직

`#[infix]`, `#[prefix]`, `#[postfix]` 세 속성은 연산자 토큰을 트레잇 메서드에 연결하는 일만 합니다. 우선순위와 결합성은 [3.2.3](../003-expressions/302-precedence-and-associativity.md#323-우선순위와-결합성-표)의 표가 언어 수준에서 고정합니다. 이 속성으로 정하거나 바꿀 수 없습니다. [연산자 디스패치](../003-expressions/301-operator-dispatch.md)에서 연산자를 메서드 호출로 푸는 메커니즘은 이 세 매직 없이는 동작하지 않습니다.

```
infix_attr      ::= "#" "[" "infix" "(" string_lit ("," like_arg)? ("," "swap")? ")" "]"
prefix_attr     ::= "#" "[" "prefix" "(" string_lit ("," like_arg)? ")" "]"
postfix_attr    ::= "#" "[" "postfix" "(" string_lit ("," like_arg)? ")" "]"
like_arg        ::= "like" "=" string_lit
```

## 6.7.1. 세 속성

세 속성은 다음과 같이 씁니다.

```nabi
trait Add<Rhs = Self> {
    type Output;
    #[infix("+")]
    fn add(self, rhs: Rhs) -> Output;
}

trait Neg {
    type Output;
    #[prefix("-")]
    fn neg(self) -> Output;
}

trait Degrees {
    #[postfix("°", like = "?")]    // 확장 토큰, 후위 ? 와 같은 단계
    fn degrees(self) -> f64;
}
```

각 속성이 붙는 위치와 나타내는 연산 형태는 다음과 같습니다.

| 속성                  | 위치          | 형태                |
|-----------------------|---------------|---------------------|
| `#[infix(sym)]`       | 트레잇 메서드 | 이항 (`a SYM b`)    |
| `#[prefix(sym)]`      | 트레잇 메서드 | 전위 단항 (`SYM a`) |
| `#[postfix(sym)]`     | 트레잇 메서드 | 후위 단항 (`a SYM`) |

## 6.7.2. 인자

각 속성이 받는 인자는 다음과 같습니다.

| 인자   | 의미                                            | 필수 여부                      |
|--------|-------------------------------------------------|--------------------------------|
| `sym`  | 연산자 토큰 (문자열 리터럴)                     | 필수                           |
| `like` | 새 토큰이 따를 기존 토큰 (그 단계와 결합성)     | 3.2 표에 없는 토큰에만, 필수   |
| `swap` | 피연산자 순서를 바꿔 연결 (infix만)             | 선택                           |

`sym`과 `like`도 여느 문자열 리터럴과 같습니다. 토큰은 문자열의 값이므로 `"\\"`와 `r"\"`는 둘 다 한 글자 토큰 `\`를 가리킵니다(`a \ b`).

`swap`은 이항 연산의 두 피연산자 순서를 바꾸어 연결합니다. `#[infix("∈", swap)]`가 붙은 `contains`가 있으면 `a ∈ b`는 `b.contains(a)`로 풀립니다. 컨테이너가 왼쪽에 오지 않는 연산자(`∈ ∉`)를 위한 인자입니다.

3.2 표에 있는 토큰에는 `like`를 쓸 수 없습니다. 우선순위나 결합성을 지정하는 인자(`prec`, `left` / `right` / `none` 등)는 없습니다. 쓰면 컴파일 에러입니다.

```nabi
#[infix("+")]
#[prefix("-")]
#[infix("⊕", like = "+")]      // 새 토큰, + 와 같은 단계, 같은 결합성
```

## 6.7.3. 연결 메커니즘

`#[infix("+")]`를 트레잇 메서드 `add`에 붙이면 컴파일러는 다음과 같이 동작합니다.

먼저 `+` 토큰을 그 트레잇에 연결합니다. 그다음 식 `a + b`를 `<typeof(a) as 그_트레잇<typeof(b)>>::add(a, b)` 형태로 풉니다. 우선순위와 결합성은 [우선순위와 결합성](../003-expressions/302-precedence-and-associativity.md)의 표에서 `+`에 고정된 값(9, 좌결합)을 그대로 씁니다.

세 속성은 모두 같은 패턴을 따릅니다. 연결되는 것은 토큰, 위치, 트레잇 메서드뿐입니다.

피연산자는 그 호출의 인자처럼 타입이 정해집니다. 리터럴 오른쪽 피연산자(`[1.0, 2.0]`, `{..}`, 숫자)는 왼쪽 피연산자에 대해 고른 impl의 매개변수 타입을 받습니다. 그래서 그 impl의 메서드가 `Vector<f64>`를 받으면 `t ⊲ [1.0, 2.0]`은 `Vector<f64>`를 넘깁니다. 클로저 피연산자는 바운드에서처럼 자기 `fn` 타입의 impl을 만족하고([4.4.2](../004-functions/404-function-type.md#442-함수--클로저-값의-타입)), 블랭킷 `impl<F: Tr> Op for F`도 적용됩니다. 타입 매개변수가 없는 트레잇이면 메서드 자신의 매개변수 타입이 오른쪽 피연산자의 타입입니다.

`ref self`를 받는 메서드는 왼쪽(또는 하나뿐인) 피연산자를 메서드 호출이 수신자를 받듯이 받습니다. 피연산자가 변수나 그 필드이면 메서드가 바꾼 값을 거기에 다시 씁니다. 그래서 `fn draw(ref self, d: D)`일 때 `g ∼ d`는 `g.draw(d)`처럼 `g`를 진행시킵니다. 클로저가 값 캡처한 변수는 메서드 호출과 같이 거부합니다([4.6.7](../004-functions/406-capture-semantics.md#467-struct와-참조-핸들의-캡처)).

연산자는 throw하지 않으므로([4.14](../004-functions/414-throws.md)) 메서드는 `throws` 없이 선언해야 합니다. throw하는 메서드에 연산자 속성을 붙이면 선언에서 에러입니다. 실패할 수 있는 연산은 에러를 값(`Result<T, E>`나 `T | E`)으로 돌려주고 호출하는 쪽이 처리하거나(`try (a ⧵ b).get()`, `match`), 속성 없는 이름 있는 메서드로 남깁니다(`try a.solve(b)`).

```nabi
trait Solve<Rhs = Self> {
    type Output;
    #[infix("⧵", like = "/")]     // ERROR: `solve`가 throw함. 연산자는 throw하지 않음
    fn solve(self, rhs: Rhs) throws (str) -> Output;
}
```

## 6.7.4. Unicode와 다중 alias

한 메서드에 `#[infix]`를 여러 개 붙이면 여러 토큰을 같은 메서드에 매핑할 수 있습니다.

```nabi
trait Join<Rhs = Self> {
    type Output;
    #[infix("⊕", like = "+")]
    #[infix("⊞", like = "+")]
    fn join(self, rhs: Rhs) -> Output;
}
```

두 토큰 모두 `join`을 부릅니다. `÷ ≡ ≠ ≤ ≥`에는 별칭이 필요 없습니다. 어휘 분석기가 이들을 `/ == != <= >=`로 읽으므로([1.10.3](../001-lexical/110-punctuation-and-operator-tokens.md#1103-고정-토큰표)) ASCII 토큰과 같은 메서드에 닿습니다. ASCII 토큰의 트레잇(`<=`이면 `PartialOrd`)을 구현하면 두 표기가 모두 동작합니다.

이 표기를 등록하면 컴파일 오류입니다. 어휘 분석기는 `≤` 토큰을 만들지 않으므로, 여기에 묶은 연결은 절대 불리지 않습니다. 오류는 ASCII 토큰과 구현할 트레잇을 알려 줍니다. 유니코드 연산자 앞에 점을 붙인 것(`.≤`, `.×`)도 토큰이 아닙니다. 어휘 분석기는 `.`과 연산자를 따로 읽고, 브로드캐스트 형태는 1.10.3의 ASCII 연산자에만 있습니다.

```nabi
trait Before {
    #[infix("≤")]     // ERROR: `≤`는 고정 연산자 `<=`입니다. `ops::PartialOrd`를 구현하세요
    fn before(self, rhs: Self) -> bool;
}
```

## 6.7.5. 충돌 검사

같은 (토큰, 위치) 조합에 서로 다른 트레잇이 붙으면 등록하는 시점에 에러입니다.

```nabi
trait MyAdd { #[infix("+")] fn add(...) ... }
// 다른 라이브러리 / 모듈.
trait Add { #[infix("+")] fn add(...) ... }
// → '+' 이항 위치에 트레잇이 둘. ERROR.
```

(토큰, 위치) 조합마다 등록은 하나만 허용됩니다.

## 6.7.6. 같은 토큰의 여러 위치

`-`처럼 전위와 이항 양쪽에 쓸 수 있는 토큰은 위치마다 따로 등록한 것으로 다룹니다.

```nabi
trait Sub<Rhs = Self> {
    type Output;
    #[infix("-")]
    fn sub(self, rhs: Rhs) -> Output;
}

trait Neg {
    type Output;
    #[prefix("-")]
    fn neg(self) -> Output;
}
```

예를 들어 식 `-a + b`에서는 전위 `-`가 이항 `+`보다 강하게 묶이므로 `(-a) + b`로 해석됩니다.

이항 `-`와 전위 `-`는 별개의 매핑이므로 서로 다른 트레잇에 붙어도 문제가 없습니다.

## 6.7.7. 점-접두(브로드캐스트) 매핑

[브로드캐스트 연산자](../003-expressions/303-broadcast-operators.md)의 점-접두 토큰도 같은 매직으로 등록합니다.

```nabi
trait DotAdd<Rhs = Self> {
    type Output;
    #[infix(".+")]
    fn dot_add(self, rhs: Rhs) -> Output;
}

trait DotMul<Rhs = Self> {
    type Output;
    #[infix(".*")]
    fn dot_mul(self, rhs: Rhs) -> Output;
}
```

토큰만 다를 뿐 등록 메커니즘은 같습니다.

## 6.7.8. 매핑의 가시성

`#[infix]` 같은 속성으로 한 등록은 그 트레잇이 보이는 범위 안에서만 효력이 있습니다. 보인다는 것은 [5.6](../005-modules/506-visibility.md)에 따라 접근할 수 있다는 뜻입니다. 경로로 닿는 `pub` 트레잇이면 충분하고 `use`는 없어도 됩니다. 트레잇이 보이지 않는 곳에서는 연산자도 동작하지 않습니다.

이 규칙은 라이브러리 격리와 잘 맞습니다. 어떤 패키지가 정의한 사용자 정의 연산자 트레잇은 그 패키지를 가져온 코드 안에서만 동작합니다. `pub` 연산자 트레잇의 토큰도 같은 코드에 닿습니다. 렉서는 등록한 패키지에 의존하는 모든 패키지의 파일에서 그 토큰을 잘라 내므로, 의존성의 `<~`나 `<-`는 그 패키지 안에서와 똑같이 읽힙니다([1.10.4](../001-lexical/110-punctuation-and-operator-tokens.md#1104-확장-토큰)). `#[literal]` 등록은 핸들러가 `pub`이면 같은 규칙으로 그 패키지에 직접 의존하는 패키지에 적용되고([6.5.2](605-literal-magic.md#652-형태)), 그 밖의 등록은 자기 패키지에 머뭅니다.

표준 라이브러리의 연산자 트레잇(`Add`, `Sub`, `Mul`, ...)은 `core::ops`에 있습니다. 연산자를 쓰는 데는 트레잇 이름이 스코프에 없어도 됩니다. `core` 트레잇의 매핑은 모든 소스에 적용되므로 따로 가져오지 않아도 산술 식과 비교 식이 동작합니다. `impl ops::Add for V`처럼 트레잇 자체를 적을 때는 prelude 모듈 `ops`를 거치거나 `use`로 가져옵니다([stdlib 0.2.3](../../refs-standard-libraries/000-meta/002-import.md)).

## 6.7.9. 사용자 정의 연산자

사용자도 자기 트레잇에 `#[infix]` 같은 속성을 붙여 연산자 매핑을 직접 정의할 수 있습니다.

```nabi
trait CustomCombine<Rhs = Self> {
    type Output;
    #[infix("⊕")]
    fn combine(self, rhs: Rhs) -> Output;
}

impl CustomCombine for MyType { ... }

let r = a ⊕ b;            // 사용자 토큰
```

`⊕`처럼 3.2 표에 없는 토큰은 `like = "+"`처럼 기존 토큰 하나를 지정하고 그 토큰의 단계와 결합성을 따릅니다. 새 단계를 만들 수는 없습니다. 이 토큰은 [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md#1104-확장-토큰)의 확장 토큰 조건을 만족해야 합니다. 모든 글자가 Unicode `Pattern_Syntax`여야 합니다. 이미 있는 고정 토큰과 같으면 에러입니다.

토큰이 고정 토큰처럼 시작해도 됩니다. 렉서는 가장 길게 일치하는 쪽을 고르므로 `#[infix("<-", like = "+")]`를 붙이면 `c <- 3`은 연산자 하나입니다. 이렇게 고정 토큰의 첫 글자로 시작하는 토큰은 그것을 등록한 패키지의 파일에서 동작하고, 트레잇이 `pub`이면 그 패키지에 의존하는 패키지에서도 동작합니다. 그 밖의 곳에서 `a<-1`은 그대로 `a < -1`입니다([1.10.4](../001-lexical/110-punctuation-and-operator-tokens.md#1104-확장-토큰)).

이항 `@`도 `like`와 함께 묶을 수 있습니다. `#[infix("@", like = "*")]`를 붙이면 NumPy처럼 `a @ b`가 행렬곱이 됩니다. `@`는 고정 토큰으로 남고, 문법에는 다른 이항 `@`가 없습니다. 언어는 `@`를 피연산자가 끝나지 않은 자리에만 씁니다. 메타 구문 앞(`@derive`, `@Self`), 패턴의 바인딩 이름 뒤(`n @ (a, b)`), `return`에 붙인 형태(`return@f`)가 그렇습니다. 그래서 온전한 피연산자 뒤의 `@`는 트레잇이 보이는 곳에서 늘 연산자이고, 같은 파일에서도 다른 쓰임은 뜻이 그대로입니다. 전위와 후위 자리는 메타 구문이므로 `@`를 전위나 후위 연산자로는 묶을 수 없습니다.

이항 `~`도 같은 이유로 비어 있습니다. 언어는 `~`를 전위 비트 부정(`~x`)으로만 읽고 피연산자 뒤에서는 읽지 않습니다. 그래서 `#[infix("~", like = "==")]`를 붙이면 `x ~ d`("분포를 따름", 모형식 `y ~ x`)가 연산자가 되고 `~x`의 뜻은 그대로입니다. 그 밖의 고정 토큰은 3.2 표가 형태를 준 자리에서만 묶을 수 있습니다. 후위 `%`는 숫자 접미사(`95pct`, [6.5.7](605-literal-magic.md#657-사용자-정의-리터럴))를 쓰라고 알려 주는 에러이고, `->`와 `|>`는 구문입니다. 후위 `!`(계승 `n!`)도 에러입니다. 이름 뒤의 `!`는 매크로 호출(`name!(..)`)을 시작하고, 피연산자 앞의 `!`는 `not`이기 때문입니다. 함수나 메서드로 적으세요(`factorial(n)`, `n.factorial()`).

토큰에는 식별자 글자가 들어갈 수 없습니다. `′`(`f′`는 이름)와 `ℱ`(글자)는 연산자가 될 수 없습니다. 메서드(`a.t()`)나 함수(`fourier(x)`)로 적거나 `†` 같은 기호를 고르세요([1.10.4](../001-lexical/110-punctuation-and-operator-tokens.md#1104-확장-토큰)).

## 6.7.10. 우선순위와 결합성 등급

연산자 등급은 [3.2.3 우선순위 표](../003-expressions/302-precedence-and-associativity.md#323-우선순위와-결합성-표) 한 곳에서만 정합니다. 표준 라이브러리도 사용자 코드도 등급을 정하거나 바꿀 수 없습니다. 새 토큰은 `like`로 기존 단계 가운데 하나에 붙습니다.

## 6.7.11. 평가 시점

컴파일러는 `#[infix]` 등의 등록을 파싱 직후의 메타 확장 단계에서 처리합니다. 이후의 식 파싱은 모두 등록 표를 참조합니다.

스캐너 사전 패스(scanner pre-pass)가 등록을 미리 모으므로 같은 컴파일 단위 안에서는 등록과 사용의 순서가 상관없습니다. 3.2 표에 있는 토큰의 우선순위는 등록과 상관없이 처음부터 정해져 있습니다.

## 6.7.12. 다른 단계의 alias 금지

한 트레잇 메서드에 붙는 별칭(alias)은 모두 같은 단계의 토큰이어야 합니다.

```nabi
trait Before {
    #[infix("<")]
    #[infix("⊲", like = "+")]    // ERROR: < 는 4 단계, + 는 9 단계
    fn lt(self, rhs: Self) -> bool;
}
```

별칭끼리는 의미가 같다고 가정하기 때문입니다.

## 6.7.13. 트레잇 메서드 외 부착 금지

`#[infix]`, `#[prefix]`, `#[postfix]`는 트레잇의 메서드 시그니처에만 붙일 수 있습니다. 자유 함수, `impl` 메서드, 트레잇 밖의 일반 메서드에는 붙일 수 없습니다.

```nabi
fn my_add(a: i32, b: i32) -> i32 { a + b }
#[infix("+++")]                              // ERROR: 자유 함수에 부착 불가
fn my_concat(a: str, b: str) -> str { ... }
```

연산자 매핑을 트레잇 시스템에 묶어야 디스패치가 일관되기 때문입니다.

## 6.7.14. 값 호출: `ops::Call`

호출 대상이 함수가 아닌 값이고 그 타입이 `core::ops::Call`([stdlib 2.3](../../refs-standard-libraries/200-core/203-ops.md))을 구현하면 `v(a)`는 `v.call(a)`입니다. 인자는 값 하나로 넘어갑니다. 하나면 그대로, 여럿이면 튜플로(`p(x, y)`는 `p.call((x, y))`), 없으면 `()`로 넘어갑니다. 그래서 보간기, 다항식, 분포의 밀도 함수를 그것이 나타내는 함수처럼 씁니다. `s(1.5)`, `xs |> s`로 부르고, `s.(xs)`는 `fn`처럼 원소마다 적용합니다.

```nabi
struct Spline { a: f64; }

impl ops::Call<f64> for Spline {
    type Output = f64;
    fn call(self, x: f64) -> f64 { self.a * x }
}

let s = Spline { a: 2.0 };
s(1.5);                          // 3: s.call(1.5)
```

`Args`가 다른 impl이 여럿이면 다른 오버로드된 트레잇 메서드처럼 인자로 고릅니다([3.1.3](../003-expressions/301-operator-dispatch.md#313-디스패치는-vtable-없이)). 구체 `Call<f64>` 옆에 제네릭 `impl<const N: usize> Call<Array<f64, N>>`이 있으면 `s(1.5)`와 모든 랭크 배열의 `s(xs)`가 되고, `s(1)`은 `f64` impl을, `s([1.0, 2.0])`은 랭크 1 impl을 고릅니다. 호출할 수 있는 값을 담은 필드는 `(r.f)(x)`로 부릅니다. `r.f(x)`는 메서드를 뜻합니다([4.9.6](../004-functions/409-method.md#496-자유-함수와-메서드의-호출-형태)). 바운드 `F: Call<f64, Output = f64>`가 있으면 `f(x)`는 그것을 거쳐 호출합니다. 인자는 위치로만 넘깁니다. `fn` 값과 클로저는 바로 호출되며 아무것도 구현하지 않습니다. 그 밖의 타입의 값을 호출하면 에러이고, 도움말이 써야 할 impl을 보여 줍니다.

## 6.7.15. 정리

연산자 매직은 `#[lang]`과 함께 [언어와 표준 라이브러리의 경계](../000-meta/004-language-vs-standard-libraries.md)에서 언어 토큰을 라이브러리 트레잇에 연결하는 중심 메커니즘입니다.

표준 라이브러리의 연산자 사양은 이 매직으로 모든 토큰의 의미를 정합니다.
