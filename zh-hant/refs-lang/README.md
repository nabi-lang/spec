# Nabi 語言參考

本文件是 Nabi 程式語言的形式規格。它定義語言的**語法**與**語意**，並提供編譯器和執行環境必須遵循的規範基準。

編譯器與標準函式庫的實際實作位於另外的儲存庫。

---

## 章節

Nabi 規格由十章組成，編號為 0 到 9。各章並非隨意排列，而是依相依順序排列，使每一章的定義只用到前面章節的概念。第 0 章（meta）在最前面；接著從語彙結構開始，逐步進入更抽象的領域，最後以執行環境與工具作結。

| # | 章                                                            | 範圍                                                                        |
|---|---------------------------------------------------------------|-----------------------------------------------------------------------------|
| 0 | [Meta：語言 / 建置模型](000-meta/README.md)                   | 執行引擎、管線、原始碼單元、語言 / 函式庫邊界、標準函式庫層級、平台、詞彙表、記號 |
| 1 | [語彙結構](001-lexical/README.md)                             | 原始檔、語彙單元、註解、陳述式終止符、識別字、關鍵字、字面值、標點與運算子 |
| 2 | [型別系統](002-types/README.md)                               | 型別運算式、`any`、struct / enum / union、和型別、niche、trait、impl、泛型、型別路徑、轉換 |
| 3 | [運算式](003-expressions/README.md)                           | 運算子、廣播、指派、成員存取、索引、範圍、可選鏈結、區塊、`if`、模式、`match`、迴圈、錯誤控制流程、解構、`let-else`、`using` |
| 4 | [函式](004-functions/README.md)                               | 宣告、參數、函式型別、閉包與擷取、`ref`、尾隨閉包、方法、產生器、async/await、串流、`throws`、`unsafe` 與未定義行為、進入點 |
| 5 | [變數 / 模組 / 可見性 / 套件](005-modules/README.md)          | let、const、static、mod、use、可見性、路徑、重新匯出、extern 區塊 |
| 6 | [元系統](006-meta-system/README.md)                           | 屬性、`#[cfg]`、lang/literal/keyword/operator 魔法、meta 定義、樣板記號、反射、檔案嵌入 |
| 7 | [執行環境模型](007-runtime/README.md)                         | 物件配置、記憶體配置、GC、屏障與根、並行標記、排程器、I/O 與計時器、協程、記憶體模型 |

| 9 | [執行 / 工具](009-tools/README.md)                            | nabic CLI、AOT 管線、.a 套件、NABIHIR、符號修飾、JIT、Jupyter、偵錯工具、nabi 前端與工具、nabi-mir 格式、C 編譯器 |

第 0 章收錄之後每一章都預設的建置模型、平台假設與記號；讀過一次，就不必再去追查本文中反覆出現的慣例。第 1 章語彙結構緊接在後，理由很簡單：語彙單元的形狀定義好之後，型別與運算式才能成形。接著第 2 章（型別）、第 3 章（運算式）和第 4 章（函式）依序介紹在單一模組內建立和操作值所需的核心結構。

模組、可見性與套件刻意到第 5 章才出現：唯有單一檔案內的語意完全定義之後，才能討論檔案邊界與封裝。第 6 章元系統以第 1-5 章的全部內容為前提。屬性、`lang` / `literal` / `keyword` 魔法與反射是*作用於*語彙結構、型別、運算式、函式和模組之上的，因此唯有這些作用目標都定義好之後，它們的意義才會清楚。

最後，第 7 章（執行環境模型）、第 8 章（ABI 與降階）和第 9 章（執行與工具）涵蓋把表層語言變成實際執行的各個步驟。第 7 章抽象地描述物件配置、GC 與排程器；第 8 章確定記憶體和暫存器中的哪些位元實作它們；第 9 章把一切串起來，並規定使用者會接觸到的 `nabic` CLI、`nabi` 前端以及建置產出的形式。

本文經常引用下列附錄與參考資料。

- [記號（BNF、交叉引用、程式碼慣例）](000-meta/008-notation.md)
- [詞彙表](000-meta/007-glossary.md)

## 閱讀方式

### 初次閱讀（依 0 → 9 順序）

本規格的寫法是：從第 0 章依序讀到第 9 章時，每個新引入的概念都只用已經出現過的概念來解釋。也就是說，任何一章只使用它之前各章的概念，這個不變條件始終成立。因此初次閱讀者應當依序閱讀、不要跳過；這是最短的路徑。

交叉引用中的定義相依只能向後：理解目前的文件不得需要後面文件中的定義。對於橫跨多處的主題（方法分派 ↔ trait 分派、算術運算式 ↔ 運算子魔法等），可以出現向前的指引作為補充參考。即使如此，也不得*必須*先讀向前的目標才能讀懂目前的文件；它只是指向額外脈絡的指引。

### 作為參考（查詢特定項目）

規格也常被用來快速找到某個項目，而非用來學習。為此，每個項目都有穩定的節號（`<chapter>.<section>` 或 `<chapter>.<section>.<subsection>`），交叉引用一律使用這個編號。檔案路徑可能隨時間改變，不用於引用。

```
spec 2.7.4    →  002-types/207-niche-optimization.md (4th subsection)
spec 4.8      →  004-functions/408-trailing-closure.md
spec 6.10     →  006-meta-system/610-reflection.md
```

### 搜尋

整份規格都是 Markdown，因此可以直接用 ripgrep 或 grep 搜尋。不需要另外的索引或搜尋工具是刻意的：閱讀規格與建置規格用的是同一套工具。

```bash
rg "trait" spec/en/refs-lang/
rg "::=" spec/en/refs-lang/                # search BNF definitions
rg "i32" spec/en/refs-lang/002-types/      # limit to one chapter
```

## 記號慣例

本文一貫使用的慣例整理如下。完整定義與例外請見 [000-meta/008-notation.md](000-meta/008-notation.md)。

| 記號                         | 意義                                       |
|------------------------------|--------------------------------------------|
| `` `let` ``                  | 關鍵字 / 識別字（程式碼字型）              |
| `` `i32` ``                  | 型別名稱（程式碼字型）                     |
| `*emphasis*`                 | 概念上的強調（斜體）                       |
| `**strong**`                 | 警告 / 關鍵決定（粗體）                    |
| `> [!NOTE]` / `> [!WARNING]` | GitHub 風格的提示框                        |
| `name ::= ...`               | BNF 風格的文法定義                         |
| `<chapter>.<section>`        | 穩定的交叉引用鍵（例如 `2.7.4`）           |

程式碼字型只用於實際出現在表層語言中的語彙單元；概念上的強調使用斜體。關鍵決定與需要注意之處以粗體標示。

## 目錄 / 檔案命名

檔案和目錄名稱本身就設計成交叉引用鍵。

| 位置     | 形式                                   | 範例                             |
|----------|----------------------------------------|----------------------------------|
| 章       | `<NNN>-<descriptive-name>/`            | `002-types/`、`006-meta-system/` |
| 節       | `<NNN>-<name>.md`                      | `207-niche-optimization.md`      |
|          | （一位數章號 + 兩位數節號）            |                                  |
| README   | 每章的 `README.md`                     | 章節目錄 + 導覽                  |

三位數前綴的第一位是章號，後兩位是節號。例如 `207` 表示「2.7」，即型別系統章的第 7 節，這個編號直接作為穩定的交叉引用鍵。

這套命名方式折衷了 [Rust Reference](https://doc.rust-lang.org/reference/) 的描述性檔名與階層式章節組織，以及 [Python Language Reference](https://docs.python.org/3/reference/) 的編號章 / 節方式。它同時滿足兩種需求：編號對機器較友善，名稱對人較友善。
