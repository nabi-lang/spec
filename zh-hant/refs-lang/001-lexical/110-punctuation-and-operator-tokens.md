# 1.10. 標點與運算子語彙單元

本文件涵蓋運算子與標點字元序列的切分規則，只限於其語彙形式。各語彙單元的意義（優先順序、結合性、分派到哪個 trait 等）定義於 [3. 運算式](../003-expressions/README.md)。

## 1.10.1. 切分原則

運算子與標點的切分在兩個層次上運作。第一，有一張固定語彙單元表：本文件列出的字元序列一律被切分為固定的語彙單元。第二，有一張擴充語彙單元表：標準函式庫透過元系統額外註冊的字元序列也會成為語彙單元。註冊機制定義於 [`#[infix]` / `#[prefix]` / `#[postfix]` 魔法](../006-meta-system/607-operator-magic.md)。

兩張表之間的衝突會在註冊時被拒絕；固定語彙單元不能被覆寫。

## 1.10.2. 最長匹配

> [!IMPORTANT]
> 當一段輸入可以切分出多個候選語彙單元時，選擇最長的匹配。註冊的擴充語彙單元（[1.10.4](#1104-擴充語彙單元)）也是候選。

| 輸入  | 切分結果                                    |
|-------|---------------------------------------------|
| `==`  | 一個語彙單元                                |
| `=`   | 一個語彙單元                                |
| `= =` | 兩個語彙單元（以空白分隔）                  |
| `..=` | 一個語彙單元（`..=` 比 `..` 長）            |
| `..`  | 一個語彙單元                                |
| `<<=` | 一個語彙單元（`<<=` 比 `<<` 長）            |
| `<-`  | 在註冊了 `<-` 之處是一個語彙單元（比 `<` 長）；否則為 `<` 與 `-` |

## 1.10.3. 固定語彙單元表

以下是語言保留的 ASCII 範圍運算子與標點字元序列的完整清單。標準函式庫只賦予這些語彙單元意義，即 trait 方法的對應；語彙單元的形式本身由這張表決定。

### 算術 / 比較 / 邏輯

```
+       -       *       /       %       %%      **
==      !=      <       >       <=      >=
&&      ||      !
&       |       ^       ~       <<      >>
```

`%` 是算術餘數（Rem；正負號跟隨被除數），`%%` 是向下取整的模數（結果的正負號跟隨除數，因此除數為正時結果一律在 `[0, divisor)` 之內；即 Python 的 `%`）。這兩個語彙單元對應到不同的 trait，意義也不同。

各語彙單元與其所呼叫之 trait 方法的對應，定義於標準函式庫的運算子規格。本文件只保證語彙上的切分。

`**` 是乘冪（`Pow`；`**=` 是其複合形式，`.**` 是逐元素形式）；依最長匹配規則，`**=` 先於 `**` 匹配，`**` 先於 `*=` 或 `*` 匹配，`.**` 先於 `.*` 匹配。`^` 仍是位元 XOR。`use a::**`（遞迴 glob）是同一個語彙單元。

### 廣播（`.` 前綴）

這些是用於逐元素（廣播）運算、帶點前綴的形式。上述每個算術、比較、邏輯、位元與移位運算子，加上一個點前綴後，都被切分為不同的語彙單元。

```
.+      .-      .*      ./      .%      .%%     .**
.==     .!=     .<      .>      .<=     .>=
.&&     .||
.&      .|      .^      .<<     .>>
.??
```

`.??` 是逐元素的 `??`（3.3.8）；它沒有 trait。

這些形式各自對應到與其無點形式不同的 trait 方法。例如 `+` 對應 `Add::add`，`.+` 對應 `DotAdd::dot_add`；這些對應定義於標準函式庫。與無點形式不同，帶點前綴的邏輯運算子（`.&&`、`.||`）**不會**短路：由於廣播被降階為融合的迴圈，兩個運算元都會被求值（詳見 [2.6 broadcast](../../refs-standard-libraries/200-core/206-broadcast.md)）。

#### 與浮點數字面值的區分

由於 `1.` 或 `1.5` 這類浮點數字面值含有點，下列兩個輸入的切分取決於位置。

| 輸入   | 切分結果       | 理由                                                         |
|--------|----------------|--------------------------------------------------------------|
| `1.+2` | `1.`、`+`、`2` | `.` 緊接在數字之後，因此被吸收進浮點數字面值                 |
| `a.+b` | `a`、`.+`、`b` | `.` 不緊接在數字之後，因此開始一個廣播語彙單元               |

總之，數值字面值中間的 `.` 一律屬於浮點數字面值，其他位置的 `.` 則優先成為其他語彙單元形式（參見[數值字面值](106-numeric-literals.md)中的 `.` 處理規則）。

### Unicode 數學運算子

下列 Unicode 運算子也是固定語彙單元。它們的優先順序見 [3.2.3](../003-expressions/302-precedence-and-associativity.md#323-優先順序與結合性表) 的表格，所連接的 trait 見標準函式庫 [2.3 ops](../../refs-standard-libraries/200-core/203-ops.md)。

```
×       ⋅       ÷       ∘       √
≡       ≠       ≤       ≥
∈       ∉       ⊂       ⊆       ∪       ∩
```

| 語彙單元 | 碼位       | 意義（ASCII 命名的方法）               |
|------|------------|----------------------------------------|
| `×`  | U+00D7     | 外積（`cross`）                        |
| `⋅`  | U+22C5     | 內積（`dot`）                          |
| `÷`  | U+00F7     | 除法（`div`，`/` 的同義詞）            |
| `∘`  | U+2218     | 函式合成（`compose`）                  |
| `√`  | U+221A     | 平方根，前綴（`sqrt`）                 |
| `≡ ≠ ≤ ≥` | U+2261、U+2260、U+2264、U+2265 | `== != <= >=` 的同義詞 |
| `∈ ∉` | U+2208、U+2209 | 成員關係（`contains`）             |
| `⊂ ⊆` | U+2282、U+2286 | 子集（`is_proper_subset`、`is_subset`） |
| `∪ ∩` | U+222A、U+2229 | 聯集、交集（`union`、`intersection`） |

`∈ ∉` 也有 ASCII 拼法 `in` 與 `!in`，由剖析器而非語彙分析器讀取：在運算子位置，字詞 `in` 是 `∈`，直接寫在 `in` 之前（不帶空格）的 `!` 是 `∉`。`x ! in xs` 與 Python 的 `x not in xs` 是錯誤，其說明會提示寫 `!in`。

運算子字元全都選自具有 Unicode `Pattern_Syntax` 屬性的碼位。`∑ ∏ ∫` 屬於 `Pattern_Syntax`，但已被指定為識別字字元（[1.4.1](104-identifiers.md#數學記號設定檔)），因此它們不是運算子。

### 指派 / 複合指派

```
=       +=      -=      *=      /=      %=      %%=     **=
&=      |=      ^=      <<=     >>=
.=      .+=     .-=     .*=     ./=     .%=     .%%=    .**=
.&=     .|=     .^=     .<<=    .>>=
```

最後兩列是原地廣播（[3.3.7](../003-expressions/303-broadcast-operators.md#337-原地廣播)）。依最長匹配規則，`.+=` 先於 `.+` 匹配，`.**=` 先於 `.**` 匹配；`.=` 只有在後面沒有第二個 `=` 時才是語彙單元，因此 `.==` 仍是逐元素比較。

複合指派的意義（左側被求值幾次、trait 對應等）定義於運算式規格。`%%=` 是 `%%`（向下取整的模數）的複合指派形式；依最長匹配規則，`%%=` 先於 `%=` 或 `%` 匹配。

### 範圍 / 切片

```
..      ..=     :       ::
```

`..` 與 `..=` 用於範圍記法。`:` 用作切片中的位置分隔符、格式規範的引導符，以及其他各種上下文。`::` 是路徑分隔符，用來存取模組或型別的靜態項目。

### 點 / 問號

```
.       ?.      ??      ?
```

`.` 用於成員或方法存取。`?.` 是穿過和型別的點存取。`??` 是以後備值填入空槽位（`none`）的二元運算。最後，單獨的 `?` 是後綴一元運算子，當 `T | none` 值為 `none` 時，從外層函式提前回傳 `none`。其詳細意義與去語法糖規則定義於[錯誤控制流程](../003-expressions/314-error-control-flow.md#31410--運算子提前回傳-none)的 `?` 運算子一節。

`try?` 與 `try!` 不是單一語彙單元。語彙分析把關鍵字 `try` 與標點 `?` 或 `!` 產生為分開的語彙單元，剖析時則把不帶空白、緊貼在 `try` 上的 `?` / `!` 解讀為 [`try?` / `try!`](../003-expressions/314-error-control-flow.md#3143-try-與-try) 前綴運算子。帶有空白時，例如 `try !ready()`，會被解讀為 `try` 與邏輯否定 `!`。`?` 不是前綴運算子，因此 `try ? f()` 是錯誤，其說明會要求寫 `try?`。

### 單引號語彙單元：字元字面值與標籤

`'` 語彙單元分成兩種形式。第一種是 `'X'` 或 `'\X'` 形式，即單一字元（或跳脫序列）後接結尾的 `'`，這是[字元字面值](108-character-literals.md)。第二種是 `'identifier` 形式，即沒有結尾 `'` 的識別字，這是標籤語彙單元（參見[標籤](../003-expressions/313-loop-expressions.md#3134-標籤控制巢狀迴圈)與[帶標籤的區塊](../003-expressions/309-block-expressions.md#3910-帶標籤的區塊label---)）。

語彙分析透過查看 `'` 之後的兩個位元組來決定。若識別字開頭字元後接結尾的 `'`，就是字元；若識別字開頭字元後接結尾 `'` 以外的語彙單元，例如識別字字元、冒號或空白，就是標籤；跳脫序列（`'\...`）一律是字元字面值。後面接著 `\` 的識別字字元序列也是字元字面值：`'e\u{301}'` 是兩個碼位，是錯誤（E0007），而不是標籤。

### Lambda / 箭頭

```
|       ||      |>      ->      =>
```

`|>` 是管線：`x |> f(a)` 是 `f(x, a)`（[3.18](../003-expressions/318-pipe-expression.md)）。`|` 依上下文用作位元 OR、和型別分隔符以及 lambda 參數界定符。`||` 用於邏輯 OR，或開始一個沒有參數的 lambda。`->` 是函式回傳型別的箭頭，在 trait 繫結它之處也是兩個值之間的運算子（[6.7.4](../006-meta-system/607-operator-magic.md)），`=>` 是 `match` 分支的箭頭。

### 標點

```
(   )   [   ]   {   }
,   ;   @
```

各標點的用途如下。`( )` 用於分組、元組與呼叫。`[ ]` 用於索引、切片、擷取清單與陣列字面值。`{ }` 用於區塊、複合字面值與結構字面值。`,` 是引數或項目的分隔符，`;` 是陳述式終止符（參見[陳述式終止符](103-statement-terminator.md)）。最後，`@` 是元系統的語彙單元；其確切意義在第 6 章討論。

### 屬性引導符

```
#[      #![
```

`#[` 引導附加在其後項目上的屬性，即外部屬性。`#![` 引導附加在外層項目或模組上的屬性，即內部屬性。

這兩個引導符各自被切分為單一的固定語彙單元。`#` 與 `[` 之間不得出現空白；分開的語彙單元 `#` 後接 `[` 沒有定義。

外部 / 內部這一對遵循與[語彙結構](102-lexical-structure.md)中文件註解 `///` 與 `//!` 相同的模式。只有附加的方向不同；意義的歸類方式相同。

## 1.10.4. 擴充語彙單元

除了上述固定表之外，標準函式庫或使用者可以註冊的字元序列必須滿足下列條件：每個字元都必須是 `Pattern_Syntax` 碼位；不得包含識別字字元（[1.4.1](104-identifiers.md#141-格式)）；不得包含空白或行終止符；不得與固定語彙單元相同。固定語彙單元 `@` 與 `~` 是例外：註冊可以繫結它們的二元位置，那是語言留著不用的位置（[6.7.9](../006-meta-system/607-operator-magic.md#679-使用者定義的運算子)）。

識別字字元絕不是運算子字元：任何文字的字母、其中的類字母符號（`ℱ`、`α`）、數字、撇號 `′ ″ ‴ ⁗`（它們延續名稱：`f′`），以及 Unicode 列為 `Pattern_Syntax` 但 Nabi 設為識別字字元的 `∑ ∏ ∫`。因此 `ℱx` 與 `f′` 是名稱，而變換或轉置要寫成函式（`fourier(x)`）、方法（`a.t()`）或其他符號（`a†`）。剩下可以註冊的是 `Pattern_Syntax` 的其餘部分：ASCII 標點、不含撇號的一般標點區塊（`† ‡ ‰`）、箭頭（U+2190-21FF）、數學運算子（U+2200-22FF）、到 U+2BFF 為止的技術符號、幾何圖形以及補充箭頭與運算子區塊，以及補充標點 U+2E00-2E7F。

例如 `⊕`、`⊗`、`⋆` 與 `°`。擴充語彙單元的優先順序跟隨註冊時以 `like` 指定的既有語彙單元（[6.7.2](../006-meta-system/607-operator-magic.md#672-引數)）。

這樣的序列一旦註冊，語彙分析器就依 1.10.2 的最長匹配把它切成單一語彙單元：註冊的 `<-` 勝過固定的 `<`，固定的 `<=` 勝過註冊的 `<`。

以固定語彙單元的開頭字元（`~ @ + - * / % ^ = ! < > & | . : ?`）開頭的註冊序列，例如 `<-` 或 `<~`，在註冊它的套件的檔案中是語彙單元；當其 trait 為 `pub` 時，在相依於該套件的每個套件的檔案中（包括其測試與基準測試）也是。其他套件的檔案保持固定語彙單元，因此在那裡 `a<-1` 仍然是 `a < -1`。以其他任何字元開頭的序列，例如 `⊕` 或 `$$`，在建置中的每個檔案裡都是語彙單元。

固定表以外、且建置中沒有任何東西註冊的 `Pattern_Syntax` 字元不是語彙單元：沒有繫結 `⊛` 之 trait 的 `1 ⊛ 2` 是錯誤，錯誤訊息會指出該字元（`U+229B CIRCLED ASTERISK OPERATOR`），並提示加入註冊它的套件或自行註冊。只是看起來像固定語彙單元的字元（`−` U+2212 之於 `-`）是錯誤，錯誤訊息會指出應該寫的語彙單元（[1.1.2](101-source-files.md#112-字元編碼)）。

格式化工具（`nabi fmt`）與語言伺服器以和編譯器相同的語彙單元切分檔案：其套件中註冊的語彙單元，以及其相依套件匯出的語彙單元（從它們的原始碼或預先建置的介面讀取）。

註冊時機、語法與意義定義於 [`#[infix]` / `#[prefix]` / `#[postfix]` 魔法](../006-meta-system/607-operator-magic.md)。

## 1.10.5. 不被切分為語彙單元的東西

下列元素不是語彙單元，而是較大單元的一部分。`f"..."` 的 `f` 是[字串字面值](107-string-literals.md)的格式字串前綴。`r"..."` 的 `r` 與 `r#"..."#` 的 `r#` 是原始字串前綴。`b"..."` 的 `b` 是位元組字串前綴。`c'...'` 的 `c` 是[字元字面值](108-character-literals.md)的 C 相容字元前綴。附加在數值字面值上的型別後綴也屬於這一類；詳見[數值字面值](106-numeric-literals.md)。

這些不出現在本文件的語彙單元表中，而且在它們所在的位置，也不會被切分為識別字或一般語彙單元。
