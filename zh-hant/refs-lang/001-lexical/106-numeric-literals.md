# 1.6. 數值字面值

本節涵蓋直接寫在原始碼中的數字字元序列的切分規則，以及決定每個字面值型別的規則。

## 1.6.1. 基本形式

數值字面值的文法定義如下。

```
numeric_lit ::= int_lit | float_lit
int_lit     ::= dec_lit | hex_lit | bin_lit | oct_lit
dec_lit     ::= dec_digit ("_"? dec_digit)*
hex_lit     ::= ("0x" | "0X") hex_digit ("_"? hex_digit)*
bin_lit     ::= ("0b" | "0B") bin_digit ("_"? bin_digit)*
oct_lit     ::= ("0o" | "0O") oct_digit ("_"? oct_digit)*
float_lit   ::= dec_lit "." dec_digit_seq? exponent?
              | dec_lit exponent
exponent    ::= ("e" | "E") ("+" | "-")? dec_digit_seq
dec_digit_seq ::= dec_digit ("_"? dec_digit)*
dec_digit   ::= [0-9]
hex_digit   ::= [0-9a-fA-F]
bin_digit   ::= [01]
oct_digit   ::= [0-7]
```

### 進位制

支援的進位制及其記法如下。

| 進位制      | 前綴           | 允許的數字                | 範例           |
|-------------|----------------|---------------------------|----------------|
| 十進位      | 無             | `0`-`9`                   | `42`、`1024`   |
| 十六進位    | `0x` 或 `0X`   | `0`-`9`、`a`-`f`、`A`-`F` | `0xFF`、`0X1a` |
| 二進位      | `0b` 或 `0B`   | `0`、`1`                  | `0b1010`       |
| 八進位      | `0o` 或 `0O`   | `0`-`7`                   | `0o755`        |

非十進位的進位制只用於整數字面值；浮點數字面值只允許十進位記法。

帶有前導零的十進位整數字面值（例如 `0123`）是編譯錯誤。Nabi 不採用 C 與 Java 中常見的「前導 0 = 八進位」規則，而把 `0123` 讀作十進位的 `123` 又會讓熟悉該規則的人感到意外；八進位以 `0o` 前綴撰寫。說明會建議八進位寫 `0o123`、十進位寫 `123`。`0` 本身以及浮點數字面值（`0.5`、`00.5`）沒有問題。

### 數字分隔符

為了可讀性，可以在數字之間放置底線（`_`）。

```nabi
1_000_000
0xFFFF_FFFF
0b1010_0101
3.141_592_653
```

底線的規則如下。

- `_` 只能出現在數字之間；第一個或最後一個字元不得是 `_`。
- `_` 不得緊接在進位制前綴之後（`0x_FF`），也不得緊接在小數點之前（`1_.0`）。`1._0` 不是浮點數字面值：它被切分為 `1` 之後接欄位存取 `._0`，而 `i32` 沒有這個欄位。
- 連續的底線（`1__000`）會被拒絕。
- `_` 在求值時被忽略，因此 `1_000` 與 `1000` 表示相同的值。

### 浮點數形式

字面值若符合下列兩種形式之一就是浮點數字面值；否則它是整數字面值，或被當作分開的語彙單元處理。

```
digit+  '.'  digit*  exponent?         // 1.5, 1., 1.5e10, 0.5
digit+              exponent           // 2e10  (an exponent without a point is still floating-point)
```

浮點數字面值在小數點之前必須有數字。它寫成 `0.5`；`.5` 不是浮點數字面值。後面接著數字的 `.` 一律是元組索引（`t.0`、`t.5`）。

指數部分（`exponent`）由 `e` 或 `E`、可選的正負號（`+` 或 `-`）以及一個以上的十進位數字組成。因此 `1.`、`0.5`、`1.5e10`、`2e-3` 與 `6.022e23` 都是有效的浮點數字面值。兩側皆空的單獨小數點（`.`）不是浮點數字面值，而是另一個語彙單元。

#### 區分 `1.` 與 `1.foo`

`digit+ '.'` 形式（`1.`）只有在小數點之後沒有開始一個識別字時，才被切分為浮點數。各種情況如下。

| 輸入                                        | 切分結果                                                |
|---------------------------------------------|---------------------------------------------------------|
| `1.5`                                       | 一個浮點數語彙單元 `1.5`                                |
| `1.`（後面接結尾 / 空白 / 標點）            | 一個浮點數語彙單元 `1.`                                 |
| `1.foo`                                     | 三個語彙單元：整數 `1`、`.`、識別字 `foo`               |
| `1 .foo`                                    | 同上（空白不影響語彙單元的切分）                        |
| `1..2`                                      | 三個語彙單元：整數 `1`、`..`、整數 `2`（`..` 是較長的匹配） |
| `1.+2`                                      | 三個語彙單元：浮點數 `1.`、`+`、整數 `2`                |

一句話總結：在數字中間，若 `.` 之後的第一個字元是 `XID_Start` 或另一個 `.`，該 `.` 就不屬於浮點數字面值；否則（標點、運算子字元、輸入結尾）它被吸收進浮點數字面值。

## 1.6.2. 型別後綴

字面值之後的後綴指定該字面值求值為哪個具體型別。

```nabi
42i32
3.14f64
2i              // a package's own suffix (6.5), e.g. an imaginary unit
0xFFu8
1_000_000i64
```

後綴格式遵循下列規則。後綴不帶空白地緊貼在字面值最後一個字元之後，且只由識別字字元（`XID_Continue`）組成。在語彙上，它被保留為一個語彙單元的一部分：語彙分析器把數值本體與後綴字串歸為單一語彙單元。

因此後綴是一個名稱：它以字母或 `_` 開頭，第一個字元之後可以含有數字（`x2`）。黏在數字上的符號絕不是後綴。`95%` 是 `95` 之後接餘數運算子，因此後面沒有運算元的 `95%` 是錯誤，錯誤訊息會說明百分比是後綴名稱（`95pct`）；`5°` 與 `5$` 中的符號不是語彙單元，它們是錯誤，錯誤訊息會指出應該寫的後綴（`5deg`、`5usd`）。在十進位字面值上，`e` / `E` 開始指數，`_` 分隔數字，因此任何後綴都不能以這兩者開頭（[6.5.7](../006-meta-system/605-literal-magic.md#657-user-defined-literals)）。

數值型別名稱後綴（`i8` `i16` `i32` `i64` `isize` `u8` `u16` `u32` `u64` `usize` `c_char` `f32` `f64`）由語言定義，並把字面值的型別設為該型別。後綴 `f16` 與 `bf16` 把它設為標準函式庫的 16 位元浮點數（[stdlib 2.1.4](../../refs-standard-libraries/200-core/201-numbers.md#f16-and-bf16---16-bit-storage-floats)）。`i128` / `u128` 是保留的：Nabi 沒有 128 位元整數（`int` 可以容納任意大小），帶有其中任一後綴的字面值是錯誤，錯誤訊息會指出應改寫的 64 位元後綴或 `int`。浮點數後綴也可以附加在十進位整數形式上（`1f64`、`2bf16`）。浮點數字面值從其十進位值捨入到其型別一次，捨入到最接近的值，平手時取偶數。在十六進位字面值中 `f` 是數字，因此 `0x1f32` 是十六進位值 `0x1F32`，而不是帶有後綴 `f32` 的 `0x1`。其他後綴（`2i` 等）由套件透過 [`#[literal(...)]` 魔法](../006-meta-system/605-literal-magic.md)註冊的處理器解讀。

## 1.6.3. 無後綴的字面值

無後綴字面值（`42`、`3.14`）的型別由預期型別決定。

- 整數字面值：若預期型別是整數或浮點數型別，就是該型別。沒有預期型別時，是其預設型別。
- 浮點數字面值：若預期型別是浮點數型別，就是該型別。沒有預期型別時，是其預設型別。它不能出現在預期整數型別之處。
- 任意精度的 std 型別 `int` 與 `float` 也算在內：整數字面值可以取 `int` 或 `float`，浮點數字面值可以取 `float`。這些型別能容納任何值，因此不做範圍檢查。
- **預設型別。** 無後綴字面值的預設型別是 `i64`（整數）或 `f64`（浮點數），除非它填入一個省略了的、宣告有預設值的型別參數（[2.10.5](../002-types/210-generics.md#2105-defaults)），且該字面值能取那個預設值：此時該預設值就是它的預設型別。字面值能取的預設值，就是它作為預期型別時能取的型別：對兩種字面值而言是浮點數型別，對整數字面值而言還有整數型別。在 `struct Vec3<T = f32>` 之下，`Vec3::new(1.0, 2.0, 3.0)` 是 `Vec3<f32>`，`Vec3::new(1, 2, 3)` 也是；在 `x: f64` 之下，`Vec3::new(x, 2.0, 3.0)` 是 `Vec3<f64>`，因為 `x` 確定了 `T`。預設型別終究只是預設：預期型別或之後的使用會先確定字面值的型別（`let v: DVec3 = Vec3::new(1.0, 2.0, 3.0)` 是 `Vec3<f64>`）。
- 必須取一個它不相容之宣告預設值的字面值是錯誤，與有型別的槽位相同（在 `Buf<T = u8>` 之下的 `Buf::new(300)`：請寫 `Buf::<u16>::new(300)` 或 `300i64`）。填入兩個預設值不同之參數的字面值是錯誤，錯誤訊息會指出兩者；請在宣告處寫出它的型別。
- 整數字面值絕不會填入一個沒有任何整數型別滿足其約束的參數（在 `T: FloatingPoint` 之下的 `lerp(0, 10, 1)` 是錯誤，其說明會寫出 `lerp(0.0, 10.0, 1.0)`）。
- 在二元運算中，若一個運算元的型別已靜態確定，該型別就成為字面值一側的預期型別。
- 把整數字面值放在預期浮點數型別之處，而該浮點數型別無法精確表示該值時，是編譯錯誤（`let f: f32 = 16777217;`）。
- 若預期型別是含有整數型別成員的和型別，整數字面值取該整數型別（`let v: i64 | f64 = 1;` 中的 `1` 是 `i64`）。
- 若和型別有多個整數成員以及一個浮點數成員，無後綴的整數字面值就有歧義，是編譯錯誤（`let v: u16 | u8 | f32 = 1;`）：請寫出後綴 `1u16` 或 `1u8`，或為浮點數成員寫 `1.0`。沒有浮點數成員時，這樣的字面值是 `i64`，並和任何 `i64` 值一樣對照和型別檢查。
- 無後綴字面值之間的算術（`1 + 2`、`-1`、`2 * (3 + 4)`）在遇到有型別的運算元或預期型別之前都保持無型別。遇到時，整個運算式取該型別；若始終沒有遇到，則取其預設型別（見上文）。
- 若 `if` / `else` 的一個分支，或型別未被任何槽位確定之 `match` 的一個分支，是無後綴的整數字面值，而另一個分支具有整數型別，該字面值就跟隨那個型別。
- 沒有預期型別、且所有元素都是無後綴數字字面值（允許 `-`，也允許巢狀串列字面值）而其中至少一個是浮點數字面值的串列字面值，是浮點數的串列：其中的整數字面值被當作浮點數字面值定型（`[0, 1.5]` 是 `[0.0, 1.5]`，`[[0, 1], [0.5, 2]]` 是 `List<List<f64>>`）。這是字面值的定型，而非值的轉換：浮點數字面值旁邊的整數型別值（`n: i64` 時的 `[n, 1.5]`）仍然是型別不符。
- 在 C 可變參數函式的 `...` 位置（[8.6](../008-abi/806-calling-convention.md)），無後綴的整數字面值是 `i32`（C 的 `int`）。

預期型別來自 `let` 的型別標註、引數位置的參數型別、回傳位置的回傳型別，以及上述的二元運算規則。

由不帶標註之 `let` 繫結的字面值，在其宣告處沒有預期型別。它的型別是一個推論變數，由該變數作用域內（區塊的其餘部分，包括閉包）其後的使用確定，與 [5.1.7](../005-modules/501-variable-declaration.md#517-type-annotations-and-type-inference) 相同；只有在沒有任何使用確定它時才套用預設值。

- 適用的情況：初始化式是字面值（`let c = 0`、`let c = -1`）、字面值算術（`let n = 1 + 2`）、分支都是字面值的 `if` / `match`（`let f = if b { 1 } else { 0 }`），或初始化式的直接元素或引數（`let xs = [0, 0]`、`let (a, b) = (0, 1)`、`let n = Atomic::new(0)`）。
- 確定它的東西：所有能確定一個開放 `let` 的東西（引數、指派、有標註的 `let`、`return`、主體的值），以及另一個運算元型別已確定的運算子（`c += x`、`c < limit`）。
- 邊界為字面值的 `for i in 0..10` 也一樣：`i` 的型別來自迴圈主體。
- 負的字面值不會因其使用而變成無號：`let i = -1; xs[i]` 保持 `i64`（從末尾算起的索引）。
- 在函式主體中，每個沒有預期型別的無後綴字面值從一開始就是一個整數或浮點數型別變數（`{integer}` / `{float}`）。每次使用都和其他型別變數一樣統一它：引數與泛型約束（包括 `where` 子句）及其關聯型別（把 `tasks.push(spawn(async { 0 }))` 放進 `List<Task<i32>>`）、閉包回傳值與有標註的閉包參數、透過迭代器配接器的有型別 `collect()` 目標（`(0..4).chain(7..10).collect::<List<i32>>()`）、運算子、`if` / `match` 分支與 `break` 值、和型別槽位中唯一的數字成員、型別模式、在結構約束下的結構字面值型別引數（`B<T: Num>` 之下的 `B { v: 3 }`）、隱含泛型的主體（以 `add(1, x_i32)` 呼叫的 `fn add(a, b) { a + b }`），以及同類數字型別中唯一適用的 impl、trait 或運算子（只為 `i32` 實作 `Twice` 時的 `9.once()`、`Foo` 實作於 `(i32, i32)` 時的 `(1, 2).foo()`、`Wave::hi(3)`、`i32` 上有 `Div<NonZero<i32>>` 時的 `84 / nz`）。主體只檢查一次；在主體結尾，所有沒被確定的變數都取其預設型別。
- `const` 項目的值、欄位預設值與參數預設值，各自在求值之前對照其宣告型別單獨檢查。
- 需要立即得到一個型別的使用會在那裡確定變數：若同類數字型別中恰好只有一個可行，變數就是該型別；否則是其預設型別（見上文）。這類使用包括：變數的型別尚未具有的方法呼叫（泛型 impl 或 blanket impl 的方法讓它保持開放）、以 trait 限定的呼叫（`Tr::f(x)`）、多載的呼叫（`int::from(i)`）、存入 `any`，以及對值的型別測試（`v is i64`、`match v { n: i64 => .. }` 之類的型別模式）。型別測試取預設值，因此 `let v = 3; v is i64` 是 `true`，`v is i32` 是 `false`。f-string 的洞不會確定它。
- 數字槽位的字面值接收者具有該槽位的型別（`let n: i32 = 7.max(-2)`），放入和型別的元組或串列字面值則取符合其形狀的成員。
- 不會加入任何轉換：繫結到整數字面值的變數絕不會變成浮點數型別（`let x = 1; let f: f64 = x;` 是錯誤；`let f: f64 = 1;` 則不是），而兩個想要不同型別的使用會在第二次使用處成為錯誤；對於字面值繫結的 `let`，錯誤訊息會指出第一次使用（`` conflicting uses of `c`: `i64` here, but `i32` fixed at 16:16 ``）。說明指向宣告處（`let c: i64 = 0` 或 `let t = 0.0`），而不是在使用處強制轉型。

```nabi
let a = 42;              // i64
let b = 3.14;            // f64
let x: f64 = 1;          // f64
let y: u8 = 200;         // u8
let r = a * 2;           // 2 is i64 (follows a)
let s: f64 = 2.0;
let t = s * 2;           // 2 is f64 (follows s)
let e: i32 = 1.5;        // ERROR: floating-point literal cannot be an integer type
let w: i64 = 7i64;
let k = w + (1 + 2);     // 1 + 2 is i64 (meets w)
let m: u8 = 2 * 100;     // 2 * 100 is u8 (expected type)
let n = 1 + 2;           // i64 (never fixed → default)
let v = if flag { 0 } else { w };   // 0 is i64 → v: i64

fn count(xs: List<i32>) -> i32 {
    let c = 0;                // i32: fixed by the body's value below
    for x in xs { if x > 0 { c += 1; } }
    c
}
let t = 0;
let big: List<u64> = [1, 2];
for x in big { t += x; }      // t: u64
let z = 0;
let f: f64 = z;               // ERROR: `z` holds an integer; write `let z = 0.0;`
```

## 1.6.4. 範圍檢查

超出其型別範圍的字面值是編譯錯誤。十六進位、八進位與二進位字面值遵循與十進位相同的範圍規則。

```nabi
let a: u8 = 256;         // ERROR: out of u8 range
let b = 0xFFi8;          // ERROR: 255 is out of i8 range
let c = 0xFFu8 as i8;    // OK: convert with as when a bit pattern is needed (-1)
```

只由字面值與常數組成的算術會在編譯期摺疊；若結果超出型別範圍或除以零，就是編譯錯誤（[5.2.4](../005-modules/502-const.md#524-constant-expressions-and-the-evaluator)）。

```nabi
let m: u8 = 2 * 200;     // ERROR: 400 is out of u8 range
```

## 1.6.5. 被拒絕的形式

下列輸入在語彙階段立即成為錯誤。

| 輸入    | 拒絕的理由                       |
|---------|----------------------------------|
| `0x`    | 十六進位前綴之後沒有數字         |
| `0b`    | 二進位前綴之後沒有數字           |
| `0o`    | 八進位前綴之後沒有數字           |
| `1__0`  | 連續的 `_`                       |
| `1_`    | 以 `_` 結尾                      |
| `0x_FF` | `_` 緊接在進位制前綴之後         |
| `1e`    | 指數中沒有數字                   |
| `0b12`  | 數字 `2` 超出二進位              |
| `0o8`   | 數字 `8` 超出八進位              |

每個錯誤都指向出錯的字元（多餘的數字、多出的 `_`、單獨的 `e`），並說明應該寫什麼。

`_1` 被切分為識別字而非數值字面值，因此它不是被拒絕的輸入，而是另一種類別的語彙單元。

## 1.6.6. 負數

沒有另外的負數字面值語彙單元。`-42` 由兩個語彙單元組成：一元運算子 `-` 與字面值 `42`；字面值本身一律以非負的形式切分。

範圍檢查有一個例外。緊接在一元 `-` 之後的字面值，允許到其型別的 `MAX + 1`，因此 `-128i8` 是 `i8` 的最小值。二元運算的運算元沒有這個例外。

```nabi
let m = -128i8;          // OK: i8::MIN
let n = a - 128i8;       // ERROR: 128 is out of i8 range
```
