# 1.8. 字元字面值

字元字面值是表示單一碼位或單一位元組的語彙單元。

## 1.8.1. 三種類別

```
char_lit    ::= "'" char_item "'"
              | "c'" byte_item "'"
              | "b'" byte_item "'"
char_item   ::= <any unicode codepoint except "'" or "\\"> | escape_seq
byte_item   ::= <any ASCII byte except "'" or "\\"> | byte_escape
byte_escape ::= "\\x" hex_digit hex_digit | escape_seq
```

### 一般字元：`'A'`

```nabi
'A'
'세'
'\n'
'\u{1F600}'
```

一對單引號（`'`）內必須恰好包含一個碼位。跳脫序列原樣遵循[字串字面值](107-string-literals.md)中的表格：`\\`、`\'`、`\"`、`\n`、`\r`、`\t`、`\0`、`\x`、`\u{...}` 等。`'\x41'` 之類的單位元組形式也是有效的，其結果是 ASCII 範圍內的單一碼位。反過來說，像 `'AB'` 這樣包含兩個以上的字元，或寫成空的 `''`，在語彙階段就是錯誤。

這種形式的字面值是 `char`（Unicode 純量值，編譯器的基本型別）。它的方法由 [stdlib 2.15](../../refs-standard-libraries/200-core/215-string.md) 定義。

### C 相容字元：`c'A'`

```nabi
c'A'
c'\n'
c'\x7F'
```

這種形式由 `c` 前綴與一對單引號組成；跳脫序列原樣遵循[字串字面值](107-string-literals.md)中的表格。內容的值必須位於 `U+0000`-`U+00FF` 之內；超出這個範圍是語彙錯誤。例如 `c'세'` 是錯誤，因為 `'세'` 是 `U+C138`，無法放進一個位元組。直接寫出字元來填滿單位元組範圍時，由於原始碼是 UTF-8，只能寫 ASCII 字元；非 ASCII 的單位元組值（`U+0080`-`U+00FF`）必須以 `\xHH` 或 `\u{H...}` 跳脫序列撰寫。

這種形式求值為基本型別 `c_char`，即外部函式介面（[FFI](../000-meta/007-glossary.md#ffi-foreign-function-interface)）的 8 位元字元型別。

### 位元組：`b'A'`

```nabi
b'0'          // 48u8
b'\n'         // 10u8
b'\xFF'       // 255u8
```

這種形式由 `b` 前綴與一對單引號組成，其內容與跳脫序列同 `c'x'`：一個直接寫出的 ASCII 字元，或值最多為 `\xFF` 的跳脫序列。`b'é'` 之類的非 ASCII 字元是語彙錯誤，其訊息會提示改寫成 `\xHH`。這個字面值是型別為 `u8`、值為該位元組的整數字面值，因此在任何可以用 `u8` 的地方都能使用，包括模式與模式範圍（`b'0'..=b'9' => ..`）。它是 `b"..."` 位元組字串（[1.7](107-string-literals.md)）的位元組版本。

## 1.8.2. 為什麼這兩種類別要分開

與其讓同一種語彙單元形式（`'X'`）擔負兩種意義，不如以前綴明確地區分兩者。Unicode 意義上的字元與 C [ABI](../000-meta/007-glossary.md#abi-application-binary-interface) 的單一位元組語意不同；若把它們歸在同一種記法之下，呼叫相容函式時就無從表達意圖。`c` 前綴也留下了程式碼「觸及 FFI」的可見訊號。

## 1.8.3. 強制的長度檢查

字元字面值必須恰好包含一個碼位（一般字元），或恰好一個位元組（C 相容字元與位元組）。這個長度檢查在語彙階段進行，不符時立即成為錯誤。

這個決定排除了下列這類歧義。組合序列（`e\u{0301}` = `é`）可以放進一個字元字面值嗎？不行：它是兩個碼位。這樣的文字屬於字串字面值。同樣地，在字素叢集層級「人眼看來是一個字元」的東西，被當作字串層級的概念，而非字元字面值。

這個簡化讓「字元 = 一個碼位」的定義從語彙階段起就保持一致。
