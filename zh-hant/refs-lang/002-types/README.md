## 定位

型別是編譯器用來決定一個值可以有什麼形狀與行為的資訊。每個 Nabi 值都屬於某個型別；沒有無型別的值。

變數稍有不同。變數要麼固定於一個型別（靜態），要麼是可以容納多種型別的槽位（動態），而這兩種模式並存於同一門語言中。

## 兩種模式：靜態與漸進式

```
static (explicit)   let x: i32 = 42i32;     x is always i32
static (inferred)   let z = 42i32;          z is fixed to the initializer's type i32
gradual (any)       let y: any = 42i32;     y is a slot that can hold any type
```

靜態變數是在宣告處寫出型別，或省略型別而由初始化式推論的變數；它始終只容納該型別的值。漸進式變數是在型別位置寫了 `any` 的變數；這樣的變數是一個動態槽位。靜態是預設；動態只存在於寫了 `any` 之處。

本章只確立這兩種模式並存於同一門語言中。

動機見於[執行引擎與使用者介面](../000-meta/001-execution-modes.md)：REPL/Jupyter 的探索與 [AOT](../000-meta/007-glossary.md#aot預先編譯) 靜態編譯必須共用同一份程式碼。結果是，探索性的程式碼傾向使用省略型別的推論風格，函式庫程式碼使用明確風格，而動態槽位只在真正需要之處寫成 `any`。

## 語言定義的內容

語言規格直接定義型別的下列事項。

型別運算式的語法，即型別名稱如何撰寫。建立型別的容器語法：`struct`、`enum`、`union`、`trait`、`impl`、泛型與和型別（`|`）。動態槽位（`any`）的意義，以及泛型的單態化規則，即在呼叫處依型別[特化](../000-meta/007-glossary.md#特化specialize)。最後，編譯器必須辨識的型別系統不變條件，例如 trait 不能作為型別以及 niche 最佳化規則。

## 標準函式庫定義的內容

標準函式庫負責型別的下列事項。

所有基本型別的名稱與意義：`i32`、`f64`、`bool`、`str` 等。所有集合型別：`List`、`Dict`、`Set`、`Tuple` 等。所有型別之間的轉換，例如 cast、from 與 into。trait 的內容：哪些 trait 有哪些方法、哪些型別實作它們。最後，字面值求值為哪個型別，也由標準函式庫透過處理器決定。

> [!IMPORTANT]
> 本章只定義形狀。內容定義於函式庫規格。

## 漸進式型別的邊界

漸進式型別只適用於寫了 `any` 之處。省略型別標註絕不會產生動態槽位。

沒有型別標註的變數成為由其初始化式型別推論出的靜態槽位。沒有型別標註的函式參數會使函式成為泛型，在呼叫處單態化（`pub` 或 `pub(pkg)` 函式要寫出每個參數型別）；它不會成為動態槽位，因此應當以漸進方式運作的參數必須明確寫成 `any`。結構欄位需要型別標註。省略回傳型別的函式由其主體推論回傳型別；無法推論時是編譯錯誤。在 `pub` 或 `pub(pkg)` 函式上，缺少回傳型別表示 `()`。

這條邊界把執行時[分派](../000-meta/007-glossary.md#分派dispatch)的成本侷限在寫成 `any` 的位置。變數、參數與欄位都要麼是靜態的，要麼明確寫成 `any`。

## trait 不能作為型別

trait 名稱不能直接寫成變數、參數或回傳型別。需要多型之處，請使用泛型、和型別，或受約束的 `any Trait`。

執行時分派侷限於寫成 `any` 的位置（`any`、`any Trait`）。

## 單態化

泛型函式與型別在呼叫處或實例化處，為每一組具體型別產生各自的編譯結果。

例如，若同一個泛型函式在兩個呼叫處分別以 `i32` 與 `f64` 使用，就會產生兩個不同的函式主體。結果是間接呼叫的成本為零，效能與直接呼叫相同。代價表現在編譯時間與二進位檔大小上，但大多會因捨棄無法到達的實例以及連結時的無用程式碼移除而抵銷。
