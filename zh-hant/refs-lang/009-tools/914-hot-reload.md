# 9.14. 熱重載

*熱重載*把一次編輯套用到執行中的程式：`nabi dev`（9.10.8）重新建置其原始碼有改變的套件，而程式在一個安全點載入新的程式碼，保留其堆積、執行緒與 static。它是建立在外掛（[9.12](912-plugins.md)）之上的開發工具：每個本地套件的程式碼都位於一個可以被取代的外掛中，而程式的其餘部分在執行期間絕不改變。

## 9.14.1. 模型

一個 dev 工作階段有兩種模組：

- *主機*：執行環境、標準函式庫的狀態，以及每個登錄庫或 git 套件。它在每個工作階段只建置一次。它是一個一般的外掛主機（[9.12.1](912-plugins.md#9121-model)），其 `main` 是 `std::reload::host_main()`：它連接 dev 頻道、載入 `NABI_DEV_PLUGINS` 所指名的熱外掛，並呼叫根套件的 `main`（`NABI_DEV_MAIN`）。
- *熱外掛*：每個本地套件一個（根套件、其 `path` 相依套件、它所使用的工作區成員），以 `nabic build --hot` 建置（[9.1](901-nabic-cli.md)）。每次儲存都會為它所觸及的套件產生新版本。

在 `--hot` 之下，對熱套件之函式的每次呼叫都經過一個槽位，以函式的修飾後名稱及其簽章作為鍵。載入一個版本會把每個已載入版本的每個槽位繫結到具有相同鍵的最新主體。因此：

- 主體改變的函式會從各處以其新形式被呼叫，包括舊版本的程式碼；
- 簽章改變的函式得到新的鍵與新的槽位：對照舊簽章建置的呼叫者持續呼叫舊主體，新的呼叫者呼叫新主體；
- 舊版本在工作階段結束之前保持對應。

熱套件的套件雜湊（[9.5](905-symbol-mangling.md)）在工作階段中是固定的（它衍生自套件名稱），因此符號在各版本之間保留其名稱。登錄庫與 git 套件保留其內容雜湊。

`--hot` 的代價是每次呼叫熱套件時一次載入與一次間接分支、熱函式不跨函式內嵌、保留框架指標，以及根重新讀取規則（[8.4](../008-abi/804-safepoint.md)）。一般建置（`nabi build`、`nabi run`）沒有這些代價。`--hot` 只建置 dev 設定檔。

## 9.14.2. 版本何時套用

程式在其 dev 頻道執行緒上載入一個版本，並在每個執行緒都停止時套用它，這與回收所使用的是同一種停止（[7.3](../007-runtime/703-gc-algorithm.md)）：

- 只有程式碼的改變在下一次停止時套用。
- 型別配置的改變在第一次沒有任何框架容納改變之型別之值的停止時套用（9.14.4）；接著會遷移存活的值（9.14.3）。
- `std::reload::point()`（[3.13](../../refs-standard-libraries/300-std/313-reload.md)）會請求一次停止，通常就是配置改變得以通過的地方。在 `nabi dev` 之外，它不做任何事。

尚無法套用的版本保持待處理狀態，並在每次停止時嘗試；下一次儲存會取代它。永遠無法套用的版本會被拒絕，程式繼續執行它現有的程式碼。

## 9.14.3. 哪些可以改變

編譯器把新版本的型別與執行中版本的型別比較（`--hot-base`，即寫在每個版本旁邊的 `.layout` 檔案），並把程式無法遷移的改變作為編譯錯誤拒絕：

| 改變 | 結果 |
|--------|--------|
| 新增帶有預設值的欄位（`mana: i32 = 0;`） | 允許；存活的值得到預設值 |
| 新增沒有預設值的欄位 | 錯誤：``new field `mana` needs a default while the program runs: write `mana: i32 = 0;` (or restart with `r`)`` |
| 移除欄位 | 允許；其值被捨棄 |
| 重新排列欄位 | 允許 |
| 以 `#[renamed_from("hp")] health: i32` 重新命名欄位（[6.2](../006-meta-system/602-built-in-attributes.md)） | 允許；值會被帶過去。指名不存在的欄位是錯誤，錯誤訊息會列出舊欄位。 |
| 欄位的型別改變 | 錯誤：``field `hp` of `Player` changed from `i32` to `f64` while the program runs; give the new field its own name with a default (`health: f64 = 100.0`) to start it fresh, or restart with `r` `` |
| 新增或重新排列列舉變體 | 允許；標籤依名稱對應 |
| 移除列舉變體 | 編譯時允許；當有存活的值容納它時，版本會等待：``waiting: a live `State::Paused` exists`` |
| 變體的酬載改變 | 與欄位相同，依各變體而定 |
| 泛型參數改變，或結構變成列舉 | 錯誤；需重新啟動 |
| 新增、移除或改變 trait impl | 允許；`any Tr` 分派項目會被取代 |

遷移是完整回收的最後一個階段：每個改變之型別的物件都被改寫為新的配置，保留的欄位依名稱（或 `#[renamed_from]`），新增的欄位來自其預設值，被移除的欄位被捨棄，列舉變體依名稱比對。當新配置放得進物件時，物件會就地改寫，否則改寫到一個新物件中，並更新指向它的每個堆積參照。必須變大的有根物件（框架的區域變數、全域根）不會被移動：它會阻擋該改變（9.14.4）。在世界停止的情況下進行的第一次檢查會找出阻擋改變的東西，因此無法執行的遷移不會改變任何東西。

## 9.14.4. 仍在執行的程式碼

| 東西 | 規則 |
|-------|------|
| 舊函式的框架 | 在舊程式碼中完成；它所進行的呼叫會到達新程式碼 |
| `main` 自己的迴圈 | 在整個工作階段中都是舊程式碼：每一幀的工作應當放在 `main` 所呼叫的函式中 |
| 容納改變之型別之值的框架 | 阻擋配置改變：``waiting: `main` (src/main.nabi:12) holds a `World` across `reload::point()`; keep it in a `reload::State`: `let world = reload::State::new(World::new());` ``。`--hot` 在編譯時會在相同的位置發出警告。 |
| 閉包 | 保留它建立時的主體；其環境容納改變之型別者會阻擋配置改變：``waiting: a closure made in `spawn_wave` (src/wave.nabi:30) holds an old `Enemy` `` |
| 暫停中的協程或任務 | 在其舊程式碼中恢復；容納改變之型別者會阻擋配置改變，訊息會指出它被產生的位置 |
| static | 保留其儲存空間與值；新的 static 從其初始化器開始；型別配置改變的 static 會被遷移 |
| `any Tr` 值 | 分派到最新的 impl |
| 有根、被釘住或被取址、會變大的改變之型別的物件 | 阻擋配置改變 |
| 以行內方式容納改變之型別之值的 `any`，或開啟中的不回收區域 | 阻擋配置改變 |

## 9.14.5. dev 頻道

`nabi dev` 經由一個頻道與程式溝通，該頻道在它啟動程式之前建立，並在程式的環境中以 `NABI_DEV` 指名：unix stream 通訊端的路徑，或在 Windows 上是具名管道的名稱（`\\.\pipe\nabi-dev-<pid>-<n>`）。設定了 `NABI_DEV` 時，執行環境會在啟動時連線；沒有它而啟動的程式絕不會開啟頻道，`std::reload::active()` 為 false。

每則訊息都是一行以 `\n` 結尾的 UTF-8。

| 來自 | 行 | 意義 |
|------|------|---------|
| 程式 | `hello 1 <pid>` | 第一行：協定版本 1 |
| `nabi dev` | `load <path>` | 載入這個檔案，即某個熱套件的新版本。一起改變的套件以多行傳來，相依套件在前。 |
| 程式 | `applied <pkg> v<n>: <what>` | 版本已套用：`applied game v3: 4 functions, 1 type (Enemy: +mana), 120 objects migrated` |
| 程式 | `waiting <pkg> v<n>: <why>` | 尚未套用（9.14.4）；原因改變時會再次傳送；之後會有針對同一次載入的最終回覆 |
| 程式 | `refused <pkg> v<n>: <why>` | 該版本不會套用；程式保留其程式碼 |
| 程式 | `superseded <pkg> v<n>` | 在它等待期間，同一個套件較新的 `load` 取代了它 |

`<pkg>` 是程式碼拼寫的套件名稱，`<n>` 是程式所計算的版本（1 是它啟動時的版本）。載入依傳送的順序套用，等待中的載入會阻擋排在它後面的載入；同一個套件較新的載入會取代等待中的那一個。每個 `load` 都恰好得到一個最終回覆（`applied`、`refused` 或 `superseded`），同一個套件的回覆依其載入的順序到達；不同套件的則不一定。`nabi dev` 在傳送下一個 `load` 之前絕不等待回覆。未知的行會得到 `refused <line>: unknown request` 回覆。頻道的結束就是程式的結束。

## 9.14.6. 不屬於熱重載的範圍

- 登錄庫與 git 套件、主機，以及 `nabi.nabion`：對它們的改變會重新啟動程式（9.10.8）。
- 把欄位的值轉換為新的型別。
- 把既有的閉包移到新的主體。
- 容納在 C 框架中的值：位於 C 回呼之下的熱框架會阻擋配置改變。
- wasm 目標、release 建置與 REPL。
- 重新載入已發行之程式所載入的外掛：熱重載只供 `nabi dev` 使用。
