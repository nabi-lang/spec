# 5.5. `use`（匯入）

`use` 關鍵字（[關鍵字](../001-lexical/105-keywords.md)）把其他模組的項目帶進目前模組的可見命名空間。

## 5.5.1. 基本形式

```
use_stmt    ::= "use" use_tree ";"
use_tree    ::= path "::" "*"
              | path "::" "**"
              | path "::" "{" use_tree ("," use_tree)* ","? "}"
              | path ("as" identifier)?
path        ::= path_root ("::" identifier)*
path_root   ::= "pkg" | "sup" | "::" identifier | identifier
```

glob（`*`、`**`）不接受 `as` 別名：它們一次匯入許多項目，因此單一別名沒有意義。因此 `path ("as" identifier)?` 只適用於單一項目的匯入。

```nabi
use foo::bar;
use std::time::SystemTime;
use pkg::geom::Point;
```

基本結構是 `use`、路徑，以及結尾的 `;`。路徑的最後一個識別字成為該項目在目前模組中的名稱。`use` 之後，該項目就可以用 `bar`、`SystemTime`、`Point` 等簡短名稱指稱。

## 5.5.2. 多重匯入：`{...}`

前綴相同的多個項目可以組合在一行中。

```nabi
use foo::{a, b, c};
use std::time::{SystemTime, UNIX_EPOCH};
```

`{..}` 的每個元素都接續該組已解析的前綴。前綴可以為空（`pkg::{..}`、到達根的 `sup::{..}`）。因此在任何模組中，`use p::{a, b}` 都恰好等於：

```nabi
use foo::a;
use foo::b;
```

- 組可以巢狀，也可以包含 `*`、`**` 與 `as`（`use foo::{bar::{x, y as z}, baz::*};`）。
- 組內的 `self` 是錯誤。
- 每個末端都必須解析為一個項目、一個列舉變體或一個模組。否則就是該末端的「unresolved import」錯誤。

## 5.5.3. 別名：`as`

`as` 關鍵字為匯入的項目改名。

```nabi
use foo::very_long_name as short;
use core::collections::Dict as Map;
```

`as` 之後接一個新名稱；在目前模組中只看得到新名稱，原本的名稱不可見。

它也可以用在多重匯入中。

```nabi
use foo::{a as alpha, b, c as charlie};
```

## 5.5.4. glob：`*`（淺層）

一次匯入一個模組所有可見的項目。

```nabi
use foo::*;                    // all visible items of foo
```

規則：`*` 必須是最後一個語彙單元，因此 `use foo::*::bar` 之類的形式是錯誤。只會匯入呼叫者看得到其可見性的項目（[可見性](506-visibility.md)）：`pub` 的項目、在同一個套件內的 `pub(pkg)` 項目等，其可及範圍包括呼叫者。只匯入 `foo` 的**直接**子項；子模組的項目不會被匯入（那是 `**` 的作用）。區塊中的 glob `use` 也會到達在該區塊中宣告之項目的標頭（[3.9.1](../003-expressions/309-block-expressions.md#391-形式)）。模組自己定義的項目勝過以 glob 匯入的同名項目：glob 讓步，而且不會回報任何東西（同名的具名匯入則是錯誤，5.5.12）。

## 5.5.5. 遞迴 glob：`**`（深層）

遞迴地匯入，包括子模組。

```nabi
use foo::**;                   // all items of foo + all items of foo's child modules + ...
```

它一次匯入包括子模組在內的每一個可見項目，因此範圍比淺層 glob（`*`）寬得多。它常被用作大型函式庫的 prelude 形式。遞迴 glob 匯入模組項目與 `enum` 變體，絕不匯入型別的關聯項目：在 `use core::time::**;` 之下，單獨的 `MAX` 不指稱 `Duration::MAX`。

## 5.5.6. glob / 遞迴 glob 的衝突

當多個 glob 匯入相同的名稱時，就會發生衝突。

```nabi
use foo::*;
use bar::*;
// if both have a name 'item', that name is ambiguous and using it is an ERROR.
```

請明確匯入其中一個，或為它取別名來解決。

```nabi
use foo::item;                 // explicit: only foo::item is visible
use bar::item as bar_item;      // alias: both under different names
```

## 5.5.7. 路徑的起點

路徑的起點遵循[路徑（5.7.1）](507-paths.md#571-路徑的起始識別字)的規則。`pkg::` 從目前套件的根開始。`sup::` 從父模組開始，可以串接為 `sup::sup::...` 往上多層。`std`、`core`、`bare` 指標準函式庫層級，除非區域名稱佔用了它（[5.7.4](507-paths.md#574-stdcorebare標準函式庫層級)）。開頭的 `::`（`use ::std::fs;`）指一個層級或本套件的某個相依套件，不受區域名稱影響（[5.7.10](507-paths.md#5710-空路徑--開頭的-)）。否則，一般識別字在它是目前可見的名稱（子模組、已經 `use` 的名稱等）時可以使用。由於同一個模組的子項只用其識別字就能存取，沒有另外的 `self::`。

路徑的第一個識別字指稱模組或型別，因此以模組名稱匯入的函式或常數不會取代該模組：在 `mod norm;` 之下，`pub use norm::norm;` 匯入函式 `norm`，而之後的 `norm::other` 仍然從模組開始。

```nabi
mod norm;                       // holds `pub fn norm` and `pub fn other`
pub use norm::{norm, other};    // the function `norm` and `other`
let a = norm::norm(-2.0);       // the module `norm`
```

### 匯入 `enum` 變體

`enum` 的變體是該 `enum` 之下的項目，因此可以用 `use` 匯入。`use` 路徑也可以從目前可見的型別名稱開始。

```nabi
use Shape::{Circle};                // a single variant
use Shape::{Square as Sq};          // alias
use Shape::*;                       // all variants
use Result::*;                      // starts with a visible type name
```

沒有 `use` 時，在預期型別是其列舉之處，變體可以不帶路徑撰寫（[2.4.8](../002-types/204-enum.md#248-依預期型別使用不帶路徑的變體)）：在回傳 `Result` 的函式中，以及在對 `Result` 的 `match` 中的 `Ok` / `Err`。當模式中的單獨名稱解析為匯入的變體或受檢值之列舉的變體時，該名稱比對的是該變體，而不是建立新的繫結。

```nabi
match r {
    Ok(v)  => v,
    Err(e) => fallback(e),
}
```

## 5.5.8. `use` 可以出現的位置

`use` 可以出現在模組層級或函式主體層級。

```nabi
// module level: visible throughout that module
use foo::bar;

fn f() {
    // inside a function: visible only within that function
    use foo::baz;
    let x = baz();
}
```

函式內的 `use` 是該函式的區域匯入，不會公開到外部。因此可見性關鍵字（`pub`）在那裡沒有意義。慣用風格是把每個 `use` 放在檔案頂端：警告 lint `local_use`（[6.2](../006-meta-system/602-built-in-attributes.md)）會回報函式主體內的 `use`。

## 5.5.9. `use` 的可見性

```nabi
pub use foo::bar;               // exposed outside (re-export)
pub(pkg) use foo::bar;          // exposed only within the same package

use foo::bar;                   // module-private: visible only within the same module
```

`pub use` 是重新匯出。詳細內容定義於[可見性](506-visibility.md)。

## 5.5.10. `core` 的自動匯入

在標準函式庫之外的每份 Nabi 原始碼開頭，編譯器都會隱含地套用 `use core::prelude::*;`。prelude 是一份固定的 `core` 名稱清單（[stdlib 0.2.3](../../refs-standard-libraries/000-meta/002-import.md)）：頂層的 core 模組、常用的集合型別與核心型別、寫在 `impl` 標頭與約束中的 trait，以及列印與 panic 函式。其他 core 項目要透過 prelude 中的模組指稱（`task::sleep`、`ops::Add`）或匯入。隱含匯入在查找中排在最後（[5.7.1](507-paths.md#571-路徑的起始識別字)），因此模組自己的項目與 `use` 會遮蔽它。`#![no_implicit_nabi]` 可為某個檔案關閉它。

`core` 以外的兩個層級，`bare`（危險領域）與 `std`（相依於目標），**不在**自動可見之列，需要明確匯入。詳細內容定義於[標準函式庫層級](../000-meta/005-standard-libraries-tiers.md)。

標準函式庫以外的每個模組（外部套件、使用者函式庫）也需要明確匯入。套件中名為 `prelude` 的模組不會被自動拉進來。它只是函式庫作者選擇的慣用名稱，因此使用者必須明確匯入它，例如 `use my_lib::prelude::*;`。

```nabi
// library side
pub mod prelude {
    pub use pkg::api::core::*;
    pub use pkg::api::ext::*;
}

// user side
use my_lib::prelude::*;            // visible only when imported explicitly
```

## 5.5.11. 兩次匯入同一個模組 / 項目：允許

```nabi
use foo::bar;
use foo::bar;                   // OK: duplicate import is harmless
```

對同一個項目的重複匯入沒有副作用，是允許的。當同一性檢查確認它真的是同一個項目時，就會通過。

## 5.5.12. 來自不同模組的同名項目：衝突

```nabi
use foo::Item;
use bar::Item;                  // ERROR: 'Item' already imported
```

從不同模組匯入相同的簡短名稱是衝突。請為其中一個取別名來解決。

函式、常數與 static 構成一個命名空間，模組與型別構成另一個，與宣告項目之處相同：同名的函式與模組不衝突（`use core::channel;` 與 `use core::channel::channel;` 並存）。

```nabi
use foo::Item;
use bar::Item as BarItem;       // OK
```

具名匯入（`use a::f;`、`use a::{f}`，或匯入名稱 `g` 的 `use a::f as g;`），與模組中在該匯入所填入之命名空間裡定義的同名項目，是編譯錯誤（`E0032`，[9.9.4](../009-tools/909-debug-tools.md#994-診斷--錯誤訊息)）：該項目會在不被察覺的情況下隱藏該匯入。請以另一個名稱匯入它（`use a::f as a_f;`），或移除該 `use`。型別匯入與同名的值項目並存不會衝突，而 glob 匯入會讓步給模組的項目（5.5.4）。

```nabi
use shapes::square;
fn square(x: f64) -> f64 { x * x }    // ERROR: `square` is both imported from `shapes::square` and defined in this module
```

## 5.5.13. `use` 的求值 / 效果

`use` 只改變編譯期的名稱解析資訊，對執行時的行為沒有直接影響。`use` 本身不執行任何程式碼；它只是在目前模組的名稱表中加入一個別名。

## 5.5.14. 匯入模組本身

```nabi
use foo::geom;                  // imports the module foo::geom itself
let p = geom::Point { ... };    // use geom as a short name
```

不只是項目，模組本身也可以被匯入。此時模組的名稱（最後一個識別字）在目前模組中以簡短名稱可見；這常用於透過子模組存取項目。
