# 0.5. 標準函式庫層級

標準函式庫分為 `bare`、`core` 與 `std` 三個套件層級，每一層都是自己的路徑根（`core::List`、`std::fs`）。它們以可用的環境以及所公開行為的風險來區分。

## 0.5.1. 三個層級

整體結構如下。

```
  bare   ←   no safety guarantees. Raw memory, FFI, transmutable bit casts.
     ↑
  core   ←   safe foundation available on every target. Uses bare internally.
     ↑
  std   ←   target-dependent tier. File system, network, OS threads, etc.
```

箭頭表示相依的方向。`core` 可以在內部實作中使用 `bare`，`std` 可以使用 `core` 與 `bare`。相反方向的相依是禁止的。

每個層級的名稱是其路徑的開頭（[5.7.4](../005-modules/507-paths.md#574-stdcorebare標準函式庫層級)）。這些名稱不是關鍵字：使用者模組或相依套件別名可以取用其中一個名稱，而 `::std::..` 仍然能越過它到達函式庫。

## 0.5.2. 各層級的職責

### `bare`

`bare` 是低階、危險的領域。編譯器無法保證安全性的行為集中在這裡；代表性的項目包括原始指標形式（原始指標抽象）與任意的位元強制轉型（類似 `transmute`）。釘選、volatile 記憶體存取，以及與 C [ABI](007-glossary.md#abi應用程式二進位介面) 相容的記憶體配置基本元件，也是 `bare` 的一部分。

這一層函式的呼叫者要為安全性負責，而路徑本身就讓這件事一目了然。

### `core`（基礎）

`core` 是最常用的安全函式庫；基礎的每個模組都在這裡（例如 `core::collections`、`core::iter`、`core::ops`）。它必須在本規格保證的每個建置目標上以相同方式提供。它的內容非常廣泛：數值、字元與字串型別及其方法，以及集合型別（串列、對應、集合、元組）。它擁有算術、比較、邏輯與位元運算子的 trait 定義，也提供迭代器、串流與 future。並行基本元件（atomic、mutex、channel）以及任務與平行執行的 API 介面也屬於這一層。最後，它涵蓋格式化、顯示、偵錯輸出、反射與檢視。

可攜的 SIMD 向量是 `core::simd`；張量 / 自動微分 / GPU 等加速領域不屬於 `core`，而是由外部函式庫實作，並透過計畫於之後版本提供的後端介面接上編譯器的後端。標準函式庫只負責一般程式碼的表層語意，把加速領域留給函式庫層的決定。

`core` 的常用項目之所以可見，是因為編譯器在每份 Nabi 原始碼開頭隱含地套用 `use core::prelude::*;`。也就是說，`core::collections::List` 可以寫成 `List`，`core::task::sleep` 可以寫成 `task::sleep`。prelude 的清單固定於 [stdlib 0.2.3](../../refs-standard-libraries/000-meta/002-import.md)。

不需要 `use` 就可見的只有 prelude 的項目。`core` 的其他每個 `pub` 項目都透過其模組（`ops::Add`、`num::Zero`）或 `use` 存取；`core` 中沒有 `pub` 的項目則和任何套件一樣是它私有的（5.6）。

### `std`

`std` 是只在特定環境（主要是作業系統之上）才有意義的領域。它包含檔案系統與網路、時間與時鐘、標準 I/O、環境變數、行程，以及直接控制作業系統執行緒。

`std` 的函式在某些目標上可能不存在。在某些領域沒有意義的環境中（例如在瀏覽器內執行的筆記本核心），對應的模組不會被建置。

## 0.5.3. 可見性慣例

可見性規則如下。

| 領域            | 隱含匯入        | 需要明確匯入             | 備註                                          |
|-----------------|-----------------|--------------------------|-----------------------------------------------|
| `core`     | ✓ 僅 prelude 項目 | ✓ 其他項目           | 自動套用 `use core::prelude::*;`              |
| `bare::**` | ✗               | ✓ 必須                   | 讓危險訊號在程式碼中顯而易見                  |
| `std::**` | ✗               | ✓ 必須                   | 讓目標相依在程式碼中顯而易見                  |
| 使用者套件      | ✗               | ✓ 必須                   | 其他套件的項目                                |

「引入」的具體語法（`use`、`import` 等）定義於模組系統規格。

## 0.5.4. 散布形式與連結機制

三個層級以原始碼形式的函式庫套件隨編譯器一起提供：

```
lib/nabi/bare/src/lib.nabi
lib/nabi/core/src/lib.nabi
lib/nabi/std/src/lib.nabi
```

編譯器在第一次使用時把它們建置進自己的快取並自動連結（[9.2.19](../009-tools/902-aot-pipeline.md#9219-安裝配置)）。這條路徑與使用者套件的一般相依套件分開，因此碰巧同名的使用者套件（例如 `mod bare`、`mod std`）不會衝突。

和編譯器本身一樣，三個層級遵循零相依原則。建置使用者套件時只連結它需要的層級，產出也不需要額外的外部函式庫。

## 0.5.5. 為什麼是三個層級

若只有兩個層級（安全、危險），就無法區分「在任何地方都安全」與「只在有作業系統時才安全」，而在缺少部分作業系統功能的環境（瀏覽器筆記本等）中，這種劃分就會瓦解。反過來說，四個以上的層級會增加使用者必須記住的規則，並削弱模組邊界的價值。

三個層級是實務上經過充分驗證、而且仍有意義的最簡單劃分。

以各自的根來命名每個層級，能讓路徑簡短並降低學習成本：`core` 透過 prelude 在任何地方都在作用域內，`std::fs` 讀起來就是它的本意，而 `bare` / `core` / `std` 之間的職責劃分可以循序漸進地學會。
