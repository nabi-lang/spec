# 0.8. 記號

本節整理本規格通篇使用的後設記號慣例。第 1 章到第 9 章都遵循這些慣例，因此在閱讀本文之前值得先查閱本節。

## 0.8.1. 程式碼 / 識別字記號

下表列出三種常用形式、它們的意義與範例。

| 記號               | 意義                                               | 範例                       |
|--------------------|----------------------------------------------------|----------------------------|
| `` ` ``（反引號）  | 關鍵字、識別字、語彙單元、型別名稱、程式碼片段     | `` `let` ``、`` `i32` ``   |
| 圍欄（` ``` `）    | 多行程式碼區塊，標明語言名稱                       | ` ```nabi ` 或 ` ```ebnf`   |
| 行內程式碼         | 簡短的程式碼片段                                   | `` `x + y` ``              |

在行文中提到的關鍵字一律以反引號包起來，使它在視覺上與周圍的文字區隔。

## 0.8.2. 強調

強調不只是視覺裝飾；每種形式都有固定的用途，如下所列。

| 記號             | 意義                                 | 用於                                             |
|------------------|--------------------------------------|--------------------------------------------------|
| `*text*`         | **斜體**：概念上的強調               | 引入新術語、強調意義                             |
| `**text**`       | **粗體**：警告、關鍵決定             | 「這是**編譯錯誤**」、「**直接拒絕**」           |
| `> [!NOTE]`      | GitHub 風格的資訊框                  | 旁註、非正式的指引                               |
| `> [!WARNING]`   | GitHub 風格的警告框                  | 陷阱、常見的誤解                                 |
| `> [!IMPORTANT]` | GitHub 風格的重要框                  | 核心不變條件、必須遵守的規則                     |

## 0.8.3. 文法定義：BNF 變體

本規格中的文法以 EBNF 變體撰寫。使用的後設字元如下。

| 後設符號            | 意義                     | 範例                           |
|---------------------|--------------------------|--------------------------------|
| `name ::= rhs`      | 定義                     | `path ::= ident ("::" ident)*` |
| `\|`                 | 選擇                     | `bool ::= "true" \| "false"`    |
| `?`                 | 零或一個（可選）         | `param ::= ident (":" type)?`  |
| `*`                 | 零或多個                 | `args ::= expr ("," expr)*`    |
| `+`                 | 一或多個                 | `digits ::= digit+`            |
| `( ... )`           | 分組                     | `(a \| b) c`                    |
| `"..."`             | 字面文字                 | `kw_let ::= "let"`             |
| 非終結符（斜體）    | 參照另一個定義           | `expr ::= literal \| call` |

文法區塊以 ` ```ebnf ` 或一般圍欄撰寫。例如，函式宣告的文法可以寫成如下。

```ebnf
fn_decl     ::= "fn" ident "(" params? ")" ret_ty? block
params      ::= param ("," param)* ","?
param       ::= ident (":" type_expr)? default_value?
ret_ty      ::= "->" type_expr
default_value ::= "=" expr
```

文法只是**形式的參考定義**。語意定義於本文的文字中，因此光靠文法無法決定程式的意義。

## 0.8.4. 交叉引用

對其他節的引用保持一致。引用另一節時，同時給出**穩定的節號**與**相對路徑連結**。

```markdown
[3.2 Precedence and associativity](../003-expressions/302-precedence-and-associativity.md)
```

在本文中順帶提及的非正式引用，可以只用節號。

> 參見規格 2.7.4 的 niche 規則。

這種形式即使檔案改名，意義也得以保留。檔案路徑由自動化工具更新。

## 0.8.5. 程式碼範例慣例

程式碼範例也遵循固定的慣例。下面是最基本的形式。

```nabi
// short one-line comment
fn example() -> i32 {
    let x = 42;        // x is i32, fixed by the return (1.6.3)
    return x;
}
```

撰寫程式碼範例的規則如下。第一，每個程式碼範例都必須是某個**可編譯**之 Nabi 程式的一部分。第二，片段以 `// ...` 標示，並在本文中說明其脈絡。第三，刻意寫錯的範例必須在本文中清楚說明，並附上 `// ERROR: ...` 註解或文字解釋。最後，執行結果或輸出以 `//→ ` 註解標示。

下面的範例套用了最後一條規則。

```nabi
let r = 1 + 2;        //→ 3
let s = "hello";      //→ str
```

## 0.8.6. 穩定的節號

每一節都有永久的 `<chapter>.<section>(.<sub>)*` 編號。即使檔案改名或搬移，編號也不會改變，因此它可作為引用的穩定錨點。編號方式如下。

| 形式      | 範例      | 意義                                 |
|-----------|-----------|--------------------------------------|
| `C.S`     | `2.7`     | 第 C 章的第 S 節                     |
| `C.S.s`   | `2.7.4`   | C.S 的第 s 小節                      |
| `C.S.s.x` | `2.7.4.1` | 更深的小節（罕見）                   |

交叉引用一律以這個編號進行。檔案路徑（`002-types/207-...md`）只是為了 IDE 與 GitHub 的方便而附加；引用的實質永遠是節號。

## 0.8.7. 記號的限制

這套記號只定義**參考形式**。編譯器究竟如何剖析輸入並賦予意義，取決於本文的文字、程式碼範例與編譯器實作。也就是說，**光靠 BNF 無法決定所有意義**。意義的權威永遠在文字。
