# 0.1. 執行引擎與使用者介面

Nabi 的執行模型有兩個軸。一個是執行引擎，決定程式碼如何變成機器碼；另一個是使用者介面，也就是使用者輸入程式碼並取得結果的環境。引擎有兩種，介面有三種。由於多個介面共用同一個引擎，引擎比介面少。

## 0.1.1. 執行引擎

### JIT（Just-in-Time）

JIT 引擎在程式碼片段輸入後立即編譯並執行。一個輸入單位，即一行或一個儲存格，可以參照截至當時累積的狀態：變數、函式、匯入的模組等。當新的輸入覆寫既有定義時，之後的輸入看到的是新定義。編譯結果快取在記憶體和磁碟上，因此重新執行相同的輸入會立即完成。

### AOT（Ahead-of-Time）

AOT 引擎預先把整份原始碼編譯成單一產出：執行檔或靜態函式庫 `.a`。啟動時不需付出編譯成本，產出也可以作為函式庫被其他 Nabi 程式碼連結。不過，無法在執行時加入新的程式碼。

### 語意相同

> [!IMPORTANT]
> 兩個引擎共用相同的語意。在 JIT 下能運作的程式碼，在 AOT 建置中產生相同的結果。差別只在於**何時編譯**。本規格同時適用於兩個引擎；沒有只適用於其中一個的語意。

這個原則也適用於進入點。對 REPL 和 Jupyter 的輸入，意義等同於把頂層陳述式與項目依序附加到可執行套件的 `main.nabi` 末尾。只有工作階段操作（重新執行或刪除儲存格、顯示最終值）是互動式介面特有的（[4.16.10](../004-functions/416-entry-point.md#41610-relationship-to-jit--repl)）。

JIT 與 AOT 這兩個縮寫依[詞彙表](007-glossary.md)使用。

### 共用同一條管線

JIT 和 AOT 都經過相同的編譯管線直到 nabi-mir（[0.2. 編譯管線](002-pipeline.md)），只在程式碼產生時分歧。**JIT 引擎**以 Nabi 的程式碼產生器把每個輸入直接編譯成機器碼，並在存活於整個工作階段的主機行程中執行（[9.6](../009-tools/906-jit-engine.md)）。**AOT 引擎**以同一個程式碼產生器產生程式碼，在 `-O1` 以上進行最佳化，並連結出原生二進位檔（[9.2](../009-tools/902-aot-pipeline.md)）。兩者遵循相同的執行環境 ABI。

在這個結構下，單一的編譯器實作同時服務兩個引擎。因此任何行為差異都必須歸因於執行時的環境，而非編譯器：記憶體、執行緒、作業系統資源。

## 0.1.2. 使用者介面

### REPL

在 REPL 介面中，於終端機輸入的一行或一個運算式會立即求值並印出結果。它主要用於探索、示範公式和檢查型別。變數與函式定義會在多次輸入間累積，最後一個運算式的值與型別會自動顯示。

引擎是 JIT，輸入單位是一行或一個運算式。

### Jupyter

Jupyter 介面以 Jupyter / JupyterLab 的 Nabi 核心執行。求值以儲存格為單位，結果以視覺化、表格與文字的形式留在筆記本中。這支援標準的資料分析工作流程；重新執行儲存格會取代先前的定義。

引擎是 JIT，輸入單位是一個儲存格。Jupyter 前端（JupyterLab、Notebook、VS Code 等）把 Nabi 核心當作獨立行程執行，並透過以 ZeroMQ 為基礎的 Jupyter wire protocol 與之通訊（[9.8](../009-tools/908-jupyter-integration.md)）。核心直接使用作業系統的檔案系統、網路和外部行程。

### AOT 產出

在 AOT 產出介面中，從原始碼建置的執行檔會被直接執行，或是產生的靜態函式庫會被連結進另一個建置。

引擎是 AOT。

## 0.1.3. 引擎與介面的對應

```
              ┌── REPL (terminal)
   JIT  ──────┤
              └── Jupyter (kernel, ZMQ)

   AOT  ────── direct artifact execution
```

三個介面共用兩個引擎。

## 0.1.4. 語意基準

規格有歧義之處，以 AOT 語意為準。JIT 逐個儲存格重現 AOT 語意。
