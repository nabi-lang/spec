# 7.5. 並行標記

完整回收可以讓其標記階段與 mutator 並行執行，並在其後進行區塊清除。minor 回收、明確的 `nabi_gc_collect` 以及疏散一律是 stop-the-world 的（[7.3](703-gc-algorithm.md)）。

> [!NOTE]
> 本節僅供參考：它描述的是參考執行環境的 GC，可能在任何版本中改變。只有在 [8.1](../008-abi/801-object-header-abi.md) 中固定為 ABI 的物件配置具規範性。

## 7.5.1. 時機

| `NABIR_GC_CONCURRENT` | 完整回收                                           |
|----------------------|----------------------------------------------------|
| `auto`（預設）      | 老物件總計 32 MiB 以上，或設定了暫停目標時（[bare 1.6.12](../../refs-standard-libraries/100-bare/106-gc-pin.md#1612-set_pause_goal---a-pause-goal)），進行並行標記 |
| `always`            | 一律並行標記                                       |
| `off`               | 一律 STW                                           |

未設定或為空的變數取其預設值。列出值以外的值會在 stderr 印出一行警告，指出該變數、該值以及接受的值，而變數取其預設值。

## 7.5.2. 階段

1. **初始暫停（STW）。**執行一次 minor 回收，並在安全點取得根的快照。設定全域的 `MARKING` 旗標。
2. **並行標記。**單一的標記執行緒從快照開始標記。mutator 繼續執行；配置速度超過標記器的 mutator 也會參與標記（7.5.4）。
3. **最終暫停（STW）。**取出 SATB 緩衝區的內容，重新掃描根，並清除大型物件。清除 `MARKING`。
4. **延遲清除。**區塊在最終暫停之後、mutator 執行期間被清除：由標記執行緒、由找不到可用區塊的配置執行緒（它改為清除幾個區塊而不是擴大堆積），以及由下一次暫停處理剩下的部分，每次暫停都會先完成它。區塊一被清除就會再次交出；超過下一個週期預算的可用區塊會先歸還給作業系統。

## 7.5.3. SATB 屏障

逐物件的 snapshot-at-the-beginning（Yuasa）：在標記期間對某個物件第一次存入之前，記錄它在那一刻所持有的參照，因此標記開始時可到達的一切都保持被標記。它不需要自己的屏障。分代的寫入屏障（[7.4.2](704-barriers-and-roots.md#742-write-barrier-object-remembering)）在第一次存入某個物件時就已經走其慢速路徑，而該慢速路徑負責記錄。分代屏障記錄的是被存入的物件；它不是會改為記錄被存入之值的增量更新屏障。

- 在 `MARKING` 已設定時，第一次寫入 `UNLOGGED` 物件的慢速路徑，會把該物件目前所有的參照記錄到 SATB 緩衝區（TLS `nabi_tls_satb_cursor` / `nabi_tls_satb_limit`，[8.3](../008-abi/803-tls-slots.md)）。
- 記錄期間，它設定標頭的 `SATB` 位元。對同一個物件的競爭存入會等待該位元被清除。
- 大型（LOS）物件一次記錄一張 512 B 的卡片：對每張卡片的第一次存入記錄該卡片所持有的參照（慢速路徑接收槽位與存入的大小），而卡片表之後的每張卡片兩個位元，表示該卡片是否正在記錄或已記錄。一次存入最多只等待一張卡片，絕不會等待整個物件；在標記的其餘期間，該物件保持 `UNLOGGED`。
- 因此無論是否使用並行標記，編譯器發出的屏障程式碼都相同。

## 7.5.4. 配置與回收

- 標記期間的配置以行為單位是黑色的（該行中的物件被視為存活）。標記期間配置的物件在標記結束之後是年輕的。
- 標記期間不會進行 minor 回收。一次標記有兩倍的年輕代預算可以配置；超過之後，配置的執行緒會自己標記剩餘工作的一部分（標記協助，4096 個物件），並依比例獲得更多空間：每標記一個物件，獲得年輕代預算除以上一次標記所標記之物件數的空間。只有在超過預算的四倍，或到達堆積上限時（[bare 1.6.14](../../refs-standard-libraries/100-bare/106-gc-pin.md#1614-set_heap_limit---a-heap-limit)），配置才會在暫停中完成標記。當協助發現已沒有東西可以標記時，它會完成標記（一次短暫的最終暫停）。
- 疏散只在 STW 的完整回收中進行。若延遲清除發現堆積碎片化，下一次完整回收會以帶疏散的 STW 進行（有暫停目標時則不會）。標記期間配置的行在那項檢測中算作已占用（[7.3.1](703-gc-algorithm.md#731-immix-mark-region)），因此單靠配置絕不會讓下一次完整回收停止整個世界。
- 當 `no_collect` 區域開啟時（[bare 1.6.13](../../refs-standard-libraries/100-bare/106-gc-pin.md#1613-no_collect---a-region-without-collections)），標記器繼續標記，但等到該區域關閉之後才進行最終暫停。
