# 8.7. 程式碼產生

`nabic` 自己產生機器碼。其程式碼產生器接受 nabi-mir 並為目標寫出目的檔，再由它自己的連結器產生執行檔（[9.2.14](../009-tools/902-aot-pipeline.md#9214-連結執行檔)）。同一個程式碼產生器服務每個最佳化等級以及 REPL 儲存格。8.8 到 8.10 的降階規則描述它所發出的內容；本節給出它們周圍的各個階段。

## 8.7.1. 轉譯流程

```
nabi source
   | parse, name resolution, type check
nabi-hir
   | specialize / monomorphize, desugar
nabi-mir
   | optimization (-O1 and above, 8.7.3)
nabi-mir
   | lowering: layouts, conventions, GC frames, barriers, checks (8.8 ~ 8.10)
LIR (one low-level form for every target)
   | instruction selection, register allocation (above -O0)
machine code
   | object writer
object (Mach-O, ELF, COFF, wasm)
   | nabic's linker
executable
```

所有步驟都在 `nabic` 內執行。8.8 到 8.10 的程式碼範例是虛擬碼：以 nabi-mir 的形式表示區塊與分支（`bb1:`、`if c then bb2 else bb3`、`goto bb4(x)`），並在發出的程式碼有關緊要之處以位元組偏移表示載入與存入。它們不是 `nabic` 會讀取的格式。

## 8.7.2. 各階段的責任

| 階段 | 它決定什麼 |
|-------|-----------------|
| nabi-mir → 最佳化後的 nabi-mir | `-O0` 以上的內嵌與簡化（8.7.3） |
| nabi-mir → LIR | 一切與指令集無關的事：每個值的配置（8.8）、呼叫慣例（[8.6](806-calling-convention.md)）、影子堆疊框架、配置的快速路徑、寫入屏障、安全點輪詢（8.9）、溢位與邊界檢查及其 panic 訊息 |
| LIR → 機器碼 | 單一指令集（`x86_64`、`aarch64`、i686、armv7、riscv64、riscv32、powerpc64le、s390x、wasm32）的指令；在 `-O0` 以上，哪些值放在暫存器中 |
| 機器碼 → 目的檔 | 容器（Mach-O、ELF、COFF、wasm 目的檔），包含其重定位、展開資訊，以及有 `-g` 時的偵錯資訊（[9.9.6](../009-tools/909-debug-tools.md#996-偵錯工具整合gdb--lldb)） |
| 目的檔 → 執行檔 | `nabic` 的連結器；`NABI_CC` 會覆寫它（[9.2.14](../009-tools/902-aot-pipeline.md#9214-連結執行檔)） |

## 8.7.3. 最佳化等級

| 等級 | nabi-mir | 值 |
|-------|----------|--------|
| `-O0` | 原樣 | 各自放在其堆疊槽位中 |
| `-O1` | 最佳化；迴圈中的呼叫與 `-O2` 一樣內嵌，其他地方只內嵌小函式、`#[inline]` 函式以及只從一處呼叫的函式 | 放得下時放在暫存器中 |
| `-O2` | 最佳化；在迴圈之外也內嵌較大的主體 | 放得下時放在暫存器中 |
| `-O3` | 與 `-O2` 相同，在迴圈中內嵌更大的主體，並展開保持純量的迴圈 | 放得下時放在暫存器中 |
| `-Os` | 最佳化；只在主體大約與呼叫一樣小之處（在迴圈中則是其數倍）才內嵌呼叫 | 放得下時放在暫存器中 |

最佳化器內嵌建置擁有其主體之 Nabi 函式的直接呼叫：套件自己的函式、泛型實例，以及每個建置都會與程式一起編譯的標準函式庫函式。呼叫循環絕不會內嵌進自己，而 `#[inline(never)]` 與 `#[cold]` 函式以及位於以 panic 結束之路徑上的呼叫保持為呼叫。內嵌進迴圈之主體中的呼叫，會作為該迴圈中的呼叫重新評估。把常數陣列（`const` 表）傳給其被呼叫者只會讀取之參數的呼叫，會改為呼叫被呼叫者的一份複本，由該複本自己建立陣列，因此該呼叫不會複製任何表。接著最佳化器傳播複本與常數、摺疊常數運算式、移除共同子運算式與無用程式碼、簡化控制流程、在進入時已經知道分支走哪一側時直接跳過該分支（內嵌之迭代器的 `next()` 所回傳、由其外圍的 `for` 迴圈測試的 `Option`）、把自身尾呼叫變成迴圈、移除結果一定放得下的溢位檢查，並把迴圈不變的計算移出迴圈。在 `-O3`，它還會展開向量化器留為純量之迴圈的各段（8.7.8；保有浮點數總和或呼叫函式的迴圈）：完整的一段在其計數器的兩次測試之間執行主體 4 次（主體較長時為 2 次）。程式所計算的每個值、每個 trap（溢位、除法、邊界）以及每個副作用都保留，順序也相同。

`-g` 在任何等級都不會改變產生的程式碼。在 `-O0` 以上，最佳化器會為偵錯資訊記錄它做了什麼：它所內嵌的每個主體都是位於該呼叫之下的獨立範圍，而指派被移除的具名區域變數，會保留改為容納其值的東西（一個常數、在該變數可見期間值不變的另一個區域變數，或就地建立之結構的欄位）。程式碼產生器接著說明每個變數在程式碼各處位於何處（[9.9.6](../009-tools/909-debug-tools.md#996-偵錯工具整合gdb--lldb)）。在 `-O3` 展開之迴圈主體的各份複本中，作為另一個區域變數之值而保留的變數，可能顯示較早一次迭代的值。

指令選擇在每個等級都相同，但在 `-O0` 以上迴圈可能被向量化（8.7.8），而 RISC-V 程式碼對每個有 16 位元壓縮（`C`）形式且沒有重定位的指令採用該形式，對跳躍範圍能到達目標的分支與跳躍也是。影子堆疊框架、輪詢與屏障在最佳化之後、針對被編譯的程式碼放置（8.9）。程式碼以目標的基準 CPU 為準，但包括 `-C target-cpu` 與 `-C target-feature` 所開啟、程式碼產生器會使用的功能（[0.6.4](../000-meta/006-platform-targets.md#064-simd)）：`x86_64` 上的 AVX2 向量迴圈與單指令位元計數，`aarch64` 上的 LSE atomics、RCpc acquire 載入與位元組內積，`s390x` 上以 `vector`、`riscv64` 上以 `v` 進行的向量迴圈，`riscv64` 與 `riscv32` 上以 `zbb` 進行的單指令旋轉，`x86_64` 上以 `fma`、`armv7` 上以 `vfp4` 進行的融合 `mul_add`；`-neon`、`-vsx` 與 `-simd128` 讓每個迴圈都保持純量。

## 8.7.4. 運算

- 整數與浮點數算術、比較、`sqrt`、位元計數（`count_ones`、`leading_zeros`、`trailing_zeros`）、`swap_bytes` 與原子運算都是指令（在沒有 LSE 的 `aarch64` 上，原子的讀取-修改-寫入是排他載入 / 儲存迴圈）。在 `-O0` 以上，原子運算的強度恰好等於程式所要求的順序，不會更強，依照一般的 C++ 對應：在 `x86_64` 與 `i686` 上只有 `SeqCst` 存入會加上柵欄；在 `aarch64` 上 `Relaxed` 載入或存入是一般的載入或存入，acquire 載入是 `ldar`（有 `rcpc` 時是 `ldapr`），release 存入是 `stlr`，讀取-修改-寫入採用 LSE 或排他指令的 acquire / release 形式；在 `armv7` 上，release 之前與 acquire 之後有一道 `dmb`；在 `powerpc64le` 上，release 之前是 `lwsync`（`SeqCst` 是 `sync`），acquire 之後是 `lwsync` 或 `isync`；在 RISC-V 上是 `fence` 以及 `aq` / `rl` 位元；在 `s390x` 上只有 `SeqCst` 存入會序列化；`wasm32` 的 atomics 是循序一致的。在 `-O0`，每個原子運算都是循序一致的，這滿足每一種順序（[0.6.4](../000-meta/006-platform-targets.md#064-simd)）。
- 當指令集沒有某個運算的指令時，程式碼會呼叫平台對應的支援常式。在 armv7 上，這包括各種寬度的整數除法（`__aeabi_idiv`、`__aeabi_uidiv`、`__aeabi_ldivmod`、`__aeabi_uldivmod`）、64 位元整數與浮點數之間的轉換（`__aeabi_l2d`、`__aeabi_d2lz`……），以及 64 位元乘法的溢位檢查（`__mulodi4`）。在使用軟體浮點的 riscv32 上，這包括所有浮點數的算術、比較與轉換（`__adddf3`、`__ltdf2`、`__floatdidf`……）以及 64 位元除法（`__divdi3`、`__umoddi3`……）。i686 在目的檔內部的一個常式中進行 64 位元整數的除法。
- 在 `-O0` 以上，在目標有融合乘加指令之處（`aarch64`、`powerpc64le`、`s390x`、`riscv64`；有 `fma` 的 `x86_64`、有 `vfp4` 的 `armv7`），`mul_add` 是一道該指令，在其他地方則是對執行環境之 `nabi_f64_mul_add` / `nabi_f32_mul_add` 的呼叫；兩者都只捨入一次。
- 其他浮點數方法（`floor`、`round`、`sin`、`exp`、`pow`……）是對執行環境之 `nabi_f64_*` / `nabi_f32_*` 函式的呼叫，它們會呼叫 libm（[8.5](805-extern-symbols.md)）：其結果來自目標的 libm，絕不來自主機上的編譯期求值。
- nabi-mir 的每個分支都是一次跳躍或雙向分支。對標籤或整數的 `match` 是依分支順序排列的一串比較（8.9.3）；不會建立跳躍表。

## 8.7.5. 加速領域的函式庫

Nabi 原始碼無法直接存取程式碼產生器。讓張量 / 自動微分 / SIMD / GPU 等加速領域的函式庫接上程式碼產生器的後端介面已在計畫中，但尚未實作：在 0.1 中，`nabic` 自己的程式碼產生器是唯一的一個，而 [8.11.13](811-backend-contract.md#81113-另外安裝的程式碼產生器) 的另外安裝之程式碼產生器是 0.2 的草案。程式碼產生器必須對其目的檔保證的事項見 [8.11](811-backend-contract.md)。

## 8.7.6. `extern` 函式（執行環境函式）

[Extern "C" 符號](805-extern-symbols.md)中列出的 `nabi_*` 函式以 C ABI（[8.6](806-calling-convention.md)）依符號呼叫，並在連結時對 `libnabir.a` 解析。字串相等（因此字串模式也是）會呼叫 `nabi_str_cmp`。TLAB 快速路徑、寫入屏障的快速路徑以及安全點輪詢是行內程式碼；它們只在慢速路徑上呼叫 `nabi_gc_alloc_slow`、`nabi_gc_wb_slow` 與 `nabi_runtime_yield`（8.9.9 ~ 8.9.11）。

## 8.7.7. TLS 存取

對 [mutator TLS 槽位](803-tls-slots.md)的存取經由執行緒區域區塊 `nabi_tls` 的位址。Nabi 函式以其隱藏的最後一個引數從呼叫者接收它（[8.6.6](806-calling-convention.md#866-nabi-對-nabi-的呼叫慣例)）；從 Nabi 之外進入的程式碼在進入時以目標的 TLS 存取序列計算它一次（[8.3.8](803-tls-slots.md#838-編譯器發出的形式)）。之後每個槽位就是在其相對於該位址之偏移上的一次載入或存入。

```
t = <nabi_tls address>            ; the hidden last argument, or computed once at entry
flag = load.u8 [t + 10p+8]        ; yield_flag: offset 88 when p = 8
```

## 8.7.8. 迴圈向量化

在 `-O0` 以上，於 `x86_64`（SSE2，或有 `avx2` 功能時的 AVX2）、`i686`（SSE2）、`aarch64`（NEON）、`armv7`（NEON，僅限整數 lane：NEON 會把次正規浮點數清為零）、`powerpc64le`（VMX 與 VSX）、有 SIMD128 的 `wasm32`、有 `vector` 的 `s390x`（z13；有 `vector-enhancements-1`（z14）時浮點 lane 可為 4 位元組）以及有 `v` 的 `riscv64`（每個向量暫存器的 128 位元，任何向量長度皆可）上（[0.6.4](../000-meta/006-platform-targets.md#064-simd)），以 1 為步長、把 `usize` 計數器推進到一個它不會改變之上限、而且在任何地方都不輪詢的迴圈（計數迴圈的一段，或短迴圈：[8.4.2](804-safepoint.md#842-發出位置)），可以在其前面加上一個向量迴圈（在 `-Os` 只限最多 24 個 nabi-mir 陳述式的主體，其向量迴圈大約與純量迴圈一樣長）。走訪 `List`、切片或字串位元組的 `for` 迴圈（`for x in xs`、`for x in xs[a:]`、`for (i, x) in xs.iter().enumerate()`、`for b in s.bytes()`），在其迭代器的 `next()` 被內嵌之後，就是這樣的迴圈，與範圍迴圈相同；最佳化器移除了其邊界檢查的迴圈也是。向量迴圈處理 16 位元組（AVX2 為 32 位元組）、容納同一寬度元素的向量，並把它沒有完成的迭代留給其後的純量迴圈。當迴圈的主體只做下列事情時，它就會得到一個向量迴圈：

- 在計數器處、在計數器加上一個小常數處，或在計數器加上一個迴圈不會改變的值（切片的起點）處，讀取與寫入緩衝區（`List` 的緩衝區）的元素；
- 讀取比它所計算之值更窄的元素，只為了把它們擴寬（`u8` 的 `b as u32`），並且只寫入為更窄元素而縮窄的值（`x as u8`），在 `powerpc64le` 以外的每個目標上；
- 對那些元素以及迴圈不會改變的值進行計算：整數的 `+`、`-` 與 `*`（回繞或受檢；`*` 限於目標能相乘的寬度，受檢的 `*` 限於目標也能給出每個乘積之高位一半之處：`x86_64` 與 `i686` 上的 2 位元組 lane，`aarch64` 與 `s390x` 上的 1 到 4 位元組，`wasm32` 上的 2 與 4，`riscv64` 上的每種寬度）、`&`、`|`、`^`、`!`、以常數移位、比較、整數之間與來自 `bool` 的 `as`、浮點數的 `+`、`-`、`*`、`/`、取負、`sqrt`、`min` 與 `max`（不在 `armv7` 上），以及在目標與其向量單元都會融合它之處的 `mul_add`（`aarch64`、`powerpc64le`、`riscv64`、有 `fma` 的 `x86_64`、8 位元組 lane 或有 `vector-enhancements-1` 時的 `s390x`）；
- 依這類值分支（`if`、`&&`、`||`）：每個 lane 計算兩側，並保留其測試所選的那一側。一側可以讀取每個 lane 都可以讀取的元素（每次迭代都會執行之區塊所讀取的元素，或迴圈所遵守之邊界檢查保護下的元素）。測試的兩側可以存入同一個元素：這些存入會被合併。只在一側的存入需要以遮罩存入（AVX2，4 與 8 位元組的元素）；
- 提前離開迴圈（`return`、`break`、失敗的邊界檢查）；
- 累積整數歸約：`+` 或 `-`（回繞或受檢）、`&`、`|`、`^`、計數（`if c { n += 1 }`、`n += c as T`）、最小值或最大值（`m = m.min(x)`、`if x > m { m = x }`），可以在測試的一側或多側；或位元組乘積的總和（`s += (a[i] as i32) * (b[i] as i32)`，在有 `dotprod` 的 `aarch64` 上每個 lane 四個乘積）；或以相同兩種方式進行的浮點數最小值或最大值。

向量化的迴圈所做的事，就是純量迴圈逐個元素所做的事：

- 容納會離開迴圈或 trap 之元素（溢位、失敗的邊界檢查）的向量不會被執行：純量迴圈從其第一個元素開始接手，並在該元素處離開或 panic，在它之前的每個元素都已完成。
- 歸約為每個 lane 保留部分結果，並在結尾合併各 lane。受檢的總和把其非負元素與負元素分開保存，這界定了純量迴圈所會產生的每個部分和（任何一次迭代的路徑上只有一次更新）；當其中任一界限放不下時，迴圈會從頭以純量程式碼重新執行（這樣的迴圈不寫入任何記憶體），因此它恰好在純量迴圈會 panic 之處 panic，或完全不 panic。最小值或最大值讓每個 lane 都從累加器開始；兩個相等的整數中保留哪一個都可以，這不會顯現出來。位元組乘積的受檢總和也保留乘積絕對值的總和，這界定了每個部分和；當該界限放不下時，迴圈會以純量程式碼重新執行。
- 浮點數總和不會被向量化：浮點數總和依程式的順序相加，另一種順序的捨入結果會不同。浮點數的最小值或最大值對每個輸入都給出與純量迴圈相同的位元。在既不是 NaN 也不是零的數之中，最小值（最大值）在任何順序下都是同一個值，因此各 lane 可以找出它：容納 NaN 或零（其正負號在某些目標上由純量 `min` / `max` 依運算元順序保留）的向量不會被執行，由純量迴圈接手它及其後的部分；迴圈開始時就是 NaN 的累加器會讓整個迴圈保持純量。對應 `y = a.min(b)` 同樣把 NaN 或兩個零相遇的向量留給純量迴圈。只有在程式呼叫 `mul_add` 之處，乘法與加法才會被融合成一道指令。
- 不會寫入純量迴圈不會寫入的任何元素：只在測試一側的存入以遮罩寫出，否則迴圈保持純量。
- 可能是同一個串列的兩個串列的元素，保持其讀取與寫入的順序：當向量會改變該順序時，只有在其前方的測試發現兩個緩衝區不同時，向量迴圈才會執行。同一個緩衝區在迴圈不會改變之偏移上的兩列（`r[o1 + i]` 與 `r[o2 + i]`）也是如此：只有在其前方的測試發現兩個偏移相等或相差整整一個向量時，向量迴圈才會執行。經由切片起點的索引（`isize` 加法，受檢）在 `isize::MAX` 以下是精確的：其前方的測試會檢查起點與上限都遠低於它，否則執行純量迴圈。
- 向量迴圈不會到達任何安全點，也不進行輪詢；它最多執行 1024 次迭代，然後純量迴圈（帶有其輪詢）會再次執行。

有 `-g` 時，向量迴圈的指令位於迴圈第一個陳述式的位置；在它執行期間，迴圈的變數保持它開始時的值。

## 8.7.9. 驗證轉譯

端對端測試（`compiler/nabic/tests/main/integration.rs`，針對 `tests/cases/` 中的程式）建置並執行 .nabi 檔案，在 `-O0` 下執行，以及在 `NABI_TEST_OPT=-O2` 時最佳化後執行；`NABI_TEST_TARGET` 會為另一個目標執行它們。

這項驗證確保本部分所定義的降階規則是正確的。
