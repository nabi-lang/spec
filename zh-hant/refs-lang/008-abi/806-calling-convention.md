# 8.6. 呼叫慣例

本文件定義函式呼叫所使用的暫存器與堆疊慣例。它預設遵循平台的 C [ABI](../000-meta/007-glossary.md#abi應用程式二進位介面)，只說明不同的部分。

## 8.6.1. 預設：平台的 C ABI

每個宣告為 [Extern "C" 符號](805-extern-symbols.md)的函式都使用平台的 C ABI。Nabi 函式之間的呼叫使用相同的暫存器，但以不同的方式傳遞聚合型別（8.6.6）。

| 平台                     | ABI                |
|--------------------------|--------------------|
| Linux x86_64             | System V AMD64     |
| Linux aarch64            | AAPCS64            |
| Linux i686               | System V i386      |
| Linux armv7              | AAPCS              |
| macOS aarch64            | AAPCS64（Apple 變體） |
| Windows x86_64           | MS x64             |
| Windows aarch64          | AAPCS64（MS 變體） |
| Windows i686             | MS x86（cdecl）    |
| FreeBSD x86_64           | System V AMD64     |
| Linux riscv64            | RISC-V LP64D       |
| riscv32（沒有作業系統）  | RISC-V ILP32（軟體浮點） |
| Linux powerpc64le        | 64-bit ELFv2       |
| Linux s390x              | s390x ELF（z/Architecture） |
| WASM                     | WebAssembly C ABI  |

`nabic` 以與平台之 C 編譯器相同的規則（8.6.3）分類聚合型別（struct / tuple / array）如何跨越 C 邊界傳遞，然後把每個純量放進其暫存器或堆疊槽位。本規格只定義其餘的變化與附加事項。在 WebAssembly C ABI 之下，只有單一純量的聚合型別以該純量傳遞，其他任何聚合型別則以指向呼叫者複本的指標傳遞（結果透過 `sret`）；執行環境的 `str` 引數以參照傳遞。

## 8.6.2. 暫存器引數 / 回傳

原樣使用各 ABI 所定義的預設引數與回傳暫存器。

| 平台           | 引數暫存器（整數）         | 回傳（整數）|
|----------------|----------------------------|-------------|
| Linux x86_64   | rdi、rsi、rdx、rcx、r8、r9 | rax、rdx    |
| Windows x86_64 | rcx、rdx、r8、r9           | rax         |
| aarch64        | x0 ~ x7                    | x0、x1      |
| i686           | （只用堆疊）               | eax、edx    |
| armv7          | r0 ~ r3                    | r0、r1      |
| riscv64        | a0 ~ a7                    | a0、a1      |
| riscv32        | a0 ~ a7                    | a0、a1      |
| powerpc64le    | r3 ~ r10                   | r3、r4      |
| s390x          | r2 ~ r6                    | r2          |

浮點數與向量值同樣使用各 ABI 所定義的標準暫存器（xmm0-7、vN、sN 等）。

## 8.6.3. `struct` 引數 / 回傳：小 `struct` 規則

當聚合型別以值跨越 C 邊界傳遞時（`extern "C"` 宣告與定義），nabic 以與平台之 C 編譯器相同的規則依目標 ABI 分類它，並在該分類所給出的暫存器中傳遞它。HFA 最多放進四個 float / double 暫存器（在 powerpc64le 上為八個）。在表中，`iN` / `[n x T]` 指稱聚合型別在其中傳遞的整數或浮點數暫存器（或堆疊字組），`byval` 指堆疊上的複本，`sret` 指透過呼叫者傳入之隱藏指標寫入的結果。

| 目標                                      | 分類                                                                                      |
|-------------------------------------------|-------------------------------------------------------------------------------------------|
| AAPCS64（Linux / Apple / Windows arm64）  | HFA（1 ~ 4 個相同浮點數型別的元素）成為 `[n x f32]` / `[n x f64]`。其他 16 位元組以下的聚合型別成為 `i64` / `[2 x i64]`（8 位元組以下的回傳值成為 `iN`）。更大的：引數以指向呼叫者複本的指標傳遞，回傳使用 `sret` |
| System V x86_64                           | 每個 eightbyte 被分類為 INTEGER / SSE，放進整數 / SSE 暫存器。若暫存器用完，整個聚合型別以 `byval` 傳遞。超過 16 位元組：引數 `byval`，回傳 `sret` |
| Windows x64                               | 大小為 1 / 2 / 4 / 8 位元組的聚合型別成為 `iN`。其他：引數以參照傳遞（指向呼叫者複本的指標），回傳 `sret` |
| System V i386 / Windows x86（i686）       | 聚合型別引數在堆疊上以 `byval` 傳遞（4 位元組對齊）。結果：在 Windows 上 1 / 2 / 4 / 8 位元組的聚合型別成為 `iN`；其他任何聚合型別結果（在 System V 上則是全部）使用 `sret` |
| AAPCS 硬體浮點（armv7）                   | HFA 成為 `[n x f32]` / `[n x f64]`。其他 64 位元組以下的聚合型別成為 `[n x i32]`（對齊 4 以下）或 `[n x i64]`；更大的以 `byval` 傳遞。結果：HFA 放在浮點數暫存器中，4 位元組以下的聚合型別以 `i8` / `i16` / `i32` 回傳，其他 `sret` |
| WebAssembly（wasm32）                     | 只有單一純量的聚合型別成為該純量。其他任何聚合型別引數以指向呼叫者複本的指標傳遞，結果使用 `sret` |
| RISC-V LP64D（riscv64）                   | 由一個 float、兩個 float，或一個 float 與一個整數組成、8 位元組以下的結構（不含 union），在把巢狀結構與陣列攤平計算之後，只要兩種暫存器都還夠用，就以其欄位放進浮點數 / 整數暫存器；有填充的結構與 `#[repr(packed)]` 結構也適用，每個欄位從其自己的偏移讀取。否則 8 位元組以下的聚合型別成為 `i64`，16 位元組以下的成為 `[2 x i64]`（16 位元組對齊時為 `i128`），更大的引數以指向呼叫者複本的指標傳遞。結果以每種各兩個暫存器遵循相同規則；更大的使用 `sret` |
| RISC-V ILP32（riscv32）                   | 軟體浮點：沒有浮點數暫存器，因此 float 結構遵循整數規則。4 位元組以下的聚合型別成為 `i32`，8 位元組以下的成為 `[2 x i32]`（8 位元組對齊時為 `i64`），更大的引數以指向呼叫者複本的指標傳遞。8 位元組以下的結果在 `a0` / `a1` 中回傳；更大的使用 `sret` |
| ELFv2（powerpc64le）                      | HFA（1 ~ 8 個相同浮點數型別的元素）成為 `[n x f32]` / `[n x f64]`。其他 8 位元組以下的聚合型別成為 `i64`，更大的成為 `[n x i64]`，經過 `r3`-`r10` 與參數保存區域。結果：HFA 在 `f1`-`f8` 中，8 位元組以下的聚合型別以 `i64` 回傳，16 位元組以下的以 `[2 x i64]` 在 `r3` / `r4` 中回傳，其他 `sret` |
| s390x                                     | 1 / 2 / 4 / 8 位元組的聚合型別成為該大小的整數（單獨的 `f32` / `f64` 欄位保持為浮點數）。其他聚合型別引數以指向呼叫者複本的指標傳遞。聚合型別結果一律使用 `sret` |
| 其他目標                                  | 以值跨越 C 邊界傳遞聚合型別是編譯錯誤                                                     |

- `union` 依其成員（重疊在其開頭）分類，與 C 的分類方式相同，而不是依其儲存的位元組：當每個成員都是同一種浮點數型別的 HFA 且成員填滿它時，它是 HFA（AAPCS64、armv7、powerpc64le），而 System V x86_64 會逐 eightbyte 合併各成員的類別（`union { f64, f32 }` 是 SSE）。RISC-V 絕不把 union 當作 float 結構傳遞，s390x 把它當作其大小的整數傳遞，wasm32 只在它只有單一成員時才把它當作純量傳遞。
- `f16` / `bf16` 是 C 的 `_Float16` / `__bf16`。純量放在 `f32` 會占用之浮點數暫存器的低 16 位元（AAPCS64 上是 `h`/`v`，x86_64 上是 `xmm`，armv7 上是 `s`，riscv64 上是 NaN-boxed 的 `fa`，s390x 上是 `f`），而半精度數是聚合型別的浮點數成員：AAPCS64 有半精度數的 HFA，System V 把它們算作 SSE，riscv64 算作 float 欄位。armv7 以整數規則傳遞半精度數的結構；i686 在堆疊上傳遞半精度數，riscv32 在整數暫存器中傳遞。i686 上的半精度數結果（C 在 `xmm0` 中回傳它）、powerpc64le 與 wasm32 上的任何半精度數，以及 s390x 上 C 沒有該型別的 `bf16`，都是編譯錯誤，錯誤訊息會提示傳遞其位元（`u16`、`x.to_bits()`、`f16::from_bits`）。作為 C 可變引數的半精度數也是錯誤（`x.to_f64()`）。
- 8 或 16 位元組（至少 2 個 lane）的 `Simd<T, N>` 是 C 中該大小的向量（`float32x4_t`、`__m128`、`__attribute__((vector_size(16)))`）。在 AAPCS64 上，它作為參數與結果都占用一個 `v` 暫存器（用完之後是堆疊上 16 對齊的 16 位元組）。在 System V x86_64 上，它占用一個 `xmm` 暫存器（用完之後是 16 對齊的堆疊位元組），並在 `xmm0` 中回傳；在 Windows x64 上，向量引數以參照傳遞到 16 對齊的呼叫者複本，結果在 `xmm0` 中回傳。其他大小、其他目標、以值傳遞之聚合型別中的 `Simd`，以及 `Simd` 可變引數，都是編譯錯誤；`Mask<T, N>` 沒有 C 型別。
- 對齊與目標細節，依 C 編譯器的配置方式：在 AAPCS64 上，16 對齊的 16 位元組聚合型別是偶數暫存器對中的 `i128`（在 Linux 上當其欄位是 16 對齊時，不計其自身的 `#[repr(align(16))]`；在 Windows 上依其對齊；在 Apple 上則永不），而 Windows 的可變參數被呼叫者在整數暫存器中接收其固定的同質浮點數聚合型別（超過 16 位元組時以參照）。在 armv7 上，偶數對與 `byval` 的對齊也來自欄位，而可變參數被呼叫者在記憶體中回傳同質浮點數聚合型別。在 powerpc64le 上，16 對齊的聚合型別從偶數的雙字組開始。在 s390x 上，結構經由巢狀結構可以是單獨的浮點數，但經由陣列則永不。在 System V x86_64 上，高位 eightbyte 為填充的超對齊聚合型別占用一個暫存器。在 i686 Windows 上，`#[repr(align(N))]` 超過 4 的聚合型別無法以值傳給 cdecl 函式（MSVC 以參照傳遞到 16 對齊的複本，而那裡的 i686 框架並不是 16 對齊），這是錯誤，錯誤訊息會提示傳遞指標；stdcall 函式以 `byval` 接收它，其 `@N` 不計隱藏的結果指標。
- 窄整數參數與回傳值（`i8` / `i16` / `u8` / `u16` / `bool` / `c_char`）上的 `signext` / `zeroext` 遵循平台的 C ABI：x86_64 SysV、Apple arm64、i686、armv7、wasm32 與 RISC-V 擴充 `i8` / `i16` / `bool`；riscv64 也會對 32 位元值（`i32` / `u32` / `char`）做符號擴充；armv7 與 RISC-V 對 `c_char` 做零擴充；Linux AAPCS64 與 Windows arm64 都不擴充；Windows x64 只擴充 `bool`。
- 函式帶有堆疊探測，因此大的框架會碰觸保護頁而不會跳過它：行內的探測，或在 Windows 上呼叫 `__chkstk`。wasm32 與 riscv32 目標沒有探測。
- 相同的分類也適用於 `extern "C" fn` **定義**。定義有一個從 C 呼叫的獨立 C ABI 進入點；從 Nabi 的呼叫仍使用 Nabi 慣例。
- 在 System V i386 上，`i64` / `u64` / `f64` 在聚合型別中的對齊是 4 位元組（與 C 相同）。
- 這種分類不適用於 Nabi 函式之間的呼叫（8.6.6）。它只在 Nabi 與 C 交會之處需要，包括接受或回傳 `str`（一個 16 位元組的結構；在 Windows x64 上以參照傳遞，[8.5](805-extern-symbols.md)）的執行環境函式。

## 8.6.4. GC 物件指標：作為一般指標

GC 物件指標以與平台一般指標相同的 ABI 傳遞。不使用特殊的暫存器或帶標籤的指標。

不過，它們必須在呼叫前後註冊在[屏障與根追蹤](../007-runtime/704-barriers-and-roots.md)的[影子堆疊](../000-meta/007-glossary.md#影子堆疊shadow-stack)中。

這個註冊由編譯器發出的影子堆疊框架連上 / 解開完成（[8.9.12](809-lowering-control.md#8912-影子堆疊框架)）。

## 8.6.5. 會擲回錯誤之函式的回傳：以值為基礎的錯誤傳播

帶有 [`throws` 簽章](../004-functions/414-throws.md)的函式把其錯誤作為回傳值的一部分回傳。不使用另外的展開機制或執行環境符號。

```
fn f(args) throws (E) -> T
```

這個函式的 ABI 回傳型別是一個有兩個欄位的 `struct`：

```
Throws<T, E> = (bool, union(T, E))
; field 0: is_err (0 on success, 1 on error)
; field 1: payload. Read as T if is_err is 0, as E if 1
```

酬載是一個 union，其大小與對齊取 `T` 與 `E` 中較大者。若 `T` 是 unit，酬載只容納 `E`。錯誤通道由簽章區分，因此 `T` 與 `E` 可以是同一個型別。對於未定型的 `throws`（`throws (any Error)`），`E` 是一個 `any Error` 值，與 [`any`](../002-types/202-any-slot.md) 具有相同的標籤 + 酬載表示方式（[8.8](808-lowering-types.md)）。

欄位 0 可以以寬於一個位元組的方式儲存（當酬載容納 GC 參照時是 `i32`，好讓回收器把它當作和型別標籤讀取）；只有位元 0 有意義，而當酬載至少 4 對齊時，偏移、大小與暫存器都與 `(bool, payload)` 的相同。會擲回錯誤之函式的 `ref` 參數（[4.7](../004-functions/407-ref-keyword.md)）的值，在承載結構旁邊作為回傳值中由實作定義的部分傳遞。

這個 `struct` 和其他任何回傳值一樣透過平台的 C ABI 傳遞：在 8.6.3 的限制內放在暫存器中，超過時透過 sret。呼叫處的 `try` 檢查欄位 0 並分支；詳細的降階定義於 [8.9.6](809-lowering-control.md#896-try--catch--finally以值為基礎的分支)。

選擇這種方案的理由如下。

- 它在每個平台上的運作方式都相同（包括 WASM；不需要 DWARF 或平台的 EH 基礎設施）。
- 它不會與[影子堆疊](../000-meta/007-glossary.md#影子堆疊shadow-stack)衝突。錯誤也經由一般的回傳路徑離開框架，因此每個框架都正常地彈出其影子堆疊。
- 沒有錯誤之路徑的成本是回傳之後的一次分支；進入 `try` 或 `catch` 不需要任何成本。

## 8.6.6. nabi 對 nabi 的呼叫慣例

Nabi 函式之間的呼叫在 8.6.2 的暫存器中傳遞純量。超過 64 位元組的聚合型別（struct、tuple、array、`str`）以位址傳遞，並透過開頭的結果指標回傳。被呼叫者在進入時複製以位址傳遞的引數，因此呼叫者的值不會被修改。被呼叫者在複製其以位址傳遞的引數之後、回傳之前的任何時間點，都可以透過結果指標寫入結果。因此結果指標可以指向某個以位址傳遞的引數，但不得指向被呼叫者在呼叫期間會讀取的其他任何記憶體。這對每一次 nabi 對 nabi 的呼叫都成立，包括對預先建置程式碼、匯出函式與函式值的呼叫。直接呼叫還會在宣告的引數之後，以隱藏的最後一個指標引數傳遞呼叫者的 `nabi_tls` 區塊位址（[8.3.8](803-tls-slots.md#838-編譯器發出的形式)）；函式值、`#[export_name]` 的 Nabi 函式以及 `any` 分派器則不接受這個引數（8.6.11）。較小的聚合型別依下列規則，逐個葉節點在目標的引數與結果暫存器中傳遞與回傳。每個建置都遵循它們，因此任何建置的程式碼（無論是否預先建置）都能呼叫其他任何建置的程式碼。它與 8.6.3 的 C ABI 分類不同。下列規則適用於 64 位元組以下的聚合型別。

> [!NOTE]
> 以位址傳遞的值在記憶體中移動（`memcpy`），絕不在暫存器中移動。

**引數**

- 聚合型別被拆成其純量葉節點，每個占用其類別的下一個暫存器；暫存器用完時，剩下的葉節點放在堆疊上。因此 `str` 可能被拆分在最後一個引數暫存器與堆疊之間。
- AArch64：`i64` / `ptr` / `f32` / `f64` 的陣列占用其類別的連續暫存器。若它放不進剩下的暫存器，就整個放在堆疊上，而該暫存器類別的其餘部分被標記為已使用。`i8` / `i16` / `i32` 的陣列像結構一樣被拆分。
- armv7：1 到 4 個成員的同質浮點數聚合型別占用連續的 VFP 暫存器，整數陣列占用連續的核心暫存器，與 AAPCS 的放置方式相同；整數區塊可以在堆疊上還沒有其他東西時被拆分在 `r3` 與堆疊之間。
- 堆疊槽位：在 Apple 目標上，頂層的純量引數取其自然大小與對齊，而聚合型別的 `i1` / `i8` / `i16` 葉節點占用 4 位元組槽位。在 i686、armv7 與 riscv32 上，槽位是 4 位元組，8 位元組的純量占用兩個（在 armv7 與 riscv32 上 8 位元組對齊）。在其他目標上，每個堆疊槽位都是 8 位元組。

**結果**

- AArch64：最多 8 個整數暫存器（`x0`-`x7`）與 8 個浮點數暫存器（`v0`-`v7`）。更大的結果透過在 `x8` 中傳入的 sret 指標回傳（該指標不會被回傳）。
- x86-64：最多三個整數暫存器（`rax`、`rdx`、`rcx`）；浮點數結果使用 `xmm0` / `xmm1`，然後是 x87 的 `st0` / `st1`。需要第 4 個整數暫存器或第 5 個浮點數暫存器的結果，透過在 `rdi` 中傳入、在 `rax` 中回傳的 sret 指標回傳。
- i686：最多三個整數字組（`eax`、`edx`、`ecx`）以及一個在 `st0` 中的浮點數值。armv7：`r0`-`r3` 與 VFP 暫存器。riscv64 / riscv32：兩個 XLEN 大小的值（`a0` `a1`，在 riscv64 上還有 `fa0` `fa1`）。powerpc64le：`r3`-`r10` 與 `f1`-`f8`。s390x：`r2`-`r5` 與 `f0` `f2` `f4` `f6`。wasm32：一個值。更大的結果透過以第一個引數傳入的隱藏結果指標回傳。

**Windows**

- Windows x64：整數與浮點數引數共用四個暫存器位置（`rcx` `rdx` `r8` `r9` / `xmm0`-`xmm3`）；每個引數占用下一個位置，放在其類別的暫存器中。堆疊槽位是 8 位元組，位於呼叫者的 32 位元組 home area 之後。sret 指標在 `rcx` 中傳入；其他方面結果與 x86-64 相同。
- Windows arm64：與上述 AAPCS64 相同。C 可變參數呼叫在整數暫存器中傳遞每個浮點數引數。

**窄整數**

被呼叫者不得依賴窄整數或 `bool` 引數與結果的高位元；呼叫者可以擴充它們。編譯後的程式碼會把收到的 `bool` 遮罩到位元 0，並重新擴充窄的值。

其他模組無法到達的函式（內部的、從未作為值使用）可以使用由實作定義的慣例。

對 `extern "C"` 與 `extern "nabi"` 執行環境函式的呼叫使用 8.6.1-8.6.5 的 C ABI 規則。

## 8.6.7. 尾呼叫

在 `-O0` 以上，函式在尾端位置對自己的呼叫會變成跳到其開頭（[8.7.3](807-code-generation.md#873-最佳化等級)）：以對自身之呼叫結尾的遞迴在一個框架中執行。尾端位置的其他呼叫是一般的呼叫。協程主體是狀態機，不受影響。

## 8.6.8. 內嵌函式的 ABI

`#[inline]`（[內建屬性](../006-meta-system/602-built-in-attributes.md)）的效果是呼叫本身可能消失。在那種情況下，呼叫慣例沒有意義。

`#[inline(never)]` 函式一律會被呼叫，並遵循一般的 ABI。

## 8.6.9. 引數傳遞的求值順序

[參數](../004-functions/402-parameters.md)由左至右的求值順序與呼叫慣例正交。

由左至右求值表示每個引數運算式從左邊開始依序求值。每個結果放進哪個暫存器或堆疊槽位，是由 ABI 決定的另一個問題。

有些 C 與 C++ ABI 由於堆疊推入的順序而偏好由右至左求值。不過 Nabi 保證由左至右的語意，編譯器會視需要使用暫存值與暫存器來協調這兩項要求。

## 8.6.10. 可變參數函式

[參數](../004-functions/402-parameters.md)的 `...T` 可變參數是語言層級的可變參數，它把引數打包成單一的切片視圖（`Slice<T>`）（通常與結構引數的 ABI 相同）。它與平台的 C 可變參數（`...` 可變引數）是不同的概念。

C 可變參數函式（例如 `printf`）可以透過 `extern "C"` 直接呼叫，此時 ABI 遵循平台的 C 可變參數慣例。

```
extern "C" {
    fn printf(fmt: ConstPtr<c_char>, ...);
}
```

- `...` 只能出現在 `extern` 區塊中的宣告裡，而且只能作為最後一個參數。Nabi 函式定義不能有 C 可變參數。
- C 預設引數提升適用於可變參數位置的引數：`bool`、`i8`、`i16`、`u8`、`u16` 與 `c_char` 以 `c_int`（`i32`）傳遞，`f32` 以 `f64` 傳遞，`str` 以 `char*`（以 NUL 結尾的位元組指標）傳遞。
- 聚合型別（struct / tuple / array）不能作為可變引數傳遞（編譯錯誤）。

## 8.6.11. 函式指標的 ABI

[函式型別](../004-functions/404-function-type.md)的 `fn(...) -> ...` 對間接呼叫使用相同的呼叫慣例。

```
code = f.0                       ; the function value's code pointer
result = call code(f.1, ...)     ; indirect call: the environment, then the arguments
```

引數與回傳具有相同的 ABI，因此直接呼叫與間接呼叫共用同一個介面，但 8.6.6 的隱藏 `nabi_tls` 位址除外：函式值不接受它。其程式碼指標是一個 thunk，它自己讀取該位址，並以它呼叫函式。

## 8.6.12. 閉包呼叫

[閉包](../004-functions/405-closure.md)中所述的閉包，是把環境與程式碼指標組合在一起的單一單位。

呼叫的運作方式如下。

```
The environment pointer as the first argument, followed by the ordinary arguments.
```

這個環境引數是閉包主體存取被擷取之變數的方式。

主體像一般函式一樣編譯（環境只是第一個引數）。

## 8.6.13. 非同步函式呼叫

[非同步](../004-functions/412-async.md)中的 `async fn` 在被呼叫時立即回傳 Future ptr，遵循一般的函式呼叫 ABI。

```
let f = async_fn(args);     // returns immediately (Future ptr)
let r = await f;             // coroutine mechanism
```

`await` 由一般的呼叫（輪詢目標 future）與狀態機的回傳組成（[8.10](810-lowering-coroutine-generic.md)），在一般的 ABI 之上運作。

## 8.6.14. 穩定性

C ABI 的部分（8.6.1 ~ 8.6.3、8.6.10）遵循平台的 C ABI，因此沒有另外的穩定性決定：在平台保證相容性的範圍內，Nabi 保持相容。

nabi 對 nabi 的慣例（8.6.6、8.6.11）以及會擲回錯誤之函式的回傳值配置（8.6.5）是執行環境 ABI 的一部分；任何變更都遵循[概觀](README.md#穩定性)中的穩定性方針。
