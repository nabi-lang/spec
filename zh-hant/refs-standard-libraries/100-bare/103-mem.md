# 1.3. `MaybeUninit<T>`：未初始化的記憶體

`bare::mem` 模組定義一個安全處理未初始化記憶體的包裝器，以及相關的操作。一般的 `T` 永遠保證已初始化，而 `MaybeUninit<T>` 則在型別層級明確表達初始化狀態。

## 1.3.1. 動機：讀取未初始化的記憶體是 UB

讀取未初始化的記憶體是 UB，即使是整數型別也一樣。問題不只是會讀出「垃圾值」；編譯器可以對該值做任何假設，並據此改寫程式碼。

```c
// C
int x;            // uninit
if (x == 0) { ... }   // the compiler may assume any value for x; either branch may become dead code
```

因此 T 本身無法表示未初始化狀態，需要另一個包裝器。

## 1.3.2. `MaybeUninit<T>`

```nabi
struct MaybeUninit<T> { /* same size + align as T, but possibly uninitialized */ }

impl<T> MaybeUninit<T> {
    fn uninit() -> MaybeUninit<T>;          // uninitialized slot
    fn zeroed() -> MaybeUninit<T>;          // filled with 0
    fn new(value: T) -> MaybeUninit<T>;     // initialized slot

    fn write(ref self, value: T);           // write value

    fn as_ptr(self) -> ConstPtr<T>;
    fn as_mut_ptr(ref self) -> Ptr<T>;

    unsafe fn assume_init(self) -> T;
    // SAFETY: only when initialization is guaranteed by write / an external mechanism

}
```

`as_ptr` / `as_mut_ptr` 要求接收者是一個位置（place）：指標指向該變數本身，而不是它的副本。`uninit()` 可以實作為 `zeroed()`。

### 範例：分離初始化步驟

典型的模式：等 FFI 填好緩衝區，再把值取出。

```nabi
let buf: MaybeUninit<[u8; 1024]> = MaybeUninit::uninit();
let p: Ptr<u8> = buf.as_mut_ptr().cast::<u8>();

unsafe {
    read_from_kernel(p, 1024);              // FFI fills buf
    let initialized: [u8; 1024] = buf.assume_init();
}
```

### 在 `write` 之後使用

`write` 只儲存值；它不回傳任何參考（Nabi 沒有 `ref` 回傳）。寫入之後，用 `assume_init` 取出值。

```nabi
let slot: MaybeUninit<Big> = MaybeUninit::uninit();
slot.write(big_value());
let v: Big = unsafe { slot.assume_init() };
process(v);
```

## 1.3.3. `Pod` trait

```nabi
unsafe trait Pod { /* marker */ }
```

Plain Old Data 的縮寫：每一種位元模式都有效的型別。[1.2.5](102-cast.md#125-reinterpreta-pod-b-pod位元強制轉型安全) 的 `reinterpret` 要求這個標記。它是 `unsafe trait`（[4.15.4](../../refs-lang/004-functions/415-unsafe.md#4154-in-traits)）：`#[derive(Pod)]` 會寫出實作，手寫的實作則是 `unsafe impl Pod for T {}`。無論哪一種，結構的佈局、欄位和 `Drop` 都會如下檢查。

| 自動實作                                     | 不適用                              |
|----------------------------------------------|-------------------------------------|
| 所有整數（i*、u*）                          | `Ptr<T>`（來源）               |
| 所有浮點數（f*）                            | 使用者結構（明確 #[derive(Pod)]） |
| `[T; N]`（T:Pod）                             | enum（變體標籤、niche）          |
| 最多 4 個元素且全為 Pod 的元組          |                                     |
| `c_char`                                     | `bool`、`char`（大多數位元模式不是值） |

### `Pod` 保證什麼

`Pod` 同時保證三件事。

1. 讀取任何位元模式都是安全的：不會暴露未初始化的內容。
2. **確定的佈局**：必須有 `#[repr(C)]` 或 `#[repr(transparent)]`。
3. **沒有 Drop**：如果實作了 `Drop`，`Pod` 會自動被拒絕。

```nabi
#[derive(Pod)]
#[repr(C)]
struct Vec3 { x: f32; y: f32; z: f32; }
// → reinterpret OK, ffi safe, etc.
```

## 1.3.4. 原始記憶體操作：read / write

低階記憶體操作的自由函式如下：

```nabi
unsafe fn read<T>(src: ConstPtr<T>) -> T;
unsafe fn write<T>(dst: Ptr<T>, value: T);

unsafe fn copy<T>(src: ConstPtr<T>, dst: Ptr<T>, count: usize);
                                               // memmove (overlap OK)
unsafe fn copy_nonoverlapping<T>(src: ConstPtr<T>, dst: Ptr<T>, count: usize);
                                               // memcpy (overlap UB, faster)

unsafe fn write_bytes<T>(dst: Ptr<T>, value: u8, count: usize);
                                               // memset (every byte = value)

unsafe fn swap<T>(a: Ptr<T>, b: Ptr<T>);
unsafe fn replace<T>(dst: Ptr<T>, value: T) -> T;     // read existing + write
unsafe fn drop_in_place<T>(p: Ptr<T>);               // runs the drop glue (does not free memory)
```

其中大多數也以 `Ptr<T>` 的方法公開（1.1.2）；本模組的自由函式作為**更順手的替代寫法**。揮發性存取則是 `bare::volatile::read` / `write`（1.5），那是它們唯一的路徑。

`drop_in_place` 執行 drop glue：先執行型別自己的 `drop`，再依宣告的相反順序處理其欄位（[2.13.4](../200-core/213-marker.md#2134-drop釋放時的清理)）。

## 1.3.5. `transmute_unchecked`：逃生門

這就是 [1.2.6](102-cast.md#126-transmute_uncheckeda-b逃生門) 所描述的函式。它定義在本模組中；`bare::transmute_unchecked` 是它在層級根部的重新匯出。

```nabi
unsafe fn transmute_unchecked<A, B>(a: A) -> B;        // no size check
```

## 1.3.6. 對齊 / 大小工具

```nabi
fn align_of<T>() -> usize;                  // T::align()
fn size_of<T>() -> usize;                   // T::size()
```

這些**不是 unsafe**。它們是 `Reflect` trait（[2.12 reflect](../200-core/212-reflect.md)）中 `T::size()` / `T::align()` 的 bare 層級形式：bare 程式碼沒有 `Reflect`。它們只定義在這裡。沒有針對值的形式：值在執行時所持內容（和型別的成員、`any` 的內容）的大小是 `x.size_of_val()`（[2.12.2](../200-core/212-reflect.md#2122-reflect靜態與實例兩種形式)）；bare 程式碼只有靜態型別。

## 1.3.7. 內建函式對應

各項目與編譯器內建函式的對應如下：

| 項目                           | 內建函式                      |
|--------------------------------|-------------------------------|
| `MaybeUninit::as_ptr` / `as_mut_ptr` | `nabi.addr_of`（`assume_init` 是一般的欄位讀取） |
| `ptr::addr_of` / `many_addr_of` | `nabi.addr_of`              |
| `Pod`                          | （標記，自動衍生） |
| `read` / `write`               | `nabi.ptr.read` / `nabi.ptr.write`（透過 `Ptr` / `ConstPtr` 的方法） |
| `copy` / `copy_nonoverlapping` | 無：逐元素 `read` / `write` 的迴圈（`dst` 高於 `src` 時 `copy` 由後往前執行） |
| `write_bytes`                  | 無：逐位元組寫入的迴圈   |
| `drop_in_place`                | `nabi.drop_in_place`           |
| `size_of` / `align_of`         | `nabi.size_of` / `nabi.align_of` |
| `buf_new` / `buf_get` / `buf_set` / `buf_same` | `nabi.buf_new` / `nabi.buf_get` / `nabi.buf_set` / `nabi.buf_same` |

## 1.3.8. 與其他語言的比較

| 面向                   | C               | Rust                  | Zig         | Nabi                    |
|------------------------|-----------------|-----------------------|-------------|------------------------|
| 未初始化的表示 | `T x;`（無聲） | `MaybeUninit<T>` | `undefined` | `MaybeUninit<T>`      |
| `Pod` / 安全 transmute | **無**        | `bytemuck::Pod`（函式庫） | `@bitCast`  | `Pod` + `reinterpret`  |
| 讀取未初始化是否 UB  | **允許**     | **UB**                | **UB**      | **UB**                 |
| memcpy / memmove       | `memcpy`        | `ptr::copy*`          | `@memcpy`   | `bare::mem::copy*` |

## 1.3.9. `GcBuf<T>` 與 `buf_*` 基本操作

集合型別建構於其上、編譯器已知的 GC 緩衝區 `GcBuf<T>` 定義在本模組中。其語意依 [2.9.12](../200-core/209-collections.md#2912-gcbuft原始-gc-緩衝區)，`core::collections::raw` 在那裡重新匯出它。

```nabi
struct GcBuf<T> { /* one GC reference to a run of Ts */ }

impl<T> GcBuf<T> {
    unsafe fn new(len: usize) -> GcBuf<T>;     // = buf_new(len)
    unsafe fn get(self, i: usize) -> T;        // = buf_get(self, i)
    unsafe fn set(self, i: usize, v: T);       // = buf_set(self, i, v)
}
impl<T> Clone for GcBuf<T>;                    // the same handle: the clone shares the buffer

unsafe fn buf_new<T>(len: usize) -> GcBuf<T>;      // zeroed
unsafe fn buf_get<T>(buf: GcBuf<T>, i: usize) -> T;        // no bounds check
unsafe fn buf_set<T>(buf: GcBuf<T>, i: usize, v: T);       // no bounds check
fn buf_same<T>(a: GcBuf<T>, b: GcBuf<T>) -> bool;  // identity, not contents; pins nothing
```
