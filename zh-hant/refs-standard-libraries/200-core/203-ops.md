# 2.3. 算術／位元／索引 trait

`core::ops` 模組定義了 Nabi 運算子語彙單元（[refs-lang 1.10](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md)）所分派到的 trait 家族。不只一般的運算子 `+` `-` `*` `/` `%` `<<` `>>` `&` `|` `^` `~` `&&` `||`，連 `arr[i]` 索引與 `s[1:3]` 切片也會呼叫本章定義的 trait 方法。[2.3.4](#234-索引-trait) 的索引 trait 是例外：它們位於 `core::index`，而不是 `core::ops`。

[refs-lang 3.1 運算子分派](../../refs-lang/003-expressions/301-operator-dispatch.md)的機制會尋找本章的**內容**；本文件 refs-standard-libraries 2.3 是這些內容的權威來源。

> [!NOTE]
> 本章所有運算子 trait 方法都宣告為不帶 `throws`。因此運算子不會擲回錯誤，impl 也不能加上 `throws`（[refs-lang 4.14.11](../../refs-lang/004-functions/414-throws.md#41411-方法上的-throws)）。可能失敗的運算以具名方法（`checked_div` 等）提供，或回傳 `Result`。

## 2.3.1. 算術 trait

### `Add`：算術加法（`+`）

首先是加法 trait。

```nabi
#[lang("add_trait")]
trait Add<Rhs = Self> {
    type Output;

    #[infix("+")]
    fn add(self, rhs: Rhs) -> Output;
}
```

**意義**：回傳兩個值的和。

```nabi
let a: i32 = 5;
let b: i32 = 3;
let c = a + b;        //→ 8 (i32)

let x: f64 = 1.5;
let y: f64 = 2.5;
let z = x + y;        //→ 4.0 (f64)
```

#### Output 規則

`Output` 關聯型別通常與 `Self` 相同，但有下列例外。第一，`int + int = int` 具有任意精度，因此永遠不會溢位；`i32 + i32` 這類固定寬度的和仍是 `i32`，不會提升為更寬的型別（[2.1.6](201-numbers.md#216-算術結果型別)）。第二，`Vec3<f64> + f64 = Vec3<f64>` 這類使用者定義的算術，以 `impl Add<f64> for Vec3<f64>` 的形式定義。

#### 溢位行為

溢位行為取決於型別。對 `i32 + i32` 而言，溢位檢查開啟時溢位會觸發 panic，關閉時則環繞。檢查由 `nabic -C overflow-checks[=yes|no]` 控制（[refs-lang 9.1.2](../../refs-lang/009-tools/901-nabic-cli.md#nabic-buildaot-建置)）；預設在每個建置設定檔中都開啟，在 `nabi.nabion` 的建置設定檔中寫 `overflow_checks: false` 可以關閉（[refs-lang 9.10.3](../../refs-lang/009-tools/910-nabi-frontend.md#9103-nabinabion--nabilock)）。`f32 + f32` 與 `f64 + f64` 遵循 IEEE 754 加法，因此溢位的結果是 ±∞ 或 NaN。`int + int` 具有任意精度，因此不存在溢位。飽和、檢查與環繞的版本以定義在此 trait 之外的獨立方法（`saturating_add`、`checked_add`、`wrapping_add`）提供。

在每個建置設定檔中都做檢查的理由，請見 [2.11.1 設計理由](211-conversion.md#設計理由)。

### `Sub`：算術減法（`-`）

減法 trait 定義如下。

```nabi
#[lang("sub_trait")]
trait Sub<Rhs = Self> {
    type Output;

    #[infix("-")]
    fn sub(self, rhs: Rhs) -> Output;
}
```

形式與 `Add` 相同；`a - b` 分派到 `Sub::sub(a, b)`。

```nabi
let r = 10i32 - 3i32;     //→ 7
let s = 1.0f64 - 0.5f64;  //→ 0.5
```

### `Mul`：算術乘法（`*`）

乘法 trait 定義如下。

```nabi
#[lang("mul_trait")]
trait Mul<Rhs = Self> {
    type Output;

    #[infix("*")]
    fn mul(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 6i32 * 7i32;      //→ 42
let s = 2.5f64 * 4.0f64;  //→ 10.0
```

#### 使用者定義的意義

除了算術乘法之外，`Mul` 也可以帶有領域特定的意義，典型的例子是矩陣乘法。

```nabi
struct Matrix2x2 { a: f64; b: f64; c: f64; d: f64; }

impl ops::Mul<Matrix2x2> for Matrix2x2 {
    type Output = Matrix2x2;

    fn mul(self, rhs: Matrix2x2) -> Matrix2x2 {
        Matrix2x2 {
            a: self.a * rhs.a + self.b * rhs.c,
            b: self.a * rhs.b + self.b * rhs.d,
            c: self.c * rhs.a + self.d * rhs.c,
            d: self.c * rhs.b + self.d * rhs.d,
        }
    }
}
```

逐元素乘法由 [2.6 廣播](206-broadcast.md)中的 `DotMul`（`m .* n`）處理。

### `Div`：算術除法（`/`）

除法 trait 定義如下。

```nabi
#[lang("div_trait")]
trait Div<Rhs = Self> {
    type Output;

    #[infix("/")]
    fn div(self, rhs: Rhs) -> Output;
}
```

詞法分析器把 `÷` 讀成 `/`，因此 `a ÷ b` 也分派到 `div`。`÷` 沒有自己的中綴繫結。

```nabi
let r = 20i32 / 7i32;      //→ 2 (integer division, truncating)
let s = 20.0f64 / 7.0f64;  //→ 2.857142857142857
```

#### 除以零

除以零依型別處理。整數 `i32 / 0` 會觸發 panic，而可常數摺疊的運算式（`1 / 0`）是編譯錯誤。浮點數 `f64 / 0.0` 依 IEEE 754 產生 ±∞ 或 NaN。

要得到 `none` 而不是 panic，請用 `checked_div`。

```nabi
let r = 20i32.checked_div(7i32);  //→ 2
let s = 20i32.checked_div(0i32);  //→ none
```

### `Rem`：算術餘數（`%`）

餘數 trait 定義如下。

```nabi
#[lang("rem_trait")]
trait Rem<Rhs = Self> {
    type Output;

    #[infix("%")]
    fn rem(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 20i32 % 7i32;     //→ 6
let s = 5.5f64 % 2.0f64;  //→ 1.5 (IEEE 754 fmod)
```

正負號規則：結果的正負號跟隨被除數（左運算元），因此 `(-5) % 3 = -2`、`5 % (-3) = 2`（截斷除法的定義，與 C／Rust 相同）。

### `Modulo`：向下取整模數（`%%`）

向下取整（商向下捨入）的餘數 trait 定義如下。

```nabi
trait Modulo<Rhs = Self> {
    type Output;

    #[infix("%%")]
    fn modulo(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = (-5i32) %% 3i32;     //→ 1   ( = -5 - (-2)*3 )
let s = 5i32 %% (-3i32);     //→ -1  ( = 5 - (-2)*(-3) )
let t = (-7.5f64) %% 2.0f64; //→ 0.5
```

它與 `Rem` 的差別在於結果的正負號規則。`a %% b = a - floor(a / b) * b`，因此結果的正負號**跟隨除數 `b`**（與 Python 的 `%` 相同）。除數為正時，結果一定落在 `[0, b)`，即使被除數為負也會得到正的餘數；除數為負時落在 `(b, 0]`（`7 %% -3 = -2`）。除數為負時，它與歐幾里得模數（一律非負）不同。它常用於索引環繞與模算術。浮點數 `%%` 的結果為零時帶有除數的正負號（`44.0 %% -4.0 = -0.0`）。

```nabi
// common pattern: negative index wrap-around
let i: i32 = -1;
let len: i32 = 8;
let wrapped = i %% len;      //→ 7    (i % len would give -1)
```

`Rem` 與 `Modulo` 的正負號差異整理如下。

| `a`  | `b`  | `a % b`（Rem） | `a %% b`（Modulo） |
|------|------|---------------|-------------------|
| `7`  | `3`  | `1`           | `1`               |
| `-7` | `3`  | `-1`          | `2`               |
| `7`  | `-3` | `1`           | `-2`              |
| `-7` | `-3` | `-1`          | `-1`              |

兩個語彙單元對應到不同的 trait，因此一個型別可以只實作其中一個，或賦予兩者不同的意義。標準函式庫對基本整數／浮點數的 impl 完全遵循上表的定義。

`%%` 語彙單元定義於 [refs-lang 1.10 標點與運算子語彙單元](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md)；它在 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 表中的優先順序是第 10 級，與 `%` 相同，左結合。

### `Pow`：冪（`**`）

```nabi
trait Pow<Rhs = Self> {
    type Output;

    #[infix("**")]
    fn pow(self, rhs: Rhs) -> Output;
}
```

`**` 的結合比前綴 `-` 更緊，且向右結合（[refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md)）：`-x**2` 是 `-(x**2)`，`2**3**2` 是 `512`。`^` 仍是位元 XOR。

| 底數                   | 指數 impl                          | 結果                                           |
|------------------------|------------------------------------|------------------------------------------------|
| `i8` .. `usize`        | `u32`                              | 底數的型別；溢位與 `*` 相同（溢位檢查開啟時觸發 panic） |
| `f32`, `f64`           | 相同的浮點型別、`i32`               | `pow`（由平台的 `pow` 正確處理）、`powi`（重複相乘） |

指數的型別不一定與底數相同：整數底數的指數是 `u32`（`n ** 2` 把字面值定型為 `u32`；`i64` 指數是型別錯誤，其提示為 `e as u32`），浮點數底數時，沒有後綴的字面值採用底數的型別（`x ** 2` 是 `x.pow(2.0)`）。整數底數搭配負的字面值指數（`2 ** -1`）是編譯錯誤（E0144），其提示寫出浮點形式 `2.0 ** -1.0`：結果會是分數。整數底數搭配浮點字面值指數（`2 ** 0.5`、`n ** -1.0`）混用了兩種數值（E0054）；其提示寫出 `2.0 ** 0.5` 或 `(n as f64) ** -1.0`。`PowAssign`（`**=`，2.4）與 `DotPow`（`.**`，2.6）是它的複合形式與逐元素形式。`Pow` 與 `Modulo`（上文）不像其他算術 trait，沒有 lang 槽位：編譯器只透過它們的 `#[infix]` 語彙單元觸及它們，從不依名稱尋找（[0.4.3](../000-meta/004-lang-slot-table.md)）。

## 2.3.2. 一元 trait

### `Neg`：一元取負（前綴 `-`）

一元取負 trait 定義如下。

```nabi
#[lang("neg_trait")]
trait Neg {
    type Output;

    #[prefix("-")]
    fn neg(self) -> Output;
}
```

```nabi
let r = -5i32;       //→ -5
let s = -3.14f64;    //→ -3.14
let t = -(a + b);    //→ -(a+b)
```

此 trait 只對有號整數與浮點型別有意義；`u32` 沒有 `Neg` impl。`Array<T, N>` 在 `T: Neg` 時實作它，將每個元素取負成為新的陣列（檢視也一樣）：`y: Vector<f64>` 的 `-y`。

特別是，`i32::MIN`（= -2147483648）的負數無法表示，因此會觸發 panic；溢位檢查關閉時則環繞（= 原樣的 i32::MIN）。要明確環繞，請用 `wrapping_neg`；要得到 `T | none` 結果，請用 `checked_neg`。

### `Not`：位元補數／邏輯否定（`!`）

`Not` trait 定義如下。

```nabi
#[lang("not_trait")]
trait Not {
    type Output;

    #[prefix("!")]
    fn not(self) -> Output;
}
```

```nabi
let r = !true;       //→ false
let s = !0u8;        //→ 255 (all bits 1)
let t = !0xFFi32;    //→ 0xFFFFFF00 (all 32 bits inverted)
```

各型別的行為：`bool::not(true) = false`、`bool::not(false) = true`，作用為邏輯否定。相對地，`u8::not(0) = 0xFF` 與 `i32::not(0) = -1` 作用為位元補數。

### `BitNot`：位元補數（`~`）

`~` 語彙單元（[refs-lang 1.10.3](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md)）是僅限整數的位元補數。

```nabi
#[lang("bitnot_trait")]
trait BitNot {
    type Output;

    #[prefix("~")]
    fn bitnot(self) -> Output;
}
```

```nabi
let s = ~0u8;        //→ 255
let t = ~0i32;       //→ -1
```

對整數型別而言，`~x` 與 `!x` 結果相同。不過 `BitNot` 只為 `i*`／`u*` 與 `int`（`~x == -x - 1`）實作，不為 `bool` 實作，因此 `~true` 是編譯錯誤。建議的慣用寫法是：邏輯否定用 `!`，要表明位元補數的意圖時用 `~`。

## 2.3.3. 位元 trait

### `BitAnd`：位元 AND（`&`）

位元 AND trait 定義如下。

```nabi
#[lang("bitand_trait")]
trait BitAnd<Rhs = Self> {
    type Output;

    #[infix("&")]
    fn bitand(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 0xF0i32 & 0x0Fi32;   //→ 0x00
let s = 0xFFi32 & 0x0Fi32;   //→ 0x0F
let b = true & false;         //→ false (bool also has a BitAnd impl)
```

> [!NOTE]
> `&&` 與 `&` 不同。`&&` 是短路邏輯 AND；`&` 是位元 AND。
> 對 bool 而言兩者結果相同，但求值的時機不同。

### `BitOr`：位元 OR（`|`）

位元 OR trait 定義如下。

```nabi
#[lang("bitor_trait")]
trait BitOr<Rhs = Self> {
    type Output;

    #[infix("|")]
    fn bitor(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 0xF0i32 | 0x0Fi32;   //→ 0xFF
```

### `BitXor`：位元 XOR（`^`）

位元 XOR trait 定義如下。

```nabi
#[lang("bitxor_trait")]
trait BitXor<Rhs = Self> {
    type Output;

    #[infix("^")]
    fn bitxor(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 0xFFi32 ^ 0x0Fi32;   //→ 0xF0
let s = 0b1010 ^ 0b1100;     //→ 0b0110
```

### `Shl`：左位移（`<<`）

左位移 trait 定義如下。

```nabi
#[lang("shl_trait")]
trait Shl<Rhs = Self> {
    type Output;

    #[infix("<<")]
    fn shl(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 1i32 << 4;     //→ 16
let s = 0xFFi32 << 24; //→ 0xFF000000
```

位移量為負，或大於等於位元寬度時，位移會觸發 panic（`attempt to shift left with overflow`，`>>` 則為 `right`）。與 `+` `-` `*` 的溢位不同，這項檢查不取決於 `-C overflow-checks`：在每個最佳化等級都會執行。要讓位移量對寬度取模，請用 `wrapping_shl`／`wrapping_shr`。

```nabi
let r = 1i32.wrapping_shl(40);  // explicit: shifts by 40 % 32 = 8
```

### `Shr`：右位移（`>>`）

右位移 trait 定義如下。

```nabi
#[lang("shr_trait")]
trait Shr<Rhs = Self> {
    type Output;

    #[infix(">>")]
    fn shr(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 256i32 >> 4;  //→ 16
let s = -1i32 >> 1;   //→ -1 (signed = arithmetic shift, sign extension)
let t = u32::MAX >> 1;  //→ 0x7FFFFFFF (unsigned = logical shift)
```

有號整數使用算術位移（符號延伸）；無號整數使用邏輯位移。

## 2.3.4. 索引 trait

索引與切片是**語言語法**（[refs-lang 3.6](../../refs-lang/003-expressions/306-indexing-and-slicing.md)），但實際的分派會經過本節的 trait。`Index`、`IndexSet`、`Sliceable` 與 `AxisIndexed` 定義於 `core::index` 模組。對 struct 或 enum 使用 `xs[i]` 與 `xs[i] = v` 會呼叫 `index`／`index_set`；固定長度陣列則直接索引，不經呼叫。

### `Index`：單一元素讀取（`arr[i]`）

`Index` trait 定義如下。

```nabi
#[lang("index_trait")]
trait Index<I> {
    type Output;

    fn index(self, idx: I) -> Output;
}
```

```nabi
let xs: List<i32> = [10, 20, 30];
let v = xs[1];        //→ 20
let s: str = "hello";
let c = s.chars().next();   //→ 'h' (char | none); str has no Index (2.9.8)
```

#### 邊界檢查

邊界處理如下。超出範圍的索引（`xs[100]`）會觸發 panic（運算子不擲回錯誤）。有號整數的負索引從尾端算起（`xs[-1]` 是最後一個元素，[refs-lang 3.6.1](../../refs-lang/003-expressions/306-indexing-and-slicing.md#361-索引arri)）。若 `len + i < 0`，則觸發 panic。

要得到 `T | none` 結果而不是 panic，請用 `xs.get(i)`。

```nabi
let v = xs.get(100);  //→ none
```

### `IndexSet`：單一元素寫入（`arr[i] = v`）

`IndexSet` trait 定義如下。

```nabi
#[lang("index_set_trait")]
trait IndexSet<I, V> {
    fn index_set(self, idx: I, value: V);     // collections are reference handles, so self
}
```

```nabi
let xs: List<i32> = [10, 20, 30];
xs[1] = 99;           // IndexSet::index_set(xs, 1, 99)
xs[1];                //→ 99
```

值的型別 `V` 是 trait 參數而不是關聯型別，因此同一個索引可以存入多種值，由值的型別選擇 impl：`Array` 可以存入填滿某個選取範圍的純量（`a[:, 0] = 0.0`），也可以存入延展到該範圍的陣列（`a[:, 0] = col`），兩者都經由 `IndexSet<(SliceArg, isize), _>`。

它與 `Index` 分開，是因為唯讀容器（例如元組的不可變檢視）仍必須能實作 `Index`。因此 `IndexSet` 是另外選擇加入的。

`IndexSet` 在超出範圍時也會觸發 panic。沒有帶檢查的寫入：要略過超出範圍索引的寫入，需先檢查（`if i < xs.len() { xs[i] = v }`），而讀取則有 `xs.get(i) -> T | none`。

### `Sliceable`：擷取子範圍（`s[a:b]`、`s[a:b:step]`）

切片 trait 定義如下。trait 名為 `Sliceable`，產生的檢視型別是 `Slice<T>`（[2.9.7](209-collections.md#297-slicet檢視)）。名稱之所以分開，是因為 prelude 與 `index` 模組把兩個名稱放在同一個名稱空間，一個名稱無法同時指稱兩者。

```nabi
#[lang("slice_trait")]
trait Sliceable<R> {
    type Output;

    fn slice(self, range: R) -> Output;
}
```

`xs[a:b]` 是 `xs.slice(a..b)`，而 `xs[a:b:k]` 是在 Python `slice.indices` 計算出的範圍上做 `xs.slice(..).step(k)`（[refs-lang 3.6.2](../../refs-lang/003-expressions/306-indexing-and-slicing.md#362-切片arrstartend)）。語意與 Python 切片相同：邊界會被夾到長度內，超出範圍的邊界永遠不會觸發 panic，且 `xs` 只求值一次。`xs[a..b]` 與 `xs[..]` 相同。每個標準的 `Sliceable<Range<usize>>` 實作都以同樣方式夾限範圍：先把終點夾到長度 `n`，再把起點夾到終點，因此 `xs[5:100]` 與 `xs.slice(9..2)`（空）永遠不會觸發 panic。使用者的實作應當以相同方式夾限範圍。

```nabi
let xs: List<i32> = [1, 2, 3, 4, 5];
let s = xs[1:3];       //→ Slice<i32> view of [2, 3]
let r = xs[::2];       //→ [1, 3, 5] (step=2)
let v = xs[::-1];      //→ [5, 4, 3, 2, 1] (reversed)

let str_part = "hello"[1:4];  //→ "ell" (new str)
```

標準函式庫為 `List<T>`、`Slice<T>`、`SliceMut<T>`、`[T; N]`、`str` 與 `StrBuf` 實作 `Sliceable<Range<usize>>`。`List`／`Slice`／陣列回傳 `Slice<T>` 檢視，`SliceMut<T>` 回傳 `SliceMut<T>` 檢視（[2.9.7a](209-collections.md)）；`str`／`StrBuf` 在檢查 UTF-8 邊界後回傳新的 `str` 複本。負的邊界從尾端算起，然後再夾限；不支援切片指派。要取得擁有的複本，請用 `xs[1:3].to_list()`。

### `AxisIndexed`：依軸索引的型別

```nabi
#[lang("axis_indexed_trait")]
trait AxisIndexed {}
```

沒有方法的標記 trait。在實作它的型別上寫 `x[..]` 時，方括號中每個整數部分都是 `isize` 位置（其他整數型別會被轉換，字面值本身就是 `isize`），`none` 是 `NewAxis`，與其他部分並列的 `..` 是 `Rest`（[refs-lang 3.6.3](../../refs-lang/003-expressions/306-indexing-and-slicing.md#363-多軸索引)），因此一組以 `isize` 為索引的 `Index`／`IndexSet` impl 就能處理所有呼叫。`Array` 實作了它（[2.9.14](209-collections.md#2914-arrayt-const-n-usizen-維陣列)）。

## 2.3.5. trait 實作矩陣

基本型別的每個 ops trait impl 都帶有 `#[intrinsic("nabi.OP.TYPE")]`，直接繫結到編譯器後端的 PrimOp（[0.3](../000-meta/003-intrinsics.md)）。這表示：

- 基本運算元上的運算子（`a + b`）不經方法呼叫，直接降階為機器運算。
- 依名稱呼叫（`a.add(b)`、`Add::add(a, b)`）也降階為相同的機器運算。

### 算術 trait

| 型別                 | 模組             | 行為                                                            |
|----------------------|------------------|-----------------------------------------------------------------|
| `i8`..`i64`, `isize` | `core::num` | `nabi.add.i32` / `nabi.sub.i32` / `nabi.rem.i32` / `nabi.mod.i32` ... |
| `u8`..`u64`, `usize` | `core::num` | `nabi.add.u32` / ...（無號家族，`Modulo` ≡ `Rem`）           |
| `f32`, `f64`         | `core::num` | `nabi.add.f32` / `nabi.add.f64` / `nabi.mod.f64`（向下取整）         |
| `int`                | `core::num` | 自動提升邏輯                                              |
| `float`              | `core::num` | （同上：自動提升）                                   |

### 位元 trait

| 型別               | 模組             | intrinsic                                                           |
|--------------------|------------------|---------------------------------------------------------------------|
| `i*`, `u*`         | `core::num` | `nabi.and.OP`, `nabi.or.OP`, `nabi.xor.OP`, `nabi.shl.OP`, `nabi.shr.OP` |
| `bool`             | `core::num` | `nabi.and.bool`, `nabi.or.bool`, `nabi.xor.bool`（無位移）            |
| `int`              | `core::num` | 對符號延伸後的值做二補數運算；`Shl<u32>`／`Shr<u32>`（右側為 `u32`） |

`f32` 與 `f64` 不實作 BitAnd 等 trait，因為這些運算對浮點數沒有意義。

### 索引 trait

| 型別         | 定義者                                                                             |
|--------------|------------------------------------------------------------------------------------|
| `List<T>`    | 標準函式庫                                                                         |
| `Dict<K, V>` | 標準函式庫（I = K）                                                                |
| `[T; N]`     | 編譯器合成（基本陣列）                                                             |
| `str`        | 標準函式庫（僅 Slice；`Index<usize>` 未定義，拒絕直接存取位元組）                  |
| `Slice<T>`   | 標準函式庫（僅 `Index`）                                                           |
| `SliceMut<T>` | 標準函式庫（`Index`、`IndexSet`）                                                 |
| `Deque<T>`   | 標準函式庫（`Index<usize>`、`IndexSet<usize, T>`）                                 |
| `Tuple`      | 編譯器合成（`.0`、`.1` 形式）；`Index` 未定義（僅在編譯期存取元組）               |

## 2.3.6. 使用者定義的 ops

標準函式庫之外的使用者可以透過 `impl ops::Add for MyType` 等寫法自由實作這些 trait。trait 分派隨後會呼叫 `MyType::add`。

```nabi
struct Vec3 { x: f64; y: f64; z: f64; }

impl ops::Add for Vec3 {
    type Output = Vec3;

    fn add(self, rhs: Vec3) -> Vec3 {
        Vec3 {
            x: self.x + rhs.x,
            y: self.y + rhs.y,
            z: self.z + rhs.z,
        }
    }
}

let a = Vec3 { x: 1.0, y: 2.0, z: 3.0 };
let b = Vec3 { x: 0.5, y: 0.5, z: 0.5 };
let c = a + b;        //→ Vec3 { x: 1.5, y: 2.5, z: 3.5 }
```

不過，在使用者的 ops 上加上 `#[intrinsic]` 是**禁止**的（refs-standard-libraries 0.3.5），因為函式主體才是權威。

## 2.3.7. trait 之間的關係：`Output` 一致性

在組合多個 trait 的運算式（`a + b * c`）中，`Output` 型別必須一致。

```nabi
let r = a + b * c;
//   = Add::add(a, Mul::mul(b, c))
//   requires: <typeof(b) as Mul<typeof(c)>>::Output compatible with Add's Rhs
```

標準函式庫中每個基本算術 impl 都使用 `Output = Self`。使用者型別可以自由定義，但為了對工具友善（例如編譯器錯誤訊息），建議使用 `Output = Self`。

## 2.3.8. 與廣播 trait 的關係

`a + b` 分派到 `Add::add`，`a .+ b` 分派到 `DotAdd::dot_add`，因此兩種運算由不同的 trait 處理。一般的算術型別（Vec3 等）通常兩者都實作。細節請見 [2.6 廣播](206-broadcast.md)。

## 2.3.9. 邏輯 trait：`LogicalAnd`（`&&`）／`LogicalOr`（`||`）

`&&` 與 `||` 以與其他運算子相同的方式連接到 trait 方法。優先順序與結合性由 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 表固定。

```nabi
#[lang("logical_and_trait")]
trait LogicalAnd<Rhs = Self> {
    #[infix("&&")]
    fn logical_and(self, rhs: Rhs) -> bool;
}

#[lang("logical_or_trait")]
trait LogicalOr<Rhs = Self> {
    #[infix("||")]
    fn logical_or(self, rhs: Rhs) -> bool;
}
```

標準函式庫只為 `bool` 實作這兩個 trait。兩個運算元都是 `bool` 時，編譯器透過 `logical_and_trait`／`logical_or_trait` 槽位辨識這個實作，並將它降階為**短路**分支而不是方法呼叫：若 `a` 為 `false`，`a && b` 不會對 `b` 求值。

> [!WARNING]
> 若使用者型別實作 `LogicalAnd`／`LogicalOr`，`a && b` 就成為一般的 trait 方法呼叫，因此**兩個運算元都會被求值**（不短路）。這與廣播形式 `.&&`／`.||`（[2.6](206-broadcast.md)）的規則相同。語言只對 `bool` 運算元保證短路。

## 2.3.10. Unicode 數學運算子 trait

[refs-lang 1.10.3](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md#unicode-數學運算子) 的 Unicode 運算子連接到下列 trait。每個方法都有 ASCII 名稱，因此可以用方法呼叫代替運算子。優先順序由 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 表固定。`÷ ≡ ≠ ≤ ≥` 沒有自己的 trait 或中綴繫結：詞法分析器把它們讀成 `/ == != <= >=`，因此它們分派到上文的 `Div` 與 [2.5 cmp](205-cmp.md) 的比較 trait。

```nabi
trait Cross<Rhs = Self> {               // a × b (level 10)
    type Output;
    #[infix("×")]
    fn cross(self, rhs: Rhs) -> Output;
}

trait Dot<Rhs = Self> {                 // a ⋅ b (level 10)
    type Output;
    #[infix("⋅")]
    fn dot(self, rhs: Rhs) -> Output;
}

trait Compose<Rhs> {                    // f ∘ g (level 11), (f ∘ g)(x) = f(g(x))
    type Output;
    #[infix("∘")]
    fn compose(self, rhs: Rhs) -> Output;
}

trait Sqrt {                            // √x (prefix unary)
    type Output;
    #[prefix("√")]
    fn sqrt(self) -> Output;
}

trait Contains<Item> {                  // a ∈ s, a ∉ s (level 4)
    #[infix("∈", swap)]
    fn contains(self, item: Item) -> bool;
    #[infix("∉", swap)]
    fn not_contains(self, item: Item) -> bool { !self.contains(item) }
}

trait Subset<Rhs = Self> {              // a ⊂ b, a ⊆ b (level 4)
    #[infix("⊂")]
    fn is_proper_subset(self, rhs: Rhs) -> bool;
    #[infix("⊆")]
    fn is_subset(self, rhs: Rhs) -> bool;
}

trait Union<Rhs = Self> {               // a ∪ b (level 9)
    type Output;
    #[must_use]
    #[infix("∪")]
    fn union(self, rhs: Rhs) -> Output;
}

trait Intersect<Rhs = Self> {           // a ∩ b (level 10)
    type Output;
    #[must_use]
    #[infix("∩")]
    fn intersection(self, rhs: Rhs) -> Output;
}
```

`∈ ∉` 把容器放在右側，因此以 `swap` 連接（[refs-lang 6.7.2](../../refs-lang/006-meta-system/607-operator-magic.md#672-引數)）。`a ∈ xs` 是 `xs.contains(a)`。`in`／`!in` 是它們的 ASCII 寫法（[refs-lang 3.2.3](../../refs-lang/003-expressions/302-precedence-and-associativity.md#323-優先順序與結合性表)）：`x in 0..=9`、`k !in d`。

| trait       | 標準函式庫的實作                                      |
|-------------|-------------------------------------------------------|
| `Sqrt`      | `f32`、`f64`（`#[intrinsic("nabi.sqrt.TYPE")]`）        |
| `Contains`  | `List<T>`、`Set<T>`、`Dict<K, V>`（鍵）、`str`（子字串或 `char`），以及所有範圍：`Range<T>`、`RangeInclusive<T>`、`RangeFrom<T>`、`RangeTo<T>`、`RangeToInclusive<T>`（`T: PartialOrd`）、`RangeFull`（任何項目） |
| `Subset`, `Union`, `Intersect` | `Set<T>`                           |
| `Compose`   | 函式型別 `fn(B) -> C` 與 `fn(A) -> B`          |
| `Cross`, `Dot` | 標準函式庫沒有實作；由向量型別實作  |

`Dot` 與 [2.6](206-broadcast.md) 的逐元素 trait 都位於 `core::ops`。

## 2.3.11. 集合型別運算子

`Set` 除了 `∪` 與 `∩` 之外，還實作 `BitOr`、`BitAnd`、`Sub` 與 `BitXor`（`a | b`、`a & b`、`a - b`、`a ^ b`：聯集、交集、差集、對稱差集），各自產生新的集合。`List<T>` 實作 `Add`（`xs + ys`，產生新的串列）。請見 [2.9.13](209-collections.md#2913-預設值運算子與建構子)。

## 2.3.12. 呼叫值：`Call`

對不是函式的值進行呼叫 `v(args)`，會分派到 `Call`（[refs-lang 6.7.14](../../refs-lang/006-meta-system/607-operator-magic.md#6714-呼叫值opscall)）。

```nabi
#[lang("call_trait")]
trait Call<Args> {
    type Output;

    fn call(self, args: Args) -> Output;
}
```

`Args` 是單一引數的型別；多個引數時是元組（`v(a, b)` 是 `v.call((a, b))`），沒有引數時是 `()`。一個型別可以為多種 `Args` 實作它（內插函式可以有 `Call<f64>` 與 `Call<Vector<f64>>`），依引數選擇。`fn` 值與閉包直接呼叫，沒有 impl。

```nabi
struct Poly { c: List<f64>; }

impl ops::Call<f64> for Poly {
    type Output = f64;
    fn call(self, x: f64) -> f64 { self.c.iter().rev().fold(0.0, |acc: f64, k: f64| -> f64 { acc * x + k }) }
}

let p = Poly { c: [1.0, 0.0, 2.0] };
p(3.0);     //→ 19
```
