# 3.2. `net::`：網路（TCP / UDP / Unix + TLS 1.3）

`std::net` 模組提供低階的網路基本型別，並把 **TLS 1.3** 一併打包在內。HTTP、HTTP/2、HTTP/3 等高階協定刻意不在範圍內，交由 `http` 等獨立套件處理。這個選擇也避開了 Go 的路：標準函式庫在 1.0 凍結之後就不再演進。

## 3.2.0. 共通規則

`net` 對同一種通訊端提供三個層次：

| 層次 | 項目 | 固定了什麼 |
|-------|-------|---------------|
| 低階 | `Socket`（[3.2.9](#329-socket低階層)） | 什麼都不固定：網域、類別、協定和每個選項都由呼叫端決定；每次呼叫就是一次系統呼叫 |
| 具型別 | `TcpStream::connect`、`TcpListener::bind`、`UdpSocket::bind` / `connect` / `send_to` | 通訊端的種類；位址經由 `ToSocketAddrs`（[3.2.4](#324-socketaddr--ipaddr)） |
| 便利 | `tcp_connect`、`tcp_listen`、`udp_bind`（[3.2.6](#326-便利函式)） | 同樣的呼叫，以自由函式的形式提供 |

- 適用整個層級的[引數慣例](README.md#引數慣例)：`Path` 參數是 `P: AsPath`，而要寫出的資料（`write` / `write_all` / `send` / `send_to` / `send_with_fd` 及其 `_async` 形式）經由 `AsBytes` 接受 `str`、`List<u8>` 和 `Slice<u8>`。讀取緩衝區是 `SliceMut<u8>`（[2.23.1](../200-core/223-io.md#2231-read)）：`read(buf)` 填入 `buf` 的前 `n` 個位元組並回傳 `n`；`0` 表示串流結束。
- 通訊端型別是 OS 控制代碼，且是仿射的（[2.13.4](../200-core/213-marker.md)）：`let b = s` 會移動通訊端；只有 `try_clone` 會複製 fd。
- 通訊端（`Socket`、`TcpStream`、`TcpListener`、`UdpSocket`、Unix 通訊端）、`tls::Client` / `tls::Server`，以及拆分後連線的兩半（`ReadHalf` / `WriteHalf`，[拆分的兩半](#拆分的兩半)）都實作 `io::Close`（[2.23.3](../200-core/223-io.md#2233-write-and-close)）：關閉可能失敗，所以擁有者必須自己關閉每一個，用 `try s.close()` 或 `using`（[2.13.4](../200-core/213-marker.md#2134-drop釋放時的清理)）；在未關閉的狀態下離開其作用域是編譯錯誤。`Drop` 只在因錯誤而離開的路徑上釋放它，並丟棄關閉時的錯誤。使用已關閉的通訊端會得到 `IoError`（`InvalidInput`）。另一個任務關閉通訊端時，該通訊端上尚未完成的 `*_async` 操作會以該錯誤完成；`shutdown(Read | Both)` 之後，尚未完成的讀取以 0 完成。
- `TcpStream`、`os::unix::net::UnixStream` 以及拆分後連線的兩半（`ReadHalf`：讀取 trait，`WriteHalf`：寫入 trait；[拆分的兩半](#拆分的兩半)）實作 `io::Read` + `io::Write` 與 `io::AsyncRead` + `io::AsyncWrite`（[2.23](../200-core/223-io.md)）；它們的讀寫就是這些 trait 方法，沒有重複的固有方法。在暫停中被取消的讀取或寫入沒有搬移任何位元組。每個通訊端和 TLS 連線都實作 `io::AsyncClose`：`try await s.close_async()`。`*_async` 方法接受 `ref self`（[0.5.13](../000-meta/005-notation.md#0513-非同步對應版本)）。

### 阻塞與 `*_async`

方法分成兩組。

| 形式                            | 如何等待                                           |
|---------------------------------|--------------------------------------------------------|
| `accept`、`read`、`write` ..    | 阻塞呼叫它的 OS 執行緒（在任務中則連同其工作者一起阻塞） |
| `accept_async`、`read_async` .. | 只暫停該任務；工作者會去執行其他任務    |

`*_async` 方法是 `async fn`，用法是 `try await s.read_async(buf)`。等待就緒是 [I/O 驅動程式](../../refs-lang/007-runtime/707-io-and-timer.md)的工作。一般函式無法暫停無堆疊協程，所以同名的同步呼叫在任務中不會自行暫停。

| 阻塞               | 非同步                        |
|------------------------|------------------------------|
| `TcpListener::accept`  | `TcpListener::accept_async`  |
| `TcpStream::connect`   | `TcpStream::connect_async`   |
| `Socket::connect` / `accept` | `Socket::connect_async` / `accept_async` |
| `Read::read`           | `AsyncRead::read_async`      |
| `Read::read_to_end`    | `AsyncRead::read_to_end_async` |
| `Write::write`         | `AsyncWrite::write_async`    |
| `Write::write_all`     | `AsyncWrite::write_all_async` |
| `Write::flush`         | `AsyncWrite::flush_async`    |
| `Close::close`         | `AsyncClose::close_async`    |
| `TcpStream::shutdown`（以及 `Socket`、`UnixStream`） | `shutdown_async` |
| `UdpSocket::connect`   | `UdpSocket::connect_async`   |
| `UdpSocket::send_to`   | `UdpSocket::send_to_async`   |
| `UdpSocket::recv_from` | `UdpSocket::recv_from_async` |
| `UdpSocket::send`      | `UdpSocket::send_async`      |
| `UdpSocket::recv`      | `UdpSocket::recv_async`      |
| `Socket::send_to` / `recv_from` | `Socket::send_to_async` / `recv_from_async` |
| `UnixListener::accept` | `UnixListener::accept_async` |
| `UnixDatagram::connect` / `send` / `recv` | `UnixDatagram::connect_async` / `send_async` / `recv_async` |
| `send_with_fd` / `recv_with_fd`（`UnixStream`、`UnixDatagram`） | `send_with_fd_async` / `recv_with_fd_async` |
| `tcp_connect`          | `tcp_connect_async`          |
| `tls::Client::new` / `with_config` | `tls::Client::new_async` / `with_config_async` |
| `tls::Server::new`     | `tls::Server::new_async`     |
| `tls::Client::read` ... `key_update`（以及 `Server`） | `read_async` ... `key_update_async` |

`UnixStream` 的讀寫就是 `Read` / `Write` 那幾列。各型別的完整清單見 [0.5.13](../000-meta/005-notation.md#0513-非同步對應版本)。

逾時只適用於阻塞的一側（`set_read_timeout` / `set_write_timeout`；超過時得到 `TimedOut`）。在非同步的一側，用 `task::timeout`（等待一個任務）或 `task::select`（[2.18.1](../200-core/218-task.md#select最先完成的-future)）包住。`select` 會取消落敗的一方，因此很適合用來放棄一次讀取。

```nabi
enum Got { Data(usize), Timeout }

let (_, got) = await task::select([
    async { Got::Data(try await s.read_async(buf) catch _ { 0 }) },
    async { await task::sleep(Duration::secs(5)); Got::Timeout },
]);
```

設定 `set_nonblocking(true)` 後，阻塞方法不會等待，而是擲回 `WouldBlock`。

在 `wasm32-wasip2` 上，`std::net`（TCP / UDP 的 connect、bind、listen、accept、DNS）經由 `wasi:sockets` 運作；主機必須授予網路存取權（例如 wasmtime 的 `-S inherit-network -S allow-ip-name-lookup`）。在 `wasm32-wasip1-threads` 上只有 `TcpListener::inherited()` 的監聽器可用；connect / bind / DNS 會擲回 `Unsupported`。

## 3.2.1. TCP

TCP 以兩個型別為中心：`TcpListener` 和 `TcpStream`。監聽器負責 bind 與 accept 流程；串流提供讀取、寫入與選項控制。

```nabi
struct TcpListener { /* OS handle */ }
struct TcpStream { /* OS handle */ }

impl TcpListener {
    fn bind<A: ToSocketAddrs>(addr: A) throws (IoError) -> TcpListener;  // the first address that binds;
                                                                       // SO_REUSEADDR (not on Windows), backlog 128
    fn inherited() -> List<TcpListener>;                            // listeners the host hands to the process
    fn accept(self) throws (IoError) -> (TcpStream, SocketAddr);
    async fn accept_async(ref self) throws (IoError) -> (TcpStream, SocketAddr);
    fn local_addr(self) throws (IoError) -> SocketAddr;              // the actual port after binding to port 0
    fn try_clone(self) throws (IoError) -> TcpListener;
    fn set_nonblocking(self, nb: bool);
    fn incoming(ref self) -> Incoming;   // view; TryIterator<Item = TcpStream, Error = IoError>
    fn into_incoming(self) -> io::Owned<Incoming, TcpListener>;  // owns the listener
    fn set_ttl(self, ttl: u32) throws (IoError);                     // IP_TTL
    fn ttl(self) throws (IoError) -> u32;
    fn close(self) throws (IoError);   // throws what the OS reports
}

impl TcpStream {
    fn connect<A: ToSocketAddrs>(addr: A) throws (IoError) -> TcpStream;   // the first address that accepts
    fn connect_timeout(addr: SocketAddr, dur: Duration) throws (IoError) -> TcpStream;
    async fn connect_async<A: ToSocketAddrs>(addr: A) throws (IoError) -> TcpStream;

    fn peer_addr(self) throws (IoError) -> SocketAddr;
    fn local_addr(self) throws (IoError) -> SocketAddr;
    fn shutdown(self, how: Shutdown) throws (IoError);
    async fn shutdown_async(ref self, how: Shutdown) throws (IoError);   // shutdown never waits
    fn try_clone(self) throws (IoError) -> TcpStream;
    fn split(self) -> (ReadHalf<TcpStream>, WriteHalf<TcpStream>);   // split halves, below
    fn close(self) throws (IoError);   // throws what the OS reports

    // TCP options
    fn set_nodelay(self, nodelay: bool) throws (IoError);           // TCP_NODELAY
    fn nodelay(self) throws (IoError) -> bool;
    fn set_ttl(self, ttl: u32) throws (IoError);                     // IP_TTL
    fn ttl(self) throws (IoError) -> u32;
    fn set_keepalive(self, alive: Duration | none) throws (IoError); // SO_KEEPALIVE + idle (seconds), none = off
    fn set_read_timeout(self, dur: Duration | none);
    fn set_write_timeout(self, dur: Duration | none);
    fn read_timeout(self) -> Duration | none;
    fn write_timeout(self) -> Duration | none;
    fn set_nonblocking(self, nb: bool);
}

impl io::Read for TcpStream { ... }       // read, read_to_end, ..
impl io::Write for TcpStream { ... }      // write, write_all, flush (no-op)
impl io::AsyncRead for TcpStream { ... }
impl io::AsyncWrite for TcpStream { ... }
impl io::Close for TcpStream { ... }
impl io::Close for TcpListener { ... }
impl io::AsyncClose for TcpStream { ... }
impl io::AsyncClose for TcpListener { ... }
impl Drop for TcpStream { ... }          // releases on an error path
impl Drop for TcpListener { ... }
impl From<Socket> for TcpStream { ... }   // a connected stream Socket (3.2.9)
impl From<Socket> for TcpListener { ... } // a bound, listening stream Socket

enum Shutdown { Read, Write, Both }
```

`TcpListener::inherited()` 回傳主機交給行程的監聽器：WASI 的預先開啟通訊端、Unix 上 systemd 的 `LISTEN_FDS` 通訊端啟用，在 Windows 上則沒有。

`Incoming` 是監聽器的作用域檢視（[2.23.1](../200-core/223-io.md#2231-read)：它留在監聽器的作用域內，監聽器仍由其擁有者關閉；`into_incoming()` 則改為擁有監聽器，供在自己的任務中執行的迴圈使用），也是 `TryIterator`（[2.7.13](../200-core/207-iter.md#2713-tryiterator可能失敗的迭代)）：每次 `next` 呼叫一次 `accept`，失敗的 `accept` 會以其錯誤結束 `try for` 迴圈。它不會自行結束。如果對端在寫入期間關閉，行程不會被 `SIGPIPE` 終止；該次寫入會產生 `IoError`（`BrokenPipe`）。

### 拆分的兩半

`split` 把一條連線拆成讀取的一半和寫入的一半，讓一個任務或執行緒讀取的同時，另一個寫入。它定義在 `TcpStream`、`os::unix::net::UnixStream`（[3.10.4](310-os.md#3104-osunixnetunix-網域通訊端)）、`tls::Client` 和 `tls::Server`（[3.2.5](#325-tls-13nettls)）上；`T` 指出某一半來自哪種連線。

```nabi
struct ReadHalf<T> { .. }                   // Send, not Sync: one owner
struct WriteHalf<T> { .. }                  // Send, not Sync: one owner

impl<T> ReadHalf<T> {
    fn close(self) throws (IoError);        // the socket closes once both halves are closed
    fn shutdown(self, how: Shutdown) throws (IoError);   // the shared socket (see below)
    async fn shutdown_async(ref self, how: Shutdown) throws (IoError);
}
impl<T> WriteHalf<T> {
    fn close(self) throws (IoError);        // ends the stream for the peer (see below)
    fn shutdown(self, how: Shutdown) throws (IoError);
    async fn shutdown_async(ref self, how: Shutdown) throws (IoError);
}
impl ReadHalf<TcpStream> {
    fn unsplit(self, w: WriteHalf<TcpStream>) -> TcpStream;
}
// and ReadHalf<UnixStream>, ReadHalf<tls::Client>, ReadHalf<tls::Server>

impl<T> io::Read for ReadHalf<T> { ... }
impl<T> io::AsyncRead for ReadHalf<T> { ... }
impl<T> io::Write for WriteHalf<T> { ... }
impl<T> io::AsyncWrite for WriteHalf<T> { ... }
impl<T> io::Close for ReadHalf<T> { ... }   // and WriteHalf<T>; io::AsyncClose for both
impl<T> Drop for ReadHalf<T> { ... }        // and WriteHalf<T>: releases on an error path
```

`split` 把連線移入兩半：舊的繫結被移動，如同 `let b = s`（[2.13.4](../200-core/213-marker.md)）。每一半都是其方向的仿射擁有者，並像任何通訊端一樣由其擁有者關閉（3.2.0）。兩者都不是連線的第二個控制代碼：讀取的一半讀到的內容，寫入的一半看不到，兩者可以同時從兩個執行緒或任務使用。

在讀取的一半仍開著時關閉寫入的一半，會為對端結束串流：`shutdown(Write)`（TLS 的寫入一半會先送出 close_notify），此後對端的讀取回傳 0；讀取的一半則繼續讀取回應。只關閉讀取的一半不會送出任何東西：之後來自對端的資料不再被讀取，通訊端則為寫入的一半保持開啟。第二個一半被關閉時，通訊端才關閉（TLS 連線的金鑰此時被抹除）；該次關閉擲回 OS 回報的錯誤。某一半的 `close_async` 與其 `close` 相同，只是暫停任務而非阻塞。

關閉方向（shutdown）是對通訊端的操作，所以任一半都有 `shutdown(how)`，它作用在兩半共同指稱的通訊端上：`Read`、`Write` 或 `Both`，與 `TcpStream::shutdown` 相同。從任一半呼叫 `Both` 會喚醒阻塞在另一半上的讀取或寫入，如同 POSIX 的 `shutdown(SHUT_RDWR)`（Windows 上為 `SD_BOTH`）：尚未完成的讀取回傳 0，尚未完成的寫入失敗。在 TLS 連線上，`Write` 和 `Both` 會先送出 close_notify。寫入方向已被 shutdown 之後再關閉寫入的一半，不會再 shutdown 一次。`shutdown_async` 相同，只是以等待 close_notify 取代阻塞。

`r.unsplit(w)` 從同一次 `split` 的兩半取回連線；兩半都被用掉，不會關閉或 shutdown 任何東西。來自另一條連線的 `w` 會觸發 panic。

```nabi
let (r, w) = (try await TcpStream::connect_async(addr)).split();
let writer = task::spawn(async {
    try! await w.write_all_async(request);
    try! await w.close_async();          // the peer reads end of stream
    0
});
let reply = try await r.read_to_end_async();
try r.close();                           // the socket closes here
await writer;
```

### 範例

```nabi
use core::task;
use std::net::{tcp_listen, TcpListener, TcpStream};

// blocking: this thread waits in accept and handle
using l = try TcpListener::bind("127.0.0.1:8080") {
    try for c in l.incoming() {
        handle(c);                      // fn handle(c: TcpStream) closes c
    }
}

// async: one task per connection; while waiting, the worker runs other tasks
async fn serve_all(l: TcpListener) throws (IoError) {
    loop {
        let (s, _) = try await l.accept_async();
        task::spawn(serve(s));          // async fn serve(s: TcpStream)
    }
}
```

## 3.2.2. UDP

UDP 只用一個 `UdpSocket` 型別涵蓋所有角色。資料包的傳送與接收是基本功能；用 `connect` 固定對端之後，只要 `send` / `recv` 即可。多點傳送成員資格與 TTL 等選項也都有提供，並考量 QUIC 這類工作負載，納入了 GSO/GRO 的區段大小控制。

```nabi
struct UdpSocket { /* OS handle */ }

impl UdpSocket {
    fn bind<A: ToSocketAddrs>(addr: A) throws (IoError) -> UdpSocket;   // the first address that binds

    fn send_to<B: AsBytes, A: ToSocketAddrs>(self, buf: B, addr: A) throws (IoError) -> usize;  // to the first address
    fn recv_from(self, buf: SliceMut<u8>) throws (IoError) -> (usize, SocketAddr);
    fn connect<A: ToSocketAddrs>(self, addr: A) throws (IoError);    // fix the peer: the first address that takes it
    async fn connect_async<A: ToSocketAddrs>(ref self, addr: A) throws (IoError);   // never waits on the socket
    fn send<B: AsBytes>(self, buf: B) throws (IoError) -> usize;
    fn recv(self, buf: SliceMut<u8>) throws (IoError) -> usize;
    // + send_to_async / recv_from_async / send_async / recv_async (ref self)

    fn local_addr(self) throws (IoError) -> SocketAddr;
    fn peer_addr(self) throws (IoError) -> SocketAddr;
    fn set_broadcast(self, on: bool) throws (IoError);              // SO_BROADCAST
    fn broadcast(self) throws (IoError) -> bool;
    fn set_ttl(self, ttl: u32) throws (IoError);                     // IP_TTL
    fn ttl(self) throws (IoError) -> u32;
    fn set_read_timeout(self, dur: Duration | none);
    fn set_write_timeout(self, dur: Duration | none);
    fn read_timeout(self) -> Duration | none;
    fn write_timeout(self) -> Duration | none;
    fn set_nonblocking(self, nb: bool);
    fn try_clone(self) throws (IoError) -> UdpSocket;
    fn close(self) throws (IoError);   // throws what the OS reports

    // multicast (IPv4)
    fn join_multicast_v4(self, addr: Ipv4Addr, interface: Ipv4Addr) throws (IoError);
    fn leave_multicast_v4(self, addr: Ipv4Addr, interface: Ipv4Addr) throws (IoError);
    fn set_multicast_loop_v4(self, on: bool) throws (IoError);
    fn set_multicast_ttl_v4(self, ttl: u32) throws (IoError);

    // for QUIC (GSO / GRO)
    fn set_segment_size(self, size: u16) throws (IoError);           // UDP_SEGMENT, Unsupported outside Linux
}

impl io::Close for UdpSocket { ... }
impl io::AsyncClose for UdpSocket { ... }
impl Drop for UdpSocket { ... }          // releases on an error path
impl From<Socket> for UdpSocket { ... }   // a datagram Socket (3.2.9)
```

`recv_from` / `recv` 把單一資料包接收到 `buf`。資料包比 `buf` 長時，多出的部分會被丟棄。

## 3.2.3. Unix 網域通訊端

Unix 網域通訊端只存在於 Unix，所以放在 `std::os::unix::net`（[3.10.4](310-os.md#3104-osunixnetunix-網域通訊端)），形狀與這裡的 TCP 型別相同。

## 3.2.4. SocketAddr / IpAddr

位址表示以 `SocketAddr` 列舉為中心，它是 IPv4 與 IPv6 的聯集；`IpAddr` 則是單純位址的相同聯集。`SocketAddrV4` / `SocketAddrV6` 的各部分是私有的：以 getter 讀取，以 setter（`ref self`）修改；複本是另一個值，所以 `let b = a; b.set_port(p);` 不會改變 `a`。`==` 比較各部分。字串剖析經由 `FromStr` 實作進行，主機名稱的 DNS 查詢則由另外的函式提供。

```nabi
enum IpAddr { V4(Ipv4Addr), V6(Ipv6Addr) }

impl IpAddr {
    fn is_ipv4(self) -> bool;
    fn is_ipv6(self) -> bool;
    fn is_loopback(self) -> bool;
}
impl From<Ipv4Addr> for IpAddr { ... }
impl From<Ipv6Addr> for IpAddr { ... }

enum SocketAddr {
    V4(SocketAddrV4),
    V6(SocketAddrV6),
}

struct SocketAddrV4 { /* ip, port */ }
struct SocketAddrV6 { /* ip, port, flow_info, scope_id */ }

impl SocketAddrV4 {
    fn new(ip: Ipv4Addr, port: u16) -> SocketAddrV4;
    fn ip(self) -> Ipv4Addr;
    fn port(self) -> u16;
    fn set_ip(ref self, ip: Ipv4Addr);
    fn set_port(ref self, port: u16);
}

impl SocketAddrV6 {
    fn new(ip: Ipv6Addr, port: u16, flow_info: u32 = 0, scope_id: u32 = 0) -> SocketAddrV6;
    fn ip(self) -> Ipv6Addr;
    fn port(self) -> u16;
    fn flow_info(self) -> u32;
    fn scope_id(self) -> u32;
    fn set_ip(ref self, ip: Ipv6Addr);
    fn set_port(ref self, port: u16);
    fn set_flow_info(ref self, flow_info: u32);
    fn set_scope_id(ref self, scope_id: u32);
}

impl SocketAddr {
    fn new(ip: IpAddr, port: u16) -> SocketAddr;     // IPv6: flow_info = scope_id = 0
    fn ip(self) -> IpAddr;
    fn port(self) -> u16;
    fn set_ip(ref self, ip: IpAddr);                // the other family replaces the whole address
    fn set_port(ref self, port: u16);
    fn is_ipv4(self) -> bool;
    fn is_ipv6(self) -> bool;
}
impl From<SocketAddrV4> for SocketAddr { ... }
```

`resolve` 透過 OS 的 `getaddrinfo` 取得位址清單，並阻塞呼叫它的執行緒。`host` 接受：

| `host`                                    | 結果                           |
|-------------------------------------------|----------------------------------|
| 通訊端位址（`"10.0.0.1:80"`、`"[::1]:80"`） | 該單一位址（不查詢） |
| `"name:port"`                             | `name` 的位址，連接埠為 `port` |
| `"[v6]:port"`                             | 該 IPv6 位址，連接埠為 `port` |
| 只有名稱或 IP                         | 其位址，連接埠為 0       |

找不到名稱時是 `IoError`（`NotFound`；其他解析器失敗則是 `Other`），訊息中包含解析器的說明。解析器失敗沒有 `os_code()`（[2.23.0](../200-core/223-io.md#2230-ioerror)），但 Windows 例外，那裡的解析器回報 Winsock 代碼。某個名稱與連接埠的第一個位址是 `resolve(f"{host}:{port}")[0]`（IPv6 主機要放在 `[..]` 中）。

`close` 擲回 OS 回報的錯誤（0.5.9）；關閉已關閉的通訊端不做任何事。`Drop` 也會關閉通訊端，並丟棄錯誤（3.2.0）。

## 3.2.5. TLS 1.3：`net::tls`

TLS 位於 `net::tls` 子模組，從一開始就只假設 1.3。它以 `core::crypto` 實作，屬於實驗性質，未經獨立稽核（[2.21.5](../200-core/221-crypto.md#2215-安全性考量)）。`ClientConfig` 與 `ServerConfig` 表達憑證、加密套件與 ALPN 協定清單，後量子選項會啟用 ML-KEM 混合金鑰交換。兩者都是 `#[non_exhaustive]` 記錄，其公開欄位都有預設值，`root_certs`、`cert_chain` 和 `private_key` 除外（[6.2.10](../../refs-lang/006-meta-system/602-built-in-attributes.md#6210-non_exhaustive-退出外部的窮盡性)）：字面值只需寫出不同之處，之後新增的每個欄位也都有預設值。交握之後，`Client` / `Server` 的行為就像明文串流，因此既有的 I/O 程式碼幾乎不必修改就能疊在上面。

```nabi
use std::net::tls;

struct ClientConfig {
    pub root_certs: List<Certificate>;                         // trust anchors (no default)
    pub cipher_suites: List<CipherSuite> = CipherSuite::all(); // TLS 1.3 suites, preference order
    pub alpn_protocols: List<List<u8>> = [];                   // ["h2", "http/1.1"], etc.
    pub enable_post_quantum: bool = true;                                // post-quantum (X25519MLKEM768 hybrid)
    pub client_cert_chain: List<Certificate> = [];             // sent when the server asks: leaf first; empty: none
    pub client_key: PrivateKey | none = none;                  // the client leaf's key
    pub session_cache: SessionCache | none = SessionCache::new(); // tickets to resume from; none: never resume
    pub early_data: List<u8> = [];                             // 0-RTT data, else the first data after the handshake
}

impl ClientConfig {
    fn new() throws (TlsError) -> ClientConfig;   // ClientConfig { root_certs: system_roots() }
}

#[non_exhaustive]
struct ServerConfig {

    pub private_key: PrivateKey;                               // the leaf's key (no default)
    pub cipher_suites: List<CipherSuite> = CipherSuite::all();
    pub alpn_protocols: List<List<u8>> = [];
    pub client_roots: List<Certificate> = [];                  // non-empty: ask for a client certificate, validated against these
    pub require_client_cert: bool = true;                      // with client_roots: refuse a client without one
    pub ocsp_response: List<u8> = [];                          // DER OCSPResponse stapled when asked; empty: none
    pub ticket_store: TicketStore | none = TicketStore::new(); // resumption; none: no tickets
    pub max_early_data: u32 = 0;                               // 0-RTT bytes accepted per connection; 0: none
}

impl ServerConfig {
    fn new(cert_chain: List<Certificate>, private_key: PrivateKey) throws (TlsError) -> ServerConfig;
        // ServerConfig { cert_chain, private_key }, checked now: the key must belong to cert_chain[0]
}

struct SessionCache { .. }                  // the client's tickets by server name; copies share them
impl SessionCache {
    fn new() -> SessionCache;
    fn len(self) -> usize;
    fn clear(self);
}

struct TicketStore { .. }                   // the server's resumable sessions; copies share them
impl TicketStore {
    fn new() -> TicketStore;

}

#[non_exhaustive]
enum CipherSuite { Aes128GcmSha256, Aes256GcmSha384, ChaCha20Poly1305Sha256 }
impl CipherSuite {
    fn all() -> List<CipherSuite>;          // all three, in the default preference order
}

struct Certificate { .. }                   // Sync: shared across threads
impl Certificate {
    fn from_der<B: AsBytes>(der: B) throws (TlsError) -> Certificate;
    fn from_pem(text: str) throws (TlsError) -> List<Certificate>;
    fn to_der(self) -> List<u8>;            // a copy of the DER encoding
    fn dns_names(self) -> List<str>;
    fn not_before(self) -> SystemTime;      // whole seconds (3.3)
    fn not_after(self) -> SystemTime;
}

struct PrivateKey { .. }                    // Ed25519, ECDSA P-256 / P-384, RSA (2048..4096 bits), RSASSA-PSS
impl PrivateKey {
    fn from_der<B: AsBytes>(der: B) throws (TlsError) -> PrivateKey;   // PKCS #8
    fn from_pem(text: str) throws (TlsError) -> PrivateKey;  // PRIVATE KEY, EC PRIVATE KEY or RSA PRIVATE KEY
}

fn system_roots() throws (TlsError) -> List<Certificate>;   // the OS trust store (read on each call)

#[non_exhaustive]
enum TlsErrorKind { Io, Certificate, Protocol, PeerAlert }
struct TlsError { .. }                      // private fields (0.5.10); + Display, Debug, Error, PartialEq, Eq, Clone

impl TlsError {

    fn message(self) -> str;               // without the "tls: " Display adds
    fn alert(self) -> u8;                  // the alert sent (received, for PeerAlert)
}

struct Client { .. }
impl Client {
    fn new(stream: TcpStream, server_name: str) throws (TlsError) -> Client;
    fn with_config(stream: TcpStream, server_name: str, cfg: ClientConfig) throws (TlsError) -> Client;
    async fn new_async(stream: TcpStream, server_name: str) throws (TlsError) -> Client;
    async fn with_config_async(stream: TcpStream, server_name: str, cfg: ClientConfig) throws (TlsError) -> Client;

    fn close_notify(self) throws (IoError);
    fn key_update(self) throws (IoError);

    fn peer_certificates(self) -> List<Certificate>;

}

impl WriteHalf<Client> {                    // and WriteHalf<Server>

}

struct Server { .. }
impl Server {
    fn new(stream: TcpStream, cfg: ServerConfig) throws (TlsError) -> Server;
    async fn new_async(stream: TcpStream, cfg: ServerConfig) throws (TlsError) -> Server;
    // close_notify, key_update, close, their *_async forms,
    // negotiated_alpn, peer_certificates and split as on Client, and:
    fn server_name(self) -> str | none;     // the client's SNI
    fn is_resumed(self) -> bool;

```

`Client` 和 `Server` 實作 `io::Read`、`io::Write`、`io::AsyncRead` 和 `io::AsyncWrite`（[2.23](../200-core/223-io.md)）、`io::Close`（`close`，見下文；擁有者必須關閉每一個，3.2.0）以及 `Drop`（在錯誤路徑上做同樣的事，並丟棄其錯誤）。失敗的交握會關閉傳給它的串流；成功的交握則擁有該串流。連線是仿射的（[2.13.4](../200-core/213-marker.md)）：`let b = c` 會移動它，且同一時間只由一個執行緒使用（`!Sync`）。若要同時有讀取者和寫入者，就 `split` 它（[3.2.1](#拆分的兩半)）：讀取的一半讀取的同時，寫入的一半寫入。兩半可以從不同的執行緒或任務使用。關閉寫入的一半會送出 close_notify，再把通訊端的寫入方向 shutdown。`Certificate` 是 `Sync`。

記錄依產生的順序送出。讀取時收到的 KeyUpdate 請求，以連線接下來的記錄回應：沒有進行中的寫入時立即回應，否則緊接在進行中寫入的記錄之後，因此讀取永遠不會等待阻塞在已滿通訊端上的寫入。一旦送出 close_notify，就不再回應 KeyUpdate 請求（close_notify 之後不會再有任何東西）。

`*_async` 方法遵循 3.2.0：通訊端尚未就緒時只暫停任務，交握（`new_async`、`with_config_async`）在對端的訊息之間也是如此。同一條連線上可以混用阻塞與非同步形式。

這套協定堆疊由實作提供，以 Nabi 撰寫於 `core::crypto`（2.21）之上：不使用作業系統或第三方的 TLS 函式庫，使用者也永遠不會呼叫它們。只使用 TLS 1.3（RFC 8446）；TLS 1.2 及更早的版本一律拒絕。交握支援 X25519 與 X25519MLKEM768 混合（ML-KEM-768 + X25519，`enable_post_quantum`）、HelloRetryRequest（針對群組或 cookie）、ALPN、SNI、KeyUpdate、close_notify、用戶端憑證、OCSP stapling，以及帶 0-RTT 資料的工作階段恢復。

工作階段恢復：有 `ticket_store` 的伺服器在每次交握後送出一張 NewSessionTicket；存放區保存工作階段（最多 4096 個，最舊的被丟棄；存續期為 2 小時），且每張票證最多兌換一次。有 `session_cache` 的用戶端把收到的票證保存在所連線的伺服器名稱底下（最多 64 張），並提供其中最新、仍有效、且其加密套件的雜湊也在它所提供之列的那一張，只提供一次（僅 psk_dhe_ke：恢復的交握仍會做新的金鑰交換）。恢復的連線跳過憑證驗證；`peer_certificates()` 回傳原始連線的憑證鏈。票證是在用戶端讀取時收到的。

0-RTT：當 `early_data` 非空且票證允許這麼多位元組時，用戶端把它當作早期資料隨 ClientHello 送出；否則，或伺服器拒絕時，它在交握之後作為第一筆應用資料送出（`is_early_data_accepted()` 會告訴你是哪一種）。伺服器只在下列條件都成立時接受早期資料：`max_early_data > 0`、針對第一張提供的票證、沒有 HelloRetryRequest、使用票證的加密套件與 ALPN 協定，且用戶端的票證年齡與伺服器端相差在 10 秒以內；它透過 `early_data()` 交出資料，並跳過它拒絕的早期資料。由於每張票證只能從其 `TicketStore` 兌換一次，重播的 ClientHello 不會恢復任何東西，其早期資料也會被跳過（RFC 8446 8.1）；應當互相拒絕對方重播的伺服器必須共用同一個存放區。早期資料相對於票證仍不具前向保密性，應當是冪等的。

用戶端憑證：`client_roots` 非空的伺服器會送出 CertificateRequest；用戶端的憑證鏈會像伺服器的一樣（見下文）依 `client_roots` 驗證，要求 extendedKeyUsage clientAuth 且不檢查名稱，並檢查其 CertificateVerify。沒有憑證的用戶端，若設定了 `require_client_cert` 則以 certificate_required 使交握失敗，否則繼續進行，且沒有 `peer_certificates()`。當伺服器接受該金鑰的簽章方案時，用戶端以 `client_cert_chain` 和由 `client_key` 產生的 CertificateVerify 回應 CertificateRequest，否則回應空的 Certificate。不屬於第一張憑證的 `client_key` 會使 `Client::with_config` 在送出任何東西之前就失敗。

伺服器驗證：憑證路徑從對端的憑證鏈建構到 `root_certs` 之一，並依 RFC 5280 驗證（簽章、目前時間的有效性、basicConstraints、keyUsage、extendedKeyUsage serverAuth、DNS 與 IP 名稱限制；未知的關鍵擴充一律失敗）。伺服器名稱只與 subjectAltName 比對（RFC 6125：不分大小寫，萬用字元必須是整個最左邊的標籤）；IP 字面值與 iPAddress 項目比對，且不送出 SNI。接受的簽章：Ed25519、搭配 SHA-256/384/512 的 ECDSA P-256 / P-384、RSA PKCS #1 v1.5（僅限憑證），以及搭配 SHA-256/384/512 的 RSA-PSS（2048-4096 位元金鑰，rsaEncryption 或 id-RSASSA-PSS；憑證中可以是任意 salt 長度，並遵守 id-RSASSA-PSS 金鑰的雜湊與最小 salt）。撤銷：用戶端要求 OCSP 回應（status_request）。裝訂的回應必須是成功的基本 OCSP 回應（RFC 6960），由葉憑證的簽發者，或由簽發者以 extendedKeyUsage OCSPSigning 簽發的憑證簽署，帶有指名葉憑證的 SHA-1 或 SHA-2 CertID，thisUpdate 不超前 5 分鐘以上，且 nextUpdate 存在且尚未過期；狀態為 revoked 時以 certificate_revoked 失敗，其他任何問題（包括 unknown 狀態）以 bad_certificate_status_response 失敗。帶有 status_request 之 TLS feature 擴充（RFC 7633）的葉憑證要求必須有裝訂的回應。沒有裝訂回應且沒有該擴充時，憑證會被接受；不使用 CRL，也不透過網路查詢 OCSP。

已過期或尚未生效的憑證以 certificate_expired 失敗，extendedKeyUsage 不允許該角色的以 unsupported_certificate 失敗，沒有通往 `root_certs` 之路徑的以 unknown_ca 失敗，其他任何失敗以 bad_certificate 失敗。ServerHello、HelloRetryRequest、EncryptedExtensions 或 Certificate 項目中出現用戶端未要求的擴充時，以 unsupported_extension 失敗。失敗的交握會送出其警示，然後關閉串流。

每一方都以其金鑰的方案簽署 CertificateVerify：`ed25519`、`ecdsa_secp256r1_sha256`、`ecdsa_secp384r1_sha384`；rsaEncryption 憑證使用對端提供的 `rsa_pss_rsae_sha256` / `_sha384` / `_sha512` 中的第一個；id-RSASSA-PSS 憑證使用對端提供、且金鑰參數允許的 `rsa_pss_pss_sha256` / `_sha384` / `_sha512` 中的第一個。`PrivateKey` 讀取 PKCS #8（Ed25519、P-256 / P-384 上的 id-ecPublicKey、rsaEncryption、id-RSASSA-PSS）、RFC 5915 `EC PRIVATE KEY` 和 PKCS #1 `RSA PRIVATE KEY`。當 `cert_chain` 為空，或金鑰的公開部分不是葉憑證的公開金鑰時，`ServerConfig::new`、`Server::new` 和 `Server::new_async` 會失敗（`TlsErrorKind::Certificate`）。

協定堆疊把流量、交握與恢復用的秘密、記錄金鑰、金鑰交換秘密、票證 PSK，以及 Ed25519 / EC 私密金鑰保存在秘密儲存區（[2.21.5](../200-core/221-crypto.md#2215-安全性考量)），並在 KeyUpdate 時、交握結束時與關閉時抹除。

無法讀取 OS 信任存放區時（找不到存放區、無法讀取的憑證包、任何 wasm 目標），`ClientConfig::new()` 擲回 `system_roots()` 的錯誤；`Client::new` 和 `Client::new_async` 以它建立設定，並擲回相同的錯誤。其他欄位以結構更新語法從它設定：`ClientConfig { alpn_protocols: [..], ..try ClientConfig::new() }`。沒有存放區時，用 `root_certs` 寫出字面值：`ClientConfig { root_certs: roots }`。

`Client::close` 和 `Server::close` 在連線狀態健全時送出 close_notify（其失敗不會回報），然後關閉通訊端並擲回 OS 回報的錯誤；無論如何金鑰都會被抹除。

`system_roots()` 讀取 OS 信任存放區：macOS 鑰匙圈的錨點（加上無條件信任的管理員 / 使用者憑證）、Windows 的 `ROOT` 存放區、Linux 上找到的第一個 CA 憑證包（`/etc/ssl/certs/ca-certificates.crt`、`/etc/pki/tls/certs/ca-bundle.crt`……）、Android 的根憑證（Android 14 起為 `/apex/com.android.conscrypt/cacerts`，否則為 `/system/etc/security/cacerts`）。`SSL_CERT_FILE` 會覆寫它。wasm 目標沒有存放區：請傳入 `root_certs`。

對端送出 close_notify 之後，`read` 回傳 0；沒有 close_notify 就結束的連線是 `IoError`（`UnexpectedEof`）；協定失敗在送出致命警示後是 `IoError`（`InvalidData`）。TLS 記錄整筆寫出，所以 `write` 會寫出整個 `buf`。

### 範例

實際用法很簡單：在明文 TCP 連線上疊一個 TLS 用戶端，再對它呼叫明文 I/O。

```nabi
use std::net::{tcp_connect, tls};

let conn = try tcp_connect("example.com:443");
let tls_conn = try tls::Client::new(conn, "example.com");
try tls_conn.write_all(b"GET / HTTP/1.1\r\nHost: example.com\r\n\r\n");
let resp = try tls_conn.read_to_end();
try tls_conn.close();                   // close_notify, then the socket
```

## 3.2.6. 便利函式

以自由函式提供的具型別建構函式，供常見情況使用。它們接受相同的 `ToSocketAddrs`（3.2.4），所以可以直接傳入主機名稱，例如 `tcp_connect("example.com:80")`。

```nabi
fn tcp_connect<A: ToSocketAddrs>(addr: A) throws (IoError) -> TcpStream;         // TcpStream::connect(addr)
async fn tcp_connect_async<A: ToSocketAddrs>(addr: A) throws (IoError) -> TcpStream; // TcpStream::connect_async(addr)
fn tcp_listen<A: ToSocketAddrs>(addr: A) throws (IoError) -> TcpListener;        // TcpListener::bind(addr)
fn udp_bind<A: ToSocketAddrs>(addr: A) throws (IoError) -> UdpSocket;            // UdpSocket::bind(addr)
```

`connect` 依序嘗試各位址，回傳第一個連上的；`bind` 繫結第一個可用的；全部失敗時擲回最後一個錯誤，空清單則是 `InvalidInput`。

## 3.2.7. zerocopy 鉤子（進階）

`sendfile`、`splice` 和 `write_zerocopy` 只存在於 Linux，所以它們是 `std::os::linux::net` 中的 trait `TcpStreamExt`（[3.10.6](310-os.md#3106-oslinuxnet核心複製)），在 Linux 上位於 prelude 中：在那裡 `stream.sendfile(ref f, 0, n)` 不需要 `use`。通訊端的 OS 描述元是 `AsRawFd`（unix）或 `AsRawSocket`（Windows）（[3.10.2](310-os.md#3102-osunixio檔案描述元)）。

## 3.2.8. 模組對應

各平台的支援整理如下。核心功能在桌面 OS 與 wasi 上都可用，但依賴 Linux 特有機制的項目，例如 Unix 通訊端與 zerocopy 鉤子，只在有限的地方啟用。

| 項目             | linux/macos/windows | wasi | 備註                          |
|------------------|---------------------|------|--------------------------------|
| TCP              | ✓                   | ✓    | wasi:sockets                   |
| UDP              | ✓                   | ✓    | wasi:sockets                   |
| Unix 通訊端      | linux/macos         | ✗    | `os::unix::net`；沒有 Windows 形式（具名管道是另外的東西） |
| TLS 1.3          | ✓                   | ✓（沒有信任存放區：請傳入 `root_certs`） | Nabi 自有實作，基於 `core::crypto` |
| sendfile         | linux               | ✗    | `os::linux::net::TcpStreamExt` |
| splice           | linux               | ✗    | `os::linux::net::TcpStreamExt` |
| MSG_ZEROCOPY     | linux 4.14+         | ✗    | `os::linux::net::TcpStreamExt` |
| `Socket`         | ✓                   | wasip2 | `SocketType::Raw` 與 `set_reuse_port`：Windows 與 WASI 上沒有 |

## 3.2.9. `Socket`：低階層

`Socket` 就是作業系統所見的通訊端，形狀仿照 Rust 的 socket2：由呼叫端選擇網域、類別與協定，並設定每個選項，每個方法都是其名稱所指的那一個系統呼叫。`bind` 不設定 `SO_REUSEADDR`，`connect` 不做任何解析，`listen` 接受 backlog。設定完成後，`TcpStream::from(s)`、`TcpListener::from(s)` 或 `UdpSocket::from(s)` 接管該通訊端（`s` 被移動），`Socket::from` 則反向轉回。

```nabi
#[non_exhaustive]
enum Domain { Ipv4, Ipv6 }                  // AF_INET, AF_INET6; Clone, Copy, PartialEq, Eq, Hash, Debug
impl Domain {
    fn for_address(addr: SocketAddr) -> Domain;
}

#[non_exhaustive]
enum SocketType { Stream, Datagram, Raw }   // SOCK_STREAM, SOCK_DGRAM, SOCK_RAW; Clone, Copy, PartialEq, Eq, Hash, Debug

struct Protocol { /* an IP protocol number */ }   // Clone, Copy, PartialEq, Eq, Hash, Debug
impl Protocol {
    const ICMPV4: Protocol;                 // 1
    const TCP: Protocol;                    // 6
    const UDP: Protocol;                    // 17
    const ICMPV6: Protocol;                 // 58
    fn new(number: i32) -> Protocol;
    fn number(self) -> i32;
}

struct Socket { /* OS handle */ }           // Debug prints `Socket`

impl Socket {
    fn new(domain: Domain, ty: SocketType, protocol: Protocol | none = none) throws (IoError) -> Socket;
                                            // none: the type's default protocol
    fn bind(self, addr: SocketAddr) throws (IoError);
    fn listen(self, backlog: i32) throws (IoError);
    fn connect(self, addr: SocketAddr) throws (IoError);      // in non-blocking mode: WouldBlock while in progress
    fn connect_timeout(self, addr: SocketAddr, dur: Duration) throws (IoError);
    async fn connect_async(ref self, addr: SocketAddr) throws (IoError);
    fn accept(self) throws (IoError) -> (Socket, SocketAddr);
    async fn accept_async(ref self) throws (IoError) -> (Socket, SocketAddr);
    fn local_addr(self) throws (IoError) -> SocketAddr;
    fn peer_addr(self) throws (IoError) -> SocketAddr;
    fn shutdown(self, how: Shutdown) throws (IoError);
    async fn shutdown_async(ref self, how: Shutdown) throws (IoError);
    fn send_to<B: AsBytes>(self, buf: B, addr: SocketAddr) throws (IoError) -> usize;
    fn recv_from(self, buf: SliceMut<u8>) throws (IoError) -> (usize, SocketAddr);
    // + send_to_async / recv_from_async (ref self)

    // options: each setter has a getter of the same name, except set_keepalive and set_nonblocking
    fn set_reuse_address(self, on: bool) throws (IoError);    // SO_REUSEADDR
    fn set_reuse_port(self, on: bool) throws (IoError);       // SO_REUSEPORT; Unsupported off Unix
    fn set_nodelay(self, on: bool) throws (IoError);          // TCP_NODELAY
    fn set_broadcast(self, on: bool) throws (IoError);        // SO_BROADCAST
    fn set_recv_buffer_size(self, size: usize) throws (IoError);  // SO_RCVBUF (the OS may round it)
    fn set_send_buffer_size(self, size: usize) throws (IoError);  // SO_SNDBUF
    fn set_ttl(self, ttl: u32) throws (IoError);              // IP_TTL
    fn set_only_v6(self, on: bool) throws (IoError);          // IPV6_V6ONLY
    fn set_linger(self, dur: Duration | none) throws (IoError);   // SO_LINGER, whole seconds; none: off
    fn set_keepalive(self, alive: Duration | none) throws (IoError); // as on TcpStream (no getter)
    fn set_nonblocking(self, nb: bool);
    fn set_read_timeout(self, dur: Duration | none);
    fn set_write_timeout(self, dur: Duration | none);
    fn read_timeout(self) -> Duration | none;
    fn write_timeout(self) -> Duration | none;

    fn try_clone(self) throws (IoError) -> Socket;
    fn close(self) throws (IoError);
}

impl io::Read for Socket { ... }            // and io::Write, io::AsyncRead, io::AsyncWrite
impl io::Close for Socket { ... }
impl Drop for Socket { ... }                // releases on an error path
impl From<TcpStream> for Socket { ... }     // and TcpListener, UdpSocket
```

新的通訊端在底層是非阻塞的，且不被子行程繼承，與本模組中的每個通訊端一樣；阻塞呼叫依 3.2.0 所述的方式等待。

```nabi
use std::net::{Socket, Domain, SocketType, Protocol, TcpListener};

let s = try Socket::new(Domain::Ipv6, SocketType::Stream, Protocol::TCP);
try s.set_only_v6(false);                   // IPv4 too, on one socket
try s.set_reuse_address(true);
try s.bind(try "[::]:8080".parse());
try s.listen(1024);
let l = TcpListener::from(s);
```
