# 3.10. `os::`：只有部分操作系统才有的功能

跨平台模块（`fs`、`net`、`process`、`io`）包含每个桌面操作系统都能做的事。只有部分操作系统才有的功能放在 `std::os` 下，每个操作系统家族一个模块，划分方式与 Rust 相同：

| 模块 | 存在于 | 包含 |
|---|---|---|
| `os::unix` | `target_family = "unix"`（Linux、macOS、FreeBSD） | `fs`、`io`、`net`、`process` |
| `os::linux` | `target_os = "linux"` | `net`、`process` |
| `os::windows` | `target_os = "windows"` | `fs`、`io`、`process` |

`os::unix` 和 `os::windows` 中的 `fs` 部分（`PermissionsExt`、`DirExt`、`OsOpenFlags`、`OsCreateFlags`、`CreateFileParams` 以及各标志常量）与文件类型一起在 [3.1.1](301-fs.md#311-core-types) 中规定；下面各节介绍其余部分。

模块只存在于它的目标上：在其他目标上 `use std::os::unix::..` 无法解析。使用它的代码要写在相同的 `#[cfg]` 下。

## 3.10.1. prelude 中的扩展 trait

只有部分操作系统才有的方法是跨平台类型上的 trait 方法：`PermissionsExt` 为 `fs::Permissions` 添加 `mode`，`CommandExt` 为 `process::Command` 添加 `process_group`，等等。在该 trait 存在的目标上，它位于 prelude 中（[0.2](../000-meta/002-import.md)），所以它的方法不需要 `use`：

| 目标 | 添加到 prelude 的名称 |
|---|---|
| unix | `PermissionsExt`（`os::unix::fs`）、`CommandExt`、`ExitStatusExt`（`os::unix::process`） |
| linux | unix 的那些，以及 `ChildExt`（`os::linux::process`）、`TcpStreamExt`（`os::linux::net`） |

在其他目标上，该 trait 及其实现都不存在，调用会得到“未找到”错误，错误中写出该方法需要的 cfg（[refs-lang 6.3](../../refs-lang/006-meta-system/603-cfg.md)）：

```text
error[E0046]: no method `process_group` found for type `Command`
   = note: `process_group` is only available on unix (`#[cfg(target_family = "unix")]`)
   = help: put the code that uses it under the same `#[cfg(target_family = "unix")]`
```

原始句柄 trait（`AsRawFd`、`AsRawHandle` 等）不在 prelude 中：在使用它们的地方导入。

## 3.10.2. `os::unix::io`：文件描述符

```nabi
// std::os::unix::io
type RawFd = i32;

trait AsRawFd {
    fn as_raw_fd(self) -> RawFd;             // still owned by self; -1 once self is closed
}

trait FromRawFd {
    unsafe fn from_raw_fd(fd: RawFd) -> Self;    // self owns fd from now on
}

trait IntoRawFd {
    fn into_raw_fd(self) -> RawFd;           // the caller owns fd from now on
}
```

实现 `AsRawFd` 的有 `File`、`Socket`、`TcpStream`、`TcpListener`、`UdpSocket`、Unix 套接字（3.10.4）、`ChildStdin` / `ChildStdout` / `ChildStderr` 以及 `Stdin` / `Stdout` / `Stderr`（0、1、2）。实现 `FromRawFd` 的有 `File`（其错误中称它为 `fd N`）和各种套接字；除标准流之外，每个 `AsRawFd` 类型都实现了 `IntoRawFd`。`from_raw_fd` 是 `unsafe` 的：`fd` 必须是打开的，并且不得被其他代码关闭，否则两个所有者会关闭同一个描述符（第二次关闭可能命中在此期间新打开的文件）。

描述符一直归句柄所有：关闭句柄就会关闭描述符，此后 `as_raw_fd` 返回 -1。`into_raw_fd` 则是交出描述符：句柄被消耗（像 `let` 那样被移动），没有任何东西会关闭该描述符，它归调用者所有，由调用者关闭，或用 `from_raw_fd` 交给新的所有者。用 `from_raw_fd` 接管的套接字按原样使用；如果描述符是阻塞的，阻塞调用会在操作系统中阻塞，而不是在 `poll` 中阻塞（此时超时和 `set_nonblocking` 不起作用）。

## 3.10.3. `os::windows::io`：句柄与套接字

```nabi
// std::os::windows::io
type RawHandle = isize;                  // a Win32 HANDLE, pointer-sized
type RawSocket = u64;                    // a Winsock SOCKET

trait AsRawHandle { fn as_raw_handle(self) -> RawHandle; }       // INVALID_HANDLE_VALUE (-1) once closed
trait FromRawHandle { unsafe fn from_raw_handle(h: RawHandle) -> Self; }
trait AsRawSocket { fn as_raw_socket(self) -> RawSocket; }       // INVALID_SOCKET once closed
trait FromRawSocket { unsafe fn from_raw_socket(s: RawSocket) -> Self; }
trait IntoRawHandle { fn into_raw_handle(self) -> RawHandle; }  // the caller owns it now
trait IntoRawSocket { fn into_raw_socket(self) -> RawSocket; }  // the caller owns it now
```

实现 `AsRawHandle` 的有 `File`、子进程管道和标准流（它们的 `GetStdHandle` 值）；实现 `FromRawHandle` 的是 `File`；实现 `IntoRawHandle` 的是 `File` 和子进程管道。`Socket`、`TcpStream`、`TcpListener` 和 `UdpSocket` 实现了 `AsRawSocket`、`FromRawSocket` 和 `IntoRawSocket`。`into_raw_handle` / `into_raw_socket` 像 `into_raw_fd` 那样交出值（3.10.2）。这些值就是 Win32 给出的 HANDLE 和 SOCKET 原值；运行时如何保存它们是不可见的。传给 `from_raw_handle` 的值如果不是内核对象句柄（例如 `GetCurrentProcess()` 这样的伪句柄），会得到一个已关闭的 `File`。

## 3.10.4. `os::unix::net`：Unix 域套接字

Unix 域套接字有三种类型：`UnixListener`、`UnixStream` 和 `UnixDatagram`。它们的形态与 TCP 相似（[3.2](302-net.md)），但由于只在同一主机内通信，它们用文件路径作标识，并提供对应 `socketpair(2)` 的 `pair()`。通过 `SCM_RIGHTS` 传递 fd 只在 Unix 套接字上有意义，所以单独提供为 `send_with_fd` / `recv_with_fd`。

```nabi
// std::os::unix::net
struct UnixListener { /* opaque */ }
struct UnixStream { /* opaque */ }
struct UnixDatagram { /* opaque */ }

impl UnixListener {
    fn bind(path: Path) throws (IoError) -> UnixListener;             // path must not exist yet; backlog 128
    fn accept(self) throws (IoError) -> (UnixStream, Path | none);   // peer's bound path, none if unnamed
    async fn accept_async(ref self) throws (IoError) -> (UnixStream, Path | none);
    fn local_addr(self) throws (IoError) -> Path | none;
    fn set_nonblocking(self, nb: bool);
    fn try_clone(self) throws (IoError) -> UnixListener;
    fn close(self) throws (IoError);   // throws what the OS reports
}

impl UnixStream {
    fn connect(path: Path) throws (IoError) -> UnixStream;
    async fn connect_async(path: Path) throws (IoError) -> UnixStream;   // on a blocking thread
    fn pair() throws (IoError) -> (UnixStream, UnixStream);          // socketpair
    fn send_with_fd<B: AsBytes>(self, buf: B, fd: RawFd) throws (IoError) -> usize;
    fn recv_with_fd(self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    async fn send_with_fd_async<B: AsBytes>(ref self, buf: B, fd: RawFd) throws (IoError) -> usize;
    async fn recv_with_fd_async(ref self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    fn peer_addr(self) throws (IoError) -> Path | none;
    fn local_addr(self) throws (IoError) -> Path | none;
    fn shutdown(self, how: Shutdown) throws (IoError);
    async fn shutdown_async(ref self, how: Shutdown) throws (IoError);   // shutdown never waits
    fn set_read_timeout(self, dur: Duration | none);
    fn set_write_timeout(self, dur: Duration | none);
    fn set_nonblocking(self, nb: bool);
    fn try_clone(self) throws (IoError) -> UnixStream;
    fn split(self) -> (ReadHalf<UnixStream>, WriteHalf<UnixStream>);   // as TcpStream::split (3.2.1)
    fn close(self) throws (IoError);   // throws what the OS reports
}

impl ReadHalf<UnixStream> {
    fn unsplit(self, w: WriteHalf<UnixStream>) -> UnixStream;
}

impl UnixDatagram {
    fn bind(path: Path) throws (IoError) -> UnixDatagram;
    fn connect(path: Path) throws (IoError) -> UnixDatagram;         // connected to path, itself unbound
    async fn connect_async(path: Path) throws (IoError) -> UnixDatagram;   // never waits
    fn pair() throws (IoError) -> (UnixDatagram, UnixDatagram);      // socketpair
    fn send<B: AsBytes>(self, buf: B) throws (IoError) -> usize;
    fn recv(self, buf: SliceMut<u8>) throws (IoError) -> usize;
    fn send_with_fd<B: AsBytes>(self, buf: B, fd: RawFd) throws (IoError) -> usize;
    fn recv_with_fd(self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    // + send_async / recv_async / send_with_fd_async / recv_with_fd_async (ref self)
    fn local_addr(self) throws (IoError) -> Path | none;
    fn set_read_timeout(self, dur: Duration | none);
    fn set_write_timeout(self, dur: Duration | none);
    fn set_nonblocking(self, nb: bool);
    fn close(self) throws (IoError);   // throws what the OS reports
}

impl io::Read for UnixStream { ... }
impl io::Write for UnixStream { ... }
impl io::AsyncRead for UnixStream { ... }
impl io::AsyncWrite for UnixStream { ... }
impl io::Close for UnixListener { ... }   // and UnixStream, UnixDatagram
impl io::AsyncClose for UnixListener { ... } // and UnixStream, UnixDatagram
impl Drop for UnixListener { ... }       // releases on an error path
impl Drop for UnixStream { ... }
impl Drop for UnixDatagram { ... }
// + AsRawFd, FromRawFd, IntoRawFd for all three
```

3.2.0 的通用规则同样适用：底层是非阻塞的，`set_*_timeout` 限制阻塞调用的时长，`*_async` 挂起任务。流的 `connect` 只在监听者的 backlog 已满时等待；`connect_async` 在阻塞线程上运行它。用 `recv_with_fd` 收到的描述符归调用者所有（close-on-exec）；用 `FromRawFd` 把它交给某个所有者。

## 3.10.5. `os::unix::process` 与 `os::linux::process`

```nabi
// std::os::unix::process
trait CommandExt {
    fn process_group(self, pgid: i32) -> Self;   // 0: a new group the child leads
}
impl CommandExt for Command { .. }

trait ExitStatusExt {
    fn signal(self) -> Signal | none;            // the signal that ended it
}
impl ExitStatusExt for ExitStatus { .. }

fn parent_id() -> u32;                           // getppid

// std::os::linux::process
trait ChildExt {
    fn pidfd(self) throws (IoError) -> RawFd;    // Linux 5.3+; valid until the child is reaped
}
impl ChildExt for Child { .. }
```

进程正常退出时，`ExitStatusExt::signal` 为 `none`；对于 `Signal` 没有命名的信号（实时信号）也是如此。pidfd 一直归子进程所有：`wait` / `try_wait` 会关闭它。

## 3.10.6. `os::linux::net`：内核复制

在代理或文件服务器这类以吞吐量为代价的地方，Linux 内核的复制路径通过 `TcpStream` 暴露出来。大多数用户不需要它们；`io::copy` 已经在可行时使用它们。

```nabi
// std::os::linux::net
trait TcpStreamExt {
    fn sendfile(self, ref file: File, offset: u64, count: u64) throws (IoError) -> u64;
                                            // sendfile(2): the bytes sent, fewer if the file ends
    fn splice(self, ref src: File, count: u64) throws (IoError) -> u64;
                                            // splice(2) through a kernel pipe, from src's offset
    fn write_zerocopy(self, buf: List<u8>) throws (IoError) -> usize;
                                            // MSG_ZEROCOPY (Linux 4.14+): some prefix of buf, read in place
}
impl TcpStreamExt for TcpStream { .. }
```

`write_zerocopy` 在内核不再需要 `buf` 时返回。内核无法固定这些页面或没有 `MSG_ZEROCOPY` 时，字节以普通复制方式发送。

## 3.10.7. `os::windows::process`：Ctrl-Break

```nabi
// std::os::windows::process
fn on_ctrl_break(handler: fn() + Send + Sync) throws (IoError);
```

`process::on_signal` 转发有对应 `Signal` 的控制台事件（Ctrl-C 对应 `Interrupt`，控制台关闭 / 注销 / 关机对应 `Hangup`，[3.6.5](306-process.md#365-signal-handling-advanced)）。Ctrl-Break 在 Unix 上没有对应物，所以由这个仅限 Windows 的函数处理：控制台每次发送 Ctrl-Break 时，`handler` 在 `nabi-signal` 分发线程上运行，之后的调用会替换它。没有处理函数时，Ctrl-Break 会结束进程（控制台的默认行为）。
