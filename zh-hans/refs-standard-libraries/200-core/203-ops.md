# 2.3. 算术 / 位运算 / 索引 trait

`core::ops` 模块定义了 Nabi 的运算符词法单元（[refs-lang 1.10](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md)）所分派到的 trait 族。不仅普通运算符 `+`、`-`、`*`、`/`、`%`、`<<`、`>>`、`&`、`|`、`^`、`~`、`&&`、`||`，`arr[i]` 索引和 `s[1:3]` 切片也调用本章定义的 trait 方法。[2.3.4](#234-索引-trait) 的索引 trait 是例外：它们位于 `core::index`，而不在 `core::ops` 中。

[refs-lang 3.1 运算符分派](../../refs-lang/003-expressions/301-operator-dispatch.md)的机制查找的是本章的**内容**；本文档 refs-standard-libraries 2.3 是这些内容的权威来源。

> [!NOTE]
> 本章的每个运算符 trait 方法在声明时都不带 `throws`。因此运算符不会抛出错误，实现也不能加上 `throws`（[refs-lang 4.14.11](../../refs-lang/004-functions/414-throws.md#41411-方法上的-throws)）。可能失败的操作以具名方法（`checked_div` 等）提供，或返回 `Result`。

## 2.3.1. 算术 trait

### `Add`：算术加法（`+`）

第一个是加法 trait。

```nabi
#[lang("add_trait")]
trait Add<Rhs = Self> {
    type Output;

    #[infix("+")]
    fn add(self, rhs: Rhs) -> Output;
}
```

**含义**：返回两个值的和。

```nabi
let a: i32 = 5;
let b: i32 = 3;
let c = a + b;        //→ 8 (i32)

let x: f64 = 1.5;
let y: f64 = 2.5;
let z = x + y;        //→ 4.0 (f64)
```

#### Output 规则

关联类型 `Output` 通常与 `Self` 相同，但有以下例外。第一，`int + int = int` 具有任意精度，因此不会溢出；`i32 + i32` 这样的定宽加法结果仍为 `i32`，不会提升为更宽的类型（[2.1.6](201-numbers.md#216-算术结果类型)）。第二，`Vec3<f64> + f64 = Vec3<f64>` 这样的用户定义算术以 `impl Add<f64> for Vec3<f64>` 的形式定义。

#### 溢出行为

溢出行为取决于类型。对于 `i32 + i32`，开启溢出检查时溢出会触发 panic，关闭时则回绕。检查由 `nabic -C overflow-checks[=yes|no]` 控制（[refs-lang 9.1.2](../../refs-lang/009-tools/901-nabic-cli.md#nabic-buildaot-构建)）；默认在所有构建配置中开启，在 `nabi.nabion` 的构建配置中写 `overflow_checks: false` 可以关闭（[refs-lang 9.10.3](../../refs-lang/009-tools/910-nabi-frontend.md#9103-nabinabion--nabilock)）。`f32 + f32` 和 `f64 + f64` 遵循 IEEE 754 加法，溢出得到 ±∞ 或 NaN。`int + int` 具有任意精度，不存在溢出。饱和、检查和回绕变体以独立的方法（`saturating_add`、`checked_add`、`wrapping_add`）提供，定义在本 trait 之外。

在所有构建配置中都做检查的原因见 [2.11.1 设计理由](211-conversion.md#设计依据)。

### `Sub`：算术减法（`-`）

减法 trait 定义如下。

```nabi
#[lang("sub_trait")]
trait Sub<Rhs = Self> {
    type Output;

    #[infix("-")]
    fn sub(self, rhs: Rhs) -> Output;
}
```

它的形式与 `Add` 相同；`a - b` 分派到 `Sub::sub(a, b)`。

```nabi
let r = 10i32 - 3i32;     //→ 7
let s = 1.0f64 - 0.5f64;  //→ 0.5
```

### `Mul`：算术乘法（`*`）

乘法 trait 定义如下。

```nabi
#[lang("mul_trait")]
trait Mul<Rhs = Self> {
    type Output;

    #[infix("*")]
    fn mul(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 6i32 * 7i32;      //→ 42
let s = 2.5f64 * 4.0f64;  //→ 10.0
```

#### 用户定义的含义

除了算术乘法，`Mul` 也可以承载领域特定的含义，矩阵乘法就是典型的例子。

```nabi
struct Matrix2x2 { a: f64; b: f64; c: f64; d: f64; }

impl ops::Mul<Matrix2x2> for Matrix2x2 {
    type Output = Matrix2x2;

    fn mul(self, rhs: Matrix2x2) -> Matrix2x2 {
        Matrix2x2 {
            a: self.a * rhs.a + self.b * rhs.c,
            b: self.a * rhs.b + self.b * rhs.d,
            c: self.c * rhs.a + self.d * rhs.c,
            d: self.c * rhs.b + self.d * rhs.d,
        }
    }
}
```

逐元素乘法由 [2.6 broadcast](206-broadcast.md) 中的 `DotMul`（`m .* n`）负责。

### `Div`：算术除法（`/`）

除法 trait 定义如下。

```nabi
#[lang("div_trait")]
trait Div<Rhs = Self> {
    type Output;

    #[infix("/")]
    fn div(self, rhs: Rhs) -> Output;
}
```

词法分析器把 `÷` 读作 `/`，所以 `a ÷ b` 也分派到 `div`。`÷` 没有自己的中缀绑定。

```nabi
let r = 20i32 / 7i32;      //→ 2 (integer division, truncating)
let s = 20.0f64 / 7.0f64;  //→ 2.857142857142857
```

#### 除以零

除以零按类型分别处理。整数 `i32 / 0` 触发 panic，能常量折叠的表达式（`1 / 0`）是编译错误。浮点数 `f64 / 0.0` 按 IEEE 754 得到 ±∞ 或 NaN。

要得到 `none` 而不是 panic，请使用 `checked_div`。

```nabi
let r = 20i32.checked_div(7i32);  //→ 2
let s = 20i32.checked_div(0i32);  //→ none
```

### `Rem`：算术余数（`%`）

余数 trait 定义如下。

```nabi
#[lang("rem_trait")]
trait Rem<Rhs = Self> {
    type Output;

    #[infix("%")]
    fn rem(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 20i32 % 7i32;     //→ 6
let s = 5.5f64 % 2.0f64;  //→ 1.5 (IEEE 754 fmod)
```

符号规则：结果的符号与被除数（左操作数）相同，因此 `(-5) % 3 = -2`，`5 % (-3) = 2`（截断除法的定义，与 C / Rust 相同）。

### `Modulo`：向下取整取模（`%%`）

向下取整（商向下舍入）的余数 trait 定义如下。

```nabi
trait Modulo<Rhs = Self> {
    type Output;

    #[infix("%%")]
    fn modulo(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = (-5i32) %% 3i32;     //→ 1   ( = -5 - (-2)*3 )
let s = 5i32 %% (-3i32);     //→ -1  ( = 5 - (-2)*(-3) )
let t = (-7.5f64) %% 2.0f64; //→ 0.5
```

它与 `Rem` 的区别在于结果的符号规则。`a %% b = a - floor(a / b) * b`，因此结果的符号**与除数 `b` 相同**（与 Python 的 `%` 一样）。除数为正时结果总在 `[0, b)` 之内，即使被除数为负也得到非负的余数；除数为负时结果在 `(b, 0]` 之内（`7 %% -3 = -2`）。对于负除数，它与欧几里得取模（总是非负）不同。它常用于索引回绕和模运算。浮点 `%%` 的结果为零时带有除数的符号（`44.0 %% -4.0 = -0.0`）。

```nabi
// common pattern: negative index wrap-around
let i: i32 = -1;
let len: i32 = 8;
let wrapped = i %% len;      //→ 7    (i % len would give -1)
```

`Rem` 与 `Modulo` 的符号差异总结如下。

| `a`  | `b`  | `a % b`（Rem） | `a %% b`（Modulo） |
|------|------|---------------|-------------------|
| `7`  | `3`  | `1`           | `1`               |
| `-7` | `3`  | `-1`          | `2`               |
| `7`  | `-3` | `1`           | `-2`              |
| `-7` | `-3` | `-1`          | `-1`              |

两个词法单元映射到不同的 trait，所以一个类型可以只实现其中之一，或者赋予它们不同的含义。标准库对原始整数 / 浮点类型的实现完全遵循上表中的定义。

`%%` 词法单元定义在 [refs-lang 1.10 标点与运算符词法单元](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md)中；它在 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 表中的优先级为第 10 级，与 `%` 相同，左结合。

### `Pow`：幂（`**`）

```nabi
trait Pow<Rhs = Self> {
    type Output;

    #[infix("**")]
    fn pow(self, rhs: Rhs) -> Output;
}
```

`**` 比前缀 `-` 结合得更紧，并且右结合（[refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md)）：`-x**2` 是 `-(x**2)`，`2**3**2` 是 `512`。`^` 仍是按位异或。

| 底数                   | 指数的实现                         | 结果                                           |
|------------------------|------------------------------------|------------------------------------------------|
| `i8` .. `usize`        | `u32`                              | 底数类型；溢出与 `*` 相同（开启溢出检查时触发 panic） |
| `f32`、`f64`           | 同一浮点类型、`i32`                | `pow`（由平台的 `pow` 正确处理）、`powi`（重复乘法） |

指数并不与底数同类型：整数底数的指数是 `u32`（`n ** 2` 把字面量的类型定为 `u32`；`i64` 指数是类型错误，提示为 `e as u32`）；浮点底数时，无后缀字面量取底数的类型（`x ** 2` 即 `x.pow(2.0)`）。整数底数配负字面量指数（`2 ** -1`）是编译错误（E0144），其提示给出浮点写法 `2.0 ** -1.0`：结果会是分数。整数底数配浮点字面量指数（`2 ** 0.5`、`n ** -1.0`）混用了两种数（E0054）；其提示给出 `2.0 ** 0.5` 或 `(n as f64) ** -1.0`。`PowAssign`（`**=`，2.4）和 `DotPow`（`.**`，2.6）是它的复合形式与逐元素形式。与其他算术 trait 不同，`Pow` 和 `Modulo`（见上）没有 lang 槽：编译器只通过它们的 `#[infix]` 词法单元找到它们，从不按名字查找（[0.4.3](../000-meta/004-lang-slot-table.md)）。

## 2.3.2. 一元 trait

### `Neg`：一元取负（前缀 `-`）

一元取负 trait 定义如下。

```nabi
#[lang("neg_trait")]
trait Neg {
    type Output;

    #[prefix("-")]
    fn neg(self) -> Output;
}
```

```nabi
let r = -5i32;       //→ -5
let s = -3.14f64;    //→ -3.14
let t = -(a + b);    //→ -(a+b)
```

这个 trait 只对有符号整数和浮点类型有意义；`u32` 没有 `Neg` 实现。`Array<T, N>` 在 `T: Neg` 时实现它，把每个元素取负得到一个新数组（视图也一样）：例如 `y: Vector<f64>` 的 `-y`。

特别地，`i32::MIN`（= -2147483648）取负的结果无法表示，因此会触发 panic，关闭溢出检查时则回绕（= i32::MIN 不变）。需要显式回绕时用 `wrapping_neg`，需要 `T | none` 结果时用 `checked_neg`。

### `Not`：按位取反 / 逻辑非（`!`）

`Not` trait 定义如下。

```nabi
#[lang("not_trait")]
trait Not {
    type Output;

    #[prefix("!")]
    fn not(self) -> Output;
}
```

```nabi
let r = !true;       //→ false
let s = !0u8;        //→ 255 (all bits 1)
let t = !0xFFi32;    //→ 0xFFFFFF00 (all 32 bits inverted)
```

各类型的行为：`bool::not(true) = false`，`bool::not(false) = true`，作用为逻辑非。而 `u8::not(0) = 0xFF`、`i32::not(0) = -1` 的作用为按位取反。

### `BitNot`：按位取反（`~`）

`~` 词法单元（[refs-lang 1.10.3](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md)）是仅用于整数的按位取反。

```nabi
#[lang("bitnot_trait")]
trait BitNot {
    type Output;

    #[prefix("~")]
    fn bitnot(self) -> Output;
}
```

```nabi
let s = ~0u8;        //→ 255
let t = ~0i32;       //→ -1
```

对整数类型，`~x` 与 `!x` 的结果相同。但 `BitNot` 只为 `i*` / `u*` 和 `int`（`~x == -x - 1`）实现，不为 `bool` 实现，所以 `~true` 是编译错误。推荐的写法是：逻辑非用 `!`，想表明按位取反的意图时用 `~`。

## 2.3.3. 位运算 trait

### `BitAnd`：按位与（`&`）

按位与 trait 定义如下。

```nabi
#[lang("bitand_trait")]
trait BitAnd<Rhs = Self> {
    type Output;

    #[infix("&")]
    fn bitand(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 0xF0i32 & 0x0Fi32;   //→ 0x00
let s = 0xFFi32 & 0x0Fi32;   //→ 0x0F
let b = true & false;         //→ false (bool also has a BitAnd impl)
```

> [!NOTE]
> `&&` 与 `&` 不同。`&&` 是短路逻辑与；`&` 是按位与。
> 对 bool 而言两者结果相同，但求值时机不同。

### `BitOr`：按位或（`|`）

按位或 trait 定义如下。

```nabi
#[lang("bitor_trait")]
trait BitOr<Rhs = Self> {
    type Output;

    #[infix("|")]
    fn bitor(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 0xF0i32 | 0x0Fi32;   //→ 0xFF
```

### `BitXor`：按位异或（`^`）

按位异或 trait 定义如下。

```nabi
#[lang("bitxor_trait")]
trait BitXor<Rhs = Self> {
    type Output;

    #[infix("^")]
    fn bitxor(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 0xFFi32 ^ 0x0Fi32;   //→ 0xF0
let s = 0b1010 ^ 0b1100;     //→ 0b0110
```

### `Shl`：左移（`<<`）

左移 trait 定义如下。

```nabi
#[lang("shl_trait")]
trait Shl<Rhs = Self> {
    type Output;

    #[infix("<<")]
    fn shl(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 1i32 << 4;     //→ 16
let s = 0xFFi32 << 24; //→ 0xFF000000
```

移位位数为负或大于等于位宽时，移位会触发 panic（`attempt to shift left with overflow`，`>>` 则为 `right`）。与 `+`、`-`、`*` 的溢出不同，这一检查不取决于 `-C overflow-checks`：在所有优化级别下都会进行。要让位数对位宽取模，请使用 `wrapping_shl` / `wrapping_shr`。

```nabi
let r = 1i32.wrapping_shl(40);  // explicit: shifts by 40 % 32 = 8
```

### `Shr`：右移（`>>`）

右移 trait 定义如下。

```nabi
#[lang("shr_trait")]
trait Shr<Rhs = Self> {
    type Output;

    #[infix(">>")]
    fn shr(self, rhs: Rhs) -> Output;
}
```

```nabi
let r = 256i32 >> 4;  //→ 16
let s = -1i32 >> 1;   //→ -1 (signed = arithmetic shift, sign extension)
let t = u32::MAX >> 1;  //→ 0x7FFFFFFF (unsigned = logical shift)
```

有符号整数使用算术右移（符号扩展）；无符号整数使用逻辑右移。

## 2.3.4. 索引 trait

索引和切片是**语言语法**（[refs-lang 3.6](../../refs-lang/003-expressions/306-indexing-and-slicing.md)），但实际的分派经过本节的 trait。`Index`、`IndexSet`、`Sliceable` 和 `AxisIndexed` 定义在 `core::index` 模块中。结构体或枚举上的 `xs[i]` 与 `xs[i] = v` 调用 `index` / `index_set`；定长数组直接索引，不经过调用。

### `Index`：单元素读取（`arr[i]`）

`Index` trait 定义如下。

```nabi
#[lang("index_trait")]
trait Index<I> {
    type Output;

    fn index(self, idx: I) -> Output;
}
```

```nabi
let xs: List<i32> = [10, 20, 30];
let v = xs[1];        //→ 20
let s: str = "hello";
let c = s.chars().next();   //→ 'h' (char | none); str has no Index (2.9.8)
```

#### 边界检查

边界的处理方式如下。越界的索引（`xs[100]`）触发 panic（运算符不抛出错误）。有符号整数的负索引从末尾计数（`xs[-1]` 是最后一个元素，[refs-lang 3.6.1](../../refs-lang/003-expressions/306-indexing-and-slicing.md#361-索引arri)）。如果 `len + i < 0`，则触发 panic。

要得到 `T | none` 结果而不是 panic，请使用 `xs.get(i)`。

```nabi
let v = xs.get(100);  //→ none
```

### `IndexSet`：单元素写入（`arr[i] = v`）

`IndexSet` trait 定义如下。

```nabi
#[lang("index_set_trait")]
trait IndexSet<I, V> {
    fn index_set(self, idx: I, value: V);     // collections are reference handles, so self
}
```

```nabi
let xs: List<i32> = [10, 20, 30];
xs[1] = 99;           // IndexSet::index_set(xs, 1, 99)
xs[1];                //→ 99
```

值类型 `V` 是 trait 参数而不是关联类型，所以同一个索引可以存入几种值，由值的类型选择实现：`Array` 可以存入一个标量来填满所选部分（`a[:, 0] = 0.0`），也可以存入一个数组并扩展到所选形状（`a[:, 0] = col`），两者都通过 `IndexSet<(SliceArg, isize), _>`。

它与 `Index` 分开，是因为只读容器（例如元组的不可变视图）也必须能实现 `Index`。因此 `IndexSet` 是单独选择加入的。

`IndexSet` 越界时同样触发 panic。没有检查式写入：想跳过越界索引的写入要先检查（`if i < xs.len() { xs[i] = v }`），而读取有 `xs.get(i) -> T | none`。

### `Sliceable`：取子区间（`s[a:b]`、`s[a:b:step]`）

切片 trait 定义如下。trait 名为 `Sliceable`，得到的视图类型为 `Slice<T>`（[2.9.7](209-collections.md#297-slicet视图)）。名字分开，是因为 prelude 和 `index` 模块把这两个名字放在同一个命名空间中，一个名字无法同时指代两者。

```nabi
#[lang("slice_trait")]
trait Sliceable<R> {
    type Output;

    fn slice(self, range: R) -> Output;
}
```

`xs[a:b]` 即 `xs.slice(a..b)`，`xs[a:b:k]` 即在按 Python `slice.indices` 计算出的区间上做 `xs.slice(..).step(k)`（[refs-lang 3.6.2](../../refs-lang/003-expressions/306-indexing-and-slicing.md#362-切片arrstartend)）。语义与 Python 切片一致：边界被截取到长度之内，越界的边界从不触发 panic，`xs` 只求值一次。`xs[a..b]` 与 `xs[..]` 也一样。每个标准的 `Sliceable<Range<usize>>` 实现都以相同方式截取区间：先把终点截到长度 `n`，再把起点截到终点，因此 `xs[5:100]` 和 `xs.slice(9..2)`（空）从不触发 panic。用户实现应当以同样的方式截取。

```nabi
let xs: List<i32> = [1, 2, 3, 4, 5];
let s = xs[1:3];       //→ Slice<i32> view of [2, 3]
let r = xs[::2];       //→ [1, 3, 5] (step=2)
let v = xs[::-1];      //→ [5, 4, 3, 2, 1] (reversed)

let str_part = "hello"[1:4];  //→ "ell" (new str)
```

标准库为 `List<T>`、`Slice<T>`、`SliceMut<T>`、`[T; N]`、`str` 和 `StrBuf` 实现了 `Sliceable<Range<usize>>`。`List` / `Slice` / 数组返回 `Slice<T>` 视图，`SliceMut<T>` 返回 `SliceMut<T>` 视图（[2.9.7a](209-collections.md)）；`str` / `StrBuf` 在检查 UTF-8 边界后返回新的 `str` 副本。负边界从末尾计数，然后再截取；不支持切片赋值。需要独立的副本时，请使用 `xs[1:3].to_list()`。

### `AxisIndexed`：按轴索引的类型

```nabi
#[lang("axis_indexed_trait")]
trait AxisIndexed {}
```

这是一个没有方法的标记 trait。在实现它的类型上的 `x[..]` 中，方括号里每个整数部分都是 `isize` 位置（其他整数类型会转换，字面量本身就是 `isize`），`none` 是 `NewAxis`，与其他部分并列的 `..` 是 `Rest`（[refs-lang 3.6.3](../../refs-lang/003-expressions/306-indexing-and-slicing.md#363-多轴索引)），因此一组基于 `isize` 的 `Index` / `IndexSet` 实现即可服务所有调用。`Array` 实现了它（[2.9.14](209-collections.md#2914-arrayt-const-n-usizen-维数组)）。

## 2.3.5. trait 实现矩阵

原始类型的每个 ops trait 实现都带有 `#[intrinsic("nabi.OP.TYPE")]`，并直接绑定到编译器后端的 PrimOp（[0.3](../000-meta/003-intrinsics.md)）。这意味着：

- 原始类型操作数上的运算符（`a + b`）直接降级为机器操作，没有方法调用。
- 按名字调用（`a.add(b)`、`Add::add(a, b)`）也降级为同一个机器操作。

### 算术 trait

| 类型                 | 模块             | 行为                                                            |
|----------------------|------------------|-----------------------------------------------------------------|
| `i8`..`i64`, `isize` | `core::num` | `nabi.add.i32` / `nabi.sub.i32` / `nabi.rem.i32` / `nabi.mod.i32` ... |
| `u8`..`u64`、`usize` | `core::num` | `nabi.add.u32` / ...（无符号系列，`Modulo` ≡ `Rem`）               |
| `f32`、`f64`         | `core::num` | `nabi.add.f32` / `nabi.add.f64` / `nabi.mod.f64`（向下取整）       |
| `int`                | `core::num` | 自动提升逻辑                                                    |
| `float`              | `core::num` | （同上：自动提升）                                              |

### 位运算 trait

| 类型               | 模块             | intrinsic                                                           |
|--------------------|------------------|---------------------------------------------------------------------|
| `i*`, `u*`         | `core::num` | `nabi.and.OP`, `nabi.or.OP`, `nabi.xor.OP`, `nabi.shl.OP`, `nabi.shr.OP` |
| `bool`             | `core::num` | `nabi.and.bool`、`nabi.or.bool`、`nabi.xor.bool`（无移位）              |
| `int`              | `core::num` | 在符号扩展后的值上按二进制补码运算；`Shl<u32>` / `Shr<u32>`（右侧为 `u32`） |

`f32` 和 `f64` 不实现 BitAnd 等，因为这些运算对它们没有意义。

### 索引 trait

| 类型         | 定义者                                                                             |
|--------------|------------------------------------------------------------------------------------|
| `List<T>`    | 标准库                                                                             |
| `Dict<K, V>` | 标准库（I = K）                                                                    |
| `[T; N]`     | 编译器合成（原始数组）                                                             |
| `str`        | 标准库（仅 Slice；`Index<usize>` 未定义，拒绝直接按字节访问）                      |
| `Slice<T>`   | 标准库（仅 `Index`）                                                               |
| `SliceMut<T>` | 标准库（`Index`、`IndexSet`）                                                     |
| `Deque<T>`   | 标准库（`Index<usize>`、`IndexSet<usize, T>`）                                     |
| `Tuple`      | 编译器合成（`.0`、`.1` 形式）；`Index` 未定义（只能在编译期访问元组）              |

## 2.3.6. 用户定义的 ops

标准库之外的用户可以通过 `impl ops::Add for MyType` 等自由实现这些 trait。trait 分派随后会调用 `MyType::add`。

```nabi
struct Vec3 { x: f64; y: f64; z: f64; }

impl ops::Add for Vec3 {
    type Output = Vec3;

    fn add(self, rhs: Vec3) -> Vec3 {
        Vec3 {
            x: self.x + rhs.x,
            y: self.y + rhs.y,
            z: self.z + rhs.z,
        }
    }
}

let a = Vec3 { x: 1.0, y: 2.0, z: 3.0 };
let b = Vec3 { x: 0.5, y: 0.5, z: 0.5 };
let c = a + b;        //→ Vec3 { x: 1.5, y: 2.5, z: 3.5 }
```

但**禁止**在用户 ops 上附加 `#[intrinsic]`（refs-standard-libraries 0.3.5），因为函数体才是权威。

## 2.3.7. trait 之间的关系：`Output` 一致性

在组合多个 trait 的表达式（`a + b * c`）中，`Output` 类型必须一致。

```nabi
let r = a + b * c;
//   = Add::add(a, Mul::mul(b, c))
//   requires: <typeof(b) as Mul<typeof(c)>>::Output compatible with Add's Rhs
```

标准库中所有原始算术实现都使用 `Output = Self`。用户类型可以自由定义，但为了对工具友好（例如编译器错误消息），推荐使用 `Output = Self`。

## 2.3.8. 与广播 trait 的关系

`a + b` 分派到 `Add::add`，`a .+ b` 分派到 `DotAdd::dot_add`，因此这两种操作由不同的 trait 处理。普通的算术类型（Vec3 等）通常两者都实现。详见 [2.6 broadcast](206-broadcast.md)。

## 2.3.9. 逻辑 trait：`LogicalAnd`（`&&`）/ `LogicalOr`（`||`）

`&&` 和 `||` 与其他运算符一样连接到 trait 方法。优先级和结合性由 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 表固定。

```nabi
#[lang("logical_and_trait")]
trait LogicalAnd<Rhs = Self> {
    #[infix("&&")]
    fn logical_and(self, rhs: Rhs) -> bool;
}

#[lang("logical_or_trait")]
trait LogicalOr<Rhs = Self> {
    #[infix("||")]
    fn logical_or(self, rhs: Rhs) -> bool;
}
```

标准库只为 `bool` 实现这两个 trait。当两个操作数都是 `bool` 时，编译器通过 `logical_and_trait` / `logical_or_trait` 槽识别这一实现，并把它降级为**短路**分支，而不是方法调用：`a` 为 `false` 时，`a && b` 不对 `b` 求值。

> [!WARNING]
> 如果用户类型实现了 `LogicalAnd` / `LogicalOr`，`a && b` 就成为普通的 trait 方法调用，因此**两个操作数都会被求值**（没有短路）。这与广播形式 `.&&` / `.||`（[2.6](206-broadcast.md)）的规则相同。语言只对 `bool` 操作数保证短路。

## 2.3.10. Unicode 数学运算符 trait

[refs-lang 1.10.3](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md#unicode-数学运算符) 中的 Unicode 运算符连接到以下 trait。每个方法都有 ASCII 名字，因此也可以不用运算符而以方法的形式调用。优先级由 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 表固定。`÷ ≡ ≠ ≤ ≥` 没有自己的 trait 或中缀绑定：词法分析器把它们读作 `/ == != <= >=`，因此它们分派到上面的 `Div` 和 [2.5 cmp](205-cmp.md) 的比较 trait。

```nabi
trait Cross<Rhs = Self> {               // a × b (level 10)
    type Output;
    #[infix("×")]
    fn cross(self, rhs: Rhs) -> Output;
}

trait Dot<Rhs = Self> {                 // a ⋅ b (level 10)
    type Output;
    #[infix("⋅")]
    fn dot(self, rhs: Rhs) -> Output;
}

trait Compose<Rhs> {                    // f ∘ g (level 11), (f ∘ g)(x) = f(g(x))
    type Output;
    #[infix("∘")]
    fn compose(self, rhs: Rhs) -> Output;
}

trait Sqrt {                            // √x (prefix unary)
    type Output;
    #[prefix("√")]
    fn sqrt(self) -> Output;
}

trait Contains<Item> {                  // a ∈ s, a ∉ s (level 4)
    #[infix("∈", swap)]
    fn contains(self, item: Item) -> bool;
    #[infix("∉", swap)]
    fn not_contains(self, item: Item) -> bool { !self.contains(item) }
}

trait Subset<Rhs = Self> {              // a ⊂ b, a ⊆ b (level 4)
    #[infix("⊂")]
    fn is_proper_subset(self, rhs: Rhs) -> bool;
    #[infix("⊆")]
    fn is_subset(self, rhs: Rhs) -> bool;
}

trait Union<Rhs = Self> {               // a ∪ b (level 9)
    type Output;
    #[must_use]
    #[infix("∪")]
    fn union(self, rhs: Rhs) -> Output;
}

trait Intersect<Rhs = Self> {           // a ∩ b (level 10)
    type Output;
    #[must_use]
    #[infix("∩")]
    fn intersection(self, rhs: Rhs) -> Output;
}
```

`∈ ∉` 的容器在右侧，因此用 `swap` 连接（[refs-lang 6.7.2](../../refs-lang/006-meta-system/607-operator-magic.md#672-参数)）。`a ∈ xs` 即 `xs.contains(a)`。`in` / `!in` 是它们的 ASCII 写法（[refs-lang 3.2.3](../../refs-lang/003-expressions/302-precedence-and-associativity.md#323-优先级与结合性表)）：`x in 0..=9`、`k !in d`。

| trait       | 标准库实现                                            |
|-------------|-------------------------------------------------------|
| `Sqrt`      | `f32`、`f64`（`#[intrinsic("nabi.sqrt.TYPE")]`）        |
| `Contains`  | `List<T>`、`Set<T>`、`Dict<K, V>`（键）、`str`（子串或 `char`），以及所有区间：`Range<T>`、`RangeInclusive<T>`、`RangeFrom<T>`、`RangeTo<T>`、`RangeToInclusive<T>`（`T: PartialOrd`）、`RangeFull`（任意项） |
| `Subset`, `Union`, `Intersect` | `Set<T>`                           |
| `Compose`   | 函数类型 `fn(B) -> C` 与 `fn(A) -> B`                 |
| `Cross`、`Dot` | 标准库中没有实现；由向量类型实现                   |

`Dot` 和 [2.6](206-broadcast.md) 的逐元素 trait 都位于 `core::ops`。

## 2.3.11. 集合类型的运算符

除 `∪` 和 `∩` 之外，`Set` 还实现了 `BitOr`、`BitAnd`、`Sub` 和 `BitXor`（`a | b`、`a & b`、`a - b`、`a ^ b`：并集、交集、差集、对称差），每个都返回新的集合。`List<T>` 实现了 `Add`（`xs + ys`，返回新的列表）。见 [2.9.13](209-collections.md#2913-默认值运算符与构造函数)。

## 2.3.12. 调用值：`Call`

对不是函数的值进行调用 `v(args)`，会分派到 `Call`（[refs-lang 6.7.14](../../refs-lang/006-meta-system/607-operator-magic.md#6714-调用值opscall)）。

```nabi
#[lang("call_trait")]
trait Call<Args> {
    type Output;

    fn call(self, args: Args) -> Output;
}
```

`Args` 是单个实参的类型，多个实参时是元组（`v(a, b)` 即 `v.call((a, b))`），没有实参时是 `()`。一个类型可以为多个 `Args` 实现它（插值函数可以同时实现 `Call<f64>` 和 `Call<Vector<f64>>`），由实参选择。`fn` 值和闭包直接调用，没有对应的实现。

```nabi
struct Poly { c: List<f64>; }

impl ops::Call<f64> for Poly {
    type Output = f64;
    fn call(self, x: f64) -> f64 { self.c.iter().rev().fold(0.0, |acc: f64, k: f64| -> f64 { acc * x + k }) }
}

let p = Poly { c: [1.0, 0.0, 2.0] };
p(3.0);     //→ 19
```
