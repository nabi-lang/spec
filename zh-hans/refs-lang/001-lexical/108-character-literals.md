# 1.8. 字符字面量

字符字面量是表示单个码位或单个字节的词法单元。

## 1.8.1. 三种形式

```
char_lit    ::= "'" char_item "'"
              | "c'" byte_item "'"
              | "b'" byte_item "'"
char_item   ::= <any unicode codepoint except "'" or "\\"> | escape_seq
byte_item   ::= <any ASCII byte except "'" or "\\"> | byte_escape
byte_escape ::= "\\x" hex_digit hex_digit | escape_seq
```

### 普通字符：`'A'`

```nabi
'A'
'세'
'\n'
'\u{1F600}'
```

一对单引号（`'`）中必须恰好包含一个码位。转义序列原样遵循[字符串字面量](107-string-literals.md)中的表：`\\`、`\'`、`\"`、`\n`、`\r`、`\t`、`\0`、`\x`、`\u{...}` 等。`'\x41'` 这样的单字节形式也是合法的，其结果是 ASCII 范围内的单个码位。反之，像 `'AB'` 这样包含两个或更多字符，或者写出空的 `''`，在词法阶段就是错误。

这种形式的字面量是 `char`（Unicode 标量值，编译器原语）。其方法由 [标准库 2.15](../../refs-standard-libraries/200-core/215-string.md) 定义。

### C 兼容字符：`c'A'`

```nabi
c'A'
c'\n'
c'\x7F'
```

这种形式由 `c` 前缀和一对单引号组成；转义序列原样遵循[字符串字面量](107-string-literals.md)中的表。内容的值必须位于 `U+0000`-`U+00FF` 之内；超出这一范围是词法错误。例如 `c'세'` 是错误，因为 `'세'` 是 `U+C138`，无法放进一个字节。直接写出字符来填充单字节范围时，由于源代码是 UTF-8，只能使用 ASCII 字符；非 ASCII 的单字节值（`U+0080`-`U+00FF`）必须用 `\xHH` 或 `\u{H...}` 转义写出。

这种形式求值为原语类型 `c_char`，即外部函数接口（[FFI](../000-meta/007-glossary.md#ffi-foreign-function-interface)）的 8 位字符类型。

### 字节：`b'A'`

```nabi
b'0'          // 48u8
b'\n'         // 10u8
b'\xFF'       // 255u8
```

这种形式由 `b` 前缀和一对单引号组成，内容和转义与 `c'x'` 相同：一个直接写出的 ASCII 字符，或值不超过 `\xFF` 的转义。`b'é'` 这样的非 ASCII 字符是词法错误，其消息会提示写成 `\xHH`。该字面量是类型为 `u8`、值为该字节的整数字面量，所以凡是 `u8` 可用的地方它都可用，包括模式和模式区间（`b'0'..=b'9' => ..`）。它是字节串 `b"..."`（[1.7](107-string-literals.md)）在单字节上的对应物。

## 1.8.2. 为什么要分成几种

Nabi 没有给同一种词法单元形式（`'X'`）赋予多种含义，而是用前缀显式地把它们分开。Unicode 意义上的字符与单个字节（C [ABI](../000-meta/007-glossary.md#abi-application-binary-interface) 的 `c'A'`、原始数据的 `b'A'`）语义不同；如果把它们归在同一种写法之下，调用兼容函数时就无法表明意图。`c` 前缀还留下了一个可见的信号，表明这段代码“涉及 FFI”。

## 1.8.3. 强制的长度检查

字符字面量必须恰好包含一个码位（普通字符），或者恰好包含一个字节（C 兼容字符和字节）。这一长度检查在词法阶段进行，不匹配时立即报错。

这一决定排除了如下歧义。组合序列（`e\u{0301}` = `é`）能放进一个字符字面量吗？不能：它是两个码位。这样的文本应当放进字符串字面量。同样，在字素簇层面上“人眼看来是一个字符”的东西，被当作字符串层面的概念，而不是字符字面量。

这一简化让“字符 = 一个码位”这一定义从词法阶段起始终保持一致。
