# 1.6. 数字字面量

本节介绍直接写在源代码中的数字字符序列的切分规则，以及确定每个字面量类型的规则。

## 1.6.1. 基本形式

数字字面量的语法定义如下。

```
numeric_lit ::= int_lit | float_lit
int_lit     ::= dec_lit | hex_lit | bin_lit | oct_lit
dec_lit     ::= dec_digit ("_"? dec_digit)*
hex_lit     ::= ("0x" | "0X") hex_digit ("_"? hex_digit)*
bin_lit     ::= ("0b" | "0B") bin_digit ("_"? bin_digit)*
oct_lit     ::= ("0o" | "0O") oct_digit ("_"? oct_digit)*
float_lit   ::= dec_lit "." dec_digit_seq? exponent?
              | dec_lit exponent
exponent    ::= ("e" | "E") ("+" | "-")? dec_digit_seq
dec_digit_seq ::= dec_digit ("_"? dec_digit)*
dec_digit   ::= [0-9]
hex_digit   ::= [0-9a-fA-F]
bin_digit   ::= [01]
oct_digit   ::= [0-7]
```

### 进制

支持的进制及其写法如下。

| 进制        | 前缀           | 允许的数字                | 示例           |
|-------------|----------------|---------------------------|----------------|
| 十进制      | 无             | `0`-`9`                   | `42`, `1024`   |
| 十六进制    | `0x` 或 `0X`   | `0`-`9`, `a`-`f`, `A`-`F` | `0xFF`, `0X1a` |
| 二进制      | `0b` 或 `0B`   | `0`, `1`                  | `0b1010`       |
| 八进制      | `0o` 或 `0O`   | `0`-`7`                   | `0o755`        |

非十进制只用于整数字面量；浮点字面量只允许十进制写法。

带前导零的十进制整数字面量（例如 `0123`）是编译错误。Nabi 不采用 C 和 Java 中常见的“前导 0 = 八进制”规则，而把 `0123` 读作十进制 `123` 又会让熟悉该规则的人感到意外；八进制用 `0o` 前缀书写。帮助信息会给出表示八进制的 `0o123` 和表示十进制的 `123`。`0` 本身以及浮点字面量（`0.5`、`00.5`）没有问题。

### 数字分隔符

为了可读性，可以在数字之间放置下划线（`_`）。

```nabi
1_000_000
0xFFFF_FFFF
0b1010_0101
3.141_592_653
```

下划线的规则如下。

- `_` 只能出现在数字之间；第一个或最后一个字符不得是 `_`。
- `_` 不得紧跟在进制前缀之后（`0x_FF`），也不得紧挨在小数点之前（`1_.0`）。`1._0` 不是浮点字面量：它被切分为 `1` 后跟字段访问 `._0`，而 `i32` 没有这个字段。
- 连续的下划线（`1__000`）会被拒绝。
- `_` 在求值时被忽略，所以 `1_000` 与 `1000` 表示同一个值。

### 浮点形式

如果字面量符合以下两种形式之一，它就是浮点字面量；否则它是整数字面量，或者被当作分开的词法单元处理。

```
digit+  '.'  digit*  exponent?         // 1.5, 1., 1.5e10, 0.5
digit+              exponent           // 2e10  (an exponent without a point is still floating-point)
```

浮点字面量的小数点之前必须有数字。应写作 `0.5`；`.5` 不是浮点字面量。`.` 后跟数字总是元组索引（`t.0`、`t.5`）。

指数部分（`exponent`）由 `e` 或 `E`、可选的符号（`+` 或 `-`）以及一个或多个十进制数字组成。因此 `1.`、`0.5`、`1.5e10`、`2e-3` 和 `6.022e23` 都是合法的浮点字面量。两侧都为空的单独小数点（`.`）不是浮点字面量，而是一个单独的词法单元。

#### 区分 `1.` 与 `1.foo`

形式 `digit+ '.'`（`1.`）只有在小数点之后没有开始一个标识符时才被切分为浮点数。各种情况如下。

| 输入                                        | 切分结果                                                |
|---------------------------------------------|---------------------------------------------------------|
| `1.5`                                       | 一个浮点词法单元 `1.5`                                  |
| `1.`（后跟结尾/空白/标点）                  | 一个浮点词法单元 `1.`                                   |
| `1.foo`                                     | 三个词法单元：整数 `1`、`.`、标识符 `foo`               |
| `1 .foo`                                    | 同上（空白不影响词法单元的切分）                        |
| `1..2`                                      | 三个词法单元：整数 `1`、`..`、整数 `2`（`..` 是更长的匹配） |
| `1.+2`                                      | 三个词法单元：浮点 `1.`、`+`、整数 `2`                  |

一句话概括：在数字中间，如果 `.` 之后的第一个字符是 `XID_Start` 或另一个 `.`，这个 `.` 就不属于浮点字面量；否则（标点、运算符字符、输入结束）它被并入浮点字面量。

## 1.6.2. 类型后缀

字面量之后的后缀指定该字面量求值为哪个具体类型。

```nabi
42i32
3.14f64
2i              // a package's own suffix (6.5), e.g. an imaginary unit
0xFFu8
1_000_000i64
```

后缀格式遵循以下规则。后缀不带空白地紧接在字面量最后一个字符之后，并且只由标识符字符（`XID_Continue`）组成。在词法上它作为一个词法单元的一部分保留：词法分析器把数字主体和后缀字符串归入同一个词法单元。

因此后缀是一个名称：它以字母或 `_` 开头，第一个字符之后可以含有数字（`x2`）。紧贴在数字后面的符号绝不是后缀。`95%` 是 `95` 后跟取余运算符，所以其后没有操作数的 `95%` 是一个错误，说明百分比应写成后缀名称（`95pct`）；`5°` 和 `5$` 中的符号不是词法单元，它们是指出应写的后缀（`5deg`、`5usd`）的错误。在十进制字面量上，`e` / `E` 开始指数，`_` 分隔数字，所以没有后缀能以二者之一开头（[6.5.7](../006-meta-system/605-literal-magic.md#657-user-defined-literals)）。

数字类型名后缀（`i8` `i16` `i32` `i64` `isize` `u8` `u16` `u32` `u64` `usize` `c_char` `f32` `f64`）由语言定义，把字面量的类型设为该类型。后缀 `f16` 和 `bf16` 把它设为标准库的 16 位浮点类型（[stdlib 2.1.4](../../refs-standard-libraries/200-core/201-numbers.md#f16-and-bf16---16-bit-storage-floats)）。`i128` / `u128` 是保留的：Nabi 没有 128 位整数（`int` 可以容纳任意大小），带其中任一后缀的字面量是一个错误，会指出应改写的 64 位后缀或 `int`。浮点后缀也可以附加在十进制整数形式上（`1f64`、`2bf16`）。浮点字面量从其十进制值向其类型舍入一次，舍入到最近值，平局时取偶数。在十六进制字面量中 `f` 是数字，所以 `0x1f32` 是十六进制值 `0x1F32`，而不是 `0x1` 加后缀 `f32`。其他后缀（`2i` 等）由包通过 [`#[literal(...)]` 魔法](../006-meta-system/605-literal-magic.md)注册的处理器解释。

## 1.6.3. 无后缀字面量

无后缀字面量（`42`、`3.14`）的类型由期望类型决定。

- 整数字面量：如果期望类型是整数或浮点类型，它就是该类型。没有期望类型时，它是其默认类型。
- 浮点字面量：如果期望类型是浮点类型，它就是该类型。没有期望类型时，它是其默认类型。它不能出现在期望整数类型的位置。
- 任意精度的 std 类型 `int` 和 `float` 也算在内：整数字面量可以取 `int` 或 `float`，浮点字面量可以取 `float`。这些类型可以容纳任何值，所以不做范围检查。
- **默认类型**。无后缀字面量的默认类型是 `i64`（整数）或 `f64`（浮点），除非它填充的是一个声明了默认值（[2.10.5](../002-types/210-generics.md#2105-defaults)）、且字面量能够取该默认值的省略类型参数：这时该默认值就是它的默认类型。字面量能取的默认值就是它作为期望类型时能取的类型：对两种字面量是浮点类型，对整数字面量还有整数类型。在 `struct Vec3<T = f32>` 下，`Vec3::new(1.0, 2.0, 3.0)` 是 `Vec3<f32>`，`Vec3::new(1, 2, 3)` 也是；在 `x: f64` 时，`Vec3::new(x, 2.0, 3.0)` 是 `Vec3<f64>`，因为 `x` 确定了 `T`。默认类型仍然只是默认值：期望类型或后面的使用会先确定字面量（`let v: DVec3 = Vec3::new(1.0, 2.0, 3.0)` 是 `Vec3<f64>`）。
- 字面量必须取一个它不适合的已声明默认值时是错误，与在有类型的槽中一样（在 `Buf<T = u8>` 下的 `Buf::new(300)`：请写 `Buf::<u16>::new(300)` 或 `300i64`）。一个字面量填充了两个默认值不同的参数时，是同时指出二者的错误；请在声明处写出它的类型。
- 整数字面量绝不填充没有任何整数类型满足其约束的参数（在 `T: FloatingPoint` 下的 `lerp(0, 10, 1)` 是错误，其帮助信息写出 `lerp(0.0, 10.0, 1.0)`）。
- 在二元运算中，如果一个操作数的类型在静态上已确定，该类型就成为字面量一侧的期望类型。
- 整数字面量位于期望浮点类型的位置、而该浮点类型无法精确表示其值时，是编译错误（`let f: f32 = 16777217;`）。
- 如果期望类型是含有整数类型成员的和类型，整数字面量取该整数类型（`let v: i64 | f64 = 1;` 中的 `1` 是 `i64`）。
- 如果该和类型有多于一个整数成员和一个浮点成员，无后缀整数字面量是有歧义的，属于编译错误（`let v: u16 | u8 | f32 = 1;`）：请写后缀 `1u16` 或 `1u8`，或为浮点成员写 `1.0`。没有浮点成员时，这样的字面量是 `i64`，并像任何 `i64` 值一样与该和类型进行检查。
- 无后缀字面量之间的算术（`1 + 2`、`-1`、`2 * (3 + 4)`）在遇到有类型的操作数或期望类型之前保持无类型。一旦遇到，整个表达式取该类型；如果始终没有遇到，它取其默认类型（见上）。
- 如果 `if` / `else` 的一个分支，或没有槽确定其类型的 `match` 的一个分支，是无后缀整数字面量，而另一个分支具有整数类型，该字面量随那个类型。
- 没有期望类型、元素全部是无后缀数字字面量（允许 `-`，也允许嵌套的列表字面量）且其中至少一个是浮点字面量的列表字面量，是浮点数列表：其中的整数字面量按浮点字面量定型（`[0, 1.5]` 即 `[0.0, 1.5]`，`[[0, 1], [0.5, 2]]` 是 `List<List<f64>>`）。这是字面量的定型，而不是值的转换：浮点字面量旁边的整数类型值（`n: i64` 时的 `[n, 1.5]`）仍然是类型不匹配。
- 在 C 可变参数函数（[8.6](../008-abi/806-calling-convention.md)）的 `...` 位置上，无后缀整数字面量是 `i32`（C 的 `int`）。

期望类型来自 `let` 的类型标注、实参位置上的参数类型、返回位置上的返回类型，以及上面的二元运算规则。

由无标注 `let` 绑定的字面量在其声明处没有期望类型。它的类型是一个推断变量，由变量作用域中（块的其余部分，包括闭包）之后的使用确定，与 [5.1.7](../005-modules/501-variable-declaration.md#517-type-annotations-and-type-inference) 相同；只有在没有任何使用确定它时，才应用默认类型。

- 哪些情况算在内：初始化表达式是字面量（`let c = 0`、`let c = -1`）、字面量算术（`let n = 1 + 2`）、分支都是字面量的 `if` / `match`（`let f = if b { 1 } else { 0 }`），或初始化表达式的直接元素或实参（`let xs = [0, 0]`、`let (a, b) = (0, 1)`、`let n = Atomic::new(0)`）。
- 什么会确定它：一切能确定未定 `let` 的东西（实参、赋值、有标注的 `let`、`return`、函数体的值），以及另一个操作数类型已确定的运算符（`c += x`、`c < limit`）。
- 带字面量边界的 `for i in 0..10` 也一样：`i` 的类型来自循环体。
- 负字面量不会因其使用而变成无符号：`let i = -1; xs[i]` 保持 `i64`（从末尾开始的索引）。
- 在函数体中，每个没有期望类型的无后缀字面量从一开始就是一个整数或浮点类型变量（`{integer}` / `{float}`）。每次使用都像对待其他类型变量一样对它进行合一：实参和泛型约束（包括 `where` 子句）及其关联类型（把 `tasks.push(spawn(async { 0 }))` 放入 `List<Task<i32>>`）、闭包返回值和有标注的闭包参数、经过迭代器适配器的有类型 `collect()` 目标（`(0..4).chain(7..10).collect::<List<i32>>()`）、运算符、`if` / `match` 分支和 `break` 值、和类型槽中唯一的数字成员、类型模式、结构体约束下结构体字面量的类型实参（`B<T: Num>` 时的 `B { v: 3 }`）、隐式泛型的函数体（以 `add(1, x_i32)` 调用的 `fn add(a, b) { a + b }`），以及同类数字类型中唯一适合的 impl、trait 或运算符（`Twice` 只为 `i32` 实现时的 `9.once()`、`Foo` 实现在 `(i32, i32)` 上时的 `(1, 2).foo()`、`Wave::hi(3)`、`Div<NonZero<i32>>` 实现在 `i32` 上时的 `84 / nz`）。函数体只检查一次；在其结尾，每个没有被任何东西确定的变量取其默认类型。
- `const` 项的值、字段默认值和参数默认值各自独立地在求值之前对照其声明类型进行检查。
- 需要立即得到一个类型的使用会在该处确定变量：如果同类数字类型中恰好有一个可行，变量就是该类型；否则是其默认类型（见上）。这样的使用包括：变量的类型尚不具有的方法调用（泛型 impl 或覆盖实现的方法让它保持未定）、trait 限定调用（`Tr::f(x)`）、重载调用（`int::from(i)`）、存入 `any`，以及对值的类型检测（`v is i64`、`match v { n: i64 => .. }` 这样的类型模式）。类型检测取默认类型，所以 `let v = 3; v is i64` 是 `true`，`v is i32` 是 `false`。f-string 的插值孔不会确定它。
- 数字槽的字面量接收者具有该槽的类型（`let n: i32 = 7.max(-2)`），放入和类型的元组或列表字面量取与其形状相符的成员。
- 不会添加任何转换：绑定到整数字面量的变量绝不会变成浮点类型（`let x = 1; let f: f64 = x;` 是错误；`let f: f64 = 1;` 不是），两处想要不同类型的使用在第二处使用时是错误；对由字面量绑定的 `let`，错误会指出第一处（`` conflicting uses of `c`: `i64` here, but `i32` fixed at 16:16 ``）。帮助信息指向声明（`let c: i64 = 0` 或 `let t = 0.0`），而不是在使用处加强制转换。

```nabi
let a = 42;              // i64
let b = 3.14;            // f64
let x: f64 = 1;          // f64
let y: u8 = 200;         // u8
let r = a * 2;           // 2 is i64 (follows a)
let s: f64 = 2.0;
let t = s * 2;           // 2 is f64 (follows s)
let e: i32 = 1.5;        // ERROR: floating-point literal cannot be an integer type
let w: i64 = 7i64;
let k = w + (1 + 2);     // 1 + 2 is i64 (meets w)
let m: u8 = 2 * 100;     // 2 * 100 is u8 (expected type)
let n = 1 + 2;           // i64 (never fixed → default)
let v = if flag { 0 } else { w };   // 0 is i64 → v: i64

fn count(xs: List<i32>) -> i32 {
    let c = 0;                // i32: fixed by the body's value below
    for x in xs { if x > 0 { c += 1; } }
    c
}
let t = 0;
let big: List<u64> = [1, 2];
for x in big { t += x; }      // t: u64
let z = 0;
let f: f64 = z;               // ERROR: `z` holds an integer; write `let z = 0.0;`
```

## 1.6.4. 范围检查

超出其类型范围的字面量值是编译错误。十六进制、八进制和二进制字面量遵循与十进制相同的范围规则。

```nabi
let a: u8 = 256;         // ERROR: out of u8 range
let b = 0xFFi8;          // ERROR: 255 is out of i8 range
let c = 0xFFu8 as i8;    // OK: convert with as when a bit pattern is needed (-1)
```

只由字面量和常量组成的算术在编译期折叠；如果结果超出类型范围或除以零，是编译错误（[5.2.4](../005-modules/502-const.md#524-constant-expressions-and-the-evaluator)）。

```nabi
let m: u8 = 2 * 200;     // ERROR: 400 is out of u8 range
```

## 1.6.5. 被拒绝的形式

以下输入在词法阶段立即报错。

| 输入    | 拒绝原因                         |
|---------|----------------------------------|
| `0x`    | 十六进制前缀之后没有数字         |
| `0b`    | 二进制前缀之后没有数字           |
| `0o`    | 八进制前缀之后没有数字           |
| `1__0`  | 连续的 `_`                       |
| `1_`    | 以 `_` 结尾                      |
| `0x_FF` | `_` 紧跟在进制前缀之后           |
| `1e`    | 指数中没有数字                   |
| `0b12`  | 数字 `2` 超出二进制范围          |
| `0o8`   | 数字 `8` 超出八进制范围          |

每个错误都指向出错的字符（多余的数字、额外的 `_`、单独的 `e`），并说明应当怎样写。

`_1` 被切分为标识符而不是数字字面量，所以它不是被拒绝的输入，而是另一种类型的词法单元。

## 1.6.6. 负数

没有单独的负数字面量词法单元。`-42` 由两个词法单元组成：一元运算符 `-` 和字面量 `42`；字面量本身总是以非负形式切分。

范围检查有一个例外。紧跟在一元 `-` 之后的字面量最大允许到其类型的 `MAX + 1`，所以 `-128i8` 是 `i8` 的最小值。二元运算的操作数没有这样的例外。

```nabi
let m = -128i8;          // OK: i8::MIN
let n = a - 128i8;       // ERROR: 128 is out of i8 range
```
