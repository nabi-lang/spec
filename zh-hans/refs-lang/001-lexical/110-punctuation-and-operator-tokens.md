# 1.10. 标点与运算符词法单元

本文档介绍运算符和标点字符序列的切分规则，仅限于其词法形式。每个词法单元的含义（优先级、结合性、分派到哪个 trait 等）在 [3. 表达式](../003-expressions/README.md)中定义。

## 1.10.1. 切分原则

运算符和标点的切分分两个层次进行。第一，有一张固定词法单元表：本文档列出的字符序列总是被切分为固定的词法单元。第二，有一张扩展词法单元表：标准库通过元系统额外注册的字符序列也成为词法单元。注册机制在 [`#[infix]` / `#[prefix]` / `#[postfix]` 魔法](../006-meta-system/607-operator-magic.md)中定义。

两张表之间的冲突在注册时被拒绝；固定词法单元不能被覆盖。

## 1.10.2. 最长匹配

> [!IMPORTANT]
> 当一段输入存在多个候选词法单元时，选择最长的匹配。已注册的扩展词法单元（[1.10.4](#1104-扩展词法单元)）同样是候选。

| 输入  | 切分结果                                    |
|-------|---------------------------------------------|
| `==`  | 一个词法单元                                |
| `=`   | 一个词法单元                                |
| `= =` | 两个词法单元（由空白分隔）                  |
| `..=` | 一个词法单元（`..=` 比 `..` 长）            |
| `..`  | 一个词法单元                                |
| `<<=` | 一个词法单元（`<<=` 比 `<<` 长）            |
| `<-`  | 在注册了 `<-` 的地方是一个词法单元（比 `<` 长）；否则为 `<` 和 `-` |

## 1.10.3. 固定词法单元表

以下是语言保留的 ASCII 范围内运算符和标点字符序列的完整列表。标准库只为这些词法单元赋予含义，即映射到 trait 方法；词法单元的形式本身由这张表决定。

### 算术 / 比较 / 逻辑

```
+       -       *       /       %       %%      **
==      !=      <       >       <=      >=
&&      ||      !
&       |       ^       ~       <<      >>
```

`%` 是算术取余（Rem；符号随被除数），`%%` 是向下取整的取模（结果的符号随除数，所以除数为正时结果总在 `[0, divisor)` 之内；即 Python 的 `%`）。这两个词法单元映射到不同的 trait，含义也不同。

每个词法单元与其调用的 trait 方法之间的映射在标准库运算符规范中定义。本文档只保证词法上的切分。

`**` 是幂运算（`Pow`；`**=` 是其复合形式，`.**` 是逐元素形式）；按照最长匹配规则，`**=` 先于 `**` 匹配，`**` 先于 `*=` 或 `*` 匹配，`.**` 先于 `.*` 匹配。`^` 仍然是按位异或。`use a::**`（递归通配导入）是同一个词法单元。

### 广播（`.` 前缀）

这些是用于逐元素（广播）运算的点前缀形式。上面的每个算术、比较、逻辑、按位和移位运算符加上一个点作为前缀后，都被切分为一个独立的词法单元。

```
.+      .-      .*      ./      .%      .%%     .**
.==     .!=     .<      .>      .<=     .>=
.&&     .||
.&      .|      .^      .<<     .>>
.??
```

`.??` 是逐元素的 `??`（3.3.8）；它没有 trait。

每种形式映射到与其不带点形式不同的 trait 方法。例如，`+` 映射到 `Add::add`，`.+` 映射到 `DotAdd::dot_add`；这些映射在标准库中定义。与不带点的形式不同，带点前缀的逻辑运算符（`.&&`、`.||`）**不**短路：由于广播被降级为融合循环，两个操作数都会被求值（详见 [2.6 broadcast](../../refs-standard-libraries/200-core/206-broadcast.md)）。

#### 与浮点字面量的区分

由于 `1.` 或 `1.5` 这样的浮点字面量含有点，以下两种输入的切分取决于位置。

| 输入   | 切分结果       | 理由                                                         |
|--------|----------------|--------------------------------------------------------------|
| `1.+2` | `1.`, `+`, `2` | `.` 紧跟在数字之后，所以被并入浮点字面量                     |
| `a.+b` | `a`, `.+`, `b` | `.` 不紧跟在数字之后，所以开始一个广播词法单元               |

总之，数字字面量中间的 `.` 总是浮点字面量的一部分，其他位置的 `.` 优先构成其他词法单元形式（参见[数字字面量](106-numeric-literals.md)中 `.` 的处理规则）。

### Unicode 数学运算符

以下 Unicode 运算符也是固定词法单元。它们的优先级由 [3.2.3](../003-expressions/302-precedence-and-associativity.md#323-优先级与结合性表) 中的表给出，它们连接的 trait 由标准库 [2.3 ops](../../refs-standard-libraries/200-core/203-ops.md) 给出。

```
×       ⋅       ÷       ∘       √
≡       ≠       ≤       ≥
∈       ∉       ⊂       ⊆       ∪       ∩
```

| 词法单元 | 码位     | 含义（ASCII 命名的方法）               |
|------|------------|----------------------------------------|
| `×`  | U+00D7     | 叉积（`cross`）                        |
| `⋅`  | U+22C5     | 点积（`dot`）                          |
| `÷`  | U+00F7     | 除法（`div`，`/` 的同义词）            |
| `∘`  | U+2218     | 函数复合（`compose`）                  |
| `√`  | U+221A     | 平方根，前缀（`sqrt`）                 |
| `≡ ≠ ≤ ≥` | U+2261, U+2260, U+2264, U+2265 | `== != <= >=` 的同义词 |
| `∈ ∉` | U+2208, U+2209 | 成员关系（`contains`）             |
| `⊂ ⊆` | U+2282, U+2286 | 子集（`is_proper_subset`、`is_subset`） |
| `∪ ∩` | U+222A, U+2229 | 并集、交集（`union`、`intersection`） |

`∈ ∉` 还有 ASCII 拼写 `in` 和 `!in`，由解析器而不是词法分析器读取：在运算符位置上，词 `in` 就是 `∈`，直接写在 `in` 之前（不带空格）的 `!` 就是 `∉`。`x ! in xs` 和 Python 的 `x not in xs` 是错误，其帮助信息提示写成 `!in`。

运算符字符全部选自具有 Unicode `Pattern_Syntax` 属性的码位。`∑ ∏ ∫` 属于 `Pattern_Syntax`，但已被指定为标识符字符（[1.4.1](104-identifiers.md#数学记法配置)），所以它们不是运算符。

### 赋值 / 复合赋值

```
=       +=      -=      *=      /=      %=      %%=     **=
&=      |=      ^=      <<=     >>=
.=      .+=     .-=     .*=     ./=     .%=     .%%=    .**=
.&=     .|=     .^=     .<<=    .>>=
```

最后两行是原地广播（[3.3.7](../003-expressions/303-broadcast-operators.md#337-原地广播)）。按照最长匹配规则，`.+=` 先于 `.+` 匹配，`.**=` 先于 `.**` 匹配；`.=` 只有在其后没有第二个 `=` 时才是词法单元，所以 `.==` 仍然是逐元素比较。

复合赋值的含义（左侧求值几次、trait 映射等）在表达式规范中定义。`%%=` 是 `%%`（向下取整的取模）的复合赋值形式；按照最长匹配规则，`%%=` 先于 `%=` 或 `%` 匹配。

### 区间 / 切片

```
..      ..=     :       ::
```

`..` 和 `..=` 用于区间写法。`:` 用作切片中的位置分隔符、格式说明符的引导符，以及其他各种上下文中。`::` 是路径分隔符，用于访问模块或类型的静态项。

### 点 / 问号

```
.       ?.      ??      ?
```

`.` 用于成员或方法访问。`?.` 是穿过和类型的点访问。`??` 是用后备值填充空槽（`none`）的二元运算。最后，单独的 `?` 是后缀一元运算符：当 `T | none` 值为 `none` 时，它从外围函数中提前返回 `none`。其详细含义和脱糖规则在[错误控制流](../003-expressions/314-error-control-flow.md#31410--运算符提前返回-none)的 `?` 运算符一节中定义。

`try?` 和 `try!` 不是单个词法单元。词法分析产生关键字 `try` 和标点 `?` 或 `!` 这两个独立的词法单元，解析阶段把不带空白地附在 `try` 上的 `?` / `!` 解释为 [`try?` / `try!`](../003-expressions/314-error-control-flow.md#3143-try-与-try) 前缀运算符。带空白时，例如 `try !ready()`，它被解释为 `try` 和逻辑非 `!`。`?` 不是前缀运算符，所以 `try ? f()` 是错误，其帮助信息要求写成 `try?`。

### 单引号词法单元：字符字面量与标签

`'` 词法单元分为两种形式。第一种是 `'X'` 或 `'\X'` 形式，即单个字符（或转义）后跟闭合的 `'`，这是[字符字面量](108-character-literals.md)。第二种是 `'identifier` 形式，即没有闭合 `'` 的标识符，这是标签词法单元（参见[标签](../003-expressions/313-loop-expressions.md#3134-标签控制嵌套循环)和[带标签的块](../003-expressions/309-block-expressions.md#3910-带标签的块label---)）。

词法分析通过查看 `'` 之后的两个字节来判断。如果标识符起始字符之后跟着闭合的 `'`，就是字符；如果标识符起始字符之后跟着闭合 `'` 以外的词法单元，例如标识符字符、冒号或空白，就是标签；转义（`'\...`）总是字符字面量。标识符字符序列之后跟着 `\` 时也是字符字面量：`'e\u{301}'` 是两个码位，属于错误（E0007），而不是标签。

### Lambda / 箭头

```
|       ||      |>      ->      =>
```

`|>` 是管道：`x |> f(a)` 即 `f(x, a)`（[3.18](../003-expressions/318-pipe-expression.md)）。`|` 根据上下文用作按位或、和类型分隔符以及 lambda 参数定界符。`||` 用于逻辑或，或开始一个无参数的 lambda。`->` 是函数返回类型箭头，`=>` 是 `match` 分支箭头。

### 标点

```
(   )   [   ]   {   }
,   ;   @
```

各标点的用途如下。`( )` 用于分组、元组和调用。`[ ]` 用于索引、切片、捕获列表和数组字面量。`{ }` 用于块、复合字面量和结构体字面量。`,` 是实参或条目的分隔符，`;` 是语句终止符（参见[语句终止符](103-statement-terminator.md)）。最后，`@` 是元系统词法单元；其确切含义在第 6 章介绍。

### 属性引导符

```
#[      #![
```

`#[` 引导一个附加到其后项的属性，即外部属性。`#![` 引导一个附加到外围项或模块的属性，即内部属性。

这两个引导符各自被切分为单个固定词法单元。`#` 与 `[` 之间不得出现空白；单独的词法单元 `#` 后跟 `[` 是未定义的。

外部/内部这一对遵循与[词法结构](102-lexical-structure.md)中文档注释 `///` 和 `//!` 相同的模式。只有附加的方向不同；含义按同样的方式归类。

## 1.10.4. 扩展词法单元

在上面的固定表之外，标准库或用户可以注册的字符序列必须满足以下条件：每个字符都必须是 `Pattern_Syntax` 码位；不得含有标识符字符（[1.4.1](104-identifiers.md#141-格式)）；不得含有空白或行终止符；不得与固定词法单元相同。固定词法单元 `@` 和 `~` 是例外：注册可以绑定它们的二元位置，语言没有使用这一位置（[6.7.9](../006-meta-system/607-operator-magic.md#679-用户定义的运算符)）。

标识符字符绝不是运算符字符：任何文字的字母、其中的类字母符号（`ℱ`、`α`）、数字、撇号 `′ ″ ‴ ⁗`（它们延续名称：`f′`），以及 `∑ ∏ ∫`（Unicode 将其列为 `Pattern_Syntax`，但 Nabi 把它们作为标识符字符）。所以 `ℱx` 和 `f′` 是名称，变换或转置应写成函数（`fourier(x)`）、方法（`a.t()`）或其他符号（`a†`）。剩下可以注册的是 `Pattern_Syntax` 的其余部分：ASCII 标点、去掉撇号的通用标点区块（`† ‡ ‰`）、箭头（U+2190-21FF）、数学运算符（U+2200-22FF）、直到 U+2BFF 的技术符号、几何图形以及补充箭头和运算符区块，以及补充标点 U+2E00-2E7F。

例如 `⊕`、`⊗`、`⋆` 和 `°`。扩展词法单元的优先级随注册时用 `like` 指定的已有词法单元（[6.7.2](../006-meta-system/607-operator-magic.md#672-参数)）。

这样的序列一旦注册，词法分析器就按照 1.10.2 的最长匹配把它切分为单个词法单元：已注册的 `<-` 胜过固定的 `<`，固定的 `<=` 胜过已注册的 `<`。

以固定词法单元的起始字符（`~ @ + - * / % ^ = ! < > & | . : ?`）开头的已注册序列，例如 `<-` 或 `<~`，在注册它的包的文件中是词法单元；当其 trait 为 `pub` 时，在依赖该包的每个包的文件中（包括其测试和基准测试）也是词法单元。其他包的文件保留固定词法单元，所以那里的 `a<-1` 仍然是 `a < -1`。以其他任何字符开头的序列，例如 `⊕` 或 `$$`，在构建的每个文件中都是词法单元。

固定表之外、构建中没有任何东西注册的 `Pattern_Syntax` 字符不是词法单元：没有绑定 `⊛` 的 trait 时，`1 ⊛ 2` 是一个错误，它指出该字符（`U+229B CIRCLED ASTERISK OPERATOR`），并提示添加注册它的包或者自行注册。仅在外观上像固定词法单元的字符（`−` U+2212 之于 `-`）是一个指出应写的词法单元的错误（[1.1.2](101-source-files.md#112-字符编码)）。

格式化工具（`nabi fmt`）和语言服务器用与编译器相同的词法单元对文件进行词法分析：即在其包中注册的词法单元，以及其依赖导出的词法单元（从依赖的源代码或预构建接口中读取）。

注册时机、语法和含义在 [`#[infix]` / `#[prefix]` / `#[postfix]` 魔法](../006-meta-system/607-operator-magic.md)中定义。

## 1.10.5. 不被切分为词法单元的内容

以下元素不是词法单元，而是更大单元的一部分。`f"..."` 的 `f` 是[字符串字面量](107-string-literals.md)中的格式字符串前缀。`r"..."` 的 `r` 和 `r#"..."#` 的 `r#` 是原始字符串前缀。`b"..."` 的 `b` 是字节串前缀。`c'...'` 的 `c` 是[字符字面量](108-character-literals.md)中的 C 兼容字符前缀。附加在数字字面量上的类型后缀也属于这一类；详见[数字字面量](106-numeric-literals.md)。

这些内容不出现在本文档的词法单元表中，在它们的位置上也不会被切分为标识符或普通词法单元。
