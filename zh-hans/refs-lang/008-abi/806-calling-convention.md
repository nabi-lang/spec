# 8.6. 调用约定

本文档定义函数调用所用的寄存器与栈约定。默认遵循平台的 C [ABI](../000-meta/007-glossary.md#abi-application-binary-interface)，只说明与之不同的部分。

## 8.6.1. 默认：平台 C ABI

每个声明为 [Extern "C" 符号](805-extern-symbols.md)的函数都使用平台的 C ABI。Nabi 函数之间的调用使用相同的寄存器，但聚合类型的传递方式不同（8.6.6）。

| 平台                     | ABI                |
|--------------------------|--------------------|
| Linux x86_64             | System V AMD64     |
| Linux aarch64            | AAPCS64            |
| Linux i686               | System V i386      |
| Linux armv7              | AAPCS              |
| macOS aarch64            | AAPCS64（Apple 变体） |
| Windows x86_64           | MS x64             |
| Windows aarch64          | AAPCS64（MS 变体） |
| Windows i686             | MS x86（cdecl）     |
| FreeBSD x86_64           | System V AMD64     |
| Linux riscv64            | RISC-V LP64D       |
| riscv32（无操作系统）     | RISC-V ILP32（软浮点） |
| Linux powerpc64le        | 64 位 ELFv2       |
| Linux s390x              | s390x ELF（z/Architecture） |
| WASM                     | WebAssembly C ABI  |

`nabic` 按照与平台 C 编译器相同的规则，对跨越 C 边界传递的聚合类型（struct / tuple / array）进行分类（8.6.3），然后把每个标量放进相应的寄存器或栈槽。本规范只定义其余的差异与补充。在 WebAssembly C ABI 下，只含单个标量的聚合类型按该标量传递，其他聚合类型通过指向调用方副本的指针传递（结果经由 `sret`）；运行时的 `str` 实参按引用传递。

## 8.6.2. 寄存器实参 / 返回

直接使用各 ABI 定义的默认实参寄存器和返回寄存器。

| 平台           | 实参寄存器（整数）          | 返回（整数） |
|----------------|----------------------------|-------------|
| Linux x86_64   | rdi, rsi, rdx, rcx, r8, r9 | rax, rdx    |
| Windows x86_64 | rcx, rdx, r8, r9           | rax         |
| aarch64        | x0 ~ x7                    | x0, x1      |
| i686           | （仅栈）                   | eax, edx    |
| armv7          | r0 ~ r3                    | r0, r1      |
| riscv64        | a0 ~ a7                    | a0, a1      |
| riscv32        | a0 ~ a7                    | a0, a1      |
| powerpc64le    | r3 ~ r10                   | r3, r4      |
| s390x          | r2 ~ r6                    | r2          |

浮点值和向量值同样使用各 ABI 定义的标准寄存器（xmm0-7、vN、sN 等）。

## 8.6.3. `struct` 实参 / 返回：小 `struct` 规则

当聚合类型跨越 C 边界按值传递时（`extern "C"` 声明与定义），nabic 按照与平台 C 编译器相同的规则，依目标 ABI 对其分类，并放进该分类给出的寄存器中传递。HFA 最多占用四个 float / double 寄存器（powerpc64le 上为八个）。表中 `iN` / `[n x T]` 表示聚合类型所占的整数或浮点寄存器（或栈字），`byval` 表示栈上的副本，`sret` 表示通过调用方传入的隐藏指针写出的结果。

| 目标                                      | 分类                                                                                      |
|-------------------------------------------|-------------------------------------------------------------------------------------------|
| AAPCS64（Linux / Apple / Windows arm64）  | HFA（1 ~ 4 个相同浮点类型的元素）变为 `[n x f32]` / `[n x f64]`。其他 16 字节及以下的聚合类型变为 `i64` / `[2 x i64]`（8 字节及以下的返回值变为 `iN`）。更大的聚合类型：实参以指向调用方副本的指针传递，返回使用 `sret` |
| System V x86_64                           | 每个 eightbyte 分类为 INTEGER / SSE，放进整数 / SSE 寄存器。寄存器用尽时，整个聚合类型以 `byval` 传递。超过 16 字节：实参 `byval`，返回 `sret` |
| Windows x64                               | 大小为 1 / 2 / 4 / 8 字节的聚合类型变为 `iN`。其他：实参按引用传递（指向调用方副本的指针），返回 `sret` |
| System V i386 / Windows x86（i686）      | 聚合类型实参以 `byval` 方式放在栈上传递（4 字节对齐）。结果：在 Windows 上，1 / 2 / 4 / 8 字节的聚合类型变为 `iN`；其他聚合类型结果（System V 上则是全部）使用 `sret` |
| AAPCS 硬浮点（armv7）                     | HFA 变为 `[n x f32]` / `[n x f64]`。其他 64 字节及以下的聚合类型变为 `[n x i32]`（对齐为 4 及以下）或 `[n x i64]`；更大的以 `byval` 传递。结果：HFA 放在浮点寄存器中，4 字节及以下的聚合类型作为 `i8` / `i16` / `i32`，其他 `sret` |
| WebAssembly（wasm32）                     | 只含单个标量的聚合类型变为该标量。其他聚合类型实参以指向调用方副本的指针传递，结果使用 `sret` |
| RISC-V LP64D（riscv64）                   | 一个 struct（非 union）若由一个浮点数、两个浮点数，或一个浮点数与一个 8 字节及以下的整数构成（嵌套的 struct 和数组展平后计数），在两类寄存器都有足够空闲时，按其字段放进浮点 / 整数寄存器；含填充的 struct 和 `#[repr(packed)]` struct 同样适用，每个字段从其自身偏移读取。否则，8 字节及以下的聚合类型变为 `i64`，16 字节及以下变为 `[2 x i64]`（16 字节对齐时为 `i128`），更大的实参以指向调用方副本的指针传递。结果遵循同一规则，每类各两个寄存器；更大的使用 `sret` |
| RISC-V ILP32（riscv32）                   | 软浮点：没有浮点寄存器，因此由浮点数构成的 struct 遵循整数规则。4 字节及以下的聚合类型变为 `i32`，8 字节及以下变为 `[2 x i32]`（8 字节对齐时为 `i64`），更大的实参以指向调用方副本的指针传递。8 字节及以下的结果在 `a0` / `a1` 中返回；更大的使用 `sret` |
| ELFv2（powerpc64le）                      | HFA（1 ~ 8 个相同浮点类型的元素）变为 `[n x f32]` / `[n x f64]`。其他 8 字节及以下的聚合类型变为 `i64`，更大的变为 `[n x i64]`，经由 `r3`-`r10` 和参数保存区传递。结果：HFA 放在 `f1`-`f8` 中，8 字节及以下的聚合类型作为 `i64`，16 字节及以下作为 `[2 x i64]` 放在 `r3` / `r4` 中，其他 `sret` |
| s390x                                     | 1 / 2 / 4 / 8 字节的聚合类型变为该大小的整数（单独一个 `f32` / `f64` 字段仍为浮点数）。其他聚合类型实参以指向调用方副本的指针传递。聚合类型结果一律使用 `sret` |
| 其他目标                                  | 跨越 C 边界按值传递聚合类型是编译错误                                                     |

- `union` 与 C 的分类方式相同，按其成员（叠放在起始处）分类，而不是按其存储字节分类：当每个成员都是同一种浮点类型且成员填满整个 union 时，它是 HFA（AAPCS64、armv7、powerpc64le）；System V x86_64 按 eightbyte 合并各成员的类别（`union { f64, f32 }` 为 SSE）。RISC-V 从不把 union 当作浮点 struct 传递，s390x 把它当作与其大小相同的整数传递，wasm32 只在它只有一个成员时才把它当作标量传递。
- `f16` / `bf16` 是 C 的 `_Float16` / `__bf16`。标量放在 `f32` 会占用的那个浮点寄存器的低 16 位（AAPCS64 上为 `h`/`v`，x86_64 上为 `xmm`，armv7 上为 `s`，riscv64 上为 NaN-boxed 的 `fa`，s390x 上为 `f`）；半精度值作为聚合类型的成员时算作浮点成员：AAPCS64 有由半精度值构成的 HFA，System V 把它们算作 SSE，riscv64 把它们算作浮点字段。armv7 按整数规则传递由半精度值构成的 struct；i686 把半精度值放在栈上传递，riscv32 放在整数寄存器中。i686 上的半精度结果（C 在 `xmm0` 中返回它）、powerpc64le 和 wasm32 上的任何半精度值，以及 s390x 上的 `bf16`（C 在那里没有这种类型）都是编译错误，错误信息会提示改为传递其位（`u16`、`x.to_bits()`、`f16::from_bits`）。半精度值作为 C 可变实参同样是错误（`x.to_f64()`）。
- 8 或 16 字节（至少 2 个 lane）的 `Simd<T, N>` 就是 C 中该大小的向量（`float32x4_t`、`__m128`、`__attribute__((vector_size(16)))`）。在 AAPCS64 上，它作为参数和结果都占用一个 `v` 寄存器（寄存器用尽后占用栈上 16 字节，16 字节对齐）。在 System V x86_64 上，它占用一个 `xmm` 寄存器（寄存器用尽后占用 16 字节对齐的栈字节），并在 `xmm0` 中返回；在 Windows x64 上，向量实参按引用传递，指向一份 16 字节对齐的调用方副本，结果在 `xmm0` 中返回。其他大小、其他目标、按值传递的聚合类型中的 `Simd`，以及作为可变实参的 `Simd`，都是编译错误；`Mask<T, N>` 没有对应的 C 类型。
- 对齐与目标细节，按 C 编译器的布局：在 AAPCS64 上，16 字节对齐的 16 字节聚合类型是放在偶数寄存器对中的 `i128`（Linux 上取决于其字段是否 16 字节对齐，其自身的 `#[repr(align(16))]` 不计；Windows 上取决于其对齐；Apple 上从不如此）；Windows 上的可变参数被调用方在整数寄存器中接收其固定的同构浮点聚合类型（超过 16 字节时按引用）。在 armv7 上，偶数寄存器对与 `byval` 的对齐同样由字段决定，可变参数被调用方在内存中返回同构浮点聚合类型。在 powerpc64le 上，16 字节对齐的聚合类型从偶数双字开始。在 s390x 上，struct 只有经由嵌套 struct（而不是经由数组）才算作单独一个浮点数。在 System V x86_64 上，高位 eightbyte 为填充的过对齐聚合类型只占一个寄存器。在 i686 Windows 上，`#[repr(align(N))]` 超过 4 的聚合类型不能按值传递给 cdecl 函数（MSVC 按引用传递一份 16 字节对齐的副本，而那里的 i686 栈帧并不满足该对齐），这是一个错误，错误信息会提示改为传递指针；stdcall 函数以 `byval` 方式接收它，其 `@N` 不计入隐藏的结果指针。
- 窄整数参数和返回值（`i8` / `i16` / `u8` / `u16` / `bool` / `c_char`）上的 `signext` / `zeroext` 遵循平台 C ABI：x86_64 SysV、Apple arm64、i686、armv7、wasm32 和 RISC-V 扩展 `i8` / `i16` / `bool`；riscv64 还会对 32 位值（`i32` / `u32` / `char`）做符号扩展；armv7 和 RISC-V 对 `c_char` 做零扩展；Linux AAPCS64 和 Windows arm64 不做任何扩展；Windows x64 只扩展 `bool`。
- 函数带有栈探测，使大栈帧触碰保护页而不是跳过它：可以是内联探测，在 Windows 上则是 `__chkstk` 调用。wasm32 和 riscv32 目标没有探测。
- 同样的分类也适用于 `extern "C" fn` **定义**。定义有一个独立的 C ABI 入口点供 C 调用；来自 Nabi 的调用仍使用 Nabi 约定。
- 在 System V i386 上，`i64` / `u64` / `f64` 在聚合类型中的对齐为 4 字节（与 C 相同）。
- 此分类不适用于 Nabi 函数之间的调用（8.6.6）。只有在 Nabi 与 C 相接之处才需要它，包括接收或返回 `str` 的运行时函数（一个 16 字节的 struct；在 Windows x64 上按引用传递，见 [8.5](805-extern-symbols.md)）。

## 8.6.4. GC 对象指针：与普通指针相同

GC 对象指针使用与平台普通指针相同的 ABI 传递。不使用特殊寄存器，也不使用带标签指针。

不过，它们必须在调用前后登记到[屏障与根追踪](../007-runtime/704-barriers-and-roots.md)中的[影子栈](../000-meta/007-glossary.md#shadow-stack)里。

这一登记由编译器生成的影子栈帧的链接 / 解链完成（[8.9.12](809-lowering-control.md#8912-shadow-stack-frame)）。

## 8.6.5. 抛出函数的返回：基于值的错误传播

带有 [`throws` 签名](../004-functions/414-throws.md)的函数把错误作为返回值的一部分返回。不使用单独的栈展开机制或运行时符号。

```
fn f(args) throws (E) -> T
```

该函数的 ABI 返回类型是一个含两个字段的 `struct`：

```
Throws<T, E> = (bool, union(T, E))
; field 0: is_err (0 on success, 1 on error)
; field 1: payload. Read as T if is_err is 0, as E if 1
```

载荷是一个 union，其大小和对齐取 `T` 与 `E` 中较大者。若 `T` 为 unit，载荷只容纳 `E`。错误通道由签名区分，因此 `T` 和 `E` 可以是同一类型。对于无类型的 `throws`（`throws (any Error)`），`E` 是一个 `any Error` 值，采用与 [`any`](../002-types/202-any-slot.md) 相同的标签 + 载荷表示（[8.8](808-lowering-types.md)）。

字段 0 可以以宽于一个字节的形式存储（当载荷持有 GC 引用时为 `i32`，以便回收器把它当作和类型标签读取）；只有第 0 位有意义，当载荷至少 4 字节对齐时，偏移、大小和寄存器与 `(bool, payload)` 相同。抛出函数的 `ref` 参数（[4.7](../004-functions/407-ref-keyword.md)）的值作为返回值中由实现定义的一部分，随载体一同传递。

这个 `struct` 与其他返回值一样经由平台 C ABI 传递：在 8.6.3 的限制内放在寄存器中，超出则经由 sret。调用处的 `try` 检查字段 0 并分支；详细的降级定义见 [8.9.6](809-lowering-control.md#896-try--catch--finally-value-based-branching)。

选择这一方案的理由如下。

- 它在每个平台上工作方式相同（包括 WASM；不需要 DWARF 或平台的异常处理设施）。
- 它与[影子栈](../000-meta/007-glossary.md#shadow-stack)不冲突。错误同样经由普通返回路径离开栈帧，因此每个栈帧都正常弹出其影子栈。
- 无错误路径上的开销只是返回后的一次分支；进入 `try` 或 `catch` 没有任何开销。

## 8.6.6. nabi 到 nabi 的调用约定

Nabi 函数之间的调用把标量放在 8.6.2 的寄存器中传递。超过 64 字节的聚合类型（struct、tuple、array、`str`）按地址传递，并通过前置的结果指针返回。被调用方在入口处复制按地址传入的实参，因此调用方的值不会被修改。被调用方在复制完按地址传入的实参之后、返回之前的任何时刻，都可以通过结果指针写出结果。因此结果指针可以指向某个按地址传入的实参，但不得指向被调用方在调用期间读取的其他内存。这一点对每一次 nabi 到 nabi 的调用都成立，包括对预构建代码、导出函数和函数值的调用。直接调用还会把调用方的 `nabi_tls` 块地址（[8.3.8](803-tls-slots.md#838-form-of-compiler-emission)）作为隐藏的最后一个指针实参，放在声明的实参之后传递；函数值、`#[export_name]` Nabi 函数和 `any` 分派器不接收它（8.6.11）。较小的聚合类型按下文规则，逐个叶子放在目标的实参寄存器和结果寄存器中传递和返回。每次构建都遵循这些规则，因此任何构建（无论是否预构建）产生的代码都可以调用其他任何构建的代码。它与 8.6.3 的 C ABI 分类不同。下列规则适用于 64 字节及以下的聚合类型。

> [!NOTE]
> 按地址传递的值在内存中移动（`memcpy`），从不经由寄存器。

**实参**

- 聚合类型被拆分为其标量叶子，每个叶子占用其类别的下一个寄存器；寄存器用尽后，其余叶子放到栈上。因此一个 `str` 可能被拆分在最后一个实参寄存器和栈之间。
- AArch64：由 `i64` / `ptr` / `f32` / `f64` 构成的数组占用其类别中连续的寄存器。若剩余寄存器放不下，它整体放到栈上，且该寄存器类别的其余寄存器标记为已用。由 `i8` / `i16` / `i32` 构成的数组像 struct 一样拆分。
- armv7：含 1 到 4 个成员的同构浮点聚合类型占用连续的 VFP 寄存器，整数数组占用连续的核心寄存器，与 AAPCS 的放置方式相同；在栈上尚无其他内容时，整数块可以被拆分在 `r3` 和栈之间。
- 栈槽：在 Apple 目标上，顶层标量实参采用其自然大小和对齐，聚合类型中的 `i1` / `i8` / `i16` 叶子占用 4 字节的槽。在 i686、armv7 和 riscv32 上，一个槽为 4 字节，8 字节标量占用两个槽（在 armv7 和 riscv32 上 8 字节对齐）。在其他目标上，每个栈槽都是 8 字节。

**结果**

- AArch64：最多 8 个整数寄存器（`x0`-`x7`）和 8 个浮点寄存器（`v0`-`v7`）。更大的结果通过放在 `x8` 中传入的 sret 指针返回（该指针不被返回）。
- x86-64：最多三个整数寄存器（`rax`、`rdx`、`rcx`）；浮点结果使用 `xmm0` / `xmm1`，然后是 x87 的 `st0` / `st1`。需要第 4 个整数寄存器或第 5 个浮点寄存器的结果，通过放在 `rdi` 中传入、在 `rax` 中返回的 sret 指针返回。
- i686：最多三个整数字（`eax`、`edx`、`ecx`）和放在 `st0` 中的一个浮点值。armv7：`r0`-`r3` 和 VFP 寄存器。riscv64 / riscv32：两个 XLEN 大小的值（`a0` `a1`，在 riscv64 上还有 `fa0` `fa1`）。powerpc64le：`r3`-`r10` 和 `f1`-`f8`。s390x：`r2`-`r5` 和 `f0` `f2` `f4` `f6`。wasm32：一个值。更大的结果通过作为第一个实参传入的隐藏结果指针返回。

**Windows**

- Windows x64：整数实参和浮点实参共享四个寄存器位置（`rcx` `rdx` `r8` `r9` / `xmm0`-`xmm3`）；每个实参占用下一个位置，放在其类别的寄存器中。栈槽为 8 字节，位于调用方 32 字节的 home 区之后。sret 指针放在 `rcx` 中传递；其余结果与 x86-64 相同。
- Windows arm64：与上文的 AAPCS64 相同。C 可变参数调用把每个浮点实参放在整数寄存器中传递。

**窄整数**

被调用方不得依赖窄整数或 `bool` 实参和结果的高位；调用方可以扩展它们。编译后的代码会把传入的 `bool` 掩码到第 0 位，并重新扩展窄值。

其他模块无法到达的函数（内部的、从不作为值使用）可以使用由实现定义的约定。

对 `extern "C"` 和 `extern "nabi"` 运行时函数的调用使用 8.6.1-8.6.5 的 C ABI 规则。

## 8.6.7. 尾调用

在 `-O0` 以上，函数在尾位置对自身的调用会变为跳转到其开头（[8.7.3](807-code-generation.md#873-optimization-levels)）：以调用自身结束的递归在一个栈帧中运行。尾位置上的其他调用是普通调用。协程主体是状态机，不受影响。

## 8.6.8. 内联函数的 ABI

`#[inline]`（[内置属性](../006-meta-system/602-built-in-attributes.md)）的效果是调用本身可能消失。此时调用约定没有意义。

`#[inline(never)]` 函数总是会被调用，并遵循普通 ABI。

## 8.6.9. 实参传递的求值顺序

[参数](../004-functions/402-parameters.md)从左到右的求值顺序与调用约定相互独立。

从左到右求值是指从左边开始依次对每个实参表达式求值。每个结果由哪个寄存器或栈槽接收，是由 ABI 决定的另一个问题。

一些 C 和 C++ ABI 由于栈压入顺序而偏好从右到左求值。但 Nabi 保证从左到右的语义，编译器根据需要使用临时变量和寄存器来协调这两项要求。

## 8.6.10. 可变参数函数

[参数](../004-functions/402-parameters.md)中的 `...T` 可变参数是语言层面的可变参数，它把实参打包为单个切片视图（`Slice<T>`）（通常与 struct 实参的 ABI 相同）。它与平台的 C 可变参数（`...` 可变实参）是不同的概念。

C 可变参数函数（例如 `printf`）可以通过 `extern "C"` 直接调用，此时 ABI 遵循平台的 C 可变参数约定。

```
extern "C" {
    fn printf(fmt: ConstPtr<c_char>, ...);
}
```

- `...` 只能出现在 `extern` 块中的声明里，且只能作为最后一个参数。Nabi 函数定义不能有 C 可变参数。
- C 的默认实参提升适用于可变位置上的实参：`bool`、`i8`、`i16`、`u8`、`u16` 和 `c_char` 作为 `c_int`（`i32`）传递，`f32` 作为 `f64` 传递，`str` 作为 `char*`（以 NUL 结尾的字节指针）传递。
- 聚合类型（struct / tuple / array）不能作为可变实参传递（编译错误）。

## 8.6.11. 函数指针 ABI

[函数类型](../004-functions/404-function-type.md)中的 `fn(...) -> ...` 在间接调用时使用相同的调用约定。

```
code = f.0                       ; the function value's code pointer
result = call code(f.1, ...)     ; indirect call: the environment, then the arguments
```

实参和返回的 ABI 相同，因此直接调用和间接调用共享同一接口，只有 8.6.6 中隐藏的 `nabi_tls` 地址例外：函数值不接收它。函数值的代码指针是一个 thunk，它自行读取该地址，再带着它调用函数。

## 8.6.12. 闭包调用

[闭包](../004-functions/405-closure.md)中描述的闭包是把环境和代码指针捆绑在一起的单个单元。

调用方式如下。

```
The environment pointer as the first argument, followed by the ordinary arguments.
```

闭包主体通过这个环境实参访问被捕获的变量。

主体像普通函数一样编译（环境只是第一个实参）。

## 8.6.13. 异步函数调用

[异步](../004-functions/412-async.md)中的 `async fn` 被调用时遵循普通函数调用 ABI，立即返回一个 Future ptr。

```
let f = async_fn(args);     // returns immediately (Future ptr)
let r = await f;             // coroutine mechanism
```

`await` 由普通调用（轮询目标 future）和状态机的返回（[8.10](810-lowering-coroutine-generic.md)）组成，在普通 ABI 之上工作。

## 8.6.14. 稳定性

C ABI 部分（8.6.1 ~ 8.6.3、8.6.10）遵循平台 C ABI，因此没有单独的稳定性决定：在平台保证兼容的范围内，Nabi 保持兼容。

nabi 到 nabi 的约定（8.6.6、8.6.11）和抛出函数的返回值布局（8.6.5）属于运行时 ABI；任何变更都遵循[概述](README.md#stability)中的稳定性政策。
