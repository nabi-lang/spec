# 8.7. 代码生成

`nabic` 自己生成机器码。它的代码生成器接收 nabi-mir，为目标写出目标文件，再由它自己的链接器生成可执行文件（[9.2.14](../009-tools/902-aot-pipeline.md#9214-linking-for-executables)）。同一个代码生成器服务于所有优化级别以及 REPL 单元（cell）。8.8 到 8.10 的降级规则描述它生成什么；本节给出这些规则前后的各个阶段。

## 8.7.1. 翻译流程

```
nabi source
   | parse, name resolution, type check
nabi-hir
   | specialize / monomorphize, desugar
nabi-mir
   | optimization (-O1 and above, 8.7.3)
nabi-mir
   | lowering: layouts, conventions, GC frames, barriers, checks (8.8 ~ 8.10)
LIR (one low-level form for every target)
   | instruction selection, register allocation (above -O0)
machine code
   | object writer
object (Mach-O, ELF, COFF, wasm)
   | nabic's linker
executable
```

所有步骤都在 `nabic` 内部运行。8.8 到 8.10 中的代码示例是伪代码：块和分支采用 nabi-mir 中的形式（`bb1:`、`if c then bb2 else bb3`、`goto bb4(x)`），在生成的代码有意义之处则写出按字节偏移的加载和存储。它们不是 `nabic` 会读取的格式。

## 8.7.2. 各阶段的职责

| 阶段 | 决定什么 |
|-------|-----------------|
| nabi-mir → 优化后的 nabi-mir | `-O0` 以上的内联与简化（8.7.3） |
| nabi-mir → LIR | 一切不依赖指令集的内容：每个值的布局（8.8）、调用约定（[8.6](806-calling-convention.md)）、影子栈帧、分配快速路径、写屏障、安全点轮询（8.9）、溢出与边界检查及其 panic 消息 |
| LIR → 机器码 | 某一指令集（`x86_64`、`aarch64`、i686、armv7、riscv64、riscv32、powerpc64le、s390x、wasm32）的指令；在 `-O0` 以上，还决定哪些值放在寄存器中 |
| 机器码 → 目标文件 | 容器格式（Mach-O、ELF、COFF、wasm 目标文件）及其重定位、栈展开信息，以及使用 `-g` 时的调试信息（[9.9.6](../009-tools/909-debug-tools.md#996-debugger-integration-gdb--lldb)） |
| 目标文件 → 可执行文件 | `nabic` 的链接器；`NABI_CC` 可以替换它（[9.2.14](../009-tools/902-aot-pipeline.md#9214-linking-for-executables)） |

## 8.7.3. 优化级别

| 级别 | nabi-mir | 值 |
|-------|----------|--------|
| `-O0` | 保持构建时的样子 | 各自放在自己的栈槽中 |
| `-O1` | 经过优化；循环中的调用按 `-O2` 的方式内联，其他地方只内联小函数、`#[inline]` 函数和只在一处被调用的函数 | 放得下时放在寄存器中 |
| `-O2` | 经过优化；在循环之外也内联较大的函数体 | 放得下时放在寄存器中 |
| `-O3` | 与 `-O2` 相同，在循环中内联较大的函数体，并展开保持标量的循环 | 放得下时放在寄存器中 |
| `-Os` | 经过优化；只有当函数体大约与调用本身一样小时（在循环中为其数倍）才内联调用 | 放得下时放在寄存器中 |

优化器内联对构建中拥有函数体的 Nabi 函数的直接调用：包自身的函数、泛型实例，以及标准库的函数（每次构建都会与程序一起编译标准库）。调用环从不内联到自身中；`#[inline(never)]` 和 `#[cold]` 函数，以及位于以 panic 结束的路径上的调用，都保持为调用。内联到循环中的函数体所含的调用，会作为该循环中的调用重新衡量。若某个调用把常量数组（`const` 表）传给被调用方只读取的参数，该调用会转向被调用方的一个副本，由副本自己构建该数组，因此调用不复制任何表。随后优化器进行复制传播和常量传播、折叠常量表达式、消除公共子表达式和死代码、简化控制流；对于进入时已知其走向的分支（例如内联的迭代器的 `next()` 返回的 `Option`，由外层 `for` 循环检测），直接跳过该分支；把自身尾调用变为循环；移除结果总能放下的溢出检查；并把循环不变的计算移出循环。在 `-O3`，它还会展开向量化器保留为标量的循环条带（8.7.8；保留浮点和的循环，或调用函数的循环）：一个完整的条带在两次检测计数器之间运行函数体 4 次（函数体较长时为 2 次）。程序计算的每个值、每个 trap（溢出、除法、边界）和每个副作用都保留，且顺序不变。

`-g` 在任何级别都不改变生成的代码。在 `-O0` 以上，优化器把它所做的事记录到调试信息中：它内联的每个函数体都是调用之下的一个独立作用域；对于其赋值被移除的具名局部变量，会改为记录持有其值的东西（一个常量、在该变量可见期间值不变的另一个局部变量，或就地构建的 struct 的字段）。随后代码生成器说明每个变量在代码各处的位置（[9.9.6](../009-tools/909-debug-tools.md#996-debugger-integration-gdb--lldb)）。在 `-O3` 展开的循环体副本中，作为另一个局部变量的值保留的变量，可能显示更早一次迭代的值。

指令选择在每个级别都相同，但在 `-O0` 以上，循环可能被向量化（8.7.8），并且 RISC-V 代码对每条有 16 位压缩（`C`）形式且无需重定位修补的指令采用该形式，对目标在其范围内的分支和跳转也是如此。影子栈帧、轮询和屏障在优化之后放置于实际编译的代码上（8.9）。代码面向目标的基线 CPU，但会使用 `-C target-cpu` 和 `-C target-feature` 开启的、代码生成器所用的特性（[0.6.4](../000-meta/006-platform-targets.md#064-simd)）：`x86_64` 上的 AVX2 向量循环和单指令位计数；`aarch64` 上的 LSE 原子操作、RCpc 获取加载和字节点积；`s390x` 上使用 `vector`、`riscv64` 上使用 `v` 的向量循环；`riscv64` 和 `riscv32` 上使用 `zbb` 的单指令循环移位；`x86_64` 上使用 `fma`、`armv7` 上使用 `vfp4` 的融合 `mul_add`；`-neon`、`-vsx` 和 `-simd128` 让所有循环保持标量。

## 8.7.4. 运算

- 整数和浮点算术、比较、`sqrt`、位计数（`count_ones`、`leading_zeros`、`trailing_zeros`）、`swap_bytes` 和原子操作都是指令（在没有 LSE 的 `aarch64` 上，原子读-改-写是一个独占加载 / 存储循环）。在 `-O0` 以上，原子操作的强度恰好等于程序要求的内存序，不会更强，采用通常的 C++ 映射：在 `x86_64` 和 `i686` 上，只有 `SeqCst` 存储会加栅栏；在 `aarch64` 上，`Relaxed` 加载或存储是普通的加载或存储，获取加载为 `ldar`（有 `rcpc` 时为 `ldapr`），释放存储为 `stlr`，读-改-写采用 LSE 或独占指令的获取 / 释放形式；在 `armv7` 上，释放之前和获取之后各有一条 `dmb`；在 `powerpc64le` 上，释放之前为 `lwsync`（`SeqCst` 时为 `sync`），获取之后为 `lwsync` 或 `isync`；在 RISC-V 上为 `fence` 以及 `aq` / `rl` 位；在 `s390x` 上只有 `SeqCst` 存储会串行化；`wasm32` 的原子操作是顺序一致的。在 `-O0`，每个原子操作都是顺序一致的，这满足所有内存序（[0.6.4](../000-meta/006-platform-targets.md#064-simd)）。
- 当指令集没有某个运算的指令时，代码调用平台为该运算提供的支持例程。在 armv7 上，这包括各种宽度的整数除法（`__aeabi_idiv`、`__aeabi_uidiv`、`__aeabi_ldivmod`、`__aeabi_uldivmod`）、64 位整数与浮点数之间的转换（`__aeabi_l2d`、`__aeabi_d2lz` 等）以及 64 位乘法的溢出检查（`__mulodi4`）。在软浮点的 riscv32 上，这包括所有浮点算术、比较和转换（`__adddf3`、`__ltdf2`、`__floatdidf` 等）以及 64 位除法（`__divdi3`、`__umoddi3` 等）。i686 在目标文件内部的一个例程中做 64 位整数除法。
- 在 `-O0` 以上，当目标有融合乘加指令时（`aarch64`、`powerpc64le`、`s390x`、`riscv64`；有 `fma` 的 `x86_64`，有 `vfp4` 的 `armv7`），`mul_add` 是一条融合乘加指令，其他情况下是对运行时 `nabi_f64_mul_add` / `nabi_f32_mul_add` 的调用；两者都只舍入一次。
- 其他浮点方法（`floor`、`round`、`sin`、`exp`、`pow` 等）是对运行时 `nabi_f64_*` / `nabi_f32_*` 函数的调用，这些函数再调用 libm（[8.5](805-extern-symbols.md)）：其结果来自目标的 libm，从不来自主机上的编译期求值。
- nabi-mir 的每个分支都是一次跳转或一个双路分支。对标签或整数的 `match` 是按分支顺序排列的比较链（8.9.3）；不构建跳转表。

## 8.7.5. 加速领域的库

Nabi 源代码无法直接访问代码生成器。一个供张量 / 自动微分 / SIMD / GPU 等加速领域的库接入代码生成器的后端接口已在计划中，但尚未实现：在 0.1 中，`nabic` 自己的代码生成器是唯一的代码生成器，[8.11.13](811-backend-contract.md#81113-separately-installed-code-generators) 中单独安装的代码生成器是面向 0.2 的草案。代码生成器必须对其目标文件保证什么，见 [8.11](811-backend-contract.md)。

## 8.7.6. `extern` 函数（运行时函数）

[Extern "C" 符号](805-extern-symbols.md)中列出的 `nabi_*` 函数按符号、以 C ABI（[8.6](806-calling-convention.md)）调用，并在链接时针对 `libnabir.a` 解析。字符串相等比较（因而字符串模式也是如此）调用 `nabi_str_cmp`。TLAB 快速路径、写屏障的快速路径和安全点轮询是内联代码；它们只在慢速路径上调用 `nabi_gc_alloc_slow`、`nabi_gc_wb_slow` 和 `nabi_runtime_yield`（8.9.9 ~ 8.9.11）。

## 8.7.7. TLS 访问

对 [Mutator TLS 槽](803-tls-slots.md)中 TLS 槽的访问经由线程局部块 `nabi_tls` 的地址进行。Nabi 函数从调用方那里把它作为隐藏的最后一个实参接收（[8.6.6](806-calling-convention.md#866-nabi-to-nabi-calling-convention)）；从 Nabi 外部进入的代码在入口处用目标的 TLS 访问序列计算一次该地址（[8.3.8](803-tls-slots.md#838-form-of-compiler-emission)）。此后每个槽都是在距该地址相应偏移处的一次加载或存储。

```
t = <nabi_tls address>            ; the hidden last argument, or computed once at entry
flag = load.u8 [t + 10p+8]        ; yield_flag: offset 88 when p = 8
```

## 8.7.8. 循环向量化

在 `-O0` 以上，在 `x86_64`（SSE2，或开启 `avx2` 特性时的 AVX2）、`i686`（SSE2）、`aarch64`（NEON）、`armv7`（NEON，仅整数 lane：NEON 会把次正规浮点数冲刷为零）、`powerpc64le`（VMX 和 VSX）、有 SIMD128 的 `wasm32`、有 `vector` 的 `s390x`（z13；有 `vector-enhancements-1` 时支持 4 字节浮点 lane，z14）以及有 `v` 的 `riscv64`（每个向量寄存器的 128 位，任意向量长度均可）上（[0.6.4](../000-meta/006-platform-targets.md#064-simd)），若一个循环让 `usize` 计数器以步长 1 递增到一个它不改变的上界，且在任何地方都不轮询（计数循环的一个条带，或一个短循环：[8.4.2](804-safepoint.md#842-emission-sites)），就可以在它前面加上一个向量循环（在 `-Os` 下仅限最多 24 条 nabi-mir 语句的函数体，且其向量循环与标量循环长度相当）。对 `List`、切片或字符串字节的 `for` 循环（`for x in xs`、`for x in xs[a:]`、`for (i, x) in xs.iter().enumerate()`、`for b in s.bytes()`）在其迭代器的 `next()` 被内联后就属于这种循环，区间循环同样如此；优化器移除了其边界检查的循环也是如此。向量循环在 16 字节（AVX2 下为 32 字节）的向量上工作，向量中的元素宽度相同，它不处理的迭代留给其后的标量循环。一个循环只有在其函数体仅做以下事情时才会得到向量循环：

- 在计数器处、计数器加一个小常量处，或计数器加一个循环不改变的值（切片的起点）处，读写缓冲区（`List` 的缓冲区）中的元素；
- 读取比其计算值更窄的元素时只是为了扩宽它们（对 `u8` 做 `b as u32`），写入更窄的元素时只写为它们收窄的值（`x as u8`），`powerpc64le` 以外的每个目标都如此；
- 对这些元素以及循环不改变的值进行计算：整数 `+`、`-` 和 `*`（回绕的或带检查的；`*` 限于目标能做乘法的宽度，带检查的乘法限于目标还能给出每个乘积高半部分的宽度：`x86_64` 和 `i686` 上为 2 字节 lane，`aarch64` 和 `s390x` 上为 1 到 4 字节，`wasm32` 上为 2 和 4 字节，`riscv64` 上为所有宽度）、`&`、`|`、`^`、`!`、按常量移位、比较、整数之间以及从 `bool` 出发的 `as`、浮点 `+`、`-`、`*`、`/`、取负、`sqrt`、`min` 和 `max`（`armv7` 上除外），以及目标及其向量单元都能融合时的 `mul_add`（`aarch64`、`powerpc64le`、`riscv64`、有 `fma` 的 `x86_64`、8 字节 lane 或有 `vector-enhancements-1` 时的 `s390x`）；
- 依据这类值分支（`if`、`&&`、`||`）：每个 lane 计算两侧，并保留其检测所选的结果。一侧可以读取每个 lane 都可以读取的元素（每次迭代都运行的块所读取的元素，或位于循环一直执行的边界检查之下的元素）。检测的两侧可以存储到同一个元素：这些存储会被合并。只在一侧的存储需要带掩码的存储（AVX2，4 字节和 8 字节的元素）；
- 提前离开循环（`return`、`break`、失败的边界检查）；
- 累积一个整数归约：`+` 或 `-`（回绕的或带检查的）、`&`、`|`、`^`、计数（`if c { n += 1 }`、`n += c as T`）、最小值或最大值（`m = m.min(x)`、`if x > m { m = x }`），可以在检测的一侧或多侧进行，或者字节乘积之和（`s += (a[i] as i32) * (b[i] as i32)`，在有 `dotprod` 的 `aarch64` 上每个 lane 四个乘积）；或者浮点最小值或最大值，同样采用上述两种方式。

向量化循环所做的，就是标量循环逐个元素所做的：

- 若一个向量中有会离开循环或触发 trap 的元素（溢出、失败的边界检查），该向量不会运行：标量循环从该向量的第一个元素开始接手，并在该元素处离开或 panic，此前的每个元素都已处理。
- 归约为每个 lane 保留一个部分结果，最后合并各 lane。带检查的求和把非负元素和负元素分开保留，它们界定了标量循环会产生的每个部分和（每次迭代的任一路径上只更新一次）；当任一界限放不下时，循环从头作为标量代码重新运行（这样的循环不写内存），因此它恰好在标量循环 panic 的位置 panic，或者根本不 panic。最小值或最大值让每个 lane 都从累加器开始；两个相等的整数可以保留任意一个，这不会显现出差别。字节乘积的带检查求和还保留各乘积绝对值之和，它界定了每个部分和；当该界限放不下时，循环作为标量代码重新运行。
- 浮点求和不会被向量化：浮点求和按程序中的顺序相加，换一种顺序舍入结果就不同。浮点最小值或最大值对每个输入都给出与标量循环相同的位。对于既不是 NaN 也不是零的数，最小（最大）值无论按什么顺序都是同一个值，因此可以由各 lane 求出：含有 NaN 或零（在某些目标上，标量 `min` / `max` 按操作数顺序保留零的符号）的向量不会运行，由标量循环接手它及其余部分；循环开始时累加器为 NaN 时，整个循环保持标量。映射 `y = a.min(b)` 同样把出现 NaN 或两个零相遇的向量留给标量循环。只有在程序调用 `mul_add` 之处，乘法和加法才会融合为一条指令。
- 不会写入标量循环不写的元素：检测一侧的存储以带掩码的方式写出，否则循环保持标量。
- 对可能是同一个列表的两个列表，其元素保持读写顺序：在向量会改变该顺序之处，只有当前置检测发现两个缓冲区不同时，向量循环才会运行。同一缓冲区中位于循环不改变的偏移处的两行（`r[o1 + i]` 和 `r[o2 + i]`）同样如此：只有当前置检测发现偏移相等或相距一整个向量时，向量循环才会运行。经由切片起点的索引（一次带检查的 `isize` 加法）在低于 `isize::MAX` 时是精确的：前置检测会检查起点和上界远低于该值，否则运行标量循环。
- 向量循环不会到达安全点，也不进行轮询；它在带轮询的标量循环再次运行之前最多运行 1024 次迭代。

使用 `-g` 时，向量循环的指令位于循环第一条语句的位置；在它运行期间，循环的变量保持其开始时的值。

## 8.7.9. 验证翻译

端到端测试（`compiler/nabic/tests/main/integration.rs`，覆盖 `tests/cases/` 中的程序）构建并运行 .nabi 文件，分别在 `-O0` 下以及在 `NABI_TEST_OPT=-O2` 时以优化方式运行；`NABI_TEST_TARGET` 让它们针对另一个目标运行。

这一验证确保本块中定义的降级规则是正确的。
