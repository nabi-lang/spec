# 0.1. 执行引擎与用户界面

Nabi 的执行模型有两个维度。一是执行引擎，它决定代码如何变成机器码；二是用户界面，即用户输入代码并接收结果的环境。引擎有两个，界面有三个。由于多个界面共用同一个引擎，引擎比界面少。

## 0.1.1. 执行引擎

### JIT（Just-in-Time）

JIT 引擎在代码片段输入后立即编译并运行它。一个输入单位，即一行或一个单元格，可以引用到该时刻为止累积的状态：变量、函数、导入的模块等。当新的输入覆盖了已有定义时，后续输入看到的是新定义。编译结果缓存在内存和磁盘上，所以重新运行相同的输入会立即完成。

### AOT（Ahead-of-Time）

AOT 引擎预先把整个源代码编译成单个产物：可执行文件或静态库 `.a`。启动时不产生编译开销，结果可以作为库被其他 Nabi 代码链接。但无法在运行时添加新代码。

### 语义相同

> [!IMPORTANT]
> 两个引擎共享相同的语义。在 JIT 下能工作的代码，在 AOT 构建中产生相同的结果。区别只在于**何时编译**。本规范同时适用于两个引擎；不存在只适用于其中一个的语义。

这一原则同样适用于入口点。输入到 REPL 和 Jupyter 的内容，与按顺序把顶层语句和项追加到可执行包的 `main.nabi` 末尾具有相同的含义。只有会话操作（重新运行或删除单元格、显示最终值）是交互式界面特有的（[4.16.10](../004-functions/416-entry-point.md#41610-relationship-to-jit--repl)）。

缩写 JIT 和 AOT 按[术语表](007-glossary.md)中的定义使用。

### 共用同一条流水线

JIT 和 AOT 都经过同一条编译流水线，直到 nabi-mir（[0.2. 编译流水线](002-pipeline.md)）。它们只在代码生成阶段分道扬镳。**JIT 引擎**用 Nabi 的代码生成器把每个输入直接编译成机器码，并在一个存活于整个会话的宿主进程中运行它（[9.6](../009-tools/906-jit-engine.md)）。**AOT 引擎**用同一个代码生成器生成代码，在 `-O1` 及以上进行优化，并链接出原生二进制文件（[9.2](../009-tools/902-aot-pipeline.md)）。两者遵循相同的运行时 ABI。

在这种结构下，一个编译器实现同时服务于两个引擎。因此，任何行为差异都必须归因于运行时环境（内存、线程、操作系统资源），而不是编译器。

## 0.1.2. 用户界面

### REPL

在 REPL 界面中，终端里输入的一行或一个表达式会被立即求值并打印结果。它主要用于探索、演示公式和检查类型。变量和函数定义在多次输入之间累积，最后一个表达式的值和类型会自动显示。

引擎是 JIT，输入单位是一行或一个表达式。

### Jupyter

Jupyter 界面作为 Jupyter / JupyterLab 的 Nabi 内核运行。求值以单元格为单位，结果以可视化、表格和文本的形式保留在笔记本中。这支持标准的数据分析工作流；重新运行单元格会替换之前的定义。

引擎是 JIT，输入单位是一个单元格。Jupyter 前端（JupyterLab、Notebook、VS Code 等）把 Nabi 内核作为独立进程运行，并通过基于 ZeroMQ 的 Jupyter 线路协议与之通信（[9.8](../009-tools/908-jupyter-integration.md)）。内核直接使用操作系统的文件系统、网络和外部进程。

### AOT 产物

在 AOT 产物界面中，直接运行从源代码构建的可执行文件，或把生成的静态库链接到另一个构建中。

引擎是 AOT。

## 0.1.3. 引擎与界面的对应关系

```
              ┌── REPL (terminal)
   JIT  ──────┤
              └── Jupyter (kernel, ZMQ)

   AOT  ────── direct artifact execution
```

三个界面共用两个引擎。

## 0.1.4. 语义基准

规范有歧义时，以 AOT 语义为准。JIT 逐个单元格地重现 AOT 语义。
