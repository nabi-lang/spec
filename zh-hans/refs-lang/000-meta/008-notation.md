# 0.8. 记法

本节总结本规范通篇使用的元记法约定。第 1 章到第 9 章都遵循这些约定，所以在阅读正文之前值得先查阅本节。

## 0.8.1. 代码 / 标识符记法

下表列出三种常用形式及其含义和示例。

| 记法               | 含义                                               | 示例                       |
|--------------------|----------------------------------------------------|----------------------------|
| `` ` ``（反引号）  | 关键字、标识符、词法单元、类型名、代码片段         | `` `let` ``、`` `i32` `` |
| 围栏（` ``` `）    | 多行代码块，注明语言名                             | ` ```nabi ` 或 ` ```ebnf`   |
| 行内代码           | 短代码片段                                         | `` `x + y` ``              |

正文中提到的关键字总是用反引号包裹，以便在视觉上与周围的文字区分开。

## 0.8.2. 强调

强调不只是视觉装饰；每种形式都有固定的用途，如下所列。

| 记法             | 含义                                 | 用途                                             |
|------------------|--------------------------------------|--------------------------------------------------|
| `*text*`         | **斜体**：概念上的强调               | 引入新术语、强调含义                             |
| `**text**`       | **粗体**：警告、关键决定             | “这是**编译错误**”、“**直接拒绝**”               |
| `> [!NOTE]`      | GitHub 风格的信息框                  | 旁注、非正式的指引                               |
| `> [!WARNING]`   | GitHub 风格的警告框                  | 陷阱、常见误解                                   |
| `> [!IMPORTANT]` | GitHub 风格的重要框                  | 核心不变量、必须遵守的规则                       |

## 0.8.3. 语法定义：BNF 变体

本规范中的语法用一种 EBNF 变体书写。使用的元字符如下。

| 元字符              | 含义                     | 示例                           |
|---------------------|--------------------------|--------------------------------|
| `name ::= rhs`      | 定义                     | `path ::= ident ("::" ident)*` |
| `\|`                 | 选择                     | `bool ::= "true" \| "false"`    |
| `?`                 | 零个或一个（可选）       | `param ::= ident (":" type)?`  |
| `*`                 | 零个或多个               | `args ::= expr ("," expr)*`    |
| `+`                 | 一个或多个               | `digits ::= digit+`            |
| `( ... )`           | 分组                     | `(a \| b) c`                    |
| `"..."`             | 字面文本                 | `kw_let ::= "let"`             |
| 非终结符（斜体）    | 引用另一个定义           | `expr ::= literal \| call` |

语法块用 ` ```ebnf ` 或普通围栏书写。例如，函数声明的语法可以写成如下形式。

```ebnf
fn_decl     ::= "fn" ident "(" params? ")" ret_ty? block
params      ::= param ("," param)* ","?
param       ::= ident (":" type_expr)? default_value?
ret_ty      ::= "->" type_expr
default_value ::= "=" expr
```

语法只是**形式的参考定义**。语义在正文中定义，所以仅凭语法无法确定程序的含义。

## 0.8.4. 交叉引用

对其他节的引用保持一致的写法。对另一节的引用同时给出**稳定的节号**和**相对路径链接**。

```markdown
[3.2 Precedence and associativity](../003-expressions/302-precedence-and-associativity.md)
```

正文中顺带提及的非正式引用可以只用节号。

> 见规范 2.7.4 中的 niche 规则。

采用这种形式，即使文件被重命名，含义也得以保留。文件路径由自动化工具更新。

## 0.8.5. 代码示例约定

代码示例同样遵循固定的约定。下面是最基本的形式。

```nabi
// short one-line comment
fn example() -> i32 {
    let x = 42;        // x is i32, fixed by the return (1.6.3)
    return x;
}
```

编写代码示例的规则如下。第一，每个代码示例都必须是某个**可编译的** Nabi 程序的一部分。第二，代码片段用 `// ...` 标记，并在正文中说明其上下文。第三，故意写错的示例必须在正文中明确说明，并附有 `// ERROR: ...` 注释或文字解释。最后，执行结果或输出用 `//→ ` 注释标记。

下面的示例应用了最后一条规则。

```nabi
let r = 1 + 2;        //→ 3
let s = "hello";      //→ str
```

## 0.8.6. 稳定的节号

每一节都有一个永久的 `<chapter>.<section>(.<sub>)*` 编号。即使文件被重命名或移动，编号也不会改变，所以它可以作为引用的稳定锚点。编号方案如下。

| 形式      | 示例      | 含义                                 |
|-----------|-----------|--------------------------------------|
| `C.S`     | `2.7`     | 第 C 章的第 S 节                     |
| `C.S.s`   | `2.7.4`   | C.S 的第 s 小节                      |
| `C.S.s.x` | `2.7.4.1` | 更深一层的小节（少见）               |

交叉引用总是使用这个编号。文件路径（`002-types/207-...md`）只是为了方便 IDE 和 GitHub 而附加的；引用的实质始终是节号。

## 0.8.7. 记法的局限

这套记法只定义**参考形式**。编译器究竟如何解析输入并赋予含义，取决于正文、代码示例和编译器实现。也就是说，**仅凭 BNF 并不能确定全部含义**。对含义的解释权始终在于正文。
