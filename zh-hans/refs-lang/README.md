# Nabi 语言参考

这是 Nabi 编程语言的形式规范。它定义语言的**语法**和**语义**，并提供编译器和运行时必须遵循的规范性基准。

参考日期为 2026-10-23。编译器和标准库的实际实现位于单独的仓库中。

---

## 章

Nabi 规范由十章组成，编号为 0 到 9。各章并非随意排列：它们按依赖顺序排列，使每一章的定义只使用前面章节中的概念。第 0 章（元）位于最前；之后的顺序从词法结构开始，逐步进入更抽象的领域，最后以执行环境和工具结束。

第 0 章汇集了后续每一章都以之为前提的构建模型、平台假设和记法；读过一遍之后，正文中反复出现的约定就不必再去查找。接下来是第 1 章词法结构，原因很简单：只有在词法单元的形状确定之后，类型和表达式才能成形。然后，第 2 章（类型）、第 3 章（表达式）和第 4 章（函数）依次介绍在单个模块内创建和操作值所需的核心结构。

模块、可见性和包特意到第 5 章才出现：只有在单个文件内的语义完全确定之后，才能讨论文件边界和封装。第 6 章元系统以第 1 章到第 5 章的全部内容为前提。属性、`lang` / `literal` / `keyword` 魔法和反射作用*于*词法结构、类型、表达式、函数和模块，所以只有在这些对象都定义好之后，它们的含义才清晰。

最后，第 7 章（运行时模型）、第 8 章（ABI 与降级）和第 9 章（执行与工具）涵盖把表层语言变成实际执行的各个步骤。第 7 章抽象地描述对象布局、GC 和调度器；第 8 章确定由内存和寄存器中的哪些位来实现它们；第 9 章把这一切串联起来，规定 `nabic` CLI、`nabi` 前端以及用户接触到的构建输出的形式。

## 如何阅读

### 初读（按 0 → 9 的顺序）

本规范的写法保证：按从第 0 章到第 9 章的顺序阅读时，每个新引入的概念都只用已经见过的概念来解释。也就是说，任何一章都只使用它之前章节中的概念，这一不变量始终成立。因此，初次阅读的读者应当按顺序阅读、不要跳过；这是最短的路径。

交叉引用中的定义依赖只能向后：理解当前文档不得需要后面文档中的定义。对于跨领域的主题（方法分派 ↔ trait 分派、算术表达式 ↔ 运算符魔法等），可以出现向前的指引作为补充参考。即便如此，阅读当前文档也不得*需要*向前引用的目标；它只用作指向更多背景的指引。

### 作为参考（查找特定条目）

规范也经常被用来快速查找某个特定条目，而不是用来学习。为此，每个条目都有一个稳定的节号（`<chapter>.<section>` 或 `<chapter>.<section>.<subsection>`），交叉引用总是使用这个编号。文件路径可能随时间变化，不用于引用。

```
spec 2.7.4    →  002-types/207-niche-optimization.md (4th subsection)
spec 4.8      →  004-functions/408-trailing-closure.md
spec 6.10     →  006-meta-system/610-reflection.md
```

### 搜索

整个规范都是 Markdown，所以可以直接用 ripgrep 或 grep 搜索。不需要单独的索引或搜索工具是有意为之：阅读规范和构建规范用的是同样的工具。

```bash
rg "trait" spec/en/refs-lang/
rg "::=" spec/en/refs-lang/                # search BNF definitions
rg "i32" spec/en/refs-lang/002-types/      # limit to one chapter
```

## 记法约定

下面总结正文通篇一致使用的约定。完整的定义和例外见 [000-meta/008-notation.md](000-meta/008-notation.md)。

| 记法                         | 含义                                       |
|------------------------------|--------------------------------------------|
| `` `let` ``                  | 关键字 / 标识符（代码字体）                |
| `` `i32` ``                  | 类型名（代码字体）                         |
| `*emphasis*`                 | 概念上的强调（斜体）                       |
| `**strong**`                 | 警告 / 关键决定（粗体）                    |
| `> [!NOTE]` / `> [!WARNING]` | GitHub 风格的提示框                        |
| `name ::= ...`               | BNF 风格的语法定义                         |
| `<chapter>.<section>`        | 稳定的交叉引用键（例如 `2.7.4`）           |

代码字体只用于表层语言中实际出现的词法单元；概念上的强调使用斜体。关键决定和需要注意的地方用粗体标出。

## 目录 / 文件命名

文件名和目录名本身就被设计为交叉引用的键。

| 位置     | 形式                                   | 示例                             |
|----------|----------------------------------------|----------------------------------|
| 章       | `<NNN>-<descriptive-name>/`            | `002-types/`、`006-meta-system/` |
| 节       | `<NNN>-<name>.md`                      | `207-niche-optimization.md`      |
|          | （一位章号 + 两位节号）                 |                                 |
| README   | 每章中的 `README.md`                   | 章的目录 + 指引                  |

三位前缀的第一位是章号，后两位是节号。例如，`207` 表示“2.7”，即类型系统一章的第 7 节，这个编号直接用作稳定的交叉引用键。

这种命名方案是 [Rust Reference](https://doc.rust-lang.org/reference/) 的描述性文件名与层级式章节组织，以及 [Python Language Reference](https://docs.python.org/3/reference/) 的编号章 / 节方案之间的折中。它同时满足两种需要：编号对机器更友好，名称对人更友好。
