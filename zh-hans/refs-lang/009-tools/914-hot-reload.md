# 9.14. 热重载

*热重载*把一次编辑应用到正在运行的程序上：`nabi dev`（9.10.8）重新构建源代码发生变化的包，程序在一个安全点加载新代码，并保留其堆、线程和静态变量。它是构建在插件（[9.12](912-plugins.md)）之上的开发工具：每个本地包的代码都位于一个可以替换的插件中，程序的其余部分在运行期间从不改变。

## 9.14.1. 模型

一个开发会话中有两类模块：

- *宿主*：运行时、标准库的状态，以及每个注册表包或 git 包。每个会话只构建一次。它是一个普通的插件宿主（[9.12.1](912-plugins.md#9121-模型)），其 `main` 为 `std::reload::host_main()`：它连接开发通道，加载 `NABI_DEV_PLUGINS` 所指定的热插件，并调用根包的 `main`（`NABI_DEV_MAIN`）。
- *热插件*：每个本地包一个（根包、它的 `path` 依赖、它所使用的工作区成员），用 `nabic build --hot` 构建（[9.1](901-nabic-cli.md)）。每次保存都会为它所涉及的包生成一个新版本。

在 `--hot` 下，每次对热包中函数的调用都经过一个槽，槽以函数修饰后的名称及其签名为键。加载一个版本时，会把每个已加载版本中的每个槽绑定到具有相同键的最新函数体。因此：

- 函数体发生变化的函数，从任何地方（包括旧版本的代码）调用时都使用其新形式；
- 签名发生变化的函数会得到新的键和新的槽：针对旧签名构建的调用者继续调用旧的函数体，新的调用者调用新的函数体；
- 旧版本保持映射，直到会话结束。

热包的包哈希（[9.5](905-symbol-mangling.md)）在整个会话中固定（由包名派生），因此符号的名称在各版本之间保持不变。注册表包和 git 包保留其内容哈希。

`--hot` 的代价是：每次调用热包都多一次加载和一次间接跳转，热函数不跨函数内联，保留帧指针，以及根重新读取规则（[8.4](../008-abi/804-safepoint.md)）。普通构建（`nabi build`、`nabi run`）没有这些开销。`--hot` 只构建 dev 构建配置。

## 9.14.2. 版本何时生效

程序在其开发通道线程上加载版本，并在所有线程的一次停顿中应用它，这与回收所用的停顿相同（[7.3](../007-runtime/703-gc-algorithm.md)）：

- 仅代码的变化在下一次停顿时生效。
- 类型布局的变化在第一个没有任何栈帧持有已变化类型的值（9.14.4）的停顿时生效；然后迁移存活的值（9.14.3）。
- `std::reload::point()`（[3.13](../../refs-standard-libraries/300-std/313-reload.md)）请求一次停顿，通常是布局变化得以通过的地方。在 `nabi dev` 之外它什么也不做。

暂时无法应用的版本保持待定，并在每次停顿时重试；下一次保存会替换它。永远无法应用的版本会被拒绝，程序继续运行已有的代码。

## 9.14.3. 允许哪些变化

编译器把新版本的类型与正在运行的版本的类型（`--hot-base`，即写在每个版本旁边的 `.layout` 文件）进行比较，并把程序无法迁移的变化作为编译错误拒绝：

| 变化 | 结果 |
|--------|--------|
| 添加带默认值的字段（`mana: i32 = 0;`） | 允许；存活的值获得默认值 |
| 添加不带默认值的字段 | 错误：``new field `mana` needs a default while the program runs: write `mana: i32 = 0;` (or restart with `r`)`` |
| 删除字段 | 允许；丢弃其值 |
| 字段重新排序 | 允许 |
| 用 `#[renamed_from("hp")] health: i32` 重命名字段（[6.2](../006-meta-system/602-built-in-attributes.md)） | 允许；值被保留。指定一个不存在的字段是错误，错误消息会列出旧字段。 |
| 字段的类型发生变化 | 错误：``field `hp` of `Player` changed from `i32` to `f64` while the program runs; give the new field its own name with a default (`health: f64 = 100.0`) to start it fresh, or restart with `r` `` |
| 添加枚举变体或重新排序 | 允许；标签按名称映射 |
| 删除枚举变体 | 编译时允许；只要有存活的值持有该变体，版本就等待：``waiting: a live `State::Paused` exists`` |
| 变体的载荷发生变化 | 按变体逐个，与字段相同 |
| 泛型参数发生变化，或结构体变成枚举 | 错误；需要重新启动 |
| 添加、删除或修改 trait 实现 | 允许；替换 `any Tr` 的分派条目 |

迁移是一次完整回收的最后阶段：每个已变化类型的对象都被改写为新布局，保留的字段按名称（或 `#[renamed_from]`）对应，新增的字段取其默认值，删除的字段被丢弃，枚举变体按名称匹配。新布局放得下时对象被原地改写，否则改写到一个新对象中，并更新堆中指向它的每个引用。需要变大的有根对象（栈帧的局部变量、全局根）不会被移动：它会阻止这次变化（9.14.4）。在世界停止时先做一次检查，找出阻止变化的对象，因此无法进行的迁移不会改变任何东西。

## 9.14.4. 仍在运行的代码

| 对象 | 规则 |
|-------|------|
| 旧函数的栈帧 | 在旧代码中运行完毕；它发出的调用到达新代码 |
| `main` 自身的循环 | 在整个会话中都是旧代码：每帧的工作应当放在 `main` 调用的函数中 |
| 持有已变化类型的值的栈帧 | 阻止布局变化：``waiting: `main` (src/main.nabi:12) holds a `World` across `reload::point()`; keep it in a `reload::State`: `let world = reload::State::new(World::new());` ``。`--hot` 在编译时会在同一位置发出警告。 |
| 闭包 | 保留创建时的函数体；环境中持有已变化类型的闭包会阻止布局变化：``waiting: a closure made in `spawn_wave` (src/wave.nabi:30) holds an old `Enemy` `` |
| 挂起的协程或任务 | 在旧代码中恢复；持有已变化类型的协程或任务会阻止布局变化，消息会指出它是在哪里创建的 |
| 静态变量 | 保留其存储和值；新的静态变量从其初始化式开始；类型布局发生变化的静态变量会被迁移 |
| `any Tr` 值 | 分派到最新的实现 |
| 需要变大的、已变化类型的有根、被固定或被取地址的对象 | 阻止布局变化 |
| 内联持有已变化类型的值的 `any`，或一个未结束的不回收区间 | 阻止布局变化 |

## 9.14.5. 开发通道

`nabi dev` 通过一个通道与程序通信。它在启动程序之前创建该通道，并在程序的环境中以 `NABI_DEV` 指明：unix 流套接字的路径，或在 Windows 上为命名管道的名称（`\\.\pipe\nabi-dev-<pid>-<n>`）。设置了 `NABI_DEV` 时，运行时在启动时连接；没有设置时启动的程序从不打开通道，`std::reload::active()` 为 false。

每条消息是以 `\n` 结尾的一行 UTF-8。

| 发送方 | 行 | 含义 |
|------|------|---------|
| 程序 | `hello 1 <pid>` | 第一行：协议版本 1 |
| `nabi dev` | `load <path>` | 加载此文件，即某个热包的新版本。一起变化的多个包以多行发送，依赖在前。 |
| 程序 | `applied <pkg> v<n>: <what>` | 版本已生效：`applied game v3: 4 functions, 1 type (Enemy: +mana), 120 objects migrated` |
| 程序 | `waiting <pkg> v<n>: <why>` | 尚未生效（9.14.4）；原因变化时再次发送；之后还会有针对同一次加载的最终一行 |
| 程序 | `refused <pkg> v<n>: <why>` | 该版本不会生效；程序保留其代码 |
| 程序 | `superseded <pkg> v<n>` | 在等待期间，同一个包的更新的 `load` 替换了这一个 |

`<pkg>` 是代码中所写的包名，`<n>` 是程序计数的版本号（1 是启动时的版本）。各次加载按发送顺序生效，等待中的加载会阻止排在它后面的加载；同一个包的更新的加载会取代等待中的那一个。每个 `load` 恰好得到一个最终回复（`applied`、`refused` 或 `superseded`），同一个包的回复按其加载的顺序到达；不同包的回复则不一定。`nabi dev` 在发送下一个 `load` 之前从不等待回复。对未知的行回复 `refused <line>: unknown request`。通道结束即程序结束。

## 9.14.6. 热重载不涵盖的内容

- 注册表包和 git 包、宿主以及 `nabi.nabion`：对它们的修改会重新启动程序（9.10.8）。
- 把字段的值转换为新类型。
- 把已有的闭包迁移到新的函数体。
- C 栈帧中持有的值：位于 C 回调之下的热栈帧会阻止布局变化。
- wasm 目标、release 构建以及 REPL。
- 重新加载已发布程序所加载的插件：热重载仅用于 `nabi dev`。
