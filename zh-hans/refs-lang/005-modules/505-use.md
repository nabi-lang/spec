# 5.5. `use`（导入）

`use` 关键字（[关键字](../001-lexical/105-keywords.md)）把其他模块的项引入当前模块的可见名称空间。

## 5.5.1. 基本形式

```
use_stmt    ::= "use" use_tree ";"
use_tree    ::= path "::" "*"
              | path "::" "**"
              | path "::" "{" use_tree ("," use_tree)* ","? "}"
              | path ("as" identifier)?
path        ::= path_root ("::" identifier)*
path_root   ::= "pkg" | "sup" | "::" identifier | identifier
```

glob（`*`、`**`）不接受 `as` 别名：它们一次导入许多项，单个别名没有意义。因此 `path ("as" identifier)?` 只适用于单项导入。

```nabi
use foo::bar;
use std::time::SystemTime;
use pkg::geom::Point;
```

基本结构是 `use`、一个路径和结尾的 `;`。路径的最后一个标识符成为该项在当前模块中的名称。`use` 之后，就可以用 `bar`、`SystemTime`、`Point` 这样的短名称引用该项。

## 5.5.2. 多项导入：`{...}`

前缀相同的多个项可以归在一行中。

```nabi
use foo::{a, b, c};
use std::time::{SystemTime, UNIX_EPOCH};
```

`{..}` 中的每个元素都接在该组已解析的前缀之后。前缀可以为空（到达根的 `pkg::{..}`、`sup::{..}`）。因此在任何模块中，`use p::{a, b}` 都恰好等价于：

```nabi
use foo::a;
use foo::b;
```

- 组可以嵌套，也可以包含 `*`、`**` 和 `as`（`use foo::{bar::{x, y as z}, baz::*};`）。
- 组内的 `self` 是错误。
- 每个叶子必须解析为一个项、一个枚举变体或一个模块。否则在该叶子处报告“unresolved import”错误。

## 5.5.3. 别名：`as`

`as` 关键字为导入的项重新命名。

```nabi
use foo::very_long_name as short;
use core::collections::Dict as Map;
```

`as` 后面跟新名称；在当前模块中只有新名称可见，原名称不可见。

它也可以在多项导入中使用。

```nabi
use foo::{a as alpha, b, c as charlie};
```

## 5.5.4. glob：`*`（浅层）

一次导入一个模块的所有可见项。

```nabi
use foo::*;                    // all visible items of foo
```

规则：`*` 必须是最后一个词法单元，所以 `use foo::*::bar` 这样的形式是错误（ERROR）。只导入调用方能看到其可见性的项（[可见性](506-visibility.md)）：即 `pub` 的项、同一包内 `pub(pkg)` 的项等，其可达范围包含调用方。只导入 `foo` 的**直接**子项；子模块中的项不导入（那是 `**` 的作用）。块中的 glob `use` 也作用于该块中声明的项的头部（[3.9.1](../003-expressions/309-block-expressions.md#391-形式)）。模块自己定义的项优先于通过 glob 导入的同名项：glob 让步，且不报告任何内容（同名的具名导入则是错误，见 5.5.12）。

## 5.5.5. 递归 glob：`**`（深层）

递归导入，包括子模块。

```nabi
use foo::**;                   // all items of foo + all items of foo's child modules + ...
```

它一次导入各级子模块中的每个可见项，所以范围比浅层 glob（`*`）大得多。它常用作大型库的 prelude 形式。递归 glob 导入模块项和 `enum` 变体，从不导入类型的关联项：在 `use core::time::**;` 之下，单独的 `MAX` 并不指 `Duration::MAX`。

## 5.5.6. glob 与递归 glob 的冲突

多个 glob 导入同一个名称时，会发生冲突。

```nabi
use foo::*;
use bar::*;
// if both have a name 'item', that name is ambiguous and using it is an ERROR.
```

可以显式导入其中一个，或者指定别名来解决。

```nabi
use foo::item;                 // explicit: only foo::item is visible
use bar::item as bar_item;      // alias: both under different names
```

## 5.5.7. 路径的起点

路径的起点遵循[路径（5.7.1）](507-paths.md#571-路径的起始标识符)的规则。`pkg::` 从当前包的根开始。`sup::` 从父模块开始，可以链式写作 `sup::sup::...` 向上多级。`std`、`core`、`bare` 指标准库层级，除非本地名称占用了它（[5.7.4](507-paths.md#574-stdcorebare标准库层级)）。前导 `::`（`use ::std::fs;`）指一个层级或本包的某个依赖，不受本地名称影响（[5.7.10](507-paths.md#5710-空路径与前导-)）。否则，普通标识符只要是当前可见的名称（子模块、已 `use` 的名称等）就可以使用。同一模块的子项仅凭其标识符就能访问，所以没有单独的 `self::`。

路径的第一个标识符指名一个模块或类型，所以以模块名导入的函数或常量不会取代该模块：有 `mod norm;` 时，`pub use norm::norm;` 导入函数 `norm`，之后的 `norm::other` 仍然从该模块开始。

```nabi
mod norm;                       // holds `pub fn norm` and `pub fn other`
pub use norm::{norm, other};    // the function `norm` and `other`
let a = norm::norm(-2.0);       // the module `norm`
```

### 导入 `enum` 变体

`enum` 的变体是该 `enum` 之下的项，所以可以用 `use` 导入。`use` 路径也可以从当前可见的类型名开始。

```nabi
use Shape::{Circle};                // a single variant
use Shape::{Square as Sq};          // alias
use Shape::*;                       // all variants
use Result::*;                      // starts with a visible type name
```

不写 `use` 时，在期望类型为其枚举的位置，变体可以单独书写（[2.4.8](../002-types/204-enum.md#248-由期望类型确定的裸变体)）：如在返回 `Result` 的函数中，以及在对 `Result` 进行的 `match` 中的 `Ok` / `Err`。模式中的单独名称解析为已导入的变体或被匹配值所属枚举的变体时，该名称匹配该变体，而不是创建新绑定。

```nabi
match r {
    Ok(v)  => v,
    Err(e) => fallback(e),
}
```

## 5.5.8. `use` 可以出现的位置

`use` 可以出现在模块级或函数体级。

```nabi
// module level: visible throughout that module
use foo::bar;

fn f() {
    // inside a function: visible only within that function
    use foo::baz;
    let x = baz();
}
```

函数内的 `use` 是该函数的局部导入，不对外暴露。因此可见性关键字（`pub`）在那里没有意义。本项目的风格是把每个 `use` 放在文件顶部：警告 lint `local_use`（[6.2](../006-meta-system/602-built-in-attributes.md)）会报告函数体内的 `use`。

## 5.5.9. `use` 的可见性

```nabi
pub use foo::bar;               // exposed outside (re-export)
pub(pkg) use foo::bar;          // exposed only within the same package

use foo::bar;                   // module-private: visible only within the same module
```

`pub use` 是重新导出。详情在[可见性](506-visibility.md)中定义。

## 5.5.10. `core` 的自动导入

编译器在标准库之外的每个 Nabi 源文件开头隐式应用 `use core::prelude::*;`。prelude 是一份固定的 `core` 名称列表（[stdlib 0.2.3](../../refs-standard-libraries/000-meta/002-import.md)）：顶层 core 模块、常用的集合类型与核心类型、在 `impl` 头部和约束中书写的 trait，以及打印和 panic 函数。其他 core 项通过 prelude 模块指名（`task::sleep`、`ops::Add`）或导入。隐式导入在查找中排在最后（[5.7.1](507-paths.md#571-路径的起始标识符)），所以模块自己的项和 `use` 会遮蔽它。`#![no_implicit_nabi]` 为一个文件关闭它。

除 `core` 之外的两个层级 `bare`（危险区域）和 `std`（依赖目标）**不在**自动可见范围内，需要显式导入。详情在[标准库层级](../000-meta/005-standard-libraries-tiers.md)中定义。

标准库之外的每个模块（外部包、用户库）也需要显式导入。包中名为 `prelude` 的模块不会被自动引入。它只是库作者选用的惯用名称，所以用户必须显式导入它，如 `use my_lib::prelude::*;`。

```nabi
// library side
pub mod prelude {
    pub use pkg::api::core::*;
    pub use pkg::api::ext::*;
}

// user side
use my_lib::prelude::*;            // visible only when imported explicitly
```

## 5.5.11. 两次导入同一模块或项：允许

```nabi
use foo::bar;
use foo::bar;                   // OK: duplicate import is harmless
```

重复导入同一个项没有副作用，是允许的。同一性检查确认它确实是同一个项时，即可通过。

## 5.5.12. 来自不同模块的同名项：冲突

```nabi
use foo::Item;
use bar::Item;                  // ERROR: 'Item' already imported
```

从不同模块导入同一个短名称是冲突。为其中一个指定别名即可解决。

与声明项时一样，函数、常量和 static 构成一个名称空间，模块和类型构成另一个：同名的函数和模块不冲突（`use core::channel;` 与 `use core::channel::channel;` 并存）。

```nabi
use foo::Item;
use bar::Item as BarItem;       // OK
```

具名导入（`use a::f;`、`use a::{f}`，或针对 `g` 的 `use a::f as g;`）与模块中定义的同名项，如果处在该导入所占的名称空间中，就是编译错误（`E0032`，[9.9.4](../009-tools/909-debug-tools.md#994-诊断--错误消息)）：否则该项会悄无声息地隐藏导入。用另一个名称导入它（`use a::f as a_f;`），或者删除该 `use`。类型导入与同名的值项并存不冲突，glob 导入则让位于模块的项（5.5.4）。

```nabi
use shapes::square;
fn square(x: f64) -> f64 { x * x }    // ERROR: `square` is both imported from `shapes::square` and defined in this module
```

## 5.5.13. `use` 的求值与效果

`use` 只改变编译期的名称解析信息，对运行时行为没有直接影响。`use` 本身不执行任何代码；它只是在当前模块的名称表中添加一个别名。

## 5.5.14. 导入模块本身

```nabi
use foo::geom;                  // imports the module foo::geom itself
let p = geom::Point { ... };    // use geom as a short name
```

不仅可以导入项，也可以导入模块本身。此时模块的名称（最后一个标识符）作为短名称在当前模块中可见；这常用于通过子模块访问其中的项。
