## 定位

类型是编译器据以判断一个值允许具有什么形态和行为的信息。每个 Nabi 值都属于某个类型；不存在无类型的值。

变量略有不同。变量要么固定为一个类型（静态），要么是可以容纳多种类型的槽（动态），两种模式共存于同一门语言中。

## 两种模式：静态与渐进

```
static (explicit)   let x: i32 = 42i32;     x is always i32
static (inferred)   let z = 42i32;          z is fixed to the initializer's type i32
gradual (any)       let y: any = 42i32;     y is a slot that can hold any type
```

静态变量是在声明处写出类型、或省略类型而由初始化表达式推断的变量；它始终只持有该类型的值。渐进变量是在类型位置写了 `any` 的变量；这样的变量是动态槽。静态是默认的；动态只存在于写了 `any` 的地方。

本章只确立两种模式共存于同一门语言中这一点。

动机见[执行引擎与用户界面](../000-meta/001-execution-modes.md)：REPL/Jupyter 中的探索和 [AOT](../000-meta/007-glossary.md#aot-ahead-of-time) 静态编译必须共享同一份代码。因此，探索性代码倾向于使用省略类型的推断风格，库代码使用显式风格，动态槽只在真正需要的地方写作 `any`。

## 语言定义的内容

语言规范直接定义以下与类型有关的内容。

类型表达式的语法，即类型名如何书写。创建类型的容器语法：`struct`、`enum`、`union`、`trait`、`impl`、泛型以及和类型（`|`）。动态槽（`any`）的含义，以及泛型的单态化规则，即在调用处按类型[特化](../000-meta/007-glossary.md#specialize)。最后是编译器必须识别的类型系统不变式，例如 trait 不能作类型的禁令和 niche 优化规则。

## 标准库定义的内容

标准库负责以下与类型有关的内容。

所有原始类型的名称和含义：`i32`、`f64`、`bool`、`str` 等。所有集合类型：`List`、`Dict`、`Set`、`Tuple` 等。类型之间的所有转换，例如 cast、from 和 into。trait 的内容：哪些 trait 有哪些方法、哪些类型实现了它们。最后，字面量求值为哪个类型，也由标准库通过处理器决定。

> [!IMPORTANT]
> 本章只定义形态。内容在库规范中定义。

## 渐进类型的边界

渐进类型只适用于写了 `any` 的地方。省略类型注解永远不会产生动态槽。

没有类型注解的变量成为由其初始化表达式类型推断出的静态槽。没有类型注解的函数参数使该函数成为泛型函数，在调用处单态化（`pub` 或 `pub(pkg)` 函数要写出每个参数类型）；它不会成为动态槽，因此应当表现为渐进的参数必须显式写作 `any`。结构体字段需要类型注解。省略返回类型的函数由主体推断返回类型；如果无法推断，就是编译错误。在 `pub` 或 `pub(pkg)` 函数上，缺少返回类型表示 `()`。

这一边界把运行时[分派](../000-meta/007-glossary.md#dispatch)的开销限制在写作 `any` 的位置上。变量、参数和字段要么是静态的，要么显式为 `any`。

## trait 不能作类型

trait 名不能直接写作变量、参数或返回类型。需要多态时，使用泛型、和类型，或受约束的 `any Trait`。

运行时分派被限制在写作 `any` 的位置上（`any`、`any Trait`）。

## 单态化

泛型函数和类型在调用处或实例化处，为每一组具体类型元组产生单独的编译结果。

例如，如果同一个泛型函数在两个调用处分别以 `i32` 和 `f64` 使用，就会生成两个不同的函数体。因此间接调用的开销为零，性能与直接调用相同。代价体现为编译时间和二进制文件大小，但这大部分被丢弃不可达的实例以及链接时的死代码剥离所抵消。
